# अपना wing बनाना

wing (विंग) **एक ऑब्जेक्ट** है। न किसी क्लास को इनहेरिट करता है, न कोई अलग
रजिस्ट्रेशन प्रक्रिया चलती है — `createNabiWith` को दी जाने वाली सरणी में डाल
देना ही रजिस्टर करना है।

बोल्ड, तालिका, अपलोड — सब यहाँ लिखे कक्षों को भरकर ही बने हैं। हाथ से बनाया
wing भी मूल wing जैसी **वही शर्तों** में काम करता है — कोई अलग शॉर्टकट नहीं है।

---

## सबसे छोटा wing

यह एक इनलाइन मार्क है जो `<kbd>` को जानता है।

```ts
import { createNabiWith, mountSurface, simpleMark, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const kbdWing: Wing = {
  ...simpleMark({
    w: 'kbd',                                                   // इस wing का नाम — सहेजे मान का `w` यही होगा
    toHtml: (_node, children, ctx) => ctx.element('kbd', children()),   // बाहर जाने वाला चित्रण
  }),
  // भीतर आने वाले HTML में `<kbd>` का मालिक होने का दावा
  claim: (el, inner) => (el.tag === 'kbd' ? [{ w: 'kbd', ch: inner(false) }] : null),
}

const surface = document.querySelector<HTMLElement>('#editor')!
const { nabi, registry } = createNabiWith([kbdWing])
mountSurface({ nabi, registry, root: surface })
```

अब `<kbd>` दस्तावेज़ में बना रहता है। पेस्ट करने, `setHtml()`, सहेजने और फिर से
लोड करने के बाद भी वैसा ही रहता है।

```
रजिस्टर किया    <p>दबाएँ: <kbd>Ctrl</kbd>+<kbd>S</kbd></p>   →   वैसा ही रहता है
रजिस्टर नहीं किया <p>दबाएँ: <kbd>Ctrl</kbd></p>              →   <p>दबाएँ: Ctrl</p>
```

**दोनों कक्ष अलग-अलग दिशा देखते हैं।** `toHtml` बाहर जाने का रास्ता है और
`claim` भीतर आने का। `claim` न लिखें तो खींचा तो जा सकता है, पर **दोबारा पढ़ा
नहीं जा सकता** — सहेजकर फिर से लोड करते ही खोल उतर जाता है।

`simpleMark` बिना attribute वाले मार्क के लिए शॉर्टकट है। मान रखने वाले मार्क
के लिए `valueMark`, ऑब्जेक्ट के लिए `boxObject`, सूची-परिवार के लिए
`listFamily` है, और बाक़ी के लिए `Wing` ऑब्जेक्ट हाथ से लिखा जाता है।

## wing स्थिरांक (constant) हैं

**ज़्यादातर wing पहले से तैयार स्थिरांक हैं** — `boldWing`·`headingWing` जैसे,
बस सरणी में डाल दें। सिर्फ़ दो को जिन्हें विकल्प चाहिए, उनका अलग फ़ैक्ट्री
फ़ंक्शन है।

```ts
makeImageWing({ allowLocalUrls: true })
makeUploadWing({ allowLocalUrls: true })
```

सिर्फ़ "जुड़ने का काम" (`attach`) बदलना हो तो स्थिरांक को फैलाकर (spread) लिखें
— नया wing बनाने के बजाय सिर्फ़ एक कक्ष बदलना है, इसलिए यह रास्ता आसान है।

```ts
const wing = { ...codeWing, attach: makeCodeAttach({ highlight: myHighlighter }) }
```

## रजिस्ट्रेशन और क्रम

```ts
const { nabi, registry } = createNabiWith([boldWing, italicWing, kbdWing])
```

**सरणी का क्रम ही जाँच का क्रम है।** किसी मार्कअप का मालिक तय करते समय
(`claim`) कोर इसी क्रम में पूछता है, और जो wing पहले जवाब दे वही उसे ले लेता
है। कोई न ले तो खोल उतार दिया जाता है।

टूलबार में **पहले समूह (`button.group`) आते हैं।** समूहों का क्रम तय है, और एक
ही समूह के भीतर यही सरणी-क्रम चलता है।

### रजिस्टर करते ही वहीं मर जाता है

जो wing कॉन्ट्रैक्ट तोड़े उसे `createNabiWith` **तुरंत फेंक देता है।** देर से
नहीं फूटता।

| क्या पकड़ में आता है | उदाहरण |
|---|---|
| आरक्षित शब्द को नाम बनाया | `w: 'p'` · `w: 'br'` |
| एक ही नाम दो बार रजिस्टर किया | `boldWing` को दो बार |
| नोड खड़ा करता है पर `toHtml` नहीं है | `place: 'mark'` हो पर खींचने का तरीक़ा न हो |
| कमांड का नाम नियम तोड़ता है | क्रिया+कर्म कैमलकेस होना चाहिए (`insertTable`) |
| ज़रूरी साथी नहीं है | अपलोड के साथ `img` या `a` में से एक होना ज़रूरी है (`requiresAnyOf`) |

## कमांड — शुद्ध फ़ंक्शन हैं

दस्तावेज़ बदलने वाला हर रास्ता एक कमांड से गुज़रता है। कमांड **न DOM जानता है,
न स्क्रीन।**

```ts
import { boxObject, insertLump, type Command, type Wing } from 'nabi-note'

const insertStamp: Command = (doc, sel, args, env) => {
  // बाहर से आया मान है इसलिए जाँचा जाता है — मेल न खाए तो कुछ नहीं होता
  if (typeof args['text'] !== 'string') return null
  const stamp = { w: 'stamp', a: { t: args['text'] }, ch: [] }
  const r = insertLump(doc, sel.focus, stamp, env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

export const stampWing: Wing = {
  ...boxObject({
    w: 'stamp',
    attrs: { t: (v) => (typeof v === 'string' ? v : null) },
    toHtml: (node, _children, ctx) =>
      ctx.element('span', ctx.escape(String(node.a?.['t'] ?? '')), { 'data-nabi-stamp': '' }),
  }),
  commands: { insertStamp },
  button: {
    group: 'insert',
    label: { hi: 'मुहर' },
    action: { kind: 'command', command: 'insertStamp', args: { text: 'ठीक है' } },
  },
}
```

| तर्क (argument) | क्या है |
|---|---|
| `doc` | अभी का दस्तावेज़ (ब्लॉक की सरणी)। **इसे बदला नहीं जाता, नया दिया जाता है** |
| `sel` | अभी का चयन |
| `args` | बटन या कॉन्टेक्स्ट पंक्ति ने दिया मान। **बाहर से आया है इसलिए जाँचना ज़रूरी है** |
| `env` | किस्म का ज्ञान — क्या किसे धारण करता है, क्या ऑब्जेक्ट है |

जवाब `{ doc, selection }` या **`null`** होता है। **कुछ न बदले तो `null` दें** —
तब `applyCommand` `false` जवाब देगा और कोई अनडू-बिंदु नहीं जुड़ेगा। दिया गया
दस्तावेज़ `cocoon` से एक बार और सँवरता है, इसलिए कोई कमांड नियम तोड़ने वाला
दस्तावेज़ नहीं छोड़ सकता।

बुलाने वाला हमेशा नाम से बुलाता है।

```ts
nabi.applyCommand('insertStamp', { text: 'ठीक है' })   // boolean
```

## भरे जा सकने वाले सारे कक्ष

`Wing` में **इकतीस (31)** कक्ष हैं और **सिर्फ़ दो ज़रूरी हैं** (`w`·`place`)।

### क्या है

| कक्ष | अर्थ |
|---|---|
| `w` | इस wing का नाम। सहेजे मान का `w` यही बनता है। आरक्षित शब्द (`p`·`br`) इस्तेमाल नहीं हो सकते |
| `place` | `'mark'` अक्षर के ऊपर · `'void'` बिना भीतरी सामग्री वाली चीज़ · `'container'` जिसके भीतर पाठ हो ऐसी चीज़ · `'attr'` पैराग्राफ़ गुण · `'tool'` दस्तावेज़ में कोई निशान न छोड़ने वाला औज़ार |
| `basic` | **क्या यह बिना तारों के ही चलता है?** न लिखें तो `false`। `wings().allBasic()` सिर्फ़ इसी निशान वाले ढूँढता है, और **कस्टम भी उसी तौल से तुलते हैं**। अगर लिखा हो तो `allBasic()` की सूची से पार होता है, पर आगे `.use(object)` से जो आए वह यहाँ के बावजूद आ ही जाता है |
| `holds` | भीतर की सामग्री कैसे धारण करता है — `'blocks'` या `'inline'` |
| `singleParagraph` | भीतर की सामग्री **एक ही** पैराग्राफ़ में सीमित रहती है (तालिका की कोशिका) |
| `boolAttrs` | जिन बूलियन attribute का इकलौता मान `1` होता है, उनके नाम |
| `allows` | इसके भीतर आ सकने वाले wing के नाम। न लिखें तो सब आ सकते हैं |
| `noAlign` | **सिर्फ़ ऑब्जेक्ट।** यह लिख दें तो **इस ऑब्जेक्ट को लपेटने वाला पैराग्राफ़ संरेखण नहीं लेता** — टूलबार में संरेखण बटन छिप जाते हैं · कमांड रद्दी से असफल हो जाता है · पहले से बने सहेजे दस्तावेज़ में बॉक्स किया मान उतार दिया जाता है। कोड-संदूक इसका पहला इस्तेमाल करता है — `pre` को `text-align` विरासत में मिलता है, इसलिए संदूक खिसकने के बजाय **कोड पंक्तियाँ खिसकती हैं।** अगर इसे मार्क, औज़ार या पैराग्राफ़ गुण पर लगाएँ तो **रजिस्ट्रेशन मर जाता है** |
| `requiresAnyOf` | इनमें से कम-से-कम एक साथ रजिस्टर होना चाहिए |
| `parts` | साथ लाया जाने वाला बटन-रहित ढाँचा — तालिका की पंक्ति-कोशिका, फ़ोल्ड की सारांश-पंक्ति |

### मान

| कक्ष | अर्थ |
|---|---|
| `attrKey` · `attrValues` | पैराग्राफ़ गुण जिस कक्ष-नाम का इस्तेमाल करता है और जो मान ले सकता है |
| `currentValue` | अभी दबा हुआ है क्या — इसी जवाब से टूलबार और कॉन्टेक्स्ट पंक्ति कक्ष रंगती हैं |

### आने-जाने का रास्ता

| कक्ष | अर्थ |
|---|---|
| `toHtml` · `partHtml` | बाहर जाने वाला चित्रण |
| `toMd` | markdown में बाहर जाने वाला चित्रण। **वैकल्पिक — न लिखें तो `toHtml` को अपना लेता है** (रेखांकन · यूट्यूब · Details जैसे जो markdown में आ नहीं सकते, यही स्थिति है कि "markdown में HTML मिला") |
| `partMd` | उस wing के `parts` का markdown हिस्सा |
| `ioFilter` | यह wing **अपने फ़ॉर्मेट की पेस्ट·सहेज·खोल को साथ लाता है** (`.nabi` फ़ाइल यही जगह है)। फ़िल्टर wing नहीं है पर उससे जुड़ा ज्ञान है, इसलिए होस्ट `ioFilters` से जो जोड़े वह इसके आगे खड़े होते हैं — नीचे [IO फ़िल्टर जोड़ना](#io-फ़िल्टर-जोड़ना) देखें |
| `claim` | भीतर आने वाले HTML में इस टैग का मालिक कौन है यह तय करता है |
| `repair` · `partRepair` | JSON के प्रवेश-द्वार पर इस नोड को सँवारता है। `null` दे तो खोल समेत हट जाता है |

### हाथ और कुंजियाँ

| कक्ष | अर्थ |
|---|---|
| `commands` | इस wing के जोड़े कमांड |
| `onKey` | कर्सर इस wing के नोड के भीतर हो तो कुंजी को पहले पकड़ता है |
| `escapeKeys` | जिन कुंजियों से अगला टाइप किया अक्षर इस मार्क से बाहर निकल जाता है |
| `doubleKeys` | `{ कुंजी का नाम: कमांड का नाम }` — उस कुंजी को **350ms के भीतर दो बार** थपथपाएँ तो वह कमांड चलता है। प्राथमिकता **सबसे कम** है, इसलिए उस कुंजी का बाक़ी काम सब पहले निपट जाता है, फिर यह आता है। रजिस्ट्रेशन के समय **कुंजी टकराव और कमांड की सच्चाई की जाँच** करता है, तो कोई उल्लंघन हो तो रजिस्ट्रेशन मर जाता है। `escapeKeys` से उलझनें न खाएँ — वह "मार्क उतार, आगे लिखो" है, यह "एक इशारे से एक कमांड" है |
| `inputRules` | सिर्फ़ टाइप करने से होने वाला ऑटो-रूपांतरण |
| `attach` | जब स्क्रीन को छूना हो — तालिका की कोशिका खींचना, कोड रंगना यही है |

### रूप-रंग

| कक्ष | अर्थ |
|---|---|
| `button` · `buttons` | टूलबार का एक या कई बटन |
| `context` | कॉन्टेक्स्ट पंक्ति की घोषणा |
| `styles` | यह wing जो CSS साथ लाता है |

## IO फ़िल्टर जोड़ना

IO फ़िल्टर **wing नहीं है** — यह किसी wing का नोड नहीं सेता। पेस्ट (अंदर का दरवाज़ा) और सहेज·खोल (बाहर के दरवाज़े) को एक सेट के रूप में संभालने वाला विस्तार बिंदु है। `ioFilter` कक्ष से wing इसे अपने साथ ला सकता है।

`IoFilter` — चार कक्ष का सारणी:

| | |
|---|---|
| `id` · `label` | यह फ़िल्टर का नाम और दिखने वाला टेक्स्ट (नाम दोहराए तो रजिस्ट्रेशन मर जाता है) |
| `paste` | clipboard का मान (`PasteData`) जाँचकर पेस्ट-उम्मीदवार लौटाने वाला फ़ंक्शन |
| `save` | सहेजने की जानकारी — ऑब्जेक्ट `{extension, write, lossy?, mime?}` |
| `read` | फ़ाइल-नाम और पाठ लेकर nabi-tree में पढ़ने वाला फ़ंक्शन (मेल न खाए तो `null`) |

**तीनों दरवाज़े वैकल्पिक हैं।** सहेज कक्ष न हो तो खोल भी नहीं हो सकता — जो फ़ॉर्मेट wing बचा नहीं सकता, उसे पढ़ा नहीं जा सकता। लेकिन paste अकेला हो सकता है, जो पेस्ट-ही-उपयोग फ़िल्टर के लिए।

**दाखिल होने की जगह और क्रम** — `mountFile()` → होस्ट → wing → भीतर के चार (`nabi` · `html` · `html-open` · `markdown`)। जहाँ भी कोई फ़िल्टर अपना काम कर दे वहीं रुक जाता है, अगला नहीं आता।

`readExtensions(filters)` — सहेज कक्ष नहीं रखने वाले फ़िल्टर इसमें आ ही नहीं सकते। आप जो `save` घोषित करते हो वही सूची दिखता है। markdown को अपने आप फ़िल्टर बना नहीं सकता — उसके `toMd` · `partMd` रखने वाली wing के **साथ** वह तब बनता है।

**नेविगेशन में नहीं आता** — `nav.ts` को इस round में नहीं छूते हैं।

## `w` — नाम रखना

`w` वह **स्ट्रिंग है जो सहेजे मान में हर नोड पर दोहराई जाती है।** जितना छोटा
उतना अच्छा — इसीलिए मूल wing `b`·`hl`·`tf` जैसे छोटे नाम रखते हैं। पर किसी और
के नाम से टकराए तो रजिस्ट्रेशन मर जाता है, इसलिए ख़ुद बनाए wing के लिए थोड़ा
लंबा पर न टकराने वाला नाम रखें।

HTML टैग के नाम जैसा होना ज़रूरी नहीं — बाहर जाने वाला टैग `toHtml` तय करता है।

::: warning बाद में नाम बदलें तो
सहेजे मान का `w` ही वह नाम है, इसलिए नाम बदलने पर **पहले से सहेजे दस्तावेज़
पढ़े नहीं जा सकते।** बदलना ज़रूरी हो तो पुराने नाम को भी `claim` से साथ स्वीकार
करने वाला संक्रमण-काल रखें।
:::
