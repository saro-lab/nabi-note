# कुंजी, ऑटो-रूपांतरण, पेस्ट

wing को इंसान का इशारा मिलने के तीन दरवाज़े हैं — **कुंजी** (`onKey`), **अक्षर**
(`inputRules`), **स्क्रीन** (`attach`)।

---

## कुंजी जिस रास्ते से गुज़रती है

जैसे ही <kbd>Enter</kbd> दबे, इसी क्रम में पूछा जाता है। पहले किसी ने संभाल
लिया तो बाद वाला नहीं आता।

```
① टूलबार शॉर्टकट        कहीं भी सुना जाता है (Ctrl+B जैसा कुछ)
② ऑटो-रूपांतरण          inputRules — सिर्फ़ Enter·Space
③ wing का onKey          कर्सर जिस जगह बैठा है उसके मालिक को
④ चीज़ को निशाना बनाना    पैराग्राफ़ के सबसे आगे backspace → पहले की चीज़ को पूरा चुन लेता है
⑤ कोर का नियम            पैराग्राफ़ बाँटना·मिटाना·कर्सर की चाल
⑥ ब्राउज़र               यहाँ तक किसी ने न लिया हो तभी
```

---

## `onKey` — कुंजी को पकड़ना

```ts
import type { OnKey } from 'nabi-note'

const noteKeys: OnKey = (intent, doc, sel, env, owner) => {
  if (intent.key !== 'backspace') return null      // मेरा काम नहीं — कोर को सौंप देता हूँ
  if (sel.focus.offset !== 0) return null
  const first = [...owner.path, 0]
  if (first.length !== sel.focus.path.length) return null
  if (!first.every((v, i) => v === sel.focus.path[i])) return null
  return toggleNote(doc, sel, {}, env)             // पहली कोशिका के सबसे आगे backspace — नोट को फैलाता है
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',
  toHtml: (_node, children, ctx) => ctx.element('aside', children()),
  commands: { toggleNote },
  onKey: noteKeys,
}
```

| तर्क | क्या है |
|---|---|
| `intent` | `{ key, dir? }` — कौन-सी कुंजी है |
| `doc` · `sel` · `env` | कमांड को मिलने वाले जैसे ही |
| `owner` | `{ path, node }` — **जिस नोड का मालिक मैं चुना गया** |

जवाब कमांड जैसा ही `{ doc, selection }` या **`null`** है। `null` का मतलब है
"नहीं लेता", तब कोर आगे बढ़ता है — शर्त पूरी न हो तो हमेशा `null` ही दें।

### आने वाली कुंजियाँ

| `intent.key` | कब |
|---|---|
| `'enter'` | <kbd>Enter</kbd> **और** <kbd>Shift</kbd>+<kbd>Enter</kbd> दोनों |
| `'tab'` · `'shiftTab'` | <kbd>Tab</kbd> · <kbd>Shift</kbd>+<kbd>Tab</kbd> |
| `'backspace'` · `'delete'` | मिटाने वाली दोनों कुंजियाँ |
| `'arrow'` | दिशा-तीर। दिशा `intent.dir` में (`'left'`·`'right'`·`'up'`·`'down'`) |

अक्षर वाली कुंजियाँ यहाँ नहीं आतीं। अक्षर ब्राउज़र टाइप करता है और कोर उसे
लिख लेता है।

### मालिक एक ही होता है

कर्सर के रास्ते को **ऊपर की ओर चलकर जो पहला ग़ैर-पैराग्राफ़ नोड मिले**, उसे रखने
वाला wing ही मालिक है।

```
पथ [1, 0, 0] पर कर्सर                     मालिक के उम्मीदवार
  [1, 0, 0]  →  p        पैराग्राफ़ है, छोड़ दिया जाता है
  [1, 0]     →  note     ← यही मालिक है
  [1]        →  p(रैपर)  यहाँ तक नहीं आता
```

इसीलिए **सबसे भीतरी कंटेनर जीतता है** — तालिका के भीतर की सूची में
<kbd>Tab</kbd> सूची को मिलता है। part (`parts`) भी मालिक हो सकता है, तब
`owner.node` part-नोड होता है पर `onKey` उसे घोषित करने वाले wing का ही बुलाया
जाता है। इसीलिए `owner.node.w` से पहले यह तय करना रिवाज है कि कौन चुना गया।

मार्क मालिक नहीं बन सकता — [वजह इनलाइन दस्तावेज़ में है](./inline#मार्क-को-अपनी-कुंजी-नहीं-मिलती)।

## `inputRules` — सिर्फ़ टाइप करने से बनाना

`# ` टाइप करने पर शीर्षक बनना और `> ` टाइप करने पर उद्धरण बनना यही है।

```ts
inputRules: [
  { trigger: 'space', pattern: /^>$/, run: () => ({ name: 'toggleQuote' }) },
]
```

| कक्ष | |
|---|---|
| `trigger` | `'space'` या `'enter'` — यह कुंजी दबते ही **उसी क्षण** चलता है |
| `pattern` | एक रेगुलर एक्सप्रेशन। `run` उसी मेल (match) को पाता है |
| `run` | `{ name, args? }` — चलाया जाने वाला कमांड |
| `scope` | `'block'` (डिफ़ॉल्ट) या `'word'` |

### `'block'` — पंक्ति की शुरुआत बदल देता है

कर्सर से पहले की **पंक्ति की शुरुआत** देखता है। मेल खाए तो वह शुरुआत (और
ट्रिगर वाला अक्षर) मिटाकर कमांड चलाता है।

```
"> " टाइप किया   →   "> " मिटता है और toggleQuote चलता है
```

यह सिर्फ़ पैराग्राफ़ की **पहली पंक्ति** पर चलता है। <kbd>Shift</kbd>+<kbd>Enter</kbd>
से बनाई अगली पंक्ति पर नहीं चलता — इससे पहले से लिखे जा रहे पाठ के बीच में
अचानक फ़ॉर्मेट कूद पड़ने से बचा जाता है।

### `'word'` — एक शब्द पर लगता है

कर्सर से पहले का **एक शब्द** देखता है। मेल खाए तो उस शब्द को चुनकर कमांड
चलाता है और कर्सर को उसकी जगह पर वापस रख देता है। पाठ मिटता नहीं — मार्क
लगाने का रास्ता यही है।

अगर वह शब्द **पहले से इसी wing का मार्क ओढ़े हो तो छोड़ दिया जाता है।** एक ही
जगह पर दो बार नहीं चलता।

### साझा नियम

- सिर्फ़ तभी चलता है जब कर्सर **सिकुड़ा (collapsed) हुआ** हो। रेंज चुनी हो और
  स्पेस दबे तो नहीं चलता।
- सिर्फ़ सामान्य पैराग्राफ़ पर चलता है — किसी चीज़ को धारण करने वाले रैपर
  पैराग्राफ़ पर नहीं चलता।
- wing की सरणी के क्रम में जाँचा जाता है, और **जो नियम पहले सफल हो वही जीतता
  है।**
- कमांड `null` दे (यानी करने को कुछ नहीं) तो **वापस पलटकर अगले नियम पर जाया
  जाता है।** असफल ऑटो-रूपांतरण का कोई निशान दस्तावेज़ पर नहीं बचता।

## `attach` — स्क्रीन को छूना

कभी-कभी दस्तावेज़ बदलना नहीं, बल्कि **स्क्रीन पर हो रही कोई चीज़** सुननी होती है
— तालिका की कोशिकाएँ खींचकर चुनना, कोड रंगना, फ़ोल्ड का त्रिकोण दबाना।

```ts
import type { Attach } from 'nabi-note'

const attachNote: Attach = (host) => {
  const onClick = (ev: MouseEvent): void => { /* … */ }
  host.root.addEventListener('click', onClick)
  return () => host.root.removeEventListener('click', onClick)   // हटाने वाला फ़ंक्शन लौटाया जाता है
}
```

`host` तीन चीज़ें देता है।

| | |
|---|---|
| `host.root` | संपादन सतह का एलिमेंट |
| `host.nabi` | एडिटर। दस्तावेज़ बदलना हो तो **कमांड से** करें |
| `host.pathOfKey(id)` | स्क्रीन के `data-key` को दस्तावेज़ के पथ में बदलता है |

`mountSurface` रजिस्टर किए गए सारे wing के `attach` को साथ जोड़ता है, और
उतारते समय जो हटाने वाले फ़ंक्शन मिले उन्हें बुलाता है। यही **इकलौती जगह है
जहाँ DOM जानने वाला कोड रह सकता है** — किसी कमांड, `toHtml` या `repair` के
भीतर `document` को छूना नहीं चाहिए।

::: tip `data-key` से दस्तावेज़ ढूँढा जाता है
एडिटर की जोड़ाई (`getEditorHtml()`) हर नोड पर `data-key` लगाती है। दबाए गए
एलिमेंट के सबसे नज़दीकी `[data-key]` को ढूँढकर `host.pathOfKey()` को दें, तो
दस्तावेज़ के भीतर की जगह मिल जाती है।
:::

## पेस्ट और शुरुआती HTML

पेस्ट करना, `setHtml()`, और सहेजा मान लोड करना — **सब एक ही दरवाज़े से** गुज़रते
हैं। wing को यहाँ बस `claim` करना होता है — इसकी बात
[इनलाइन दस्तावेज़ के `claim`](./inline#claim) में है।

```
पेस्ट        ─┐
setHtml       ─┼→ पार्सिंग → wing का claim → कोर का मूल टैग-मिलान → repair → cocoon → दस्तावेज़
शुरुआती HTML ─┘
```

`claim` न हो तो **उस टैग का खोल उतर जाता है और सिर्फ़ भीतर का पाठ बचता है।**
इसी नियम की वजह से किसी और एडिटर से कॉपी किया अनजान मार्कअप दस्तावेज़ में
ज्यों का त्यों नहीं जड़ता।

JSON से आने वाला रास्ता (`setJson()`) टैग नहीं, नोड लेकर आता है, इसलिए वहाँ
पहरेदार `claim` नहीं, `repair` है।
