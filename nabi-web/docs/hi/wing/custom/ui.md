# UI और व्यवहार

wing जिन तीन जगहों पर इंसान के सामने खड़ा होता है वे ये हैं।

| कक्ष | कहाँ |
|---|---|
| `button` · `buttons` | ऊपर की **टूलबार** — हमेशा दिखने वाली जगह |
| `context` | **कॉन्टेक्स्ट पंक्ति** — सिर्फ़ तब दिखती है जब कर्सर किसी चीज़ को छू रहा हो |
| `styles` | यह wing जो **CSS** साथ लाता है |

---

## टूलबार बटन

```ts
button: {
  group: 'emphasis',                   // किस समूह में खड़ा होगा — ज़रूरी
  svg: '<path d="…"/>',                // 16×16 कोऑर्डिनेट का भीतरी हिस्सा। न हो तो टेक्स्ट के रूप में खड़ा होता है
  label: { hi: 'बोल्ड' },
  shortcut: 'B',                       // हिंट मोड में यह अक्षर
  accelerator: 'mod+b',                // Ctrl/⌘ का संयोजन
  action: { kind: 'mark' },
}
```

कई बटन हों तो `buttons` में सरणी के रूप में लिखे जाते हैं — जैसे संरेखण wing
अकेले बाएँ·बीच·दाएँ तीनों खड़े करता है। तब `name` से एक-दूसरे को अलग किया जाता
है और `value` में हर बटन जो मान दिखाता है वह लिखा जाता है।

### `group` — क्रम समूह तय करता है

```
font · heading · emphasis · script · color · link ·
align · list · structure · media · container · clear · file
```

**यह क्रम स्थिर है।** wing को सरणी में कहीं भी रखें, बटन अपने समूह की जगह पर ही
खड़ा होगा। सिर्फ़ एक ही समूह के भीतर रजिस्ट्रेशन-क्रम के हिसाब से क्रम लगता है।
सूची से बाहर का नाम इस्तेमाल हो तो सबसे पीछे एक नया समूह बन जाता है।

जब कोई समूह पूरा ख़ाली हो जाए (उसके सारे बटन छिपे हों) तो वह समूह स्क्रीन से
ग़ायब हो जाता है — कोई ख़ाली विभाजक-रेखा नहीं बचती।

### `action` — दबाने पर क्या होता है

| `kind` | क्या करता है | साथ क्या लिखा जाता है |
|---|---|---|
| `'mark'` | कोर के मार्क-टॉगल पर जाता है। **कमांड नहीं चाहिए** | — |
| `'command'` | एक कमांड चलाता है | `command` · `args?` |
| `'menu'` | मान-सूची को पैनल के रूप में खोलता है | `command` · `argKey` · `values` |
| `'grid'` | पंक्ति×स्तंभ का ग्रिड खोलता है (तालिका डालना) | `command` · `rowsKey` · `colsKey` · `max?` |
| `'prompt'` | इनपुट कक्ष खोलकर मिला मान कमांड को देता है | `command` · `fields` |
| `'file'` | फ़ाइल चुनने वाली विंडो खोलता है | `accept?` · `multiple?` |
| `'host'` | होस्ट को सौंप देता है (`mountToolbar` का `onHost`) | — |

`action` न लिखें तो वह बटन दबाने पर कुछ नहीं करता।

### `shortcut` और `accelerator`

| | शक्ल | नियम |
|---|---|---|
| `shortcut` | `'B'` | लैटिन **बड़ा अक्षर या एक अंक** |
| `accelerator` | `'mod+b'` | `mod+` के बाद **एक छोटा अक्षर** |

दोनों **wing के बीच टकराएँ तो रजिस्ट्रेशन वहीं मर जाता है।** बाद में चुपचाप
किसी एक का काम न करना जैसी स्थिति नहीं बनती।

`accelerated` अलग से लिखें तो accelerator से दबाने पर अलग व्यवहार होता है —
बटन दबाने पर पैनल खुलता है, पर <kbd>Ctrl</kbd>+कुंजी से सीधे डिफ़ॉल्ट मान लग
जाता है।

## दबा हुआ कैसे दिखता है

बटन को "अभी चालू है" रंगने का आधार सिर्फ़ एक है।

| `place` | क्या देखा जाता है |
|---|---|
| `'mark'` | कर्सर की जगह पर वह मार्क है क्या |
| `'attr'` | कर्सर जिस पैराग्राफ़ पर है उसका `currentValue` |
| `'container'`·`'void'` | कर्सर उस चीज़ के भीतर या ऊपर है क्या |
| `'tool'` | **हमेशा बंद** |

जिस wing के कई मान हों (संरेखण, शीर्षक), वह हर बटन पर `value` लिखता है, और
सिर्फ़ वही बटन रंगा जाता है जिसका मान wing के `currentValue` से मेल खाता है।

```ts
currentValue: (node) => {
  const h = node.a?.['h']
  return typeof h === 'number' && h >= 1 && h <= 6 ? String(h) : undefined
}
```

**`currentValue` टेक्स्ट लौटाता है** — संख्या मान भी `String()` से बदलकर
लौटाया जाता है। `undefined` का मतलब है "इस नोड पर मेरा मान नहीं है"।

## बटन जहाँ खड़ा नहीं हो सकता वहाँ अपने-आप छुप जाता है

| `place` | कब छुपता है |
|---|---|
| `'mark'` | सिर्फ़ अक्षर रहने वाली जगह (जैसे कोड-बॉक्स के भीतर), जब वहाँ का मालिक हो |
| `'attr'` | कर्सर किसी चीज़ को धारण करने वाले रैपर पैराग्राफ़ पर हो तब। **सिर्फ़ संरेखण (`a`) अपवाद है** |
| `'void'`·`'container'` | सिर्फ़ अक्षर रहने वाली जगह हो, या अभी के कंटेनर का `allows` मुझे स्वीकार न करे |
| `'tool'` | नहीं छुपता |

सिर्फ़ संरेखण अपवाद होने की वजह पहले देखी जा चुकी है — ऑब्जेक्ट का संरेखण
ऑब्जेक्ट नहीं, उसे धारण करने वाला रैपर पैराग्राफ़ ओढ़ता है। छवि के ऊपर भी
"बीच में" दबाना संभव होना चाहिए।

`allows` लिखा हो तो **टूलबार ख़ुद उसका अनुसरण करता है।** कोड-बॉक्स के भीतर
तालिका का बटन ग़ायब होना कोई अलग से लिखा नियम नहीं, बस एक `allows` से निकलता
है।

## कॉन्टेक्स्ट पंक्ति

यह वह पंक्ति है जो सिर्फ़ तब दिखती है जब कर्सर किसी चीज़ को छू रहा हो। यही वह
जगह है जहाँ छवि दबाने पर आकार बदलने का नियंत्रण, और लिंक पर कर्सर रखने पर
पता-कक्ष दिखता है।

```ts
context: {
  title: { hi: 'नोट' },
  controls: [
    {
      kind: 'select',
      name: 'tone',
      label: { hi: 'भाव' },
      command: 'setNoteTone',
      argKey: 'value',
      attr: 't',                                    // अभी का मान जिस attribute-कक्ष से पढ़ा जाता है
      values: [
        { value: 'info', label: { hi: 'सूचना' } },
        { value: 'warn', label: { hi: 'चेतावनी' } },
      ],
    },
  ],
}
```

### कब दिखती है

कर्सर की जगह जिन-जिन चीज़ों को **छूती है वे सब** अपनी-अपनी पंक्ति खोलती हैं।

- कर्सर के पथ पर पड़ने वाले कंटेनर (पहले भीतरी, फिर बाहरी)
- निशाना बनी चीज़ (जैसे रैपर पैराग्राफ़ पर चुनी गई छवि)
- कर्सर की जगह पर लगे **मार्क** — टूलबार बटन के विपरीत, मार्क की भी अपनी
  कॉन्टेक्स्ट पंक्ति होती है
- वह **पैराग्राफ़-गुण** wing जिसका मान कर्सर वाले पैराग्राफ़ पर है

तालिका के भीतर के लिंक पर कर्सर रखें तो लिंक-पंक्ति और तालिका-पंक्ति साथ
दिखती हैं।

### `ContextControl` की सात क़िस्में

| `kind` | क्या है | साथ क्या लिखा जाता है |
|---|---|---|
| `'button'` | एक बार दबाने पर कमांड | `command` · `args?` |
| `'toggle'` | चालू/बंद दो अवस्थाएँ | `command` · `token` |
| `'select'` | सूची में से एक | `command` · `argKey` · `values` · `attr?` |
| `'range'` | निशान खिसकाना (आकार बदलना) | `command` · `argKey` · `values` · `rest?` · `readout?` |
| `'text'` | एक टेक्स्ट कक्ष (लिंक का पता) | `command` · `argKey` · `initial?` · `placeholder?` · `validate?` |
| `'prompt'` | कई कक्ष पैनल में | `command` · `fields` |
| `'lightbox'` | बड़ा करके देखना | `src` · `alt?` |

सातों में साझा हैं `name` (ज़रूरी) · `label?` · `svg?` · `tip?` · `visible?`।

`visible: (node) => boolean` **एक ही wing के भीतर किसी कक्ष को छिपाने** का
दरवाज़ा है — जैसे "मर्ज खोलना" सिर्फ़ पहले से मर्ज हुई कोशिका पर दिखाना।

`attr` लिखें तो अभी का मान सीधे उसी attribute-कक्ष से पढ़कर रंगा जाता है।
`'toggle'` `token` से `currentValue` के लौटाए टेक्स्ट के साथ तुलना करता है।

## `styles` — wing जो CSS साथ लाता है

```ts
styles: `
.nabi-content aside[data-nabi-note] {
  border-inline-start: 3px solid var(--nabi-accent);
  padding: .6rem .9rem;
  background: color-mix(in srgb, var(--nabi-accent) 8%, transparent);
}
`
```

चार नियम हैं।

- **`.nabi-content` के भीतर तक ही सीमित रखें।** होस्ट पेज के दूसरे पाठ तक न
  फैले।
- **अक्षर-आकार `rem` या `em` में** लिखें।
- **डार्क क़िस्म सिर्फ़ `.dark` क्लास से** अलग करें। मीडिया-क्वेरी से अलग करेंगे
  तो होस्ट के जान-बूझकर रखे लाइट स्क्रीन पर भी सिर्फ़ एडिटर डार्क हो जाएगा।
- **चौड़ा-संकरा container query से** नापें। आधार स्क्रीन की चौड़ाई नहीं, बल्कि
  एडिटर जिस जगह रखा है उसकी चौड़ाई है।

सिर्फ़ रजिस्टर किया हुआ चाहिए तो हाथ से जोड़ें।

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const detach = injectSheets(document, collectSheets(registry))
```

एक जैसे पाठ की शीट **सिर्फ़ एक बार** लगती है — कई wing एक ही CSS बाँटें तो भी
दस्तावेज़ में सिर्फ़ एक ही चिपकता है। जवाब हटाने वाला फ़ंक्शन है, और **यह सिर्फ़
इसी पुकार ने जो अभी जोड़ा** उसे हटाता है।

## इंसान से पूछना

```ts
const { nabi, registry } = createNabiWith(wings, {
  ask: {
    message: (text) => window.alert(text),
    confirm: (text) => window.confirm(text),
  },
})
```

`confirm` `boolean` और `Promise<boolean>` दोनों लेता है — ब्राउज़र का `confirm`
ज्यों का त्यों लगाया जा सकता है, या अपना पैनल खोलकर बाद में जवाब दिया जा सकता
है।

::: warning न दें तो जवाब हमेशा "नहीं" है
`ask` न जोड़ें तो एक चुप डिफ़ॉल्ट लग जाता है। `message` कहीं नहीं जाता और
`confirm` `false` लौटाता है। यह सोच है कि **पूछकर मिटाने का काम चुपचाप न होना**,
चुपचाप हो जाने से बेहतर है। लोकल-हिस्ट्री का "क्या सच में मिटाएँ" इसी दरवाज़े
से गुज़रता है।
:::

::: tip कमांड नहीं पूछ सकता
कमांड एक शुद्ध फ़ंक्शन है, इसलिए न स्क्रीन जानता है न समय। जो पूछना हो वह
कमांड के बाहर पूछा जाता है और **जवाब मिलने के बाद** कमांड बुलाया जाता है।
wing के भीतर इसकी जगह `attach` है, और वहाँ से `host.nabi.$ask` से पहुँचा जाता
है।
:::
