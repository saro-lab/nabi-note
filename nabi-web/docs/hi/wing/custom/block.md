# ब्लॉक और पैराग्राफ़ गुण बनाना

जगह घेरने वाली चीज़ें तीन तरह की होती हैं।

| `place` | क्या है | उदाहरण |
|---|---|---|
| `'void'` | **बिना भीतरी सामग्री वाली चीज़।** कर्सर इसके भीतर नहीं जा सकता | क्षैतिज रेखा, छवि, YouTube |
| `'container'` | **जिसके भीतर पाठ हो ऐसी चीज़** | उद्धरण, फ़ोल्ड, तालिका, सूची, कोड |
| `'attr'` | पैराग्राफ़ पर ही चिपकने वाला मान। कोई नोड नहीं खड़ा करता | शीर्षक, संरेखण, ड्रॉप कैप |

---

## ऑब्जेक्ट रैपर पैराग्राफ़ के भीतर रहता है

दस्तावेज़ **ब्लॉक की एक सरणी** है, और सबसे ऊपरी स्तर पर सिर्फ़ पैराग्राफ़ (`p`)
खड़ा हो सकता है। ऑब्जेक्ट सीधे वहाँ नहीं खड़ा होता, बल्कि **सिर्फ़ उसी को धारण
करने वाले** एक पैराग्राफ़ में लिपटकर खड़ा होता है।

```json
[{ "w": "p", "ch": [{ "w": "hr", "ch": [] }] }]
```

यही **रैपर पैराग्राफ़** है, और स्क्रीन पर यह `<div data-nabi-p>` बनकर खींचा
जाता है।

इसकी दो वजहें हैं। ऑब्जेक्ट के आगे-पीछे कर्सर खड़े होने की जगह हमेशा रहती है
(क्योंकि वहाँ एक पैराग्राफ़ हमेशा मौजूद है), और **संरेखण जैसा पैराग्राफ़ गुण
ऑब्जेक्ट को ज्यों का त्यों मिल जाता है** — "बीच में संरेखित छवि" असल में
"बीच में संरेखित पैराग्राफ़ के भीतर की छवि" है।

---

## बिना भीतरी सामग्री वाली चीज़ बनाना

```ts
import { boxObject, createNabiWith, insertLump, type Command, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const insertStar: Command = (doc, sel, _args, env) => {
  const r = insertLump(doc, sel.focus, { w: 'star', ch: [] }, env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const starWing: Wing = {
  ...boxObject({
    w: 'star',
    toHtml: (_node, _children, ctx) => ctx.element('hr', '', { 'data-nabi-star': '' }),
  }),
  commands: { insertStar },
  button: {
    group: 'insert',
    label: { hi: 'तारा' },
    action: { kind: 'command', command: 'insertStar' },
  },
}
```

`insertLump` रैपर पैराग्राफ़ ख़ुद पहना देता है।

```
<div data-nabi-p><hr data-nabi-star/></div>
```

खाली पैराग्राफ़ पर बुलाएँ तो **वही पैराग्राफ़ बदल जाता है** — हर बार डालने पर
एक नई खाली पंक्ति नहीं बचती। और उस पैराग्राफ़ का पहले से लगा संरेखण भी ज्यों का
त्यों बचा रहता है।

`boxObject` जो अपने-आप भर देता है वह है `place: 'void'` और **attribute
जाँचने वाला।**

```ts
boxObject({
  w: 'stamp',
  attrs: { c: (v) => (v === 'red' || v === 'blue' ? v : null) },   // सूची से बाहर का मान गिरा दिया जाता है
  requires: ['c'],                                                 // न हो तो यह ऑब्जेक्ट खड़ा नहीं होता
  toHtml: /* … */,
})
```

`attrs` में न लिखा attribute **अनजान कक्ष माना जाकर पूरा गिरा दिया जाता है।**
कॉन्ट्रैक्ट से बाहर का कोई मान सहेजे मान में चुपचाप घुसने की कोई जगह नहीं है।

## भीतरी सामग्री वाली चीज़ बनाना

`place: 'container'` के साथ `holds` लिखना ज़रूरी है — न लिखें तो रजिस्ट्रेशन
मर जाता है।

```ts
import { createNabiWith, toggleWrap, type Command, type Wing } from 'nabi-note'

const toggleNote: Command = (doc, sel, _args, env) => {
  const r = toggleWrap(doc, sel, 'note', env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',                  // भीतर पैराग्राफ़ रहता है ('inline' होता तो सिर्फ़ अक्षर)
  allows: ['p'],                    // इसके भीतर क्या आ सकता है
  toHtml: (_node, children, ctx) => ctx.element('aside', children(), { 'data-nabi-note': '' }),
  claim: (el, inner) => (el.tag === 'aside' ? [{ w: 'note', ch: inner(true) }] : null),
  commands: { toggleNote },
  inputRules: [{ trigger: 'space', pattern: /^!$/, run: () => ({ name: 'toggleNote' }) }],
  button: {
    group: 'container',
    label: { hi: 'नोट' },
    action: { kind: 'command', command: 'toggleNote' },
  },
}
```

`toggleWrap` एक **टॉगल** है। चयन जिन शीर्ष-स्तर ब्लॉक को छूता है उन्हें इस
कंटेनर में लपेट देता है, और अगर पहले से सब लिपटे हैं तो भीतरी सामग्री को
वहीं फैला देता है।

```
लपेटने से पहले  [p"पहली पंक्ति", p"दूसरी"]
लपेटने के बाद    [p[ note[ p"पहली पंक्ति", p"दूसरी" ] ]]
फिर दबाने पर     [p"पहली पंक्ति", p"दूसरी"]
```

### `holds`

| | भीतर क्या रहता है | उदाहरण |
|---|---|---|
| `'blocks'` | पैराग्राफ़ और दूसरी चीज़ें | उद्धरण, फ़ोल्ड, तालिका की कोशिका |
| `'inline'` | सिर्फ़ अक्षर और मार्क | फ़ोल्ड की सारांश-पंक्ति, कोड |

### `allows`

लिखें तो **उसके बाहर का कुछ भी भीतर नहीं आ सकता।** कोर अपने-आप एक सफ़ाई-कर्ता
जोड़ देता है, ताकि पेस्ट हो या सहेजा मान — सूची से बाहर की चीज़ का खोल उतारकर
सिर्फ़ उसका भीतरी पाठ पैराग्राफ़ बनकर बैठ जाए।

न लिखें तो सब कुछ स्वीकार्य है। `allows` में अनजान नाम लिखें तो
**रजिस्टर करते ही वहीं मर जाता है।**

---

## `parts` — बिना बटन वाला भीतरी ढाँचा

तालिका की पंक्ति-कोशिका, फ़ोल्ड की सारांश-पंक्ति जैसा ढाँचा जो **अकेला खड़ा
नहीं हो सकता और जिसका टूलबार में अपना बटन नहीं है**, उसे part के रूप में
घोषित किया जाता है।

```ts
const detailsWing: Wing = {
  w: 'details',
  place: 'container',
  holds: 'blocks',
  boolAttrs: ['o'],                                   // इकलौता मान 1 वाला attribute — खुला है क्या
  parts: { summary: { holds: 'inline' } },            // सारांश-पंक्ति
  toHtml: /* … */,
  partHtml: { summary: /* … */ },                     // हर part का अपना जोड़ना (assembly) होना चाहिए
  repair: repairDetails,
}
```

चार नियम हैं।

- part सिर्फ़ **container** हो सकता है। दूसरे `place` में लिखें तो
  रजिस्ट्रेशन मर जाता है।
- हर part का अपना `partHtml` होना चाहिए। न हो तो रजिस्ट्रेशन मर जाता है।
- part का नाम किसी wing के नाम या दूसरे part के नाम से नहीं टकरा सकता।
- किसी part को सँवारना हो तो `partRepair` में उस part के नाम से लिखें।

`StructureDecl` तीन चीज़ें लेता है — `holds` · `singleParagraph` ·
`boolAttrs`।

### `singleParagraph`

भीतरी सामग्री **एक ही पैराग्राफ़ में सीमित** रहती है। तालिका की कोशिका यही है
— कोशिका के भीतर <kbd>Enter</kbd> दबाने पर भी पैराग्राफ़ दो में नहीं बँटता,
और दो कोशिकाओं में फैला चुनाव मिटाने पर भी कोशिकाएँ आपस में जुड़ती नहीं। ग्रिड
को यही एक कक्ष बचाए रखता है।

### `boolAttrs`

जिस attribute का इकलौता मान `1` हो सकता है — फ़ोल्ड का `o` (खुला है),
टास्क-लिस्ट का `ck` (चेक किया), पैराग्राफ़ का `dc` (ड्रॉप कैप)। बंद अवस्था
`0` नहीं, बल्कि **वह कक्ष सिरे से न होना** है।

## `repair` — सहेजे मान के प्रवेश-द्वार का आख़िरी दरवाज़ा

`repair` **JSON के दस्तावेज़ बनने से ठीक पहले** इस नोड को एक बार सँवारता है।

```ts
repair: (node) => {
  if (!सही_है(node)) return null    // null — यह नोड खोल समेत हट जाता है
  return सँवारा_हुआ_नोड              // वैसा ही रह सकता है (वही ऑब्जेक्ट लौटाएँ तो कुछ नहीं बदलता)
}
```

हाथ से सुधारा गया सहेजा मान, किसी दूसरे वर्ज़न से आया दस्तावेज़, किसी और का लिखा
JSON — सब इसी दरवाज़े से गुज़रते हैं। जो इसे पार कर जाए वही दस्तावेज़ बनता है,
इसलिए यही **वह इकलौती जगह है जहाँ कोई wing अपने नोड की शक्ल की ख़ुद गारंटी दे
सकता है।**

`allows` और `repair` दोनों साथ लिखें तो पहले `allows` की सफ़ाई चलती है और
उसका नतीजा **बाद में** `repair` को मिलता है।

---

## `requiresAnyOf` — जिसे खड़े होने के लिए साथी चाहिए

```ts
requiresAnyOf: ['img', 'a']
```

इनमें से एक भी साथ रजिस्टर न हो तो **रजिस्टर करते ही वहीं मर जाता है।** upload
wing यही इस्तेमाल करता है — अपलोड की गई चीज़ को छवि या लिंक बनकर खड़ा होना
होता है, और दोनों में से कोई न हो तो चढ़ाकर भी कुछ नहीं किया जा सकता।

## पैराग्राफ़ गुण (`place: 'attr'`)

पैराग्राफ़ गुण कोई नोड नहीं खड़ा करता। बस पैराग्राफ़ के `a` पर एक मान चिपका
देता है।

```json
{ "w": "p", "a": { "h": 2, "a": "c" }, "ch": ["बीच में संरेखित शीर्षक 2"] }
```

::: warning कक्ष सिर्फ़ तीन पर बंद हैं
`attrKey` इन तीन में से एक होना चाहिए — **`h` (शीर्षक) · `a` (संरेखण) ·
`dc` (ड्रॉप कैप)** — इससे बाहर का नाम लिखें तो रजिस्ट्रेशन मर जाता है। इस
वर्ज़न में **नया पैराग्राफ़ गुण बनाया नहीं जा सकता** — पैराग्राफ़ के गुण-कक्ष
कोर के जाने इन्हीं तीन पर बंद हैं।

इसी वजह से इन तीनों पर पहले से `headingWing`·`alignWing`·`dropCapWing` का
क़ब्ज़ा है, इसलिए असल में नया `place: 'attr'` wing लिखने की कोई जगह नहीं बचती।
हर पैराग्राफ़ पर मान चिपकाना हो तो अभी के लिए container में लपेटने वाला रास्ता
चुनें।
:::

मान संभालने वाले दो कक्ष हैं।

| | |
|---|---|
| `attrValues` | जो मान मिल सकते हैं उनकी सूची (शीर्षक के लिए `[1,2,3,4,5,6]`) |
| `currentValue` | इस पैराग्राफ़ का अभी का मान। इसी जवाब से टूलबार-कॉन्टेक्स्ट पंक्ति दबा हुआ कक्ष रंगती हैं |

## सार्वजनिक दस्तावेज़-सहायक

यह वर्ज़न बाहर चार संपादन-सहायक देता है।

| | क्या करता है |
|---|---|
| `insertLump(doc, caret, lump, env, wrap?)` | एक ऑब्जेक्ट को उसके रैपर पैराग्राफ़ समेत खड़ा करता है |
| `removeLump(doc, topIndex, env)` | शीर्ष-स्तर के एक रैपर पैराग्राफ़ को पूरा हटाता है |
| `toggleWrap(doc, sel, containerW, env)` | छुए गए ब्लॉक को container में लपेटता या फैलाता है |
| `topNodeAt(doc, path)` | यह पथ जिस शीर्ष-स्तर नोड का हिस्सा है |

चारों `{ doc, caret }` लौटाते हैं, इसलिए कमांड की चाही शक्ल में एक बार बदलना
पड़ता है।

```ts
return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
```

::: tip इससे बारीक़ संपादन चाहिए तो
अक्षर-स्तर पर काटने-जोड़ने वाले भीतरी सहायक (मार्क लगाना, पैराग्राफ़ गुण लिखना
आदि) अभी सार्वजनिक API नहीं हैं। तब तक `doc` सरणी को हाथ से नया बनाकर लौटाया
जा सकता है — लौटाया गया दस्तावेज़ `cocoon` से एक बार और सँवरता है, इसलिए नियम
तोड़ने वाला दस्तावेज़ कभी नहीं बचता।
:::
