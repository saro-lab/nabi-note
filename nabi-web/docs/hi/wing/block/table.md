# तालिका

## विवरण

`tableWings` (नाम `table`, शॉर्टकट `T`) `table > tr > td` ढाँचे का स्वामी है।

पंक्ति (`tr`) और कोशिका (`td`) अलग से रजिस्टर नहीं की जातीं — table wing इन्हें
`parts` के ज़रिए साथ ले आता है, इसलिए table हटाएँ तो पंक्ति-कोशिका भी साथ ही
निकल जाती हैं।

```ts
parts: {
  tr: { holds: 'blocks' },
  td: { holds: 'blocks', singleParagraph: true, boolAttrs: ['th'] },
}
```

कोशिका का `singleParagraph` होना ही ग्रिड को बचाए रखता है — कोशिका के भीतर
<kbd>Enter</kbd> दबाने पर भी पैराग्राफ़ दो में नहीं बँटता, और दो कोशिकाओं में
फैला चुनाव मिटाने पर भी कोशिकाएँ आपस में जुड़ती नहीं।

बटन दबाने पर टॉगल नहीं होता, बल्कि पंक्ति×स्तंभ का आकार चुनने वाला ग्रिड
(अधिकतम 8×8) दिखता है; चुने हुए आकार की तालिका कर्सर की जगह पर आ जाती है और
कर्सर पहली कोशिका में चला जाता है।

कॉन्टेक्स्ट पंक्ति में कमांड सिर्फ़ तभी दिखते हैं जब कर्सर तालिका के भीतर हो।

| किस्म | कक्ष |
|---|---|
| पंक्ति | ऊपर पंक्ति जोड़ें · नीचे पंक्ति जोड़ें · पंक्ति हटाएँ |
| स्तंभ | बाएँ स्तंभ जोड़ें · दाएँ स्तंभ जोड़ें · स्तंभ हटाएँ |
| मर्ज | मर्ज (एक ही टॉगल) |
| शीर्षक | इस पंक्ति को शीर्षक बनाएँ · इस स्तंभ को शीर्षक बनाएँ (`<th>` में बदल जाते हैं) |
| क्रम लगाना | क्रम लगाना चालू/बंद (पढ़ने वाले पक्ष पर स्तंभ क्रमबद्ध होते हैं) |
| हटाना | तालिका हटाएँ |

**मर्ज एक ही टॉगल है** — दिशा के हिसाब से अलग बटन नहीं। कई कोशिकाएँ चुनकर दबाएँ
तो वे एक में जुड़ जाती हैं, और जुड़ी हुई कोशिका पर कर्सर रखकर फिर दबाएँ तो वापस
अलग हो जाती हैं।

**तालिका के बक्से को बाएँ·बीच में·दाएँ रखने वाला कक्ष इस पंक्ति में नहीं है।**
तालिका की जगह तालिका खुद नहीं, बल्कि उसे धारण करने वाला रैपर पैराग्राफ़ तय करता
है, इसलिए यह काम टूलबार का संरेखण बटन करता है।

::: warning क्रम लगाने का चिह्न और मर्ज
क्रम लगाना सिर्फ़ **एक चिह्न** है। एडिटर मर्ज की गई तालिका पर भी यह चिह्न लगा
रहने देता है, और मर्ज करने से पहले से लगा चिह्न उतरता भी नहीं।

बस **पढ़ने वाला पक्ष इसे मना कर देता है** — `attachTableSort` उस तालिका पर
सिरे से नहीं जुड़ता जिसमें मर्ज की हुई कोशिका दिखे। जुड़ी हुई पंक्तियाँ बँधी
होने से पुनर्व्यवस्था ग्रिड को तोड़ देती है। इसलिए मर्ज की गई तालिका में चिह्न
होने पर भी कुछ नहीं होता।
:::

## चौड़ाई सामग्री तय करती है

तालिका में चौड़ाई की कोई सेटिंग नहीं है। तालिका **सिर्फ़ उतनी ही** चौड़ी होती है
जितनी उसकी सामग्री, और अपनी जगह से चौड़ी पड़ने पर वहीं **बग़ल में स्क्रॉल** करती
है — पन्ना नहीं खिसकता। कोई लपेटने वाला `<div>` भी नहीं है। सहेजे गए मान में
सिर्फ़ एक `<table>` जाता है, और उस पर लगने वाले attribute बस संरेखण
(`data-nabi-align`) और क्रम लगाने का चिह्न हैं।

## आवाजाही और चुनाव

`Tab`/`Shift+Tab` से कोशिकाओं के बीच आना-जाना होता है (तालिका के छोर पर कर्सर
वहीं ठहर जाता है)। कोशिका के भीतर सिर्फ़ इनलाइन सामग्री समाती है, इसलिए Enter
कोशिका को तोड़ता नहीं बल्कि **उसी कोशिका के भीतर पंक्ति बदलता है** — तोड़ने के
लिए ऐसा ब्लॉक गढ़ना पड़ता जिसे ग्रिड समा ही नहीं सकता। दिशा-कुंजियाँ स्क्रीन के
हिसाब से नहीं, ग्रिड के हिसाब से चलती हैं।

माउस से कई कोशिकाओं पर खींचकर चुनाव किया जा सकता है। यह ड्रैग-चुनाव भी wing
अपने `attach` में लिए रहता है, इसलिए **अलग से mount नहीं करना पड़ता** —
`mountSurface` इसे साथ जोड़ देता है।

## उपयोग का उदाहरण

```ts
import { createNabiWith, mountSurface, mountToolbar, mountContextToolbar, tableWings } from 'nabi-note'
import 'nabi-note/nabi.css'

const surface = document.querySelector<HTMLElement>('#editor')!

// wing की सूची किस्म का ज्ञान·कमांड·बिल्डर एक साथ बनाती है — वही `registry` है
const { nabi, registry } = createNabiWith([...tableWings])

mountSurface({ nabi, registry, root: surface })
mountToolbar({ nabi, registry, surface, root: document.querySelector<HTMLElement>('#toolbar')! })
mountContextToolbar({ nabi, registry, surface, root: document.querySelector<HTMLElement>('#context')! })

// nabi.onChange(() => user_callback(nabi.getHtml()))
```
