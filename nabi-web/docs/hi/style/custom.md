# स्टाइल बदलना

शीट **होस्ट जोड़ता है** — बंडलर इस्तेमाल हो तो `import 'nabi-note/nabi.css'` की एक
लाइन, CDN हो तो `<link>` की एक लाइन। उसके बाद बस वेरिएबल बदलने होते हैं।

कंपोनेंट के नियमों में **एक भी रंग सीधा (literal) नहीं लिखा है।** सब कुछ
`--nabi-*` वेरिएबल से खींचा गया है, इसलिए वेरिएबल बदलते ही बाक़ी सब उसी के पीछे
चलता है।

```css
.nabi.nabi.nabi {
  --nabi-accent: #7c3aed;
}
```

क्लास को तीन बार दोहराने की वजह नीचे
[विशिष्टता (specificity) से न टकराने](#विशिष्टता-specificity-से-न-टकराने) में है।

::: tip इस दस्तावेज़ की बड़ी बुनियाद — सहेजा मान अकेला खड़ा नहीं रहता
बाहर जाने वाला HTML (`getHtml()`) में **एक भी इनलाइन `style` नहीं होता।** सहेजा
मान सिर्फ़ *क्या* है यह attribute से बताता है (`data-nabi-align="center"`), और
*कैसा दिखता है* यह यह शीट बताती है। इसीलिए सहेजा HTML जहाँ भी पढ़कर खींचा जाए,
वहाँ भी वही असर पाने के लिए **यही शीट जुड़े `.nabi-content` के भीतर** होना चाहिए
— नीचे [सहेजे HTML को बाहर खींचते समय](#सहेजे-html-को-बाहर-खींचते-समय) देखें।
:::

::: tip डार्क · लाइट पहले से शामिल हैं
थीम के लिए होस्ट को कोई टोकन बदलना **नहीं पड़ता।** कोर शीट खुद लाइट डिफ़ॉल्ट ·
`.dark` पुनर्परिभाषा · स्पष्ट `.light` पुनर्परिभाषा — तीनों साथ लाती है। यह साइट
भी एडिटर के भीतर फ़ॉन्ट के चार टोकन के अलावा कुछ नहीं बदलती।
:::

## रंग · आकार टोकन

| टोकन | अर्थ | डिफ़ॉल्ट (लाइट) |
|---|---|---|
| `--nabi-bg` · `--nabi-soft` | पृष्ठभूमि · हल्का दबा हुआ तल | `#fff` · `rgb(0 0 0 / 4.5%)` |
| `--nabi-fg` · `--nabi-muted` · `--nabi-on-accent` | अक्षर · धुँधले अक्षर · एक्सेंट पर के अक्षर | `#1b1b1f` · `#6b6b76` · `#fff` |
| `--nabi-line` · `--nabi-accent` | रेखा · एक्सेंट रंग | `#e2e2e8` · `#3b6fe0` |
| `--nabi-danger` · `--nabi-on-danger` | ख़तरा · उस पर के अक्षर | `#d93b3b` · `#fff` |
| `--nabi-shadow` · `--nabi-scrim` | बॉक्स की छाया · पूर्वावलोकन की पृष्ठभूमि | — |
| `--nabi-radius` · `--nabi-radius-sm` · `--nabi-radius-xs` | कोने | `6px` · `4px` · `3px` |
| `--nabi-layer-radius` | परत (पैनल·पूर्वावलोकन·लाइटबॉक्स) के कोने | `.25rem` |
| `--nabi-z-sticky` | चिपकी हुई पंक्ति की परत-संख्या | `20` |
| `--nabi-grid-cell` | तालिका के आकार-ग्रिड की कोशिका का आकार | `1.125rem` |
| `--nabi-hl-yellow`·`green`·`cyan`·`pink`·`purple`·`orange` | हाइलाइट के छह रंग | पारभासी रंग |
| `--nabi-tc-green`·`coral`·`violet`·`amber`·`blue` | टेक्स्ट के पाँच रंग | गहरे रंग |

यह तालिका सिर्फ़ वही रखती है जो कोर शीट (`nabi.css`) **सीधे घोषित करती है।**
घोषणा की जगह सिर्फ़ `.nabi` एक नहीं, तीन हैं —
`:is(.nabi, .nabi-scrim, .nabi-content:where(:not(.nabi *)))`। क्योंकि
पूर्वावलोकन ओवरले `body` की संतान है इसलिए `.nabi` से विरासत (inheritance) नहीं
पहुँचती, और एडिटर से बाहर अकेला खड़ा `.nabi-content` भी सीधे टोकन पाना चाहिए।

यही सूची तीन बार लिखी है (लाइट डिफ़ॉल्ट · `.dark` · स्पष्ट `.light`)। **बदलने
वाले को तीनों देखने की ज़रूरत नहीं** — बस विशिष्टता में जीत जाए तो एक बार बदला
मान तीनों जगह लागू हो जाता है। हाँ, डार्क में अलग मान चाहिए तो `.dark` शर्त खुद
जोड़नी होगी।

## बिना मान वाले, सिर्फ़ संदर्भित टोकन

नीचे वे वेरिएबल हैं जिन्हें कोर **घोषित नहीं करता, सिर्फ़ संदर्भित करता है।**
होस्ट मान न दे तो कोष्ठक में लिखा फ़ॉलबैक लागू होता है। घोषणा की कोई जगह न होने
से **`:root` में लिखने से भी वे उतनी ही असर करते हैं** — ऊपर के रंग-आकार टोकन
से यही फ़र्क़ है (वे `.nabi` में घोषित हैं इसलिए विरासत उन्हें हरा नहीं सकती)।

| टोकन | अर्थ | फ़ॉलबैक |
|---|---|---|
| `--nabi-font` · `--nabi-font-serif` · `--nabi-font-mono` · `--nabi-font-cursive` | टाइपफ़ेस wing की चार क़िस्मों पर असल में लगने वाला फ़ॉन्ट | सिस्टम फ़ॉन्ट |
| `--nabi-cursive-adjust` | हस्तलिपि (cursive) का `font-size-adjust`। हस्तलेख वाले फ़ॉन्ट की x-height कम होती है, जिससे वही px भी छोटा दिखता है — यह मान x-height के हिसाब से फिर सेट करता है | `0.4` |
| `--nabi-sticky-top` | चिपकी पंक्ति कितना नीचे बैठती है। साइट पर ऊपर स्थिर हेडर हो तो उसकी ऊँचाई | `0px` |
| `--nabi-preview-width` | पूर्वावलोकन कार्ड की चौड़ाई। **`openPreview` खुलते समय संपादन क्षेत्र की चौड़ाई नापकर सीधे कार्ड पर लिख देता है**, इसलिए होस्ट बाहर से बदले तो भी वह इनलाइन मान जीतता है | `720px` |

`--nabi-typeface-base` इस समूह में नहीं है — इसे **कोर घोषित करता है** (डिफ़ॉल्ट
`--nabi-font` का अनुसरण करता है)। टाइपफ़ेस wing में यह मान तय करने का कोई विकल्प
नहीं है, इसलिए बदलना हो तो यही टोकन बदलें।

`--nabi-keyboard-top` · `--nabi-keyboard-bottom` भी इसी जगह रहते हैं, पर इन्हें
**कोर इस्तेमाल करता है** — `mountSticky()` मोबाइल कीबोर्ड ने स्क्रीन को जितना
धकेला उतना नापकर यहाँ लिखता है, और चिपकी पंक्ति व फ़ुल-स्क्रीन इसे पढ़ते हैं। ये
हाथ से लिखने वाले मान नहीं हैं।

## जहाँ टोकन नहीं है — नियम को ही बदलें

नीचे के तीन में **कोई वेरिएबल नहीं है।** कोर ने मान सीधे नियम में जड़ दिया है,
इसलिए बदलना हो तो वही चयनकर्ता (selector) बदलें।

**अक्षर-आकार के चार स्तर** — `em` में हैं इसलिए माता-पिता (parent) के आकार का
अनुसरण करते हैं।

```css
.nabi-content [data-nabi-size="xs"] { font-size: .75em; }
.nabi-content [data-nabi-size="sm"] { font-size: .875em; }
.nabi-content [data-nabi-size="lg"] { font-size: 1.25em; }
.nabi-content [data-nabi-size="xl"] { font-size: 1.5em; }
```

**ड्रॉप कैप का आकार** — कितनी पंक्तियाँ ढकेगा यह तय करने वाला मान नहीं, बस एक
अक्षर-आकार है। असल में कितनी पंक्तियाँ ढकेगा यह उस पैराग्राफ़ की लाइन-हाइट तय
करती है।

```css
.nabi-content [data-nabi-dropcap="1"]::first-letter { font-size: 5.9em; line-height: .83; }
```

**कोड टोकन का रंग** — code wing की शीट `[data-nabi-token]` पर सीधे रंग लिखती है।
अभी रंग पाने वाले समूह **पाँच** हैं।

```css
.nabi-content [data-nabi-token="comment"] { color: #7a8a7a; font-style: italic; }
.nabi-content [data-nabi-token="string"] { color: #a2543a; }
.nabi-content [data-nabi-token="keyword"] { color: #7b4fd0; }
.nabi-content [data-nabi-token="number"] { color: #2f6fd0; }
.nabi-content [data-nabi-token="literal"] { color: #2f8f4e; }
```

हाइलाइटर जो `type` लौटाता है वह खुला (free) टेक्स्ट है — ऊपर के पाँच से बाहर का
नाम आए तो बिना रंग के दिखता है, इसलिए कोई और समूह चाहिए तो होस्ट उसी ढंग से एक
नियम जोड़ दे। डार्क में अलग रंग चाहिए तो `.dark` शर्त खुद जोड़ें — कोर इन पाँच
के लिए कोई डार्क वैरिएंट नहीं देता।

upload wing की प्रगति-एनिमेशन (`--nabi-per`·`--nabi-t`·`--nabi-span`·
`--nabi-clear`·`--nabi-blur-max`) **wing के भीतरी इस्तेमाल के लिए है** — नाम
`--nabi-` से शुरू होता है, पर यह होस्ट के बदलने के लिए खुली जगह नहीं है।

## बाहरी नाप `rem` में हैं

बटन, हाशिया, टूलबार-चिप जैसी बाहरी नाप ज़्यादातर `rem` में हैं इसलिए **जड़
(`html`) के अक्षर-आकार के साथ बढ़ती हैं।** उपयोगकर्ता ब्राउज़र या OS में अक्षर
बड़े करे तो एडिटर का ढाँचा भी साथ बड़ा हो जाता है। आकार बदलना हो तो जड़ का
`font-size` बदलें। बॉर्डर (`border`) नाप नहीं, **रेखा** है, इसलिए कुछ जगह अब भी
`px` में है।

## विशिष्टता (specificity) से न टकराने

रंग-आकार टोकन बदलने के लिए **क्लास को तीन बार** दोहराएँ।

```css
.nabi.nabi.nabi,
.nabi-scrim.nabi-scrim.nabi-scrim {
  --nabi-accent: var(--मेरा-एक्सेंट-रंग);
}
```

गिनकर देखें तो ऐसा है। लाइट डिफ़ॉल्ट नियम `:is(.nabi, …)` की विशिष्टता
**(0,1,0)** है क्योंकि `:is()` अपने argument में सबसे ऊँची विशिष्टता लेता है;
डार्क नियम `:where(html, body).dark :is(.nabi, …)` की विशिष्टता **(0,2,0)** है
क्योंकि `:where()` शून्य है और `.dark` व `:is()` एक-एक क्लास जोड़ते हैं। इसलिए
`.nabi.nabi` से डार्क के साथ **बराबरी** हो जाती है — बराबरी में जो बाद में लोड
हो वह जीतता है, और कोर शीट होस्ट की शीट से बाद में भी लोड हो सकती है। क्रम पर
निर्भर न रहने के लिए क्लास तीन बार दोहराकर (0,3,0) तक चढ़ना पड़ता है।

पूर्वावलोकन ओवरले `.nabi` के बाहर (यानी `body` की संतान के रूप में) खड़ा होता
है, इसलिए वही रंग पाने के लिए उसका चयनकर्ता भी साथ लिखना होगा।

**फ़ॉन्ट जैसे जिन टोकन को कोर घोषित नहीं करता, उनके लिए यह जद्दोजहद नहीं
चाहिए** — घोषणा की कोई जगह न होने से विरासत से ही पहुँच जाते हैं, बस `:root`
में एक लाइन काफ़ी है।

```css
:root {
  --nabi-font: 'Noto Sans', system-ui, sans-serif;
}
```

## लाइट · डार्क

`html` या `body` — **दोनों में से किसी एक** — पर `dark` क्लास हो तो डार्क, `light`
हो तो लाइट। कोई क्लास न हो तो लाइट डिफ़ॉल्ट है, दोनों हों तो स्पष्ट `light`
जीतता है (`.light` नियम `.dark` नियम के बाद लोड होता है)।

```html
<html class="dark"><!-- या <body class="dark"> --></html>
```

क्लास टॉगल करते ही CSS ख़ुद प्रतिक्रिया देता है। बुलाने के लिए कोई API नहीं है।
थीम सिर्फ़ रंग-वेरिएबल बदलती है, कंपोनेंट के नियम वैसे ही रहते हैं — अपनी बनाई
स्टाइल भी सिर्फ़ `--nabi-*` वेरिएबल इस्तेमाल करे तो डार्क का अनुसरण करती है।

## शीट जोड़ने के दो रास्ते

**① एक फ़ाइल** — सबसे आम रास्ता। इसमें हर wing का CSS होता है।

```ts
import 'nabi-note/nabi.css'
```

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note/dist/nabi.css">
```

**② सिर्फ़ रजिस्टर किए का इंजेक्शन** — जब सिर्फ़ चालू किए गए wing की शीट चाहिए।

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const drop = injectSheets(document, collectSheets(registry))
// drop() बुलाने पर सिर्फ़ इसी पुकार ने जो डाला वह हटता है
```

एक जैसे पाठ की शीट **सिर्फ़ एक बार** भीतर जाती है — डुप्लिकेट हटाने की कुंजी
शीट की **सामग्री** है, इसलिए एक ही दस्तावेज़ में कई एडिटर खड़े हों तो भी ढेर
नहीं लगता, और अलग-अलग wing की बनावट मिले तो भी एक मिले-जुले संघ (union) में
समा जाती है।

::: tip दोनों में दो फ़र्क़ हैं — क्या लदता है, और कब जुड़ता है
**क्या लदता है।** फ़ाइल को पता नहीं कि कौन-सा wing रजिस्टर हुआ, इसलिए वह **सब**
ढोती है। इंजेक्शन `registry` देखकर **सिर्फ़ रजिस्टर किया हुआ** ढोता है। जो पेज
सहेजा HTML सिर्फ़ दिखाता है, उसके पास एडिटर नहीं इसलिए `registry` भी नहीं —
उसके लिए फ़ाइल वाला रास्ता इस्तेमाल करें।

**कब जुड़ता है।** फ़ाइल `<link>` के ज़रिए हेड में आती है और **रेंडर होने से पहले
रोकती है**, पर इंजेक्शन एडिटर की जावास्क्रिप्ट **पहुँचने के बाद ही** जुड़ता है।
इसलिए जो पेज दस्तावेज़ को सर्वर पर पहले से खींचकर भेजता है, उसे फ़ाइल वाला रास्ता
ही लेना चाहिए — इंजेक्शन से जोड़ने पर सर्वर का भेजा दस्तावेज़ पहले बिना स्टाइल के
दिखता है, फिर स्टाइल चढ़ते ही ले-आउट फिर से जमता है।
:::

रजिस्टर किए wing की शीट कोर शीट के **बाद** जुड़ती है, इसलिए एक जैसी प्राथमिकता
में wing जीतता है।

## जुड़ने लायक जगहें

जो वेरिएबल से नहीं हो सकता, उसे असल में मौजूद क्लास को सीधे निशाना बनाकर करें।

| चयनकर्ता | क्या है | कौन जोड़ता है |
|---|---|---|
| `.nabi` | पूरे एडिटर (chrome + संपादन क्षेत्र) को लपेटने वाला खोल। रंग-आकार टोकन यहीं टँगते हैं | होस्ट |
| `.nabi-content[contenteditable]` | संपादन क्षेत्र स्वयं | होस्ट |
| `.nabi-toolbar` | टूलबार पंक्ति + कॉन्टेक्स्ट पंक्ति को लपेटने वाली जगह। यही क्लास "ऊपर चिपकना" है | होस्ट |
| `.nabi-toolbar-row` | टूलबार जिस पात्र में बैठता है | `mountToolbar()` |
| `.nabi-context` | कॉन्टेक्स्ट पंक्ति जिस पात्र में बैठती है | `mountContextToolbar()` |
| `.nabi-tools` | पूर्वावलोकन·फ़ुल-स्क्रीन दो बटनों की जगह — कोर इन्हें ऊपर दाईं ओर तैराता है | `mountViewTools()` |
| `.nabi-tool` | वे दोनों बटन स्वयं | `mountViewTools()` |
| `.tb-group` | टूलबार के बटनों का समूह | `mountToolbar()` |
| `.ctb-group` · `.ctb-button` · `.ctb-swatch` · `.ctb-input` | कॉन्टेक्स्ट पंक्ति के समूह·बटन·रंग-नमूना·टेक्स्ट कक्ष | `mountContextToolbar()` |
| `.tb-picker` · `.tb-picker-grid` · `.tb-picker-cell` | तालिका आकार-ग्रिड जैसा बटन के नीचे उभरने वाला बक्सा | `mountToolbar()` |
| `.tb-prompt` · `.tb-prompt-input` | नई चीज़ डालते समय उभरने वाली पता-इनपुट परत | `mountToolbar()` |
| `.nabi-hints [data-hint]` | Shift दो बार दबाने पर दिखने वाला शॉर्टकट बैज — बैज `::before` है, लेबल `::after`, इसलिए दोनों साथ दिखते हैं | `mountHints()` |
| `[data-nabi-tip]` | लेबल (tooltip) — सिर्फ़ CSS `::after` से खींचा जाता है | कोर सामान्यतः |
| `.nabi-content.nabi-dropping` | फ़ाइल खींचकर लाने के दौरान का संपादन क्षेत्र। मार्गदर्शक टेक्स्ट `data-nabi-drop` attribute पर होता है | `mountUpload()` |

पूर्वावलोकन·फ़ुल-स्क्रीन भी **कोर ही बनाता है।**

| चयनकर्ता | क्या है | कौन |
|---|---|---|
| `.nabi-scrim` > `.nabi-card` > (`.nabi-close` · `.nabi-content.nabi-preview-body`) | दस्तावेज़ पूर्वावलोकन ओवरले | `openPreview()` |
| `.nabi-scrim` > `.nabi-card.nabi-lightbox` | सिर्फ़ एक छवि को बड़ा दिखाने वाला बक्सा | `openImageLightbox()` |
| `.nabi.is-fullscreen` | फ़ुल-स्क्रीन — `.nabi` बक्से को स्क्रीन पर जकड़ता है | `setFullscreen()` (क्लास का नाम `FULLSCREEN_CLASS`) |

`mountViewTools()` जोड़ें तो दोनों बटन इन्हें खुद खोलते-बंद करते हैं। खुद खोलना
हो तो `openPreview({ nabi, editor })` · `openImageLightbox({ editor, src, alt?, locale })`
· `setFullscreen(root, on)` · `isFullscreen(root)` बुलाएँ।

::: tip टूल की जगह खुद खड़ी होती है
`mountViewTools` `.nabi-tools` बक्सा खुद बनाकर मिले पात्र के सबसे आगे डाल देता
है। होस्ट को टूलबार से पहले `<span>` रखने की ज़रूरत नहीं — जगह पहले से बनाकर
रखी हो तो सिर्फ़ दो बक्से बन जाते हैं।
:::

संपादन स्क्रीन के लिए ख़ास निशान भी पकड़े जा सकते हैं — `[data-nabi-token]`
(कोड ब्लॉक के टोकन का रंग), `[data-nabi-lang]` (कोड ब्लॉक की भाषा),
`[data-color]` (हाइलाइट·टेक्स्ट-रंग — `<mark>`·`<span>` टैग से अलग पहचाने
जाते हैं), `data-nabi-align`·`data-nabi-typeface`·`data-nabi-size`·
`data-nabi-dropcap` (पैराग्राफ़ गुण)। इन निशानों के असली नाम की प्रामाणिक
जगह हर wing फ़ाइल का `*_ATTR` स्थिरांक है।

## सहेजे HTML को बाहर खींचते समय

बाहर जाने वाला मान (`getHtml()`) `data-nabi-*` attribute वाला HTML है, और
**उसमें एक भी इनलाइन `style` नहीं है।** मतलब दिखावट पूरी तरह शीट के हवाले है,
इसलिए शीट के बिना खींचें तो न संरेखण, न अक्षर-आकार, न तालिका की रेखा वाला नंगा
HTML मिलता है।

एडिटर जैसा ही दिखाना हो तो इसे `.nabi-content` में लपेटें — यह क्लास `.nabi`
में लपेटे बिना भी रंग-आकार टोकन सीधे पाती है (`nabi.css` का
`.nabi-content:where(:not(.nabi *))` नियम)।

```html
<div class="nabi-content">सहेजा हुआ HTML</div>
```

शीट ऊपर «शीट जोड़ने के दो रास्ते» में दिखाए तरीक़े से ही जोड़ें — बंडलर हो तो
`import 'nabi-note/nabi.css'`, नहीं तो एक `<link>`। एडिटर न खड़ा करने वाले पेज
पर भी सिर्फ़ `.nabi-content` होने से कोर शीट टोकन घोषित कर देती है।

### पढ़ने वाले पक्ष पर चलने वाला व्यवहार — तालिका छाँटना

अभी सिर्फ़ **तालिका छाँटना** एक ऐसा काम है जो पढ़ने वाले पक्ष के लिए अलग फ़ंक्शन
के रूप में मिलता है। किसी भी मनचाहे wing को अपना पढ़ने-वाला व्यवहार टाँगने की
सामान्य व्यवस्था अभी नहीं है।

```ts
import { attachTableSort } from 'nabi-note/viewer'

const detach = attachTableSort(document.querySelector('#article')!, { locale: 'hi' })
```

`data-nabi-sortable` लगी तालिकाएँ ढूँढकर उनके शीर्षक-कक्ष में छाँटने वाला बटन
जोड़ता है। हटाने वाला फ़ंक्शन (`detach`) जोड़े गए बटन और बदले गए पंक्ति-क्रम
दोनों को वापस लौटा देता है।

::: danger संपादित होने वाले एलिमेंट पर मत जोड़ें
`attachTableSort()` DOM में बटन जड़ता है और पंक्ति-क्रम बदलता है। जुड़े रहने के
दौरान का DOM सहेजा जाए तो वह मान में स्थायी हो जाता है — इसे सिर्फ़ पढ़ने वाले
पक्ष की एक read-only कॉपी पर ही जोड़ें।
:::
