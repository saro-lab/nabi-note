# SSR समर्थन

## केवल सहेजा हुआ रूप बनाने की जगह — एडिटर खड़ा नहीं करता

टिप्पणी सूची जैसी **सिर्फ़ दिखाने वाली जगह** को एडिटर की ज़रूरत नहीं। दस्तावेज़ बनाने में
जो लगता है वह रजिस्टर किए wing की सूची (`registry`) भर है, इसलिए सिर्फ़ वही लेने वाला
अलग रास्ता है।

```ts
import { makeRegistry, defaultWings, renderStoredHtml, renderStoredEditorHtml } from 'nabi-note/ssr'

// सर्वर शुरू होते समय एक बार — कितने भी सहेजे दस्तावेज़ हों, यही एक बाँटा जाता है
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['टिप्पणी की एक पंक्ति'] }]   // DB से पढ़ा गया nabi-tree

renderStoredHtml(saved, registry)        // '<p>टिप्पणी की एक पंक्ति</p>'
renderStoredEditorHtml(saved, registry)  // '<p data-key="n0">टिप्पणी की एक पंक्ति</p>'
```

**`nabi-note/ssr` सिर्फ़ बनाने में लगने वाली चीज़ों वाला प्रवेश-बिंदु है।** यह एडिटर सतह
(`surface`) और स्क्रीन के औज़ार (`ui`) को एक फ़ाइल भी नहीं छूता (जाल इसे पकड़ता है), इसलिए
सर्वर बंडल में DOM कोड नहीं घुलता। यही रास्ता `nabi-note` में भी है, तो जिस पेज पर एडिटर
पहले से खड़ा है वह उसी को इस्तेमाल कर सकता है।

| | |
|---|---|
| `renderStoredHtml(json, registry, options?)` | सहेजने-प्रकाशित करने वाला HTML — `getHtml()` जैसा ही मान |
| `renderStoredEditorHtml(json, registry, options?)` | एडिटर वाला HTML — `getEditorHtml()` जैसा ही मान (`data-key` लगा हुआ) |

- **दोनों DOM इस्तेमाल नहीं करते** — सर्वर पर वैसे ही चलते हैं।
- **nabi-tree न हो तो `null`** — अस्वीकार का नियम `setJson()` जैसा ही है (पूरा दस्तावेज़ एक
  ऐरे होना चाहिए)। फेंकता नहीं।
- **एडिटर के दिए मान से एक अक्षर भी अलग नहीं।** वही क़दम (सामान्यीकरण → जोड़ना) से गुज़रता है,
  इसलिए XSS छनने की जगह भी वही है — सिर्फ़ दिखाने वाला पक्ष कम धुला नहीं रहता।
- `options` सिर्फ़ `{ allowLocalUrls }` है — `createNabiWith` के उसी विकल्प जैसा मतलब।

**एक ही सहेजा दस्तावेज़ हमेशा एक ही `data-key` पाता है।** इसीलिए सर्वर `renderStoredEditorHtml`
से एडिटर पहले से खींचकर भेज सकता है, और ब्राउज़र में `hydrate` इसे आगे बढ़ाए तो स्क्रीन दोबारा
नहीं खींचता।

```ts
mountSurface({ nabi, registry, root: surface, hydrate: true })
```

बेमेल हो तभी वहीं नए सिरे से खींचता है, इसलिए सर्वर और क्लाइंट के wing की सूची बस बराबर होनी चाहिए।

::: tip इस साइट का अपना होम पेज ही वह नमूना है
होम डेमो का दस्तावेज़ **बिल्ड के समय `renderStoredEditorHtml` से पहले खींचकर** पेज में जड़ा गया
है, और एडिटर उसी के ऊपर `hydrate` से जागता है। इसलिए एडिटर का कोड आने से पहले भी लेख पहले
से दिखता है — खाली जगह अचानक भर जाने वाला हिस्सा नहीं है।
:::

## टूलबार भी पहले से खींची जा सकती है

बटन-पंक्ति **दस्तावेज़ को नहीं देखती।** यह सिर्फ़ रजिस्टर किए wing की सूची, भाषा और ग्रुप के
क्रम को देखती है, इसलिए निकलने वाला अक्षर **स्थिर (constant)** होता है — सर्वर शुरू होते समय
एक बार बुलाया जाता है और वही अक्षर बार-बार इस्तेमाल होता है। हर रिक्वेस्ट पर दोबारा बुलाने की
ज़रूरत नहीं।

```ts
import { makeRegistry, defaultWings, renderToolbarHtml } from 'nabi-note/ssr'

const registry = makeRegistry(defaultWings)

const toolbarHtml = renderToolbarHtml({ registry, locale: 'hi' })
// '<div class="nabi-group" data-group="font">...</div>'
```

यह अक्षर टूलबार के कंटेनर में ज्यों का त्यों भेज दें, तो ब्राउज़र में `mountToolbar` **वही
फ़ंक्शन** इस्तेमाल करके खींचता है। पहले से वैसी ही पंक्ति खड़ी हो तो **दोबारा नहीं खींचता,
सिर्फ़ वायरिंग जोड़ता है।**

```ts
mountToolbar({ nabi, registry, surface, root: toolbar })
```

::: warning कंटेनर पर `class="nabi-toolbar-row"` साथ लिखें
पहले से खींची पंक्ति भेजते समय **पहली ही ड्रॉइंग से** यह क्लास होनी चाहिए। कोर यह क्लास न
मिलने पर mount के समय खुद जोड़ता है, और तब दाएँ-बाएँ मार्जिन उस वक़्त लगने से **बटन-पंक्ति
एक बार बग़ल में खिसक जाती है।** होस्ट पहले से लिख दे तो कोर उसे छूता नहीं (सिर्फ़ अपना जोड़ा
हुआ हटाता है)।

```html
<div class="nabi-toolbar-row">पहले से खींची पंक्ति</div>
```
:::

- **बेमेल हो तो भी नहीं टूटता** — खड़ी पंक्ति अभी के wing की सूची से अलग हो तो वहीं नए सिरे से
  खींच देता है। सिर्फ़ पहले से खींचा मान खोता है, स्क्रीन हमेशा सही रहती है।
- **पहले से खींची पंक्ति "कुछ भी दबा नहीं, कुछ भी छुपा नहीं" वाली हालत में होती है।** दबाव
  (`aria-pressed`) और छुपाव कर्सर तय करता है, जिसे सर्वर नहीं जानता। कर्सर के हिसाब से बटन
  छुपने वाली रचना हो तो, mount के बाद कुछ बटन ग़ायब होकर पंक्ति फिर से सिकुड़ सकती है।
- **सिर्फ़ एडिटर खड़ा करने वाली जगह पर ही भेजें।** सिर्फ़ पढ़ने वाले पेज पर टूलबार नहीं होती,
  इसलिए यह अक्षर लेने की कोई वजह नहीं।

**पूर्वावलोकन और फ़ुल-स्क्रीन के दो बटन भी इसी रास्ते से जाते हैं।** ये wing नहीं, कवर
(chrome) के हिस्से हैं, इसलिए ऊपर के टूलबार अक्षर में शामिल नहीं होते — अलग से खींचकर
`mountViewTools` जिस कंटेनर पर खड़ा होगा वहाँ डाले जाते हैं।

```ts
import { renderViewToolsHtml } from 'nabi-note/ssr'

renderViewToolsHtml({ locale: 'hi' })
// '<span class="nabi-tools">...</span>'
```

::: tip इस साइट का अपना होम पेज ही वह नमूना है
होम डेमो की टूलबार **बिल्ड के समय `renderToolbarHtml`·`renderViewToolsHtml` से पहले खींचकर**
जड़ी गई है, और `mountToolbar`·`mountViewTools` उस पंक्ति को पहचानकर सिर्फ़ वायरिंग जोड़ते हैं।
इसीलिए पैंतीस आइकॉन देर से भरने वाला हिस्सा नहीं दिखता।
:::
