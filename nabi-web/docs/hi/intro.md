# NABI NOTE क्या है?

NABI NOTE ब्राउज़र में चलने वाला एक **ओपन-सोर्स WYSIWYG एडिटर** है।

---

## दस्तावेज़ की असली शक्ल nabi-tree है

दस्तावेज़ को ढोने वाला पात्र HTML स्ट्रिंग नहीं बल्कि **nabi-tree** है — फ़ॉर्मेटिंग
और गुणों की जानकारी रखने वाली एक सादी JS ऑब्जेक्ट-सरणी। HTML सिर्फ़ उन दो सिरों पर
होता है जहाँ से यह ट्री गुज़रता है।

<FlowChain :steps="stepsIn" caption="इनपुट — बाहर से आया HTML setHtml() से nabi-tree बनने के बाद ही स्क्रीन पर रखा जाता है।" />

<FlowChain :steps="stepsOut" caption="आउटपुट — एक ही nabi-tree से तीन चीज़ें निकलती हैं। स्क्रीन का DOM ज्यों का त्यों बाहर नहीं भेजा जाता।" />

| फ़ंक्शन | क्या है |
|---|---|
| `getHtml()` | **वह HTML जिसे आप सहेजते और प्रकाशित करते हैं।** इस पर एडिटर-भर का कोई निशान नहीं होता |
| `getJson()` | **nabi-tree है।** आंतरिक कुंजी (`_id`) बाहर जाते समय हटा दी जाती है |
| `getEditorHtml()` | अभी एडिटर की स्क्रीन का HTML है। इस पर `data-key` लगा होता है, इसलिए यह निर्यात करने लायक मान नहीं है |

**सहेजने के लिए पहले दो में से एक चुनें।** `getEditorHtml()` उस जगह के लिए है जब
सर्वर पर पहले से एडिटर खींचना हो। पूरी शक्ल [{{ t('menu_intro_usage') }}](./intro/usage)
में है।

तीनों **उसी एक nabi-tree से, उसी वक़्त निकाले जाते हैं** — कहीं भी HTML स्ट्रिंग
जमा करके नहीं रखी जाती। इसीलिए `onChange` से मिला `getHtml()` का मान फिर से
`setHtml()` से पढ़वाने पर वही nabi-tree लौटता है।

::: tip आउटपुट को DOM नहीं चाहिए
`createNabiWith()` · `getJson()` · `getHtml()` · `getEditorHtml()` शुद्ध गणना हैं।
मतलब सहेजा हुआ nabi-tree ज्यों का त्यों देकर सर्वर (Node.js) से भेजने वाला HTML
जोड़ा जा सकता है — न ब्राउज़र चाहिए, न नक़ली DOM। जिसे DOM चाहिए वह सिर्फ़
**इनपुट** (`setHtml()`) और स्क्रीन से जुड़ने वाले `mount*` हैं।

```ts
import { createNabiWith, defaultWings } from 'nabi-note'

const { nabi } = createNabiWith(defaultWings, { doc: सहेजा_हुआ_nabi_tree })
const html = nabi.getHtml()
```
:::

आने वाला HTML (हाथ से लिखा हो, पेस्ट किया हो, या सहेजकर फिर लोड किया हो) जब
`setHtml()` से गुज़रता है, तो रजिस्टर किए गए wing जिन टैग·गुणों को नहीं जानते वे
सब छान दिए जाते हैं। ट्री को खुद `cocoon` एक बार और सँवारता है, ताकि ब्लॉक साफ़-सुथरे
नेस्ट हों, आंतरिक कुंजियाँ अद्वितीय रहें, और पत्ती-ब्लॉक कभी खाली न बचे।

::: tip सहेजा हुआ HTML दोबारा खींचते समय
`getHtml()` ने जो छाना वह **अरजिस्टर्ड मार्कअप** था। सहेजकर निकाले HTML को एडिटर
में नहीं बल्कि एक **सामान्य पेज** पर ज्यों का त्यों खींचना हो, तो उस पेज को अब भी
अपना sanitize चाहिए — एडिटर का फ़िल्टर एडिटर के अपने लिए है, यह गारंटी नहीं कि
मनमाना HTML सुरक्षित रूप से खींचा जा सकता है।
:::

## हर फ़ॉर्मेट एक wing है

जिसे बाक़ी एडिटर "प्लगइन" कहते हैं, उसे हम **wing** कहते हैं। कोर सीधे सिर्फ़
पैराग्राफ़ (`p`), लाइन (`br`) और सादे टेक्स्ट को जानता है — शीर्षक·सूची·तालिका·बोल्ड
सब wing हैं। कोड में भी यही शब्द इस्तेमाल होता है — टाइप है `Wing`।

**सारे wing तैयार-तैयार स्थिरांक (constant) हैं।** बस उन्हें सरणी में डाल दें। जिन
दो को विकल्प चाहिए सिर्फ़ उन्हीं का फ़ैक्ट्री फ़ंक्शन अलग से है —
`makeImageWing({ allowLocalUrls })` और `makeUploadWing({ allowLocalUrls })`। जब
सिर्फ़ जुड़ने वाला काम बदलना हो, जैसे कोड रंगना, तो स्थिरांक को फैलाकर लिखें:
`{ ...codeWing, attach: makeCodeAttach({ highlight }) }`।

```ts
import { createNabiWith, parseNodes, boldWing } from 'nabi-note'

const bare = createNabiWith([], { parseHtml: parseNodes }).nabi
bare.setHtml('<p><b>बोल्ड</b> <i>इटैलिक</i></p>')
bare.getHtml()
// '<p>बोल्ड इटैलिक</p>'                    — कोई wing नहीं है
const bold = createNabiWith([boldWing], { parseHtml: parseNodes }).nabi
bold.setHtml('<p><b>बोल्ड</b> <i>इटैलिक</i></p>')
bold.getHtml()
// '<p><b>बोल्ड</b> इटैलिक</p>'              — सिर्फ़ बोल्ड बचता है
```

जो मार्कअप रजिस्टर नहीं किया, उसका खोल उतर जाता है और वह **सादे टेक्स्ट में बदल
जाता है।** "इस एडिटर से क्या लिखा जा सकता है" का जवाब रजिस्टर किए गए wing की सूची
ही है।

## संपादन एक ही दरवाज़े से गुज़रता है

दस्तावेज़ बदलने वाला **हर** रास्ता एक ही `applyCommand()` से गुज़रता है — टूलबार का
बटन भी, ऑटो-रूपांतरण भी, पेस्ट भी, अनडू भी। मूल ट्री को हाथ से बदलने का कोई रास्ता
शुरू से नहीं है।

```ts
nabi.applyCommand('toggleMark', { w: 'b' })     // बोल्ड — कोर का मार्क टॉगल
nabi.applyCommand('setHeading', { value: 2 })   // शीर्षक स्तर 2 — किसी wing ने जोड़ा कमांड
nabi.undo()
nabi.redo()
```

कमांड **जवाब `boolean` में देते हैं।** वे अपवाद नहीं फेंकते, और कुछ न बदले तो
`false` जवाब देकर न कोई अनडू-बिंदु छोड़ते हैं न कोई सिग्नल।

जिस जगह कोई wing कमांड जोड़ता है वह एक ही घोषणा है (`commands`)। **मूल (built-in)
wing भी वही दरवाज़ा इस्तेमाल करते हैं जो किसी और के लिखे wing के लिए है** — "सिर्फ़
मूल wing के लिए शॉर्टकट" जैसी कोई चीज़ नहीं है।

## परतें नीचे से ऊपर तक चढ़ती हैं

यह क्रम गद्य नहीं, **एक जाँच** है। अगर नीचे की परत ऊपर की किसी परत को import करे तो
जाल गिर जाता है। भाई-बहन wing का एक-दूसरे को बुलाना भी रोका गया है, इसलिए साझा कोड
`wing` परत में नीचे उतर जाता है।

नई सुविधा एक wing है। अगर लगे कि कोर की किसी फ़ाइल को बदलना पड़ेगा, तो अक्सर इसका
मतलब है कि **कॉन्ट्रैक्ट (`Wing` टाइप) में कमी है।**

## शब्दावली

यह साइट और रिपॉज़िटरी जो बाक़ी शब्द इस्तेमाल करते हैं वे यहाँ हैं। कुछ शब्द दूसरे
एडिटर के शब्दों से मिलते-जुलते हैं पर मतलब अलग है, इसलिए यहाँ सिर्फ़ नीचे लिखे
अर्थ में इस्तेमाल होते हैं।

### दस्तावेज़ किससे बनता है

| शब्द | अर्थ |
|---|---|
| **मार्क (mark)** | अक्षरों पर लगाई गई फ़ॉर्मेटिंग है — `<b>` · `<i>` · `<a>`। यह कहीं भी रह सकता है — वाक्य के बीच, तालिका की कोशिका में, शीर्षक के भीतर |
| **ब्लॉक (block)** | पैराग्राफ़ की जगह घेरने वाला टुकड़ा है — पैराग्राफ़, शीर्षक, सूची, तालिका, छवि |
| **पैराग्राफ़ गुण (paragraph attribute)** | नया टैग नहीं बनाता, सिर्फ़ पैराग्राफ़ का स्वभाव बदलता है — शीर्षक स्तर, संरेखण, ड्रॉप कैप |
| **रैपर पैराग्राफ़** | तालिका, सूची या छवि जैसी पैराग्राफ़ की जगह घेरने वाली चीज़ के चारों ओर एक परत लपेटने वाला पैराग्राफ़ है। यही पैराग्राफ़ संरेखण ओढ़ता है, और यही कर्सर को उस चीज़ के आगे-पीछे खड़े होने की जगह देता है |
| **क्लेम (claim)** | कौन-सा मार्कअप किस wing का है, यह तय करने वाला फ़ैसला है। कोई न ले तो उसका खोल उतार दिया जाता है |
| **पार्ट्स (parts)** | कोई wing अपने साथ लाने वाला बटन-रहित ढाँचा है — तालिका की पंक्तियाँ-कोशिकाएँ, Details का सारांश-पंक्ति |

### जो शब्द सिर्फ़ संपादन स्क्रीन पर हैं

| शब्द | अर्थ |
|---|---|
| **कर्सर (caret)** | अक्षर कहाँ जाएगा यह दिखाने वाली टिमटिमाती पट्टी |
| **कॉन्टेक्स्ट पंक्ति (context row)** | जहाँ कर्सर अभी खड़ा है वहीं सिर्फ़ किए जा सकने वाले काम दिखने वाली पंक्ति — तालिका के पंक्ति-स्तंभ कमांड, कोड का भाषा कक्ष, लिंक के पता-नाम कक्ष, शीर्षक के H1–H6 |
| **एस्केप की (escape key)** | किसी मार्क के भीतर यह की दबाने पर अगला अक्षर उस मार्क के बाहर खड़ा होता है — कोई wing इसे `escapeKeys` से घोषित करता है |
| **जगह-धारक (placeholder)** | अपलोड चलने के दौरान ही खड़ी रहने वाली अस्थायी जगह। यह मान में कभी नहीं मिलती |

### बनाने वाले पक्ष के शब्द

| शब्द | अर्थ |
|---|---|
| **cocoon** | nabi-tree को सँवारने वाला सामान्यीकरण चरण है। यह **हर कमांड के बाद** चलता है, ताकि कोई कमांड नियम तोड़ने वाला दस्तावेज़ पीछे न छोड़ सके |
| **अटैच (attach)** | जब किसी wing को स्क्रीन को छूना हो तब घोषित किया जाने वाला हुक है — तालिका की कोशिका खींचना, कोड रंगना, चेक टॉगल सब यही हैं। रजिस्टर किए गए wing का यह हिस्सा `mountSurface` जोड़ता है |
| **ऑटो-रूपांतरण (input rule)** | सिर्फ़ टाइप करने से होने वाला रूपांतरण है — हाइफ़न और स्पेस सूची में बदल जाते हैं, `#` और स्पेस शीर्षक में |

## सीमाएँ

React और Vue कभी import नहीं किए जाते, सिर्फ़ शुद्ध DOM API इस्तेमाल होते हैं —
क्योंकि यह एक ही पेज पर तरह-तरह के फ़्रेमवर्क और वर्ज़न के साथ चलाया जा सकता है।

कोड ब्लॉक के रंग के लिए **एक हल्का टोकनाइज़र पैकेज के भीतर ही आता है** — यह C
परिवार, Python, JSON, CSS, मार्कअप, SQL और शेल जानता है। अधिक सटीक रंगाई चाहिए तो
Prism, highlight.js या Shiki जैसा कुछ `makeCodeAttach({ highlight })` से जोड़ें,
वह इसकी जगह रंगेगा।
