# NABI NOTE क्या है?

NABI NOTE ब्राउज़र में चलने वाला एक **ओपन-सोर्स WYSIWYG एडिटर** है।


## nabi-tree

HTML को सीधे संभालने पर DOM-रहित सर्वर साइड पर काम न कर पाने की समस्या आती है, इसलिए
दस्तावेज़ **nabi-tree** नाम की एक JavaScript ऑब्जेक्ट से संभाला जाता है और JSON, HTML
दोनों तरफ़ द्वि-दिशा में सीरियलाइज़ होता है। साथ ही nabi-tree और HTML के बीच के इस
रूपांतरण के दौरान XSS तत्व हटा दिए जाते हैं।

> NABI NOTE के साथ आने वाले सभी wing XSS से सुरक्षा देते हैं, लेकिन `कस्टम wing (बाहरी प्लगइन)` के मामले में यह सुरक्षा है या नहीं, यह उस डेवलपर से ही पूछना होगा।

## DOM रहित SSR (सर्वर साइड) समर्थन

सहेजे हुए nabi-tree को सर्वर (Node.js) पर **ज्यों का त्यों पढ़कर** भेजने वाला HTML
जोड़ा जा सकता है। जिन्हें DOM चाहिए वे सिर्फ़ **इनपुट** (`setHtml()`) और स्क्रीन से जुड़ने
वाले `mount*` हैं।

सिर्फ़ दिखाने वाली जगह पर एडिटर खड़ा करने की भी ज़रूरत नहीं — एक ही फ़ंक्शन काफ़ी है।
यह सहेजा हुआ दस्तावेज़ और `registry`(रजिस्टर किए गए wing की सूची) दोनों लेता है, और
जवाब में HTML स्ट्रिंग देता है।

**सर्वर पर `nabi-note/ssr` जोड़ते हैं** — यह सिर्फ़ खींचने के लिए ज़रूरी चीज़ों वाला
एंट्री पॉइंट है, इसलिए संपादन सतह और स्क्रीन के औज़ार बिल्कुल नहीं लदते।

```ts
import { makeRegistry, defaultWings, renderStoredHtml } from 'nabi-note/ssr'

// wing की सूची सर्वर उठते समय एक ही बार बनती है — कितने भी सहेजे दस्तावेज़ हों, यही एक इस्तेमाल होती है।
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['एक टिप्पणी की पंक्ति'] }]   // DB से पढ़ा गया nabi-tree
renderStoredHtml(saved, registry)
// '<p>एक टिप्पणी की पंक्ति</p>'
```

**nabi-tree न हो तो `null` जवाब देता है** — मनाही का नियम `setJson()` जैसा ही है। जो
मान पास होता है वह एडिटर के `getHtml()` से **एक अक्षर भी अलग नहीं होता।** दोनों एक ही
कदम (सामान्यीकरण → जोड़ना) से गुज़रते हैं, इसलिए XSS छानने की जगह भी वही है।

एडिटर को सर्वर पर पहले से खींचना हो तो इसका जोड़ीदार फ़ंक्शन इस्तेमाल करें — बस
`data-key` जुड़ जाता है।

```ts
import { renderStoredEditorHtml } from 'nabi-note/ssr'

renderStoredEditorHtml(saved, registry)
// '<p data-key="n0">एक टिप्पणी की पंक्ति</p>'
```

एक ही सहेजा हुआ दस्तावेज़ हमेशा एक ही `data-key` पाता है, इसलिए यह HTML ज्यों का त्यों
भेजकर ब्राउज़र में `mountSurface({ nabi, registry, root, hydrate: true })` से आगे पकड़
लिया जाए तो स्क्रीन दोबारा नहीं खींची जाती। **इस साइट का होम डेमो असल में इसी तरह चलता
है** — पहली स्क्रीन का दस्तावेज़ सर्वर ने खींचकर भेजा है, और एडिटर उसी के ऊपर जागता है।

### तीन एंट्री पॉइंट

| जोड़ते हैं | क्या मिलता है | कब |
|---|---|---|
| `nabi-note` | पूरा एडिटर — जोड़ना · सतह · स्क्रीन के औज़ार | जहाँ **लिखा** जाता है |
| `nabi-note/ssr` | सिर्फ़ सहेजे दस्तावेज़ को HTML में खींचने वाला हिस्सा | सर्वर, या सिर्फ़ पढ़ने वाला पेज |
| `nabi-note/viewer` | पढ़ने वाले पक्ष के काम (तालिका छाँटना, कोड रंगना) | प्रकाशित HTML को **दिखाने** वाली जगह |

`nabi-note/ssr` संपादन सतह(`surface`) और स्क्रीन के औज़ार(`ui`) की **एक भी फ़ाइल नहीं
छूता** — यह जाल (net) सोर्स को जाँचकर इसे लागू कराता है। इसलिए सर्वर बंडल में DOM कोड
घुसने का कोई रास्ता नहीं है।

## हर फ़ॉर्मेट wing है

जिसे बाक़ी एडिटर "प्लगइन" कहते हैं, उसे हम **wing** कहते हैं। कोर सीधे सिर्फ़ पैराग्राफ़
(`p`) और लाइन (`br`), और सादे टेक्स्ट को जानता है — शीर्षक·सूची·तालिका·बोल्ड सब wing हैं।

```ts
import { createNabiWith, parseNodes, boldWing } from 'nabi-note'

const bare = createNabiWith([], { parseHtml: parseNodes }).nabi
bare.setHtml('<p><b>बोल्ड</b> <i>इटैलिक</i></p>')
bare.getHtml()
// '<p>बोल्ड इटैलिक</p>'                    — कोई wing घोषित नहीं है इसलिए सादे टेक्स्ट में बदल जाता है।

const bold = createNabiWith([boldWing], { parseHtml: parseNodes }).nabi
bold.setHtml('<p><b>बोल्ड</b> <i>इटैलिक</i></p>')
bold.getHtml()
// '<p><b>बोल्ड</b> इटैलिक</p>'              — सिर्फ़ boldWing घोषित है इसलिए वही बचता है और बाक़ी सादे टेक्स्ट में बदल जाता है।
```

wing के रूप में रजिस्टर न किया गया मार्कअप **सादे टेक्स्ट में बदल जाता है।** इसलिए
घोषित न किया गया html बाहर रह जाता है, और NABI NOTE जिन wing को आधिकारिक रूप से सपोर्ट
करता है वे सभी नुक़सानदेह स्क्रिप्ट हटाते हैं।


## इंटरफ़ेस

दस्तावेज़ सिर्फ़ `applyCommand()` के ज़रिए बदला जा सकता है।

```ts
nabi.applyCommand('toggleMark', { w: 'b' })     // Bold
nabi.applyCommand('setHeading', { value: 2 })   // H2
nabi.undo()
nabi.redo()
```
कमांड **सफलता को `boolean` में लौटाते हैं।** कुछ न बदले तो `false` जवाब देकर न कोई
हिस्ट्री छोड़ते हैं, न कोई बदलाव करते हैं।


## कोड की परतें

इसका मतलब यह नहीं कि मान इसी क्रम में बहता है। यह नीचे से ऊपर तक चढ़ी **निर्भरता की
दिशा** है, और नियम एक ही है — **नीचे की परत ऊपर की परत को नहीं जानती।** इसलिए नीचे की
परतें(`schema`·`doc`·`html`) DOM नहीं छूती, और यही वजह है कि यह सर्वर पर भी ज्यों का
त्यों चलता है। मान किस रास्ते आता-जाता है यह ऊपर के nabi-tree डायग्राम में है।

## शब्दावली

| शब्द | अर्थ |
|---|---|
| **मार्क (mark)** | अक्षरों की फ़ॉर्मेटिंग ex) `<b>` · `<i>` · `<a>` |
| **ब्लॉक (block)** | ex) पैराग्राफ़ · शीर्षक · सूची · तालिका · छवि |
| **पैराग्राफ़ गुण (paragraph attribute)** | पैराग्राफ़ का गुण ex) संरेखण · ड्रॉप कैप |
| **रैपर पैराग्राफ़** | तालिका · सूची · छवि जैसी एक-पैराग्राफ़ ऑब्जेक्ट को लपेटने वाला पैराग्राफ़। |
| **क्लेम (claim)** | कौन-सा मार्कअप किस wing का है, यह तय करने वाला फ़ैसला। |
| **पार्ट्स (parts)** | wing के भीतर की सुविधा ex) तालिका की पंक्ति·कोशिका, Details की सारांश-पंक्ति |

### संपादन स्क्रीन

| शब्द                          | अर्थ                                                                                                                 |
|--------------------------------|-----------------------------------------------------------------------------------------------------------------------|
| **कर्सर (caret)**              | एडिटर में चुनने वाला कर्सर                                                                                             |
| **कॉन्टेक्स्ट पंक्ति (context row)** | कर्सर अभी जो चुना हुआ है उसे नियंत्रित करने वाला टूलबार ex) तालिका के पंक्ति·स्तंभ कमांड, कोड का भाषा कक्ष, लिंक के पता·नाम कक्ष, शीर्षक के H1~H6 |

### कोर

| शब्द | अर्थ                                                                                                                            |
|---|----------------------------------------------------------------------------------------------------------------------------------|
| **cocoon** | nabi-tree का सामान्यीकरण चरण है। **हर कमांड के बाद** चलता है, ताकि कोई कमांड नियम तोड़ने वाला दस्तावेज़ पीछे न छोड़ सके                              |
| **अटैच (attach)** | wing को स्क्रीन को छूना हो तब घोषित किया जाने वाला हुक है। ex) तालिका की कोशिका खींचना, कोड रंगना, चेक टॉगल सब यही हैं। रजिस्टर किए गए wing का यह हिस्सा `mountSurface` जोड़ता है |
| **ऑटो-रूपांतरण (input rule)** | सिर्फ़ टाइप करने से होने वाला रूपांतरण है। ex) हाइफ़न और स्पेस सूची में, `#` और स्पेस शीर्षक में                                                        |
