# প্রাথমিক ব্যবহার

npm থেকে ইনস্টল করে ব্যবহারের পথ। একটিমাত্র `<script>` দিয়ে ব্যবহারের পথ
আছে [{{ t('menu_intro_cdn') }}](./cdn)-এ।

```sh
npm i nabi-note
```

---

## টুকরোগুলো জোড়া লাগানো

হোস্ট জায়গা তৈরি করে, mount একটা একটা করে জুড়ে দেয়। নিচেরটাই ন্যূনতম গঠন,
আর প্রতিটি wing নথিতে আসা উদাহরণ এই একই কাঠামোতে এক-দুটো wing জুড়ে দেওয়া রূপ।

```html
<div id="app" class="nabi">
  <div id="chrome" class="nabi-toolbar">
    <div id="toolbar"></div>
    <div id="context"></div>
  </div>
  <div id="editor" class="nabi-content" contenteditable="true"></div>
</div>
```

```ts
import {
  createNabiWith,
  mountSurface,
  mountToolbar,
  mountContextToolbar,
  mountHints,
  mountViewTools,
  mountSticky,
  watchSettle,
  parseNodes,
  boldWing,
  italicWing,
} from 'nabi-note'
import 'nabi-note/nabi.css'

const app = document.querySelector<HTMLElement>('#app')!
const surface = document.querySelector<HTMLElement>('#editor')!

// wing-এর তালিকাই ধরন-জ্ঞান·কমান্ড·জোড়াকারী একসঙ্গে গড়ে তোলে — সেটাই `registry`
const { nabi, registry } = createNabiWith([boldWing, italicWing], {
  parseHtml: parseNodes,
})

mountSurface({ nabi, registry, root: surface })

const settle = watchSettle(document, { surface })
const shared = { nabi, registry, surface, settle, locale: 'bn' }

const toolbar = mountToolbar({ ...shared, root: document.querySelector<HTMLElement>('#toolbar')! })
const context = mountContextToolbar({ ...shared, root: document.querySelector<HTMLElement>('#context')! })

mountHints({ toolbar, context, root: document.querySelector<HTMLElement>('#chrome')!, surface })
mountViewTools({ nabi, surface, root: app, container: document.querySelector<HTMLElement>('#toolbar')!, locale: 'bn' })
mountSticky({ root: app, surface })

// মান বদলালেই — এখানে আপনার কোড জুড়ে দিন
// nabi.onChange(() => user_callback(nabi.getHtml()))
```

জায়গা তৈরি করে হোস্ট, আর **সেই জায়গা কেমন দেখতে হবে তা জানে কোর** — mount
নিজের পাত্রে `.nabi-toolbar-row`·`.nabi-context`·`.nabi-editing` নিজে থেকেই
বসিয়ে দেয়, টুল-বাক্সও নিজে থেকেই দাঁড় করায়। মানে হোস্টের সাজানোর কোনো কাজ
নেই, তাই উপরের মার্কআপে ক্লাস মাত্র তিনটি।

- **`class="nabi"`** — রঙের টোকেন আর স্টাইলশিট এর ভিতরেই বাস করে। ফুলস্ক্রিন
  পুরোটাই আটকে রাখা বাক্সও এটিই, তাই টুলবার আর সম্পাদনার জায়গা **একসঙ্গেই**
  এর ভিতরে থাকতে হয়।
- **`class="nabi-toolbar"`** — টুলবার সারি আর কনটেক্সট সারি একসঙ্গে বেঁধে
  **উপরে আটকে (sticky)** রাখে। দুটো আলাদা করে আটকালে কনটেক্সট সারি উঠলে
  লেখা সরে গিয়ে পর্দা কাঁপে।
- **`class="nabi-content" contenteditable`** — সম্পাদনার জায়গা নিজেই।

সাইটে একটি স্থির শিরোনাম-বার থাকলে `--nabi-sticky-top` দিয়ে ততটা নামিয়ে
দিন, আর `mountSticky()` জুড়লে মোবাইল কিবোর্ড পর্দা যতটা ঠেলে দিয়েছে ততটা
কোর নিজেই মেপে ফিরিয়ে দেয়।

**স্টাইলশিট হোস্টই জোড়ে।** বান্ডলার ব্যবহার করলে `import 'nabi-note/nabi.css'`
একটাই যথেষ্ট, নিবন্ধিত wing-এরটুকুই রাখতে চাইলে
`injectSheets(document, collectSheets(registry))` ডাকুন। **নথি সার্ভারে আগে
থেকে এঁকে পাঠানো পাতায় ফাইলের পথ বেছে নিন** — ইনজেকশন সম্পাদক জাভাস্ক্রিপ্ট
পৌঁছানোর পরেই জোড়ে, তার মাঝে নথি একবার খালি গায়ে আঁকা হয়ে যায়।

**এই কথাটাই লেখার দিক ঠিক করে দেয়।** আরবি (`ar`)·উর্দু (`ur`) দিলে সেই
mount-এর গোড়ায় `dir="rtl"` জুড়ে যায়, ডান থেকে বাম দিকে দাঁড়ায় — পাতা
`<html dir>` দিয়ে কিছু না বললেও তা-ই হয়। `locale` **না দিলে হাত দেয় না** —
দিকটা নিজের হাতে রাখা হোস্টের সিদ্ধান্তে ঢাকনা পড়ে না। কোন ভাষার দিক কী তা
বলে দেয় `localeDirection(code)`।

```ts
mountSurface({ nabi, registry, root: surface, locale: 'ar' })   // সম্পাদনার জায়গা RTL
mountToolbar({ nabi, registry, surface, root: toolbar, locale: 'ar' })   // টুলবারও আয়নার মতো
```

প্রদর্শনের ভাষা প্রতিটি mount-এ `locale` দিয়ে ঠিক হয় — নথির লেখা যেমন আছে
তেমনই থাকে, কেবল টুলবার·কনটেক্সট সারির নামই বদলায়। **হোস্টকে লোকেল একবারই
ঘোষণা করতে হয়** — উপরের উদাহরণের মতো একটি বান্ডলে (shared) ভরে mount-গুলোতে
দিলে, টুলবার দাঁড়ানোর সময় নিজের `locale` কোরেও জুড়ে দেয় (`nabi.$bindLocale`),
তাই কোরের বলা কথাও (toast ইত্যাদি) একই ভাষায় বেরোয়। টুলবার ছাড়া ব্যবহারের
জায়গায় `createNabiWith` অপশনের `locale` দিন। বাছাইকারী আঁকতে চাইলে
প্যাকেজের এক্সপোর্ট করা `LOCALES` (কোডের তালিকা) ব্যবহার করুন।

### খালি সম্পাদকের নির্দেশ-লেখা

কিছুই নেই এমন সম্পাদক প্রথম লাইনে ফিকে নির্দেশ-লেখা দাঁড় করায়। একটি অক্ষর
এলেই মিলিয়ে যায়, মুছে আবার খালি হলে আবার দাঁড়ায়। **কিছু না করলেও ফোটে** —
কথাটা কোরের অভিধানের বলে সেই mount-এর ভাষা অনুসরণ করে। জায়গা ঠিক করে
**লেখার দিক** (LTR হলে বাঁয়ে, RTL হলে ডানে) — সারি মাঝে বা ডানে সাজানো হলেও
নির্দেশ-লেখা তা অনুসরণ করে না।

```ts
mountSurface({ nabi, registry, root: surface, placeholder: 'এখানে নোট লিখুন' })
mountSurface({ nabi, registry, root: surface, placeholder: 'প্রথম লাইন\nদ্বিতীয় লাইন' })   // একাধিক লাইন
mountSurface({ nabi, registry, root: surface, placeholder: '' })   // নির্দেশ-লেখা ছাড়া
```

লাইন-ভাঙা (`\n`) তেমনই লাইন হয়ে যায়। নির্দেশ-লেখা **প্রবাহের বাইরে** দাঁড়ায় (ক্যারেট ঠেলে না দিতে), তাই সম্পাদনার জায়গা এক লাইন উঁচু হলে একাধিক লাইনের নির্দেশ-লেখা নিচে উপচে পড়ে। খালি সম্পাদনার জায়গা ডিফল্টে **১২.৫ rem উঁচু** থাকে বলে বেশিরভাগ সময় ফেলে দিন; বেশি দরকার হলে `--nabi-content-min-height` দিয়ে বাড়ান।

**নির্দেশ-লেখা একটি আলাদা স্তর।** সম্পাদনার মূলে `::before` ছাড়িয়ে গেছে বলে এটি **নথির সাজসজ্জার (শিরোনাম·সারিবদ্ধতা·ড্রপ ক্যাপ) প্রভাব পায় না**। লেখার দিক (LTR হলে বাঁয়ে, RTL হলে ডানে) এক-ই সিদ্ধান্ত নেয়।

কথাটা বসে সম্পাদনার জায়গার গোড়ার `--nabi-placeholder`-এ, আঁকে স্টাইলশিট।
রং বা গঠন বদলাতে চাইলে শুধু সেটি নিয়ে লিখুন।

```css
.nabi-content.nabi-editing:has(> :is(p, h1, h2, h3, h4, h5, h6):only-child > br:only-child)::before {
  color: #999;
}
```

| জোড়া লাগানো | আবশ্যক | কী করে |
|---|---|---|
| `createNabiWith(wings, options?)` | হ্যাঁ | `{ nabi, registry }` ফিরিয়ে দেয়। DOM লাগে না। wing-এর অ্যারে, বাছাই-বিল্ডার (`wings()`, [{{ t('menu_intro_cdn') }}](./cdn#wing-বাছাই) দেখুন)-ও তেমনই নেয় |
| `mountSurface({ nabi, registry, root })` | হ্যাঁ | ক্যারেট·IME·ইনপুট নাবিট্রির সঙ্গে মেলায়। নিবন্ধিত wing-এর `attach`-ও একসঙ্গে জুড়ে দেয় |
| `mountToolbar({ nabi, registry, root, surface?, locale?, file? })` | না | মূল টুলবার। না থাকলেও `applyCommand()` দিয়ে সরাসরি সম্পাদনা চলে। `mountFile()`-এর উত্তর `file`-এ গুঁজলে **সংরক্ষণ তক্তা বিনা-বাঁকাইয়েই দাঁড়ায়** — সংরক্ষণ বোতাম আর <kbd>⌘</kbd><kbd>S</kbd> সেটি খোলে। ছাড়লে চাপ `onHost('save')`-এ আগের মতো আসে। `surface` হলো **এক্সিলারেটররা যে মাটিতে শোনে** তার (নিচে দেখুন) |
| `mountContextToolbar({ nabi, registry, root, surface? })` | না | ক্যারেটের জায়গা অনুযায়ী কনটেক্সট সারি (টেবিলের সারি·কলাম, কোডের ভাষা, লিঙ্কের ঠিকানা·নাম ইত্যাদি) |
| `mountHints({ toolbar, context?, root, surface? })` | না | Shift দুবার দ্রুত চাপলে ওঠা শর্টকাট ব্যাজ |
| `mountViewTools({ nabi, surface, root, container, onBody? })` | না | প্রিভিউ·ফুলস্ক্রিন দুটো বোতাম। `root` হলো ফুলস্ক্রিন যে `.nabi` বাক্স আটকে রাখবে, `onBody` হলো প্রিভিউয়ের মূল অংশে দেখার পক্ষের রানটাইম জোড়ার হুক (নিচে) |
| `mountSticky({ root, surface, chrome?, nabi? })` | না | মোবাইল কিবোর্ড পর্দা যতটা ঠেলেছে ততটা আটকে থাকা টুলবার ফিরিয়ে দেয়। `nabi` দিলে **সম্পাদনার পর বিনা-ডাকেই ক্যারেট টুলবারের নিচ থেকে বেরিয়ে আসে** — ছাড়লে আগের মতো শুধু হোস্ট `aim()` ডাকলে আসে (নিচে দেখুন) |
| `mountPickedMark({ nabi, surface })` | না | ছবি·ভিডিও বাছাই করার চিহ্ন (ব্রাউজার নিজে আঁকে না) |
| `mountFile({ nabi, store, registry, parse?, name? })` | সংরক্ষণ·খোলা ব্যবহারে | **তিনটি ফরম্যাটে** সংরক্ষণ করে — `.nabi`·`.nhtml`·`.md` — আর **চারটিতে** খোলে, সেই তিনটা + বাইরে থেকে আসা সাধারণ `.html`। **`registry` আবশ্যক** — ফরম্যাট তালিকা আর md, HTML জোড়া সবই এর থেকে আসে। `parse` হলো HTML পড়ার দরজা; ব্রাউজারে ছাড়লে `parseNodes` আপনা থেকে দাঁড়ায়, কিন্তু মাথা নেই এমন জায়গায় (সার্ভার, টেস্ট) `.nhtml`·`.html` খুলতে হলে পাঠাতেই হবে। উত্তর `FileMount` হলো **wing ছাড়াই সংরক্ষণ·খোলা করার খাঁটি পথ** (`file.save()` · `file.saveAs(id, name)` · `file.formats()` · `await file.open()`) |
| `mountLocalHistory({ nabi, storage })` | localHistory ব্যবহারে | নির্দিষ্ট বিরতিতে ব্রাউজারে রেকর্ড রাখে। `storage` `null` হলেও (`file://`-এর মতো আটকানো জায়গা) দাঁড় করানো যায় — তাহলেই বোতাম কেন চলছে না তা toast-এ বলে |
| `mountUpload({ … })` + `mountUploadView({ … })` | upload ব্যবহারে | ড্রপ·পেস্ট·ফাইল বাছাইয়ের আপলোড অগ্রগতি আর তার প্রদর্শন |

**ছবি·চেকবক্স·টেবিল-ঘর টানা·কোড রং বসাতে আলাদা mount করার কিছু নেই** —
সবই wing নিজেই `attach` দিয়ে ধরে রাখে, `mountSurface` একসঙ্গে জুড়ে দেয়।
কোড রং বসাতে কেবল যে রং বসাবে তাকে গুঁজে দিলেই হয়
(`makeCodeAttach`, [{{ t('menu_block_code') }}](../wing/block/code) দেখুন)।

### এক্সিলারেটররা যেখানে শোনে

<kbd>⌘</kbd><kbd>S</kbd>-র মতো এক্সিলারেটর একটি জায়গাই শোনে — টুলবার। তার কান কতদূর পৌঁছায় তা আঁকে `mountToolbar({ surface })`। **সেই surface-এর ভিতরে অথবা টুলবার সারিতেই** ওঠা কী-ই শুধু সেই সম্পাদকের।

- **একটি পাতায় সম্পাদক দুটি থাকলে অবশ্য `surface` পাঠাতে হবে।** ছাড়লে টুলবার পুরো নথি শোনতে দাঁড়ায়, আর তখন নিচের সম্পাদকে <kbd>⌘</kbd><kbd>S</kbd> উপরেরটা সংরক্ষণ করে। হোস্টের নিজের সাধারণ ইনপুটেও হাত পড়ে।
- **wing নিবন্ধন না করলে চাবিটাই থাকে না।** সংরক্ষণ·খোলা কোরে থাকে (`mountFile`), কিন্তু বোতাম আর এক্সিলারেটর wing-এর — তাই `wings().allBasic()` দিয়ে বানানো সম্পাদকে <kbd>⌘</kbd><kbd>S</kbd> নেই, <kbd>⌘</kbd><kbd>O</kbd>ও নেই। ফিরিয়ে আনার এক-ই পথ `.use('save').use('open')`।
- **বসার জায়গা থাকলে চাবিটা গিলবে না।** সংরক্ষণ বোতাম কোথাও গিয়ে পড়ছে না এমন গঠনে (`file` এবং `onHost` দুটোই খোঁজা হয় না) <kbd>⌘</kbd><kbd>S</kbd> ব্রাউজারের কাছে চলে যায়, যেমনটা ঘটে। যে কাজ আমরা করি না তার এক্সিলারেটর চুপে চাপে গিলে ফেলে না — ধরে ফেলেছি আর কাজ করছি না বলে তার মনে হয় ব্রাউজার ভাঙা।

wing ছাড়াই সংরক্ষণ·খোলা করতে হলে `mountFile` যে হ্যান্ডেল দেয় তা ব্যবহার করুন — কোনো বোতাম নেই এমন সম্পাদকে হোস্ট নিজে `file.save()`·`file.open()` ডাকে।

### মোবাইল কিবোর্ড আর আটকে থাকা টুলবার

`mountSticky` এখন মোবাইলে আরও কাজ করে — কিবোর্ড উঠছে-নামছে দেখে ক্যারেটকে **টুলবারের নিচ আর কিবোর্ডের উপরে** নিয়ে আসে। হোস্টকে তিনটি বিষয় জানতে হবে।

- **ফোকাস থাকার সময়ই নড়ে।** অন্যত্র ফোকাস গেলে এক পিক্সেলও নড়ে না — হোস্ট যখন `setHtml()` দিয়ে মান গুঁজছে তখন পাতা ঝাঁকুনি খাবে না।
- **হাত স্ক্রল করার সময়ই এক পিক্সেল নড়ে না।** স্ক্রল করার ২৫০ মিলিসেকেন্ড বন্ধ থাকে। একেবারে নড়া পর্দার হাত থেকে ছিনিয়ে নিয়ে আসা যা, সেটাই কাঁপনা।
- **শুধু কিবোর্ড-পরিমাণ বদল গেট খোলে।** ঠিকানা-দণ্ড ভেঙে যাওয়া (কয়েক দশ পিক্সেল) কিছু নড়ায় না; গেট শুধু `max(120px, পাতার উচ্চতার ১৫%)`-এর উপরে খোলে।

টাইপ করা **যতটা লাগে ততটুকু** পর্দা উপরে ঠেলে দেয় — প্রতিটি অক্ষরে পর্দা টুলবারে ঠেকে যাওয়া অসম্ভব। কিবোর্ড বসার মুহূর্তে আর এক বার, যাতে **টুলবার পাতার মাথায় লেগে থাকে**, আর ভিউপোর্ট স্থির হলে আর একবার সারিবদ্ধ করে দেয়।

`--nabi-bar-height` হলো এই কাজের ভিত্তি — `mountSticky` যে ক্রম-এ গুঁজেছে তার **মাপা উচ্চতা** লিখে রাখে `.nabi` মূলে, আর শিটের `.nabi-content > *` `scroll-margin-block-start`-এ সেটি গুঁজে রাখে। **হোস্টের বদলানোর মান নয়, বরং কেন ক্যারেট টুলবারের নিচে লুকায় না তার ব্যাখ্যা** — mount ছাড়া অনুমান ৩.৫ rem বসে, কিন্তু টুলবার দুই সারিতে ভাঙলে বা কনটেক্সট সারি উঠলে সেটা অনেক কম।

::: warning ভিউপোর্ট মেটায় জুম বন্ধ করবেন না
iOS Safari যখন ১৬ পিক্সেলের কম লেখার ফরম হাতে ফোকাস আসে তখন পুরো পাতা বড় করে ফেলে। কোর সেটা **লেখা বড় করে** বন্ধ করে দেয় — `--nabi-touch-font-size` (`16px` ডিফল্ট)। জুম বন্ধ করার অন্য রাস্তা (`user-scalable=no` বা `maximum-scale=1`) **নিই না** — পড়া মানুষের জুম করার অধিকার নেই করে দেওয়া। হোস্ট নিজের পাতায় সেই মেটা লিখলে কোরের বাঁধা অর্থহীন হয়ে পড়ে — সেটা লিখবেন না।
:::

### প্রিভিউতে দেখার পক্ষের রানটাইম জোড়া

প্রিভিউ হলো `getHtml()` সরাসরি বসানো স্ট্যাটিক HTML, তাই টেবিল সাজানো·কোড
রং বসানোর মতো **পড়ার পক্ষে জাভাস্ক্রিপ্ট করা কাজ** নিজে থেকে জোড়ে না।
`nabi-note/viewer`-এর `attachViewer` সেই পুরোটা একটি দরজা দিয়েই জোড়ে, আর
প্রিভিউতে `onBody` হুক-ই সেই জোড়ার জায়গা — উপরের ন্যূনতম গঠনের
`mountViewTools` লাইনটা এভাবে বদলান।

```ts
import { attachViewer } from 'nabi-note/viewer'

mountViewTools({
  nabi,
  surface,
  root: app,
  container: document.querySelector<HTMLElement>('#toolbar')!,
  locale: 'bn',
  onBody: (body) => attachViewer(body, { locale: 'bn' }),
})
```

`onBody` ডাকা হয় প্রিভিউয়ের মূল অংশ দাঁড়ানোর পরে, আর জবাবে দেওয়া তোলার
ফাংশন ডাকা হয় ঢাকনা তোলার সময়। প্রকাশিত পাতাতেও **সেই একই লাইন**
(`attachViewer`) জুড়ে দিন — প্রিভিউ প্রকাশিত পক্ষের মতোই হতে হয় বলে দুটোতেই
একই দরজা জোড়াই এই হুকের মূল বিষয়। বিস্তারিত আছে
[{{ t('menu_intro_cdn') }} ▸ দেখার পক্ষ](./cdn#দেখার-পক্ষ)-এ।

কোড রং বসানোর কাজ ডিফল্টে অন্তর্নির্মিত টোকেনাইজার করে (নির্ভরতা ০)। Shiki-র
মতো হাইলাইটার ব্যবহার করা হোস্ট `attachViewer(body, { locale, highlight })`
দিয়ে একই হুক পাঠায় — `makeCodeAttach({ highlight })`-এ যা দেওয়া হয়েছে তার
সঙ্গে একই হলে সম্পাদনার পর্দা আর পড়ার পর্দার রং আলাদা হয় না।

wing বদলাতে চাইলে এই পুরো টুকরোটা তুলে (`unmount()`) নতুন করে বানাতে হয় —
বাদ পড়া wing যে মার্কআপ ধরে রেখেছিল তা সেখানেই সাধারণ লেখায় নেমে আসে। এই
সাইটের ডেমো ঠিক এভাবেই কাজ করে — wing চিপ বন্ধ-চালু করলে পুরো জোড়া লাগানোটাই
নতুন করে তৈরি হয়।

রং·রূপসহ CSS ভেরিয়েবল আছে [{{ t('menu_style_custom') }}](../style/custom)-এ।

## নথি বের করার তিন পথ

```ts
nabi.getHtml()        // সংরক্ষণ·প্রকাশের HTML
nabi.getJson()        // নাবিট্রি (JSON)
nabi.getEditorHtml()  // এখনকার সম্পাদক-পর্দার HTML (data-key লাগানো)
```

**সংরক্ষণের মান আগের দুটোর একটি।** `getEditorHtml()`-এ পর্দা-নির্দিষ্ট চিহ্ন
(`data-key`) লাগানো থাকে বলে এটি বের করার মান নয় — সার্ভার রেন্ডারিং (SSR)
দিয়ে সম্পাদক আগে থেকে এঁকে রাখার জায়গা এটি।

বেরোনো JSON দেখতে এমন। **নথি মানেই ব্লকের একটি অ্যারে**, তাকে মোড়ানো কোনো
রুট নোড নেই।

```json
[
  {"w":"p","a":{"h":2},"ch":["শিরোনাম"]},
  {"w":"p","ch":["লেখা ",{"w":"b","ch":["গাঢ়"]}," আর ",
    {"w":"a","a":{"href":"https://nabi.saro.me/"},"ch":["লিঙ্ক"]}]},
  {"w":"p","a":{"a":"c"},"ch":["মাঝে"]},
  {"w":"p","ch":[{"w":"ul","ch":[
    {"w":"li","ch":[{"w":"p","ch":["এক"]}]},
    {"w":"li","ch":[{"w":"p","ch":["দুই"]}]}]}]}
]
```

পড়ার নিয়ম কেবল চারটি।

- **`w` হলো সেই নোড আঁকা wing-এর id।** সংরক্ষিত শব্দ কেবল দুটি — `p`
  (অনুচ্ছেদ) আর `br` (লাইন), বাকি সবই নিবন্ধিত wing-এর id — `b`·`ul`·`li`-এর
  মতো। শিরোনাম আলাদা wing নয়, বরং **অনুচ্ছেদের অ্যাট্রিবিউট**
  (`{"w":"p","a":{"h":2}}`)।
- **স্ট্রিং হলে লেখা, অবজেক্ট হলে wing।** ধরন লেখার আলাদা কোনো ঘর নেই।
- **`a` হলো সেই wing বহন করা মান** — লিঙ্কের ঠিকানা, হাইলাইটের রং, শিরোনামের
  স্তরের মতো। না থাকলে ঘরও নেই। সারিবদ্ধতার মানও `a`, তবে এই ঘরের **ভিতরে**
  থাকে বলে গুলিয়ে যায় না (`{"w":"p","a":{"a":"c"}}` — মাঝে-সারিবদ্ধ অনুচ্ছেদ)।
- **টেবিল·তালিকা·ছবির মতো অনুচ্ছেদের জায়গা নেওয়া জিনিস একটি অনুচ্ছেদ দিয়ে
  মোড়া থাকে** (উপরের `ul` দেখুন)। সেই অনুচ্ছেদই সারিবদ্ধতা বহন করে, আর
  ক্যারেট সেই বস্তুর আগে-পরে দাঁড়ানোর জায়গা পায়। HTML-এ তা
  `<div data-nabi-p>` হয়ে বেরোয় — `<p>` ব্যাকরণে টেবিল·তালিকা ধরে রাখতে পারে
  না বলে।

ভিতরে চলা ট্রিতে প্রতিটি নোডে আরেকটি `_id` থাকে — **ক্যারেট নোড ধরার
অভ্যন্তরীণ ঠিকানা**, বেশিরভাগ সম্পাদনায় নতুন করে বসে, আর বেরোনোর সময় ছেঁকে
বাদ যায় (উপরের উদাহরণে ৪৭০ → ৩২৩ বাইট)। বেরোনো মান যেমন আছে তেমনই
`setJson()`-এ আবার বসিয়ে দেওয়া যায়।

## নথি ঢোকানোর চার পথ

```ts
createNabiWith(wings, { doc })   // আগে থেকেই বানানো নাবিট্রি দিয়ে শুরু
nabi.setJson(json)               // নাবিট্রি দিয়ে গোটাটাই বদলে দেওয়া
nabi.setHtml(html)               // HTML স্ট্রিং দিয়ে গোটাটাই বদলে দেওয়া
nabi.applyCommand('setHeading', { value: 2 })  // সম্পাদনা কমান্ড (wing যে দরজা ব্যবহার করে সেটিই)
```

চারটিই **সাফল্য-ব্যর্থতা `boolean` হিসেবে জানায়।** ছোঁড়ে না, ব্যর্থ হলে
নথি ছোঁয় না। কিছুটা এলোমেলো মান বাতিল না করে **পড়ার সময়ই ঠিক করে নেয়** —
খালি টেবিল-ঘর, সারি নয় এমন টেবিলের সন্তান, উপচে পড়া মার্জ এসবই এমন, আর
বিপজ্জনক ঠিকানা ছেঁকে বাদ দেওয়াও একই পদক্ষেপে হয়। বাতিল একেবারেই পড়া না
যাওয়া রূপের ভাগ্য। আর কোনো মান পড়ার মাঝে ব্যতিক্রম (exception) ছুঁড়লেও
সম্পাদক থামে না — বাতিল (`false`)-এ বদলে যায়, আর `console.error`-এ কী
বাতিল হলো তা জানায়।

| উত্তর `false` হয় যেখানে | |
|---|---|
| `setJson` | নাবিট্রির রূপ নয় (খালি মান বাদে — নিচে) |
| `setHtml` | `parseHtml` অ্যাডাপ্টার গোঁজা হয়নি (নিচে দেখুন) অথবা সম্পাদনা লক করা (খালি মান বাদে) |
| `applyCommand` | এমন কোনো কমান্ড নেই, অথবা **কিছুই বদলায়নি** |

**খালি নথির রূপ একটাই — `[{"w":"p","ch":[]}]`।** সব বাছাই করে মুছে ফেলার
মতো লেখা পুরোপুরি মুছে ফেলা জায়গায় প্রথম ব্লকের শিরোনাম·সারিবদ্ধতা থেকে
যায় না। একাধিক লাইনের একটিমাত্র লাইন খালি করা আলাদা — সেই লাইন আবার লিখতে
চাওয়া বলে সেই অনুচ্ছেদের ধর্ম তেমনই থেকে যায়।

**খালি মান বিন্যাস-ভুল নয়, খালি নথি।** `null`·`undefined`·খালি স্ট্রিং
(শুধু স্পেস হলেও)·খালি অ্যারে দিলে বাতিল না করে **খালি পর্দায় বসে `true`**
ফেরায় — `setJson`·`setHtml` দুটোই এমন, তাই "খালি করা" সবসময় সফল হয়। খালি
মানে পড়ার কিছুই নেই বলে `setHtml`-এর তখন অ্যাডাপ্টারও (নিচে) লাগে না। রূপ
ভুল হওয়া মান তো বাতিলই — খালি আর ভুল আলাদা।

শেষ লাইনটিই একটি নিয়ম — **কিছু না বদলালে চুপ থাকে।** আগে থেকেই স্তর-২
শিরোনাম হওয়া অনুচ্ছেদে আবার `setHeading` চাপলে `false` ফেরত দেয়, undo-এর
জায়গা বা সংকেত কিছুই রেখে যায় না।

`applyCommand`-এর তৃতীয় আর্গুমেন্ট **যে হাত ডাকল তা**ই — `applyCommand(name,
args?, by?)`-এর `by` হলো `'keyboard' | 'pointer'` (টাইপ `CommandHand`), না
বললে কিবোর্ড ধরা হয়। যেখানে পথ ভাগ হয় তা একটাই: ক্যারেট গুটিয়ে থাকা জায়গার
মার্ক কমান্ড কিবোর্ড হলে সংরক্ষণ (reservation) বসে (পরের অক্ষর থেকে প্রয়োগ),
পয়েন্টার হলে সংরক্ষণ ছাড়াই `false` ফেরায় আর "প্রয়োগ করার কিছু নেই" toast-এ
বলে। সরাসরি UI বানিয়ে কমান্ড ডাকলে ক্লিক হ্যান্ডলারে `'pointer'` জানিয়ে দিন।

### `setHtml`-এর একটি অ্যাডাপ্টার লাগে

HTML পড়ার কাজ করে ব্রাউজারের `DOMParser`। কোর DOM চেনে না বলে ঘোষণার সময়
সেই অ্যাডাপ্টার গুঁজে দিতে হয়।

```ts
import { createNabiWith, parseNodes } from 'nabi-note'

const { nabi } = createNabiWith(wings, { parseHtml: parseNodes })
```

`setJson`-এর কোনো অ্যাডাপ্টার লাগে না — সংরক্ষিত JSON **সার্ভারে (Node.js)
সরাসরি বসিয়ে দিলেও** চলে। জোড়া লাগানো (`getHtml`)-ও DOM ব্যবহার করে না, তাই
সার্ভারে JSON পড়ে HTML বানিয়ে বের করার পথ খোলাই থাকে।

## নোটিফিকেশন আসে toast দিয়ে

আপলোড ত্রুটি, লোকাল-হিস্ট্রির নির্দেশ, "প্রয়োগ করার কিছু নেই"-এর মতো
একলাইনের কথা সবই আসে **toast-এর একটি পথ দিয়েই**। ডিফল্ট পাত্র কোরই ধরে
রাখে বলে কিছু না গুঁজলেও চলে — টুলবার দাঁড়ালে টুলবারের নিচের দিকে একটি স্থির
জায়গায় ফোটে (কনটেক্সট সারি উঠলে-নামলেও সেই জায়গা নড়ে না)।

- মাত্রা তিনটি — `'info' | 'warn' | 'error'`। সফল-বিফলের ফলাফল নয়, **পড়া
  মানুষের কতটা সতর্ক হতে হবে** তার মাত্রা।
- ডিফল্ট ১ সেকেন্ড পরে উঠে যায় (বাকি ০.৫ সেকেন্ড থেকে ফিকে হতে শুরু করে),
  ক্লিক করলেও বন্ধ হয়। একসঙ্গে দাঁড়ানো ডিফল্ট সর্বোচ্চ ৩টা — বেশি হলে যার
  সময় সবচেয়ে কম বাকি সেটাই আগে ওঠে।
- বার্তায় `\n` থাকতে পারে, আর হালকা-গাঢ় দুই থিমেই আঁকা হয়।

রূপ বদলানোর দুটো অপশন আর প্রদর্শন গোটাটাই বদলানোর একটা অপশন আছে
`createNabiWith`-এ।

```ts
const { nabi } = createNabiWith(wings, {
  toastMs: 2000,   // বেঁচে থাকার সময় — ডিফল্ট 1000ms। ডাকার সময় প্রতিটাতেও চাপানো যায়
  toastMax: 5,     // একসঙ্গে দাঁড়ানোর সর্বোচ্চ — ডিফল্ট 3
  // নিজস্ব নোটিফিকেশন সিস্টেম থাকা পাতা প্রদর্শনটাই বদলে দেয় — কোরের ডিফল্ট পাত্র একবারও আঁকা হয় না
  // toast: (level, message, ms) => user_callback(level, message),
})
```

wing-এর বলার দরজাও এটিই — `nabi.$toast(level, message, ms?)`। সময় কথার
সঙ্গেই বহন হয় বলে একটা লম্বা নির্দেশের জন্য পুরো ডিফল্ট বাড়ানোর দরকার নেই।

## বসানো, সংরক্ষণ আর খোলা

**বসানো একটি ক্লিপবোর্ড পড়ে নানা চোখে** — `HTML`·`MARKDOWN`·`TEXT` আর নাবির নিজস্ব ফরম্যাট (`NABI`)। একাধিক পড়ার রাস্তা থাকলে ছোট তক্তা জিজ্ঞেস করে কোনটা বসাবে; একটা থাকলে না জিজ্ঞেস করে সেটাই বসায়। লেখা একটোও নেই এমন বসানো (শুধু ফাইল) [{{ t('menu_etc_upload') }}](../wing/etc/upload)-এ যায়।

**তিনটি ফরম্যাটে সংরক্ষণ হয়** — `.nabi` (উৎস), `.nhtml` (স্বনির্ভর একটা পাতা) আর `.md` (মার্কডাউন; সেখানে জায়গা নেই তা মিশিয়ে পড়ায়, তাই সবটা আবার ফিরে নাও পেতে পারে)। **চারটিতে খোলে** — সেই তিনটা + বাইরে থেকে আসা সাধারণ `.html`। যে দরজায় ঢুকাতে হয় সেটি উপরের সারণীর `mountFile()`। আরেকটি ফরম্যাট গোঁজা যায় [{{ t('menu_wing_custom') }}](../wing/custom#একটি-io-ফিল্টার-গোঁজা)-এর নিয়মে।

## সম্পাদক মানুষকে যেভাবে জিজ্ঞেস করে

ফাইল খোলার সময় "লেখা এখনও আছে, তবু কি খুলবেন?" জাতীয় প্রশ্ন দরকার হয়। সেই
বাক্স **ঘোষণার সময় একবারই** গুঁজে দেওয়া হয়।

```ts
const { nabi } = createNabiWith(wings, {
  ask: {
    message: (text) => window.alert(text),
    confirm: (text) => window.confirm(text),
    choose: (question, options) => user_choose_panel(question, options),
  },
})
```

| | রূপ |
|---|---|
| `message` | `(text: string) => void` — একটিমাত্র কথা, উত্তর নেয় না |
| `confirm` | `(text: string) => boolean \| Promise<boolean>` — সিঙ্ক্রোনাস বা অ্যাসিনক্রোনাস দুটোই নেয় |
| `choose` | `(question: string, options: ChooseOption[]) => number \| Promise<number>` — একটার মধ্যে বাছাই করা। উত্তর হলো **সূচী**, আর আউট-অফ-রেঞ্জ বা নেগেটিভ মানে বাতিল। `ChooseOption` হলো `{ label, icon? }` যেখানে `icon` হলো **ভিতরে** `16×16` svg — ছাড়লে নামই দাঁড়ায় |

**কোর ব্রাউজারেরটা নিজে থেকে ব্যবহার করে না।** নিজস্ব ডায়ালগ থাকা পাতায়
ধূসর বাক্স এসে ঢুকে পড়া ঠিক নয়, আর প্লাগইনে (IntelliJ, VS Code)
`window.confirm` আদৌ নেই বলে। উপরের লাইনগুলো হোস্টই বানায়।

**শুধু যা গুঁজেছ সেটাই জেগে থাকে** — `message` একটাই, বা `confirm` একটাই গুঁজলেও যায়। যা নেই সেটা হলো — `message` না দিলে কোর toast হয়ে বেরোয় (info স্তর), আর `confirm` না দিলে "না" বলে।

**`choose` বেশির ভাগ সময় ছাড়ানো হয়।** বসানো তক্তা টুলবার দাঁড়ানোর সঙ্গে সঙ্গে কোরে গুঁজে যায় (toast-র মতোই), তাই টুলবার দাঁড়ানো পাতায় সেই তক্তা বিনা-কাজে দাঁড়ায়। নিজের তক্তা বসাতে চাইলেই এটি গুঁজুন। কোনো তক্তা ঝোলানো নেই আর গুঁজেওনি হলে **উত্তর ০ (মাথার একটা)** — এটি `confirm`-এর "না"-এর বিপরীত। এখানে বাতিল দিলে বসানো সবই উড়ে যাবে, আর তালিকার প্রথমটা সবসময় "সবচেয়ে সম্ভব পড়া", তাই কাউকে না জিজ্ঞেস করলে সেটাই ঠিক।

::: warning না দিলে উত্তর "না"
কেউ উত্তর না দেওয়া প্রশ্নের অর্থ "হ্যাঁ" নয় — বাতিল, Escape, বা জানালা বন্ধ
করার মতোই। এই উত্তর যেখানে বসে সেটি "লেখা এখনও থাকা অবস্থায় খুলব কি না" —
জিজ্ঞেস করার কেউ নেই বলে ফেলে দেওয়ার দিকে যাওয়া ঠিক না। সার্ভারেও (Node)
এই মান দিয়ে চুপচাপ পার হয়ে যায়।
:::

**একটিমাত্র সম্পাদকের নিজস্ব** — গ্লোবাল নয় বলে একই পাতার দুটো সম্পাদক
আলাদা আলাদাভাবে জিজ্ঞেস করতে পারে। wing-ও একই জিনিস পায় (`nabi.$ask`) —
[{{ t('menu_wing_custom') }} ▸ UI ও আচরণ](../wing/custom/ui)-এ এই গল্প আছে।

## এই সম্পাদকের নাম আর "বদলেছে কি না"

```ts
nabi.sessionId   // '1755245678901-1x9k3af' — <ইউনিক্স-সময়>-<nonce>, প্রতিটি ইনস্ট্যান্সে একটি
nabi.isChanged() // শেষ ভিত্তিরেখার পর থেকে নথি নড়েছে কি না
```

`sessionId` একবারই তৈরি হয় আর বদলায় না। সময়টি এই সম্পাদক কখন দাঁড়িয়েছিল তা
বলে আর নিজেই সাজানো, আর nonce একই মিলিসেকেন্ডে দাঁড়ানো দুটো সম্পাদককে আলাদা
করে। খসড়া·লগ·অটো-সেভ চাবিতে জোড়ার নাম-লেবেল এটি।

`isChanged()`-এর **ভিত্তিরেখা নতুন করে টানে তিনটি জিনিস** — নথি গোটাটাই
বসানো (`createNabiWith({ doc })`·`setJson()`·`setHtml()`) আর সংরক্ষণ হয়েছে
বলে জানানো।

```ts
nabi.$markSaved(savedDoc)   // সংরক্ষণ সফল হওয়ার পরে — সেই মুহূর্তে সংরক্ষণ করা নথিটাই পাঠান
```

**সংরক্ষণের সেই মুহূর্তের ট্রিটাই পাঠাতে হয়** (এখনকার ট্রি নয়)। সংরক্ষণ
হতে সময় লাগার মধ্যে টাইপ করা অক্ষরও তখনও "বদলে গেছে" হিসেবেই থেকে যেতে হয়
বলে। সংরক্ষণ wing (`save`) ফাইল সত্যিই লেখা হওয়ার পরে এটি ডাকে, তাই `.nabi`
তে সংরক্ষণ করলে `isChanged()` `false` হয়ে যায়।

**`.html`·`.md` সংরক্ষণ ভিত্তিরেখা নড়ায় না** — সেগুলো সাইড-কপি বলে (সেখান থেকে আবার খুলতে পারলেও খাঁটি সংরক্ষণ নয়), আগে থেকে রাখা নাবিট্রি তা অপরিবর্তিত থাকে।

**undo করে আগের জায়গায় ফিরলে আবার `false`** — নাবিট্রি অপরিবর্তনীয় আর
প্রতিটি সম্পাদনায় গোটাটাই বদলে যায় বলে, একই নথি কি না তা ঘেঁটে বা হ্যাশ না
করেই সেখানেই বোঝা যায়।

```ts
window.addEventListener('beforeunload', (e) => {
  if (nabi.isChanged()) e.preventDefault()
})
```
