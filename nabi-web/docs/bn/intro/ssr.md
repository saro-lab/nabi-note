# SSR সহায়তা

## শুধু সংরক্ষিত রূপ আঁকার জায়গা — সম্পাদক দাঁড় করাই না

মন্তব্য তালিকার মতো **শুধু দেখানোর জায়গায়** সম্পাদক লাগে না। নথি আঁকতে যা লাগে তা
নিবন্ধিত wing তালিকা (`registry`) একটাই, তাই সেটুকু নেয় এমন আলাদা দরজা আছে।

```ts
import { makeRegistry, defaultWings, renderStoredHtml, renderStoredEditorHtml } from 'nabi-note/ssr'

// সার্ভার ওঠার সময় একবার — সংরক্ষিত রূপ যতগুলোই হোক এই একটাই ভাগ করে ব্যবহার হয়
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['মন্তব্যের একটা লাইন'] }]   // DB থেকে পড়া নাবিট্রি

renderStoredHtml(saved, registry)        // '<p>মন্তব্যের একটা লাইন</p>'
renderStoredEditorHtml(saved, registry)  // '<p data-key="n0">মন্তব্যের একটা লাইন</p>'
```

**`nabi-note/ssr` আঁকতে যা লাগে শুধু তা-ই নিয়ে গড়া একটা প্রবেশপথ।** সম্পাদন-তল
(`surface`) আর পর্দার সরঞ্জাম (`ui`) একটা ফাইলও ছোঁয় না (জাল এটা পাহারা দেয়), তাই
সার্ভার বান্ডেলে DOM কোড মিশে যায় না। একই দরজা `nabi-note`-এও আছে, তাই সম্পাদক
ইতিমধ্যে বসানো পাতা সেটাই ব্যবহার করতে পারে।

| | |
|---|---|
| `renderStoredHtml(json, registry, options?)` | সংরক্ষণ·প্রকাশের HTML — `getHtml()`-এর মতোই মান |
| `renderStoredEditorHtml(json, registry, options?)` | সম্পাদকের HTML — `getEditorHtml()`-এর মতোই মান (`data-key` জোড়া থাকে) |

- **দুটোই DOM ব্যবহার করে না** — সার্ভারে যেমন তেমনই চলে।
- **নাবিট্রি না হলে `null`** — বাতিলের নিয়ম `setJson()`-এর মতোই (পুরো নথি একটা
  অ্যারে হতেই হবে)। থ্রো করে না।
- **সম্পাদক যা দেয় তার সঙ্গে একটা অক্ষরও আলাদা নয়।** একই ধাপ (স্বাভাবিকীকরণ →
  জোড়া লাগানো) পার হয় বলে, XSS ছাঁকা পড়ার জায়গাও একই — শুধু দেখানোর দিকটা কম
  ধোয়া হয় না।
- `options` কেবল `{ allowLocalUrls }` — `createNabiWith`-এর সেই অপশনের মতোই মানে।

**একই সংরক্ষিত রূপ সবসময় একই `data-key` পায়।** তাই সার্ভার `renderStoredEditorHtml`
দিয়ে সম্পাদক আগেভাগে এঁকে পাঠালে, আর ব্রাউজারে `hydrate` দিয়ে ধরে নিলে, পর্দা আবার
আঁকা হয় না।

```ts
mountSurface({ nabi, registry, root: surface, hydrate: true })
```

না মিললে সেই জায়গাতেই নতুন করে আঁকা হয়, তাই সার্ভার আর ক্লায়েন্টের wing তালিকা
মিললেই হয়।

::: tip এই সাইটের নিজের হোমই সেই নমুনা
হোম ডেমোর নথি **বিল্ডের সময় `renderStoredEditorHtml` দিয়ে আগেভাগে আঁকা** হয়ে পাতায়
বসানো, আর সম্পাদক তার উপরেই `hydrate` দিয়ে জেগে ওঠে। তাই সম্পাদকের কোড পৌঁছানোর
আগেও লেখা ইতিমধ্যে পড়া যায় — খালি জায়গা হঠাৎ ভরে ওঠার কোনো ফাঁক নেই।
:::

## টুলবারও আগেভাগে আঁকা যায়

বাটনের সারি **নথি দেখে না।** নিবন্ধিত wing তালিকা, ভাষা, আর গ্রুপের ক্রম দেখেই বসে, তাই
বেরিয়ে আসা লেখাটা **স্থির (constant)।** সার্ভার ওঠার সময় একবার ডেকে সেই লেখা বারবার
ব্যবহার করা যায় — প্রতিটা রিকোয়েস্টে নতুন করে ডাকার দরকার নেই।

```ts
import { makeRegistry, defaultWings, renderToolbarHtml } from 'nabi-note/ssr'

const registry = makeRegistry(defaultWings)

const toolbarHtml = renderToolbarHtml({ registry, locale: 'bn' })
// '<div class="nabi-group" data-group="font">...</div>'
```

এই লেখা টুলবারের বাক্সে যেমন আছে তেমন বসিয়ে পাঠালে, ব্রাউজারে `mountToolbar`
**একই ফাংশন** দিয়ে আঁকে। একই সারি আগে থেকেই বসানো থাকলে **আবার আঁকে না, শুধু তার
সঙ্গে জোড়ে (wiring)।**

```ts
mountToolbar({ nabi, registry, surface, root: toolbar })
```

::: warning বাক্সে `class="nabi-toolbar-row"` লিখে দিন
আগেভাগে আঁকা সারি পাঠানোর সময় **প্রথম ছবি থেকেই** এই ক্লাস থাকা চাই। কোরে এই ক্লাস
না থাকলে mount হওয়ার সময় নিজে থেকে জুড়ে দেয়, আর তখন ডান-বাম মার্জিন সেই মুহূর্তে
বসে **বাটনের সারি একবার পাশে সরে যায়।** হোস্ট আগে থেকে লিখে রাখলে কোর তা ছোঁয় না
(নিজে যা জুড়েছে শুধু তা-ই খোলে)।

```html
<div class="nabi-toolbar-row">আগেভাগে আঁকা সারি</div>
```
:::

- **না মিললেও ভাঙে না** — বসানো সারি এখনকার wing তালিকার সাথে না মিললে সেই জায়গাতেই
  নতুন করে আঁকা হয়। হারানোর মতো শুধু আগেভাগে আঁকা মানটাই, পর্দা সবসময় ঠিকই থাকে।
- **আগেভাগে আঁকা সারি "কিছুই চাপা নেই, কিছুই ঢাকা নেই" অবস্থায় থাকে।** চাপা থাকা
  (`aria-pressed`) আর ঢাকা থাকা ঠিক করে ক্যারেট, যা সার্ভার জানে না। ক্যারেট অনুযায়ী
  বাটন ঢাকা পড়ার বিন্যাস হলে, mount হওয়ার পর কয়েকটা হারিয়ে সারি আবার গুটিয়ে যেতে পারে।
- **সম্পাদক বসানোর জায়গাতেই দিন।** শুধু দেখানোর পাতায় টুলবার নেই, তাই এই লেখা
  নেওয়ার কারণ নেই।

**প্রিভিউ·ফুলস্ক্রিন দুটো বাটনও একই পথে।** এই দুটো wing নয়, ঢাকনার অংশ, তাই উপরের
টুলবারের লেখায় নেই — আলাদা করে এঁকে `mountViewTools` যে বাক্সে বসবে সেখানে দিতে হয়।

```ts
import { renderViewToolsHtml } from 'nabi-note/ssr'

renderViewToolsHtml({ locale: 'bn' })
// '<span class="nabi-tools">...</span>'
```

::: tip এই সাইটের নিজের হোমই সেই নমুনা
হোম ডেমোর টুলবার **বিল্ডের সময় `renderToolbarHtml`·`renderViewToolsHtml` দিয়ে
আগেভাগে আঁকা** হয়ে বসানো, আর `mountToolbar`·`mountViewTools` সেই সারি চিনে শুধু
তার সঙ্গে জোড়ে (wiring)। তাই পঁয়ত্রিশটা আইকন দেরিতে ভরে ওঠার কোনো ফাঁক নেই।
:::
