# NABI NOTE কী?

NABI NOTE ব্রাউজারে চলা একটি **ওপেন-সোর্স WYSIWYG এডিটর**।


## নাবিট্রি

HTML দিয়ে সরাসরি কাজ করলে DOM ছাড়া সার্ভার সাইডে প্রক্রিয়া করা অসম্ভব হয়ে পড়ে,
তাই এটি **নাবিট্রি** নামের একটি জাভাস্ক্রিপ্ট অবজেক্ট দিয়ে প্রক্রিয়া করা হয় এবং JSON, HTML-এ দ্বিমুখীভাবে সিরিয়ালাইজ করা হয়।
আর নাবিট্রি ও HTML-এর মধ্যে রূপান্তরের সময় XSS উপাদানগুলো বাদ দেওয়া হয়।

> নাবি নোট সমর্থিত সব wing XSS প্রতিরোধ সমর্থন করে, কিন্তু `কাস্টম wing (বাহ্যিক প্লাগইন)`-এর ক্ষেত্রে XSS প্রতিরোধ আছে কি না তা সেই ডেভেলপারের কাছ থেকেই নিশ্চিত করে নিতে হবে।

## DOM ছাড়া SSR (সার্ভার সাইড) সমর্থন

সংরক্ষিত নাবিট্রি **সার্ভারে (Node.js) সেভাবেই পড়ে** পাঠানোর HTML জোড়া লাগানো যায়।
DOM লাগে কেবল **ইনপুটে** (`setHtml()`) আর পর্দায় জোড়া `mount*`-এ।

শুধু দেখানোর জায়গায় এডিটর দাঁড় করানোর দরকারই নেই, একটিমাত্র ফাংশনই যথেষ্ট। যা নেয়
তা সংরক্ষিত মান আর `registry` (নিবন্ধিত wing-এর তালিকা) — এই দুটি, আর যা ফেরায় তা HTML স্ট্রিং।

**সার্ভারে `nabi-note/ssr` ধরতে হয়** — আঁকার জন্য যা লাগে তা-ই আছে এই এন্ট্রি পয়েন্টে,
সম্পাদনার তল আর পর্দার টুল একেবারেই বহন করে না।

```ts
import { makeRegistry, defaultWings, renderStoredHtml } from 'nabi-note/ssr'

// wing-এর তালিকা সার্ভার চালু হওয়ার সময় একবারই তৈরি হয় — সংরক্ষিত মান যতটাই থাকুক, এই একটিই ভাগ করে ব্যবহার করা হয়
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['এক লাইন মন্তব্য'] }]   // DB থেকে পড়া নাবিট্রি
renderStoredHtml(saved, registry)
// '<p>এক লাইন মন্তব্য</p>'
```

**নাবিট্রি না হলে `null` ফেরায়** — বাতিলের নিয়ম `setJson()`-এর মতোই। পাস করা মান
এডিটরের `getHtml()`-এর ফলাফলের সঙ্গে **এক অক্ষরও আলাদা হয় না**। একই ধাপ (নর্মালাইজেশন → জোড়া লাগানো)
পার হয় বলেই এমন, তাই XSS ছেঁকে বাদ দেওয়ার জায়গাও একই।

এডিটর সার্ভারে আগে থেকে এঁকে রাখতে চাইলে জোড়ার আরেকটি ফাংশন আছে — যুক্ত হয় কেবল `data-key`।

```ts
import { renderStoredEditorHtml } from 'nabi-note/ssr'

renderStoredEditorHtml(saved, registry)
// '<p data-key="n0">এক লাইন মন্তব্য</p>'
```

একই সংরক্ষিত মান সবসময় একই `data-key` পায়, তাই এই HTML যেমন আছে তেমনই পাঠিয়ে ব্রাউজারে
`mountSurface({ nabi, registry, root, hydrate: true })` দিয়ে ধরলে পর্দা আবার আঁকা হয় না.
**এই সাইটের হোম ডেমো আসলে এভাবেই চলে** — প্রথম পর্দার নথি সার্ভার এঁকে পাঠানো, আর এডিটর তার উপরেই জেগে ওঠে।

### তিন এন্ট্রি পয়েন্ট

| যা ধরতে হয় | কী আছে | কখন |
|---|---|---|
| `nabi-note` | এডিটরের সবকিছু — জোড়া লাগানো·তল·পর্দার টুল | লেখা **লেখার** জায়গায় |
| `nabi-note/ssr` | সংরক্ষিত মানকে HTML-এ আঁকা মাত্র | সার্ভারে, বা শুধু পড়ার পাতায় |
| `nabi-note/viewer` | পড়ার পক্ষের আচরণ (টেবিল সাজানো·কোড রং বসানো) | প্রকাশিত HTML **দেখানোর** জায়গায় |

`nabi-note/ssr` সম্পাদনার তল (`surface`) আর পর্দার টুল (`ui`) **এক ফাইলও ধরে না** —
জাল সোর্স ঘেঁটে এটি বলবৎ করে। তাই সার্ভার বান্ডলে DOM কোড মিশে যাওয়ার কোনো পথ নেই।

## ফরম্যাট মানেই wing

অন্য এডিটরে "প্লাগইন" বলা এককটিকে এখানে **wing** বলা হয়।
কোর সরাসরি চেনে কেবল অনুচ্ছেদ (`p`) আর লাইন (`br`), আর সাধারণ লেখা — শিরোনাম·তালিকা·টেবিল·গাঢ় সবই wing।

```ts
import { createNabiWith, parseNodes, boldWing } from 'nabi-note'

const bare = createNabiWith([], { parseHtml: parseNodes }).nabi
bare.setHtml('<p><b>গাঢ়</b> <i>তির্যক</i></p>')
bare.getHtml()
// '<p>গাঢ় তির্যক</p>'                    — ঘোষণা করা কোনো wing নেই বলে সাধারণ লেখায় বদলে যায়।

const bold = createNabiWith([boldWing], { parseHtml: parseNodes }).nabi
bold.setHtml('<p><b>গাঢ়</b> <i>তির্যক</i></p>')
bold.getHtml()
// '<p><b>গাঢ়</b> তির্যক</p>'              — boldWing-ই কেবল ঘোষণা করা হয়েছে বলে boldWing টিকে থাকে, বাকিটা সাধারণ লেখায় বদলে যায়।
```

wing হিসেবে নিবন্ধিত নয় এমন মার্কআপ **সাধারণ লেখায় রূপান্তরিত হয়।** এভাবে ঘোষণা না করা html বাদ পড়ে যায়, আর নাবিতে অফিসিয়ালভাবে সমর্থিত সব wing ক্ষতিকর স্ক্রিপ্ট বাদ দেয়।


## ইন্টারফেস

নথি বদলানো যায় কেবল `applyCommand()`-এর মধ্য দিয়ে।

```ts
nabi.applyCommand('toggleMark', { w: 'b' })     // Bold
nabi.applyCommand('setHeading', { value: 2 })   // H2
nabi.undo()
nabi.redo()
```
কমান্ড **সফল হয়েছে কি না তা `boolean` হিসেবে ফেরায়।** কিছু না বদলালে `false` ফেরায়, আর তখন হিস্ট্রিতেও কিছু জমা রাখে না, কোনো পরিবর্তনও করে না।


## কোডের স্তর

**মান এই ক্রমেই বয়ে যায় এমন অর্থ নয়।** নিচ থেকে উপরে সাজানো **নির্ভরতার দিক**, আর নিয়ম একটাই
— **নিচের স্তর উপরের স্তরকে চেনে না।** তাই নিচের স্তরগুলো (`schema`·`doc`·`html`) DOM ধরে না,
আর সেটিই সার্ভারে সেভাবে চলার কারণ। মান আসা-যাওয়ার পথটাই ওপরের নাবিট্রি চিত্র।

## পরিভাষা

| শব্দ | অর্থ |
|---|---|
| **মার্ক (mark)** | লেখার ফরম্যাট ex) `<b>` · `<i>` · `<a>` |
| **ব্লক (block)** | ex) অনুচ্ছেদ·শিরোনাম·তালিকা·টেবিল·ছবি |
| **অনুচ্ছেদ-অ্যাট্রিবিউট (paragraph attribute)** | অনুচ্ছেদের ধর্ম ex) সারিবদ্ধতা·ড্রপ ক্যাপ |
| **র‍্যাপার অনুচ্ছেদ** | টেবিল·তালিকা·ছবির মতো একক-অনুচ্ছেদ অবজেক্টকে মুড়ে রাখা অনুচ্ছেদ। |
| **মালিকানা (claim)** | কোন মার্কআপ কোন wing-এর — এই বিচার। |
| **অংশ (parts)** | wing-এর ভেতরের কার্যকারিতা ex) টেবিলের সারি·ঘর, ভাঁজের সারাংশ-লাইন |

### সম্পাদনার পর্দা

| শব্দ | অর্থ |
|---|---|
| **ক্যারেট (caret)** | এডিটরের ভিতরের নির্বাচন কার্সার |
| **কনটেক্সট সারি (context row)** | এখনকার ক্যারেট যা নির্বাচন করেছে তা নিয়ন্ত্রণ করা টুলবার ex) টেবিলের সারি·কলাম কমান্ড, কোডের ভাষার ঘর, লিঙ্কের ঠিকানা·নামের ঘর, শিরোনামের H1~H6 |

### কোর

| শব্দ | অর্থ |
|---|---|
| **cocoon** | নাবিট্রি গোছানোর একটি নর্মালাইজেশন ধাপ। **প্রতিটি কমান্ডের পরেই ফেরে** বলে কোনো কমান্ডই নিয়ম ভাঙা নথি রেখে যেতে পারে না |
| **জোড়ার কাজ (attach)** | wing পর্দায় হাত দিতে চাইলে ঘোষণা করা হুক। ex) টেবিলের ঘর টেনে বদলানো, কোড রং বসানো, চেকবক্স টগল — সবই এটি। `mountSurface` নিবন্ধিত wing-এর এটি একসঙ্গে জুড়ে দেয় |
| **স্বয়ংক্রিয় রূপান্তর (input rule)** | কেবল লেখার মধ্য দিয়েই ঘটে যাওয়া রূপান্তর। ex) হাইফেন আর স্পেস তালিকায়, `#` আর স্পেস শিরোনামে |
