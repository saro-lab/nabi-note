# স্টাইল বদলানো

স্টাইলশিট **হোস্টই জোড়ে** — বান্ডলার ব্যবহার করলে `import 'nabi-note/nabi.css'`
একটি লাইন, CDN হলে `<link>` একটি লাইন। তারপর থেকে কেবল ভেরিয়েবল ওভাররাইড
করলেই হয়।

কম্পোনেন্টের নিয়মে **একটাও রং সরাসরি লেখা নেই।** সবই `--nabi-*` ভেরিয়েবল
দিয়ে আঁকা, তাই ভেরিয়েবল ওভাররাইড করলে বাকিটা নিজে থেকেই অনুসরণ করে।

```css
.nabi.nabi.nabi {
  --nabi-accent: #7c3aed;
}
```

ক্লাস তিনবার পরপর লেখার কারণ নিচে [স্পেসিফিসিটির ফাঁদ এড়ানো](#স্পেসিফিসিটির-ফাঁদ-এড়ানো)-তে।

::: tip এই নথির বড় শর্ত — সংরক্ষিত মান একা দাঁড়ায় না
বেরোনো HTML-এ (`getHtml()`) **একটাও ইনলাইন `style` নেই।** সংরক্ষিত মান
কেবল কী তা অ্যাট্রিবিউট দিয়ে বলে (`data-nabi-align="center"`), কেমন দেখাবে
তা বলে এই স্টাইলশিট। তাই সংরক্ষিত HTML অন্য কোথাও পড়ে আঁকতে হলেও **এই
স্টাইলশিট জোড়া `.nabi-content`-এর ভিতরেই** হতে হবে, তবেই সম্পাদকের মতো
একই রূপ পাওয়া যায় — নিচে [সংরক্ষিত HTML বাইরে আঁকার সময়](#সংরক্ষিত-html-বাইরে-আঁকার-সময়) দেখুন।
:::

::: tip ডার্ক·লাইট আগে থেকেই আছে
থিমের জন্য হোস্টকে কোনো টোকেন ওভাররাইড করতে হয় **না।** কোরের স্টাইলশিট
লাইট ডিফল্ট, `.dark` রিডিফাইন, স্পষ্ট `.light` রিডিফাইন — তিনটিই সঙ্গে
নিয়ে আসে। এই সাইটও সম্পাদকের ভিতরে ফন্ট টোকেন চারটি বাদে আর কিছুই
ওভাররাইড করে না।
:::

## রং · রূপের টোকেন

| টোকেন | অর্থ | ডিফল্ট মান (লাইট) |
|---|---|---|
| `--nabi-bg` · `--nabi-soft` | পটভূমি · সামান্য চাপা তল | `#fff` · `rgb(0 0 0 / 4.5%)` |
| `--nabi-fg` · `--nabi-muted` · `--nabi-on-accent` | লেখা · ফিকে লেখা · অ্যাকসেন্টের উপরের লেখা | `#1b1b1f` · `#6b6b76` · `#fff` |
| `--nabi-line` · `--nabi-accent` | রেখা · অ্যাকসেন্ট রং | `#e2e2e8` · `#3b6fe0` |
| `--nabi-danger` · `--nabi-on-danger` | বিপদ · তার উপরের লেখা | `#d93b3b` · `#fff` |
| `--nabi-shadow` · `--nabi-scrim` | বাক্সের ছায়া · প্রিভিউ পটভূমি | — |
| `--nabi-radius` · `--nabi-radius-sm` · `--nabi-radius-xs` | কোণা | `6px` · `4px` · `3px` |
| `--nabi-layer-radius` | স্তরের (প্যানেল·প্রিভিউ·লাইটবক্স) কোণা | `.25rem` |
| `--nabi-z-sticky` | আটকে থাকা সারির স্তর-সংখ্যা | `20` |
| `--nabi-grid-cell` | টেবিল আকার গ্রিডের ঘরের মাপ | `1.125rem` |
| `--nabi-hl-yellow`·`green`·`cyan`·`pink`·`purple`·`orange` | হাইলাইটের ছয়টি রং | স্বচ্ছ-ঘেঁষা রং |
| `--nabi-tc-green`·`coral`·`violet`·`amber`·`blue` | লেখার রঙের পাঁচটি রং | গাঢ় রং |

এই তালিকায় কোরের স্টাইলশিট (`nabi.css`) **যা সরাসরি ঘোষণা করে** তা-ই আছে।
ঘোষণার জায়গা `.nabi` একটি নয়, তিনটি —
`:is(.nabi, .nabi-scrim, .nabi-content:where(:not(.nabi *)))`। প্রিভিউ
ওভারলে `body`-র সন্তান বলে `.nabi` থেকে উত্তরাধিকার পৌঁছায় না, আর সম্পাদকের
বাইরে একা দাঁড়ানো `.nabi-content`-কেও সরাসরি টোকেন পেতে হয় বলে এমনটা।

একই তালিকা তিন কপিতে (লাইট ডিফল্ট · `.dark` · স্পষ্ট `.light`) লেখা আছে।
**ওভাররাইড করার পক্ষে তিনটাই দেখার দরকার নেই** — স্পেসিফিসিটিতে জিতলেই
একবার ওভাররাইড করা মান তিন ক্ষেত্রেই বসে যায়। তবে ডার্কে আলাদা মান চাইলে
`.dark` শর্তটা নিজেই জুড়ে দিতে হবে।

## মান ছাড়া কেবল রেফারেন্স করা টোকেন

নিচেরগুলো কোর **ঘোষণা করে না, কেবল রেফারেন্স করে** এমন ভেরিয়েবল। হোস্ট মান
না দিলে বন্ধনীর ভিতরের ফলব্যাক বসে। ঘোষণার কোনো জায়গা নেই বলে **`:root`-এ
লিখলেও কাজ করে** — উপরের রং·রূপ টোকেন থেকে এখানেই তফাত (সেগুলো `.nabi`-তে
ঘোষিত বলে উত্তরাধিকার জিততে পারে না)।

| টোকেন | অর্থ | ফলব্যাক |
|---|---|---|
| `--nabi-font` · `--nabi-font-serif` · `--nabi-font-mono` · `--nabi-font-cursive` | টাইপফেস wing-এর চার ধরনে সত্যিকারের যে ফন্ট জোড়া হবে | সিস্টেম ফন্ট |
| `--nabi-cursive-adjust` | হাতের লেখার `font-size-adjust`। হাতের লেখার ফন্টে x-height কম বলে একই px-এও ছোট দেখায়, এই মান x-height ধরে আবার মাপে | `0.4` |
| `--nabi-sticky-top` | আটকে থাকা সারি কতটা নেমে বসবে। সাইটে স্থির শিরোনাম-বার থাকলে তার উচ্চতা | `0px` |
| `--nabi-preview-width` | প্রিভিউ কার্ডের প্রস্থ। **`openPreview` খোলার সময় সম্পাদনার জায়গার প্রস্থ মেপে সরাসরি কার্ডে বসিয়ে দেয়** বলে, হোস্ট বাইরে থেকে ওভাররাইড করলেও সেই ইনলাইন মানই জেতে | `720px` |

`--nabi-typeface-base` এই দলের নয় — **কোর নিজেই এটি ঘোষণা করে** (ডিফল্টে
`--nabi-font` অনুসরণ করে)। টাইপফেস wing-এ এই মান ঠিক করার কোনো অপশন নেই,
বদলাতে হলে এই টোকেনই ওভাররাইড করতে হবে।

`--nabi-keyboard-top` · `--nabi-keyboard-bottom`-ও একই জায়গায় থাকে তবে
এগুলো **কোর নিজেই ব্যবহার করে** — `mountSticky()` মোবাইল কিবোর্ড পর্দা
যতটা ঠেলে দিয়েছে তা মেপে এখানে বসায়, আর আটকে থাকা সারি ও ফুলস্ক্রিন সেই
মান পড়ে। হাতে লেখার মতো মান নয়।

## টোকেন নেই এমন জায়গা — নিয়মই ওভাররাইড করতে হয়

নিচের তিনটির **কোনো ভেরিয়েবল নেই।** কোর নিয়মেই মান বসিয়ে রেখেছে, বদলাতে
হলে সেই সিলেক্টরই ওভাররাইড করতে হয়।

**লেখার আকারের চার স্তর** — `em`-এ, তাই প্যারেন্টের আকার অনুসরণ করে।

```css
.nabi-content [data-nabi-size="xs"] { font-size: .75em; }
.nabi-content [data-nabi-size="sm"] { font-size: .875em; }
.nabi-content [data-nabi-size="lg"] { font-size: 1.25em; }
.nabi-content [data-nabi-size="xl"] { font-size: 1.5em; }
```

**ড্রপ ক্যাপের আকার** — কতগুলো লাইন জুড়ে থাকবে তা নয়, একটি লেখার আকার মাত্র।
সত্যিকারের কতটা লাইন জুড়ে থাকবে তা ঠিক করে সেই অনুচ্ছেদের লাইন-উচ্চতা।

```css
.nabi-content [data-nabi-dropcap="1"]::first-letter { font-size: 5.9em; line-height: .83; }
```

**কোড টোকেনের রং** — কোড wing-এর স্টাইলশিট `[data-nabi-token]`-এ সরাসরি
রং বসায়। এখন রং পাওয়া ধরন **পাঁচটি**।

```css
.nabi-content [data-nabi-token="comment"] { color: #7a8a7a; font-style: italic; }
.nabi-content [data-nabi-token="string"] { color: #a2543a; }
.nabi-content [data-nabi-token="keyword"] { color: #7b4fd0; }
.nabi-content [data-nabi-token="number"] { color: #2f6fd0; }
.nabi-content [data-nabi-token="literal"] { color: #2f8f4e; }
```

হাইলাইটার যে `type` ফেরত দেয় তা মুক্ত লেখা — উপরের পাঁচটির বাইরের নাম
ফেরত দিলে রং ছাড়াই আঁকা হয়, তাই যে ধরন ব্যবহার করতে চান হোস্ট একই ছাঁচে
নিয়ম জুড়ে দিতে পারে। ডার্কে আলাদা রং চাইলে `.dark` শর্ত নিজেই জুড়ে দিন —
কোর এই পাঁচটিতে ডার্ক ভ্যারিয়েন্ট জোড়ে না।

আপলোড wing-এর অগ্রগতি অ্যানিমেশন (`--nabi-per`·`--nabi-t`·`--nabi-span`·
`--nabi-clear`·`--nabi-blur-max`) **wing-এর ভিতরের বাস্তবায়নের জন্য** —
নাম `--nabi-` দিয়ে শুরু হলেও হোস্টকে ওভাররাইড করতে খোলা জায়গা নয়।

## বাইরের মাপ `rem`-এ

বোতাম·মার্জিন·টুলবার চিপসহ বাইরের বেশিরভাগ মাপ `rem`-এ, তাই **রুট
(`html`)-এর লেখার আকার অনুসরণ করে বড়-ছোট হয়।** ব্যবহারকারী ব্রাউজার বা
OS-এ লেখা বড় করলে সম্পাদকের কাঠামোও একসঙ্গে বড় হয়। আকার বদলাতে চাইলে
রুটের `font-size` বদলান। রেখা (`border`) মাপ নয় **রেখা** বলে কিছু জায়গায়
`px`-এই থেকে গেছে।

## স্পেসিফিসিটির ফাঁদ এড়ানো

রং·রূপ টোকেন ওভাররাইড করতে **তিনটি ক্লাস** পরপর লিখুন।

```css
.nabi.nabi.nabi,
.nabi-scrim.nabi-scrim.nabi-scrim {
  --nabi-accent: var(--my-accent-color);
}
```

গুনে দেখলে এমন দাঁড়ায়। লাইট ডিফল্ট নিয়ম `:is(.nabi, …)`-এ `:is()`
আর্গুমেন্টের মধ্যে সবচেয়ে বেশিটা অনুসরণ করে বলে **(0,1,0)**, ডার্ক নিয়ম
`:where(html, body).dark :is(.nabi, …)`-এ `:where()` শূন্য আর `.dark` ও
`:is()` প্রতিটি একটি করে ক্লাস বলে **(0,2,0)**। তাই `.nabi.nabi` দিয়ে
ডার্কের সঙ্গে **টাই হয়** — টাই হলে পরে লোড হওয়া নিয়ম জেতে, আর কোরের
স্টাইলশিট হোস্টের স্টাইলশিটের পরেও লোড হতে পারে। তিনবার পরপর লিখে (0,3,0)-এ
তুলে দিলে ক্রমের উপর নির্ভর করতে হয় না।

প্রিভিউ ওভারলে `.nabi`-এর বাইরে (`body`-র সন্তান) দাঁড়ায় বলে সেই সিলেক্টরও
একসঙ্গে লিখলে তবেই একই রং হয়।

**ফন্টের মতো কোর ঘোষণা করে না এমন টোকেনে এই কুস্তি লাগে না** — ঘোষণার
জায়গা নেই বলে উত্তরাধিকারেই পৌঁছায়, তাই `:root`-এ একটি লাইনই যথেষ্ট।

```css
:root {
  --nabi-font: 'Noto Sans', system-ui, sans-serif;
}
```

## লাইট · ডার্ক

`html` বা `body` **দুটোর একটিতে** `dark` ক্লাস থাকলে ডার্ক, `light` থাকলে
লাইট। ক্লাস না থাকলে লাইট ডিফল্ট, দুটোই থাকলে স্পষ্ট `light` জেতে (`.light`
নিয়ম `.dark` নিয়মের পরেই লোড হয়)।

```html
<html class="dark"><!-- অথবা <body class="dark"> --></html>
```

ক্লাস টগল করলে CSS নিজে সাড়া দেয়। ডাকার মতো কোনো API নেই। থিম বদলে দেয়
কেবল রঙের ভেরিয়েবল, কম্পোনেন্টের নিয়ম যেমন আছে তেমনই থাকে — নিজে বানানো
স্টাইলও `--nabi-*` ভেরিয়েবল ব্যবহার করলে ডার্ক অনুসরণ করবে।

## স্টাইলশিট জোড়ার দুই পথ

**① একটিমাত্র ফাইল** — সবচেয়ে প্রচলিত পথ। সব wing-এর CSS-ই এতে আছে।

```ts
import 'nabi-note/nabi.css'
```

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note/dist/nabi.css">
```

**② নিবন্ধিতটুকুই ইনজেক্ট** — যেসব wing সত্যিই চালু করেছেন কেবল তাদেরটাই
রাখতে চাইলে।

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const drop = injectSheets(document, collectSheets(registry))
// drop() ডাকলে এই ডাকই যা বসিয়েছে তা-ই সরে যায়
```

একই লেখার স্টাইলশিট **একবারই** ঢোকে — ভাঁজের চাবি স্টাইলশিটের **বিষয়বস্তু**
বলে, একই নথিতে একাধিক সম্পাদক থাকলেও জমে না, আর ভিন্ন ভিন্ন wing-সমন্বয়
মিশে গেলেও একটি ঐক্যেই জড়ো হয়।

::: tip দুইয়ের তফাত দুইটা — কী বহন করে, কখন জোড়ে
**কী বহন করে।** ফাইল কোন wing নিবন্ধিত তা জানে না বলে **সবটাই** বহন করে। ইনজেকশন
`registry` দেখে **কেবল নিবন্ধিতটুকুই** বহন করে। সংরক্ষিত HTML কেবল দেখানো
পাতায় সম্পাদক নেই বলে `registry`-ও নেই, তাই ফাইলের পথটাই ব্যবহার করতে হয়।

**কখন জোড়ে।** ফাইল `<link>` হয়ে head-এ ঢোকে আর আঁকা **আটকে রাখে**, কিন্তু
ইনজেকশন সম্পাদকের জাভাস্ক্রিপ্ট **পৌঁছানোর পরই** বসে। তাই নথি সার্ভারে আগে
থেকে এঁকে পাঠানো পাতার বেলায় ফাইলের পথই নিতে হয় — ইনজেকশন দিয়ে করলে
সার্ভারের পাঠানো নথি প্রথমে খালি গায়ে আঁকা হয়ে যায়, তারপর স্টাইল বসে বিন্যাস
আবার সাজে।
:::

নিবন্ধিত wing-এর স্টাইলশিট কোরের স্টাইলশিটের **পরে** বসে, তাই একই
অগ্রাধিকারে wing-ই জেতে।

## জোড়ার মতো জায়গা

ভেরিয়েবল দিয়ে হয় না এমন কিছুর জন্য সত্যিই থাকা ক্লাস সরাসরি ধরতে হয়।

| সিলেক্টর | কী | কে বসায় |
|---|---|---|
| `.nabi` | পুরো সম্পাদক (chrome + সম্পাদনার জায়গা) মুড়ে রাখা খোলস। রং·রূপ টোকেন এখানেই বসে | হোস্ট |
| `.nabi-content[contenteditable]` | সম্পাদনার জায়গা নিজেই | হোস্ট |
| `.nabi-toolbar` | টুলবার সারি + কনটেক্সট সারি মুড়ে রাখা জায়গা। এই ক্লাসই "উপরে আটকানো"-র মানে | হোস্ট |
| `.nabi-toolbar-row` | টুলবার বসা পাত্র | `mountToolbar()` |
| `.nabi-context` | কনটেক্সট সারি বসা পাত্র | `mountContextToolbar()` |
| `.nabi-tools` | প্রিভিউ·ফুলস্ক্রিন দুই বোতামের জায়গা — কোর ডান উপরে ভাসিয়ে রাখে | `mountViewTools()` |
| `.nabi-tool` | সেই দুই বোতাম নিজে | `mountViewTools()` |
| `.tb-group` | টুলবারের বোতাম-গুচ্ছ | `mountToolbar()` |
| `.ctb-group` · `.ctb-button` · `.ctb-swatch` · `.ctb-input` | কনটেক্সট সারির গুচ্ছ·বোতাম·রঙের নমুনা·লেখার ঘর | `mountContextToolbar()` |
| `.tb-picker` · `.tb-picker-grid` · `.tb-picker-cell` | টেবিল আকার গ্রিডের মতো বোতামের নিচে ওঠা বাক্স | `mountToolbar()` |
| `.tb-prompt` · `.tb-prompt-input` | নতুন কিছু বসানোর সময় ওঠা ঠিকানা-ইনপুট প্যানেল | `mountToolbar()` |
| `.nabi-hints [data-hint]` | Shift দুবার দ্রুত চাপলে ওঠা শর্টকাট ব্যাজ — ব্যাজ `::before`, লেবেল `::after` বলে দুটোই একসঙ্গে দেখা যায় | `mountHints()` |
| `[data-nabi-tip]` | লেবেল (tooltip) — কেবল CSS `::after` দিয়ে আঁকা | সামগ্রিক কোর |
| `.nabi-content.nabi-dropping` | ফাইল টেনে আনার সময়কার সম্পাদনার জায়গা। নির্দেশনার লেখা `data-nabi-drop` অ্যাট্রিবিউটে বসে | `mountUpload()` |

প্রিভিউ·ফুলস্ক্রিনও **কোরই বানায়।**

| সিলেক্টর | কী | কে |
|---|---|---|
| `.nabi-scrim` > `.nabi-card` > (`.nabi-close` · `.nabi-content.nabi-preview-body`) | নথি প্রিভিউ ওভারলে | `openPreview()` |
| `.nabi-scrim` > `.nabi-card.nabi-lightbox` | কেবল একটি ছবি বড় করে দেখার বাক্স | `openImageLightbox()` |
| `.nabi.is-fullscreen` | ফুলস্ক্রিন — `.nabi` বাক্স পর্দায় আটকে রাখে | `setFullscreen()` (ক্লাসের নাম `FULLSCREEN_CLASS`) |

`mountViewTools()` জুড়লে দুই বোতাম নিজে থেকেই এগুলো খোলে-বন্ধ করে। নিজে
থেকে খুলতে চাইলে `openPreview({ nabi, editor })` ·
`openImageLightbox({ editor, src, alt?, locale })` · `setFullscreen(root, on)` ·
`isFullscreen(root)` ডাকুন।

::: tip টুলের জায়গা নিজে থেকেই দাঁড়ায়
`mountViewTools` নিজেই `.nabi-tools` বাক্স বানিয়ে পাওয়া পাত্রের একদম
সামনে বসায়। হোস্টের টুলবারের আগে `<span>` রাখার কোনো দরকার নেই — জায়গা
আগে থেকে বানিয়ে রাখলে বরং বাক্স দুটো হয়ে যায়।
:::

সম্পাদনার পর্দা-নির্দিষ্ট চিহ্নও ধরা যায় — `[data-nabi-token]` (কোড ব্লকের
টোকেন রং), `[data-nabi-lang]` (কোড ব্লকের ভাষা), `[data-color]` (হাইলাইট·
লেখার রং — `<mark>`·`<span>` ট্যাগ দিয়ে আলাদা), `data-nabi-align`·
`data-nabi-typeface`·`data-nabi-size`·`data-nabi-dropcap` (অনুচ্ছেদ
অ্যাট্রিবিউট)। এই চিহ্নগুলোর আসল নাম প্রতিটি wing ফাইলের `*_ATTR`
কনস্ট্যান্টেই মূল রূপে আছে।

## সংরক্ষিত HTML বাইরে আঁকার সময়

বেরোনো মান (`getHtml()`) `data-nabi-*` অ্যাট্রিবিউট রেখে দেওয়া HTML, আর
**একটাও ইনলাইন `style` নেই।** মানে রূপ পুরোটাই স্টাইলশিটের দায়িত্ব, তাই
স্টাইলশিট ছাড়া আঁকলে সারিবদ্ধতাও লেখার আকারও টেবিলের রেখাও ছাড়া খালি HTML
হয়ে যায়।

সম্পাদকের মতো একই রূপে আঁকতে চাইলে `.nabi-content` দিয়ে মুড়ে দিন — এই ক্লাস
`.nabi` দিয়ে না মুড়েও সরাসরি রং·রূপ টোকেন পায় (`nabi.css`-এর
`.nabi-content:where(:not(.nabi *))` নিয়ম)।

```html
<div class="nabi-content">সংরক্ষিত HTML</div>
```

স্টাইলশিট উপরের "স্টাইলশিট জোড়ার দুই পথ"-এ দেখানো মতোই জুড়লেই হয় —
বান্ডলার হলে `import 'nabi-note/nabi.css'`, অন্যথায় `<link>` একটি। সম্পাদক
দাঁড় না করানো পাতাতেও কেবল `.nabi-content` থাকলে কোরের স্টাইলশিট টোকেন
ঘোষণা করে দেয়।

### দেখার পক্ষে চলা আচরণ — টেবিল সাজানো

এখন কেবল **টেবিল সাজানো একটিই** দেখার পক্ষের আলাদা ফাংশন হিসেবে বেরোয়।
যেকোনো wing নিজের দেখার-পক্ষের আচরণ জোড়ার সাধারণ কোনো ব্যবস্থা এখনও নেই।

```ts
import { attachTableSort } from 'nabi-note/viewer'

const detach = attachTableSort(document.querySelector('#article')!, { locale: 'bn' })
```

`data-nabi-sortable` লাগানো টেবিল খুঁজে শিরোনাম ঘরে সাজানোর বোতাম বসায়।
বিচ্ছিন্ন করার ফাংশন (`detach`) বসানো বোতাম আর বদলানো সারির ক্রম ফিরিয়ে
দেয়।

::: danger সম্পাদনার এলিমেন্টে জুড়বেন না
`attachTableSort()` DOM-এ বোতাম বসায় আর সারির ক্রম বদলায়। জোড়া থাকা অবস্থার
DOM সংরক্ষণ করলে তা-ই মানে বসে যায় — দেখার পক্ষ কেবল কেবল-পড়ার কপিতেই জোড়া
উচিত।
:::
