# UI ও আচরণ

wing মানুষের সামনে দাঁড়ায় এমন জায়গা তিনটি।

| ঘর | কোথায় |
|---|---|
| `button` · `buttons` | উপরের **টুলবার** — সবসময় দেখা যায় এমন জায়গা |
| `context` | **কনটেক্সট সারি** — ক্যারেট যা ছুঁয়েছে সেখানেই কেবল ওঠে |
| `styles` | এই wing বহন করা **CSS** |

---

## টুলবার বোতাম

```ts
button: {
  group: 'emphasis',                   // কোন গুচ্ছে বসবে — আবশ্যক
  svg: '<path d="…"/>',                // 16×16 কোঅর্ডিনেটের ভিতরটুকু। না থাকলে লেখা হয়ে বসে
  label: { bn: 'গাঢ়', en: 'Bold' },
  shortcut: 'B',                       // হিন্ট মোডে এই অক্ষর
  accelerator: 'mod+b',                // Ctrl/⌘ জোড়
  action: { kind: 'mark' },
}
```

বোতাম একাধিক হলে `buttons`-এ অ্যারে করে লেখা হয় — সারিবদ্ধতা wing একাই
বাঁয়ে·মাঝে·ডানে তিনটে দাঁড় করায় এভাবেই। তখন `name` দিয়ে একে অপরকে আলাদা
করা হয় আর `value` দিয়ে প্রতিটি কী মান বহন করে তা লেখা হয়।

### `group` — ক্রম গুচ্ছই ঠিক করে

```
font · heading · emphasis · script · color · link ·
align · list · structure · media · container · clear · file
```

**এই ক্রম বাঁধা।** wing অ্যারের যেখানেই রাখুন, বোতাম নিজের গুচ্ছের
জায়গাতেই বসে। একই গুচ্ছের ভিতরে কেবল নিবন্ধনের ক্রমেই সাজে। তালিকায়
নেই এমন নাম দিলে একদম শেষে নতুন গুচ্ছ দাঁড়ায়।

গুচ্ছ পুরোপুরি খালি হলে (ভিতরের সব বোতাম লুকিয়ে গেলে) সেই গুচ্ছ পর্দা
থেকে অদৃশ্য হয়ে যায় — খালি বিভাজক রেখা থেকে যায় না।

### `action` — চাপলে কী হয়

| `kind` | কী করে | সঙ্গে লিখতে হয় |
|---|---|---|
| `'mark'` | কোরের মার্ক টগলে যায়। **কমান্ড লিখতে হয় না** | — |
| `'command'` | একটি কমান্ড চালায় | `command` · `args?` |
| `'menu'` | মানের তালিকা প্যানেলে খোলে | `command` · `argKey` · `values` |
| `'grid'` | সারি×কলাম গ্রিড খোলে (টেবিল বসানো) | `command` · `rowsKey` · `colsKey` · `max?` |
| `'prompt'` | ইনপুট ঘর তুলে পাওয়া মান কমান্ডে পাঠায় | `command` · `fields` |
| `'file'` | ফাইল বাছার উইন্ডো খোলে | `accept?` · `multiple?` |
| `'host'` | হোস্টের কাছে পাঠায় (`mountToolbar`-এর `onHost`) | — |

`action` না লিখলে সেই বোতাম চাপলেও কিছুই ঘটে না।

### `shortcut` আর `accelerator`

| | রূপ | নিয়ম |
|---|---|---|
| `shortcut` | `'B'` | ল্যাটিন **বড় হাতের অক্ষর বা সংখ্যা একটি** |
| `accelerator` | `'mod+b'` | `mod+`-এর পরে **ছোট হাতের অক্ষর একটি** |

দুটোই **wing-এর মধ্যে মিলে গেলে নিবন্ধনের মুহূর্তেই ভেঙে পড়ে।** পরে
চুপচাপ একদিক কাজ না করার ঘটনা ঘটে না।

`accelerated` আলাদা করে লিখলে অ্যাক্সিলারেটর দিয়ে চাপলে তবেই ভিন্ন
আচরণ যায় — বোতাম চাপলে প্যানেল খোলে কিন্তু <kbd>Ctrl</kbd>+কী দিয়ে
ডিফল্ট মানই সরাসরি বসে, এমন।

## চাপা আছে বলে দেখানোর নিয়ম

বোতাম "এখন চালু আছে" বলে রাঙা হওয়ার ভিত্তি একটিই।

| `place` | কী দেখে |
|---|---|
| `'mark'` | ক্যারেটের জায়গায় সেই মার্ক আছে কি না |
| `'attr'` | ক্যারেট দাঁড়ানো অনুচ্ছেদের `currentValue` |
| `'container'`·`'void'` | ক্যারেট সেই বস্তুর ভিতরে বা তার উপরে আছে কি না |
| `'tool'` | **সবসময়ই বন্ধ** |

একাধিক মান নেওয়া wing-এ (সারিবদ্ধতা·শিরোনাম) প্রতিটি বোতামে `value`
লেখা হয়, আর wing-এর `currentValue` যে মান ফিরিয়ে দেয় তার সঙ্গে মেলা
বোতামটিই রাঙা হয়।

```ts
currentValue: (node) => {
  const h = node.a?.['h']
  return typeof h === 'number' && h >= 1 && h <= 6 ? String(h) : undefined
}
```

**`currentValue` লেখা ফিরিয়ে দেয়** — মান সংখ্যা হলেও `String()` দিয়ে
বদলে দিতে হয়। `undefined` মানে "এই নোডে আমার মান নেই"।

## দাঁড়ানোর জায়গা না থাকলে বোতাম নিজে থেকেই লুকায়

| `place` | কখন লুকায় |
|---|---|
| `'mark'` | কেবল লেখা থাকে এমন জায়গায় (কোড বাক্সের ভিতরের মতো), সেই জায়গার মালিক হলে |
| `'attr'` | ক্যারেট বস্তু ধরে রাখা র‍্যাপার অনুচ্ছেদের উপরে থাকলে। **কেবল সারিবদ্ধতা (`a`) ব্যতিক্রম** |
| `'void'`·`'container'` | কেবল লেখা থাকা জায়গা, বা এখনকার পাত্রের `allows` আমাকে গ্রহণ না করলে |
| `'tool'` | লুকায় না |

সারিবদ্ধতাই কেবল ব্যতিক্রম হওয়ার কারণ আগে দেখা সেই একই — বস্তুর
সারিবদ্ধতা বস্তু নয়, তাকে ধরে রাখা র‍্যাপার অনুচ্ছেদ বহন করে। ছবির
উপর থেকেই "মাঝে" চাপতে পারতে হয়।

`allows` লিখে রাখলে **টুলবার নিজে থেকেই অনুসরণ করে।** কোড বাক্সের ভিতরে
টেবিল বোতাম অদৃশ্য হয়ে যাওয়া আলাদা করে লেখা কোনো নিয়ম নয়, `allows`
থেকেই বেরোয়।

## কনটেক্সট সারি

ক্যারেট এখন যা ছুঁয়েছে সেখানেই কেবল ওঠে এমন সারি। ছবিতে চাপলে আকার
বদলানোর, লিঙ্কে ক্যারেট রাখলে ঠিকানার ঘর ওঠার জায়গা এটিই।

```ts
context: {
  title: { bn: 'নোট', en: 'Note' },
  controls: [
    {
      kind: 'select',
      name: 'tone',
      label: { bn: 'সুর', en: 'Tone' },
      command: 'setNoteTone',
      argKey: 'value',
      attr: 't',                                    // এখনকার মান পড়ার অ্যাট্রিবিউট
      values: [
        { value: 'info', label: { bn: 'তথ্য' } },
        { value: 'warn', label: { bn: 'সতর্কতা' } },
      ],
    },
  ],
}
```

### কখন ওঠে

ক্যারেটের জায়গায় **যা কিছু ছুঁয়ে থাকে তার সবাই** নিজের সারি খোলে।

- ক্যারেটের পথের উপরে থাকা পাত্রগুলো (ভিতরেরটা আগে, বাইরেরটা পরে)
- লক্ষ্য করা বস্তু (র‍্যাপার অনুচ্ছেদের উপর থেকে নির্বাচিত ছবির মতো)
- ক্যারেটের জায়গায় বসা **মার্কগুলো** — টুলবার বোতামের থেকে ভিন্ন, মার্কও
  কনটেক্সট সারি পায়
- ক্যারেট দাঁড়ানো অনুচ্ছেদে মান আছে এমন **অনুচ্ছেদ-অ্যাট্রিবিউট** wing

টেবিলের ভিতরের লিঙ্কে ক্যারেট রাখলে লিঙ্কের সারি আর টেবিলের সারি
একসঙ্গেই ওঠে।

### `ContextControl`-এর সাতটি ধরন

| `kind` | কী | সঙ্গে লিখতে হয় |
|---|---|---|
| `'button'` | একবার চাপলে কমান্ড | `command` · `args?` |
| `'toggle'` | চালু/বন্ধ দুই অবস্থা | `command` · `token` |
| `'select'` | তালিকা থেকে একটি | `command` · `argKey` · `values` · `attr?` |
| `'range'` | স্কেল টানা (আকার বদলানো) | `command` · `argKey` · `values` · `rest?` · `readout?` |
| `'text'` | একটি লেখার ঘর (লিঙ্কের ঠিকানা) | `command` · `argKey` · `initial?` · `placeholder?` · `validate?` |
| `'prompt'` | একাধিক ঘর প্যানেলে | `command` · `fields` |
| `'lightbox'` | বড় করে দেখা | `src` · `alt?` |

সাতটিই সাধারণভাবে `name` (আবশ্যক) · `label?` · `svg?` · `tip?` ·
`visible?` রাখে।

`visible: (node) => boolean` হলো **একই wing-এর ভিতরে ঘর লুকানোর** দরজা —
আগে থেকেই মার্জ করা ঘরেই কেবল "মার্জ খুলুন" দেখানোর মতো।

`attr` লিখলে এখনকার মান সরাসরি সেই অ্যাট্রিবিউট থেকে পড়ে রাঙায়।
`'toggle'` `token` দিয়ে `currentValue`-এর ফেরত দেওয়া লেখার সঙ্গে মেলায়।

## `styles` — wing বহন করা CSS

```ts
styles: `
.nabi-content aside[data-nabi-note] {
  border-inline-start: 3px solid var(--nabi-accent);
  padding: .6rem .9rem;
  background: color-mix(in srgb, var(--nabi-accent) 8%, transparent);
}
`
```

নিয়ম চারটি।

- **`.nabi-content`-এর নিচে সীমাবদ্ধ রাখুন।** হোস্ট পাতার অন্য লেখায়
  ছড়িয়ে পড়া উচিত নয়।
- **ফন্টের আকার `rem` বা `em`-এ** লিখুন।
- **ডার্ক ভ্যারিয়েন্ট কেবল `.dark` ক্লাস দিয়েই** আলাদা করুন। মিডিয়া
  কোয়েরি দিয়ে করলে হোস্টের চালু করা আলোকিত পর্দায় শুধু সম্পাদকই অন্ধকার
  হয়ে যায়।
- **চওড়া-সরু কনটেইনার কোয়েরি দিয়ে মাপুন।** পর্দার প্রস্থ নয়, সম্পাদক
  যেখানে বসানো সেই জায়গার প্রস্থই ভিত্তি।

কেবল নিবন্ধিতটুকুই রাখতে চাইলে নিজে জড়ো করে জুড়ে দিন।

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const detach = injectSheets(document, collectSheets(registry))
```

একই লেখার স্টাইলশিট **একবারই** বসে — একাধিক wing একই CSS ভাগ করলেও
নথিতে একটিই জোড়ে। উত্তর একটি বিচ্ছিন্ন-ফাংশন, আর **এই ডাকটি যা নতুন
জুড়েছে তা-ই** সরায়।

## মানুষকে জিজ্ঞেস করা

```ts
const { nabi, registry } = createNabiWith(wings, {
  ask: {
    message: (text) => window.alert(text),
    confirm: (text) => window.confirm(text),
  },
})
```

`confirm` `boolean`-ও `Promise<boolean>`-ও নেয় — ব্রাউজারের `confirm`
সরাসরি গুঁজে দেওয়া যায়, অথবা নিজে বানানো প্যানেল তুলে পরে উত্তর দিলেও
চলে।

::: warning না দিলে উত্তর সবসময় "না"
`ask` না গুঁজলে চুপচাপ একটি ডিফল্ট বসে। `message` কোথাও যায় না আর
`confirm` `false` ফিরিয়ে দেয়। **জিজ্ঞেস করে মোছার কাজ চুপচাপ না হওয়াটা**
চুপচাপ হয়ে যাওয়ার চেয়ে ভালো — এই পক্ষ নেওয়া হয়েছে। লোকাল হিস্ট্রির
"সত্যিই মুছবেন" এই দরজা দিয়ে যায়।
:::

::: tip কমান্ড জিজ্ঞেস করতে পারে না
কমান্ড বিশুদ্ধ ফাংশন বলে পর্দা বা সময় কিছুই চেনে না। জিজ্ঞেস করার দরকার
হলে কমান্ডের বাইরে জিজ্ঞেস করে **উত্তর পাওয়ার পরে** কমান্ড ডাকতে হয়।
wing-এর ভিতরে সেই জায়গা `attach`, আর সেখানে `host.nabi.$ask` দিয়ে
পৌঁছানো যায়।
:::
