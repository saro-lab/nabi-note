# কী·স্বয়ংক্রিয় রূপান্তর·পেস্ট

wing মানুষের হাতের ইশারা পায় এমন দরজা তিনটি — **কী** (`onKey`), **লেখা**
(`inputRules`), **পর্দা** (`attach`)।

---

## কী যে পথ দিয়ে যায়

<kbd>Enter</kbd> একবার চাপলে এই ক্রমে জিজ্ঞেস করা হয়। আগেরটা কেউ ধরে
নিলে পরেরটায় আর যায় না।

```
① টুলবার শর্টকাট        যেকোনো জায়গা থেকে শোনে (Ctrl+B-এর মতো)
② স্বয়ংক্রিয় রূপান্তর    inputRules — কেবল Enter·Space
③ wing-এর onKey         ক্যারেট যেখানে বসে সেখানকার মালিকের কাছে
④ বস্তু লক্ষ্য করা       অনুচ্ছেদের একদম শুরুতে Backspace → আগের বস্তু গোটাই নির্বাচিত হয়
⑤ কোরের নিয়ম            অনুচ্ছেদ ভাগ করা·মোছা·ক্যারেট চলাফেরা
⑥ ব্রাউজার              এখানে পৌঁছানো পর্যন্ত কেউ না নিলে তবেই
```

---

## `onKey` — কী হাতে নেওয়া

```ts
import type { OnKey } from 'nabi-note'

const noteKeys: OnKey = (intent, doc, sel, env, owner) => {
  if (intent.key !== 'backspace') return null      // আমার কাজ নয় — কোরের কাছে ফিরিয়ে দিন
  if (sel.focus.offset !== 0) return null
  const first = [...owner.path, 0]
  if (first.length !== sel.focus.path.length) return null
  if (!first.every((v, i) => v === sel.focus.path[i])) return null
  return toggleNote(doc, sel, {}, env)             // প্রথম ঘরের শুরুতে Backspace — নোট খুলে দেয়
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',
  toHtml: (_node, children, ctx) => ctx.element('aside', children()),
  commands: { toggleNote },
  onKey: noteKeys,
}
```

| আর্গুমেন্ট | কী |
|---|---|
| `intent` | `{ key, dir? }` — কোন কী |
| `doc` · `sel` · `env` | কমান্ড যা পায় তা-ই |
| `owner` | `{ path, node }` — **যে নোড মালিক হিসেবে বাছা হয়েছে** সেটি |

উত্তর কমান্ডের মতোই `{ doc, selection }` অথবা **`null`**। `null` মানে
"নিচ্ছি না", তখন কোর নিজেই ধরে নেয় — শর্ত না মিললে অবশ্যই `null` ফিরিয়ে
দিন।

### যে কী আসে

| `intent.key` | কখন |
|---|---|
| `'enter'` | <kbd>Enter</kbd> **আর** <kbd>Shift</kbd>+<kbd>Enter</kbd> দুটোই |
| `'tab'` · `'shiftTab'` | <kbd>Tab</kbd> · <kbd>Shift</kbd>+<kbd>Tab</kbd> |
| `'backspace'` · `'delete'` | মোছার দুটোই |
| `'arrow'` | তীর-কী। দিক `intent.dir`-এ (`'left'`·`'right'`·`'up'`·`'down'`) |

লেখার কী আসে না। লেখা ব্রাউজার টাইপ করে আর কোর তা তুলে নেয়।

### মালিক একজনই

ক্যারেটের পথ **উপরের দিকে হেঁটে প্রথম যে অনুচ্ছেদ-নয় নোড পাওয়া যায়**,
সেই নোড যে wing-এর তা-ই মালিক।

```
পথ [1, 0, 0]-এর ক্যারেট                   মালিক প্রার্থী
  [1, 0, 0]  →  p        অনুচ্ছেদ বলে বাদ যায়
  [1, 0]     →  note     ← মালিক
  [1]        →  p(র‍্যাপার)  এতদূর আসেই না
```

তাই **সবচেয়ে ভিতরের পাত্রই জেতে** — টেবিলের ভিতরের তালিকায়
<kbd>Tab</kbd> চাপলে তালিকাই তা পায়। অংশ (`parts`)-ও মালিক হতে পারে,
তখন `owner.node` অংশের নোড হলেও `onKey` ডাকা হয় সেটি ঘোষণা করা wing-এরটাই।
তাই আগে `owner.node.w` দিয়ে কোনটি বাছা হয়েছে তা আলাদা করাই রেওয়াজ।

মার্ক মালিক হতে পারে না — [কারণ ইনলাইন নথিতে](./inline#মার্ক-কী-পায়-না)।

## `inputRules` — কেবল লেখা দিয়ে বানানো

`# ` লিখলে শিরোনাম হয়, `> ` লিখলে উদ্ধৃতি হয় — এটিই তার পিছনে।

```ts
inputRules: [
  { trigger: 'space', pattern: /^>$/, run: () => ({ name: 'toggleQuote' }) },
]
```

| ঘর | |
|---|---|
| `trigger` | `'space'` বা `'enter'` — এই কী চাপার **মুহূর্তেই** ধরা হয় |
| `pattern` | একটি রেজেক্স। `run` সেই ম্যাচ পায় |
| `run` | `{ name, args? }` — চালানো কমান্ড |
| `scope` | `'block'` (ডিফল্ট) বা `'word'` |

### `'block'` — লাইনের শুরুটাই বদলে দেয়

ক্যারেটের আগের **লাইনের শুরু** দেখে। মিললে সেই শুরু (আর ট্রিগার অক্ষর)
মুছে কমান্ড চালায়।

```
"> " লিখলে   →   "&gt;" মুছে গিয়ে toggleQuote চলে
```

কেবল অনুচ্ছেদের **প্রথম লাইনে** ধরা পড়ে। <kbd>Shift</kbd>+<kbd>Enter</kbd>
দিয়ে নামানো পরের লাইনে ধরা পড়ে না — লেখার মাঝখানে হঠাৎ ফরম্যাট বেরিয়ে
পড়া এভাবেই আটকানো হয়।

### `'word'` — একটি শব্দে বসায়

ক্যারেটের আগের **একটি শব্দ** দেখে। মিললে সেই শব্দ নির্বাচন করে কমান্ড
চালায় আর ক্যারেট আগের জায়গায় ফিরিয়ে দেয়। লেখা মোছে না — মার্ক বসানোর
নিয়ম এইদিকেই।

সেই শব্দ **আগে থেকেই এই wing-এর মার্ক পরে থাকলে বাদ যায়।** একই জায়গায়
দুবার ধরা পড়ে না।

### সাধারণ নিয়ম

- ক্যারেট **ভাঁজ করা (collapsed) অবস্থায়ই** কেবল চলে। পরিসর ধরে স্পেস
  চাপলেও ধরা পড়ে না।
- কেবল সাধারণ অনুচ্ছেদেই চলে — বস্তু ধরে রাখা র‍্যাপার অনুচ্ছেদে ধরা পড়ে
  না।
- wing-এর অ্যারের ক্রমে যাচাই হয়, **প্রথম যেটি সফল হয়** সেটিই জেতে।
- কমান্ড `null` ফিরিয়ে দিলে (= করার কিছু নেই) **ফিরিয়ে নিয়ে পরের নিয়মে
  যায়।** ব্যর্থ স্বয়ংক্রিয় রূপান্তরের কোনো চিহ্ন নথিতে থেকে যায় না।

## `attach` — পর্দায় হাত দেওয়া

নথি বদলানো নয়, **পর্দায় ঘটা কিছু** শুনতে হয় এমন সময় আছে — টেবিলের ঘর
টেনে বাছা, কোডে রং বসানো, ভাঁজের ত্রিভুজে চাপা।

```ts
import type { Attach } from 'nabi-note'

const attachNote: Attach = (host) => {
  const onClick = (ev: MouseEvent): void => { /* … */ }
  host.root.addEventListener('click', onClick)
  return () => host.root.removeEventListener('click', onClick)   // বিচ্ছিন্ন করার ফাংশন ফিরিয়ে দিন
}
```

`host` তিনটি জিনিস দেয়।

| | |
|---|---|
| `host.root` | সম্পাদনা তলের এলিমেন্ট |
| `host.nabi` | সম্পাদক। নথি বদলাতে হলে **কমান্ড দিয়েই** করতে হয় |
| `host.pathOfKey(id)` | পর্দার `data-key` কে নথির পথে বদলায় |

`mountSurface` নিবন্ধিত সব wing-এর `attach` একসঙ্গে জুড়ে দেয়, আর তুলে
নেওয়ার সময় ফিরিয়ে দেওয়া বিচ্ছিন্ন-ফাংশনগুলো ডাকে। **DOM চেনা কোড থাকার
একমাত্র জায়গা** এটিই — কমান্ড·`toHtml`·`repair`-এর ভিতরে `document`
ছোঁয়া উচিত না।

::: tip `data-key` দিয়ে নথি খোঁজা
সম্পাদকের জোড়া লাগানো (`getEditorHtml()`) প্রতিটি নোডে `data-key` বসায়।
চাপা এলিমেন্ট থেকে সবচেয়ে কাছের `[data-key]` খুঁজে `host.pathOfKey()`-এ
দিলে নথির ভিতরের জায়গা বেরিয়ে আসে।
:::

## পেস্ট আর প্রাথমিক HTML

পেস্ট·`setHtml()`·সংরক্ষিত মান লোড করা — **সবই একই দরজা** দিয়ে যায়।
wing-এর এখানকার কাজ কেবল `claim` — [ইনলাইন নথির `claim`](./inline#claim)-এ
লেখা আছে।

```
পেস্ট ─────┐
setHtml   ─┼→ পার্স → wing-এর claim → কোরের ডিফল্ট ট্যাগ মেলানো → repair → cocoon → নথি
প্রাথমিক HTML ─┘
```

`claim` না থাকলে **সেই ট্যাগের খোলস খসে গিয়ে ভিতরের লেখাটুকু থাকে।**
অন্যের সম্পাদক থেকে কপি করা অচেনা মার্কআপ নথিতে যেমন-তেমন বসে না যাওয়ার
কারণ এই নিয়মই।

JSON দিয়ে ঢোকার পথে (`setJson()`) ট্যাগ নয়, নোড আসে বলে দ্বাররক্ষী `claim`
নয়, `repair`।
