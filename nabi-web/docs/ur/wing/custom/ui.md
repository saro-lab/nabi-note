# UI اور برتاؤ

جن تین جگہوں پر wing انسان کے سامنے کھڑی ہوتی ہے۔

| خانہ | کہاں |
|---|---|
| `button` · `buttons` | اوپر کا **ٹول بار** — ہمیشہ نظر آنے والی جگہ |
| `context` | **سیاق سطر** — صرف کیریٹ جو چھو رہا ہے اسی پر نکلنے والی جگہ |
| `styles` | اس wing کا اٹھایا ہوا **CSS** |

---

## ٹول بار کا بٹن

```ts
button: {
  group: 'emphasis',                   // کس گروہ میں کھڑا ہے — لازمی
  svg: '<path d="…"/>',                // 16×16 نقشے کا مواد۔ نہ ہو تو حرف سے کھڑا ہوتا ہے
  label: { ur: 'جلی' },
  shortcut: 'B',                       // hint mode میں یہی حرف دکھتا ہے
  accelerator: 'mod+b',                // Ctrl/⌘ کا مجموعہ
  action: { kind: 'mark' },
}
```

بٹن کئی ہوں تو `buttons` میں صف کے طور پر لکھیں — جیسے سیدھ کی wing ایک ساتھ
بائیں، درمیان، دائیں تین بٹن کھڑے کرتی ہے۔ تب `name` سے ایک دوسرے سے الگ کیا
جاتا ہے اور `value` سے ہر ایک کی نمائندہ قدر لکھی جاتی ہے۔

### `group` — ترتیب گروہ طے کرتا ہے

```
font · heading · emphasis · script · color · link ·
align · list · structure · media · container · clear · file
```

**یہ ترتیب طے شدہ ہے۔** wing صف میں کہیں بھی رکھی جائے، بٹن اپنے گروہ کی جگہ
پر ہی کھڑا ہوتا ہے۔ ایک ہی گروہ کے اندر صرف رجسٹریشن کی ترتیب سے قطار بنتی ہے۔
فہرست میں نہ ہونے والا نام آخر میں نیا گروہ بنا کر کھڑا ہوتا ہے۔

جب کوئی گروہ مکمل خالی ہو جائے (اس کے سب بٹن چھپ جائیں) تو وہ گروہ سکرین سے غائب
ہو جاتا ہے — خالی جداکار (divider) پیچھے نہیں رہتا۔

### `action` — دبانے پر کیا ہوتا ہے

| `kind` | کرتا ہے | ساتھ لکھا جاتا ہے |
|---|---|---|
| `'mark'` | سیدھا کور کے mark toggle پر جاتا ہے۔ **command کی ضرورت نہیں** | — |
| `'command'` | ایک command چلاتا ہے | `command` · `args?` |
| `'menu'` | قدروں کی فہرست کو panel کے طور پر کھولتا ہے | `command` · `argKey` · `values` |
| `'grid'` | قطار×کالم کا grid کھولتا ہے (جدول ڈالنا) | `command` · `rowsKey` · `colsKey` · `max?` |
| `'prompt'` | ان پٹ خانہ دکھا کر ملی قدر command کو دیتا ہے | `command` · `fields` |
| `'file'` | فائل چننے کی ونڈو کھولتا ہے | `accept?` · `multiple?` |
| `'host'` | میزبان کو دیا جاتا ہے (`mountToolbar` کا `onHost`) | — |

`action` نہ لکھیں تو بٹن دبانے سے کچھ نہیں ہوتا۔

### `shortcut` اور `accelerator`

| | شکل | قاعدہ |
|---|---|---|
| `shortcut` | `'B'` | لاطینی **بڑا حرف یا ہندسہ، ایک حرف** |
| `accelerator` | `'mod+b'` | `mod+` کے بعد **چھوٹا ایک حرف** |

دونوں **wing کے درمیان ٹکرا جائیں تو رجسٹر کرتے ہی مر جاتے ہیں۔** بعد میں
خاموشی سے کوئی ایک طرف کام نہ کرنے کی صورت نہیں بنتی۔

`accelerated` الگ سے لکھیں تو accelerator سے دبانے پر مختلف عمل ہوتا ہے — بٹن
دبانے سے panel کھلتا ہے مگر <kbd>Ctrl</kbd>+کلید سے default قدر سیدھی لگ جاتی
ہے۔

::: warning accelerator صرف **اسی ایڈیٹر کی زمین** پر اٹھی کلید سنتا ہے
accelerator سننے کی جگہ ایک ہی ہے — ٹول بار — اور اس کا کان کہاں تک پہنچتا ہے یہ
`mountToolbar({ surface })` طے کرتا ہے۔ صرف اسی surface یا ٹول بار کی سطروں میں اٹھی کلید
اسی ایڈیٹر کی مانی جاتی ہے۔ **ایک صفحے پر دو ایڈیٹر ہوں تو یہ ضرور دیں** — نہ دیں تو ٹول بار
پورے دستاویز کو سننے پر واپس چلا جاتا ہے، اور دونوں ایڈیٹر ایک دوسرے کی کلید کھا جاتے ہیں۔

دو اور حدیں ہیں۔ **بٹن کھڑا ہونا لازم ہے** (یعنی وہ wing ابھی رجسٹر اور نظر آ رہی ہو)، اور
**دبانا کہیں پہنچنا لازم ہے** اس سے پہلے کہ کلید نگلی جائے۔ `'host'` action تبھی کہیں پہنچا
مانا جاتا ہے جب `onHost` یا محفوظ کرنے کا panel جوڑا ہو؛ کہیں نہ پہنچے تو کلید براؤزر کی اپنی
سمجھ کر آگے بہہ جاتی ہے۔
:::

## دبے ہوئے دکھنے کا طریقہ

بٹن کے "ابھی آن ہے" رنگا جانے کی بنیاد صرف ایک ہے۔

| `place` | کیا دیکھا جاتا ہے |
|---|---|
| `'mark'` | کیریٹ کی جگہ پر وہ mark موجود ہے یا نہیں |
| `'attr'` | کیریٹ جس پیراگراف پر کھڑا ہے اس کا `currentValue` |
| `'container'`·`'void'` | کیریٹ اس جسم کے اندر یا اوپر ہے یا نہیں |
| `'tool'` | **ہمیشہ بند** |

کئی قدر رکھنے والی wing (سیدھ، سرخی) ہر بٹن پر `value` لکھتی ہے، اور صرف وہ بٹن
رنگا جاتا ہے جس کی قدر wing کے `currentValue` کے جواب سے میچ کرے۔

```ts
currentValue: (node) => {
  const h = node.a?.['h']
  return typeof h === 'number' && h >= 1 && h <= 6 ? String(h) : undefined
}
```

**`currentValue` ہمیشہ متن جواب دیتا ہے** — عددی قدر ہو تب بھی `String()` سے
بدل کر جواب دیا جاتا ہے۔ `undefined` کا مطلب ہے "اس node میں میری قدر نہیں ہے"۔

## بٹن نہ کھڑے ہونے والی جگہ پر خود بخود چھپ جاتے ہیں

| `place` | کب چھپتا ہے |
|---|---|
| `'mark'` | صرف سادہ متن رہنے والی جگہ (کوڈ کے ڈبے کے اندر جیسی) میں، جب وہ اس جگہ کا مالک ہو |
| `'attr'` | کیریٹ جسم رکھنے والے wrapper پیراگراف پر ہو۔ **صرف سیدھ (`a`) استثنا ہے** |
| `'void'`·`'container'` | صرف سادہ متن رہنے والی جگہ ہو، یا ابھی کے ظرف کا `allows` مجھے قبول نہ کرے |
| `'tool'` | نہیں چھپتا |

سیدھ کے استثنا ہونے کی وجہ پہلے دیکھی جا چکی ہے — جسم کی سیدھ خود جسم نہیں بلکہ
اسے تھامنے والا wrapper پیراگراف رکھتا ہے۔ تصویر کے اوپر "درمیان" دبانا ممکن
ہونا چاہیے۔

`allows` لکھ دیں تو **ٹول بار خود بخود اس کی پیروی کرتا ہے۔** کوڈ کے ڈبے کے
اندر جدول کا بٹن غائب ہونا کوئی الگ سے لکھا گیا قاعدہ نہیں، صرف `allows` سے
نکلتا ہے۔

## سیاق سطر

صرف اس چیز پر نکلنے والی سطر جسے کیریٹ ابھی چھو رہا ہو۔ تصویر دبانے پر سائز
بدلنے کا کنٹرول، اور لنک پر کیریٹ رکھنے پر پتے کا خانہ اسی جگہ نکلتا ہے۔

```ts
context: {
  title: { ur: 'نوٹ' },
  controls: [
    {
      kind: 'select',
      name: 'tone',
      label: { ur: 'انداز' },
      command: 'setNoteTone',
      argKey: 'value',
      attr: 't',                                    // جہاں سے ابھی کی قدر پڑھی جاتی ہے
      values: [
        { value: 'info', label: { ur: 'اطلاع' } },
        { value: 'warn', label: { ur: 'توجہ' } },
      ],
    },
  ],
}
```

### کب نکلتی ہے

کیریٹ کی جگہ پر **جو کچھ چھوتا ہے وہ سب** اپنی اپنی سطر کھولتا ہے۔

- کیریٹ کے راستے پر آنے والے ظروف (پہلے اندر والا، بعد میں باہر والا)
- نشانہ بنایا گیا جسم (wrapper پیراگراف پر منتخب تصویر جیسی چیز)
- کیریٹ کی جگہ پر لگے **mark** — ٹول بار کے بٹن کے برعکس، mark کی بھی اپنی سیاق
  سطر ہوتی ہے
- کیریٹ جس پیراگراف پر کھڑا ہے اس کی **پیراگراف کی خاصیت** والی wing، اگر قدر
  رکھتی ہو

جدول کے اندر لنک پر کیریٹ رکھیں تو لنک کی سطر اور جدول کی سطر ساتھ نکلتی ہیں۔

### `ContextControl` کی سات قسمیں

| `kind` | کیا | ساتھ لکھا جاتا ہے |
|---|---|---|
| `'button'` | ایک دبانے سے command | `command` · `args?` |
| `'toggle'` | آن/آف دو حالتیں | `command` · `token` |
| `'select'` | فہرست سے ایک چننا | `command` · `argKey` · `values` · `attr?` |
| `'range'` | نشان سرکانا (سائز بدلنا) | `command` · `argKey` · `values` · `rest?` · `readout?` |
| `'text'` | ایک متن کا خانہ (لنک کا پتہ) | `command` · `argKey` · `initial?` · `placeholder?` · `validate?` |
| `'prompt'` | کئی خانے panel میں | `command` · `fields` |
| `'lightbox'` | بڑا دکھانا | `src` · `alt?` |

ساتوں میں مشترک: `name` (لازمی) · `label?` · `svg?` · `tip?` · `visible?`۔

`visible: (node) => boolean` **ایک ہی wing کے اندر خانہ چھپانے** کا دروازہ ہے —
جیسے پہلے سے ملے ہوئے خانوں پر ہی "الگ کرنا" دکھانا۔

`attr` لکھیں تو ابھی کی قدر اسی خاصیت خانے سے سیدھا پڑھ کر رنگی جاتی ہے۔
`'toggle'` `token` سے `currentValue` کے جواب کا متن ملاتا ہے۔

## `styles` — wing کا اٹھایا ہوا CSS

```ts
styles: `
.nabi-content aside[data-nabi-note] {
  border-inline-start: 3px solid var(--nabi-accent);
  padding: .6rem .9rem;
  background: color-mix(in srgb, var(--nabi-accent) 8%, transparent);
}
`
```

چار قواعد ہیں۔

- **`.nabi-content` کے نیچے تک محدود رکھیں۔** میزبان کے صفحے کے دوسرے متن تک
  نہیں پھیلنا چاہیے۔
- **فونٹ کا سائز `rem` یا `em` میں** لکھیں۔
- **گہرا انداز صرف `.dark` کلاس سے** پکڑیں۔ media query سے پکڑیں تو میزبان کی
  روشن سکرین پر بھی صرف ایڈیٹر گہرا ہو جاتا ہے۔
- **چوڑا تنگ ہونا container query سے** ناپیں۔ معیار سکرین کی چوڑائی نہیں بلکہ
  ایڈیٹر جہاں کھڑا ہے اس جگہ کی چوڑائی ہے۔

صرف رجسٹر شدہ چاہیے تو خود جمع کر کے لگائیں۔

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const detach = injectSheets(document, collectSheets(registry))
```

ایک جیسے متن کی سٹائل شیٹ **صرف ایک بار** لگتی ہے — کئی wing ایک جیسا CSS بانٹ
کر لائیں تب بھی دستاویز میں صرف ایک بار چپکتی ہے۔ جواب ہٹانے والا فنکشن ہے، اور
**یہی call جو نیا لگایا وہی** ہٹاتا ہے۔

## صارف سے سوال پوچھنا

```ts
const { nabi, registry } = createNabiWith(wings, {
  ask: {
    message: (text) => window.alert(text),
    confirm: (text) => window.confirm(text),
  },
})
```

`confirm` `boolean` اور `Promise<boolean>` دونوں قبول کرتا ہے — براؤزر کا
`confirm` سیدھا جوڑا جا سکتا ہے، یا اپنا بنایا panel دکھا کر جواب بعد میں دیا
جا سکتا ہے۔

تیسرا خانہ، `choose`، **کئی میں سے ایک چننے** کا ہے — یہ دروازہ تب کھلتا ہے جب پیسٹ کے دو یا
زیادہ candidate ہوں۔

```ts
choose: (question, options) => user_callback(question, options),   // جواب ایک index ہے
```

جو فہرست ملتی ہے وہ `ChooseOption` کی صف ہے، جس میں دو خانے ہیں۔

| | |
|---|---|
| `label` | اس جگہ کا نام |
| `icon?` | 16×16 svg کا **اندر کا حصہ** (چند path)۔ panel خول خود لگاتا ہے، اور **نہ ہو تو صرف نام کھڑا ہوتا ہے** |

جواب **ایک index** ہے — `0` سب سے اوپر والا ہے، اور `-1` (یا حد سے باہر کچھ بھی) منسوخی ہے، جس
کی صورت میں کچھ پیسٹ نہیں ہوتا۔ `number` اور `Promise<number>` دونوں قبول ہیں۔

::: warning نہ دیں تو `confirm` کا جواب "نہیں" اور `choose` کا جواب سب سے اوپر والا ہے
`ask` نہ جوڑیں تو خاموش default لگ جاتا ہے۔ `message` کہیں نہیں جاتا اور
`confirm` کا جواب `false` آتا ہے۔ یہاں انتخاب یہ ہے کہ **سوال اور مٹانا خاموشی
سے نہ ہونا** اس سے بہتر ہے کہ **سوال کے بغیر خاموشی سے مٹ جانا۔** لوکل ہسٹری کا
"واقعی مٹا دیں؟" اسی دروازے سے گزرتا ہے۔

`choose` اکیلا الٹی سمت چلتا ہے — اس کا default **0 (سب سے اوپر والا)** ہے۔ یہاں منسوخی جواب
دینے سے پورا پیسٹ ہی غائب ہو جائے گا، اور فہرست کا پہلا candidate ہمیشہ "سب سے زیادہ ممکنہ
پڑھت" ہوتا ہے، اس لیے پوچھنے والا کوئی نہ ہو تب یہی صحیح جواب ہے۔ اور `choose` کو عام طور پر
جوڑنے کی ضرورت بھی نہیں پڑتی — ٹول بار کھڑا ہوتے ہی وہ اپنا panel خود کور پر لگا دیتا ہے۔
:::

::: tip command سوال نہیں پوچھ سکتا
command خالص فنکشن ہے، نہ سکرین جانتا ہے نہ وقت۔ سوال پوچھنا ہو تو command سے
باہر پوچھیں اور **جواب آنے کے بعد** command بلائیں۔ wing کے اندر اس کی جگہ
`attach` ہے، اور وہاں سے `host.nabi.$ask` تک پہنچا جاتا ہے۔
:::
