# بلاک اور پیراگراف کی خاصیت بنانا

جگہ لینے والی چیز کی تین قسمیں ہیں۔

| `place` | کیا | مثال |
|---|---|---|
| `'void'` | **بغیر اندرونی مواد کا جسم۔** کیریٹ اس کے اندر نہیں جا سکتا | افقی لکیر · تصویر · یوٹیوب |
| `'container'` | **اندر متن رکھنے والا جسم** | quote · تہہ بلاک · جدول · فہرست · کوڈ |
| `'attr'` | پیراگراف پر خود لگنے والی قدر۔ کوئی node کھڑا نہیں ہوتا | سرخی · سیدھ · ڈراپ کیپ |

---

## جسم wrapper پیراگراف کے اندر رہتا ہے

دستاویز **بلاکس کی صف** ہے، اور سب سے اوپر صرف پیراگراف (`p`) کھڑا ہو سکتا ہے۔
جسم سیدھا سب سے اوپر نہیں کھڑا ہوتا، بلکہ **صرف اسے تھامنے والا** ایک پیراگراف
پہن کر کھڑا ہوتا ہے۔

```json
[{ "w": "p", "ch": [{ "w": "hr", "ch": [] }] }]
```

یہ پیراگراف **wrapper پیراگراف** ہے، اور سکرین پر `<div data-nabi-p>` بن کر
کھینچا جاتا ہے۔

اس کی دو وجہیں ہیں۔ جسم کے آگے پیچھے کیریٹ کے لیے ہمیشہ جگہ موجود رہتی ہے (کیونکہ
ایک پیراگراف وہاں ہمیشہ موجود ہوتا ہے)، اور **سیدھ جیسی پیراگراف کی خاصیت جسم کو
جوں کی توں ملتی ہے** — "درمیان میں سیدھی کی گئی تصویر" دراصل "درمیان میں سیدھے
کیے گئے پیراگراف کے اندر تصویر" ہی ہے۔

---

## بغیر اندرونی مواد کا جسم بنانا

```ts
import { boxObject, createNabiWith, insertLump, type Command, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const insertStar: Command = (doc, sel, _args, env) => {
  const r = insertLump(doc, sel.focus, { w: 'star', ch: [] }, env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const starWing: Wing = {
  ...boxObject({
    w: 'star',
    toHtml: (_node, _children, ctx) => ctx.element('hr', '', { 'data-nabi-star': '' }),
  }),
  commands: { insertStar },
  button: {
    group: 'insert',
    label: { ur: 'ستارہ' },
    action: { kind: 'command', command: 'insertStar' },
  },
}
```

`insertLump` خود wrapper پیراگراف پہنا دیتا ہے۔

```
<div data-nabi-p><hr data-nabi-star/></div>
```

خالی پیراگراف پر بلائیں تو **وہی پیراگراف بدل جاتا ہے** — ہر بار ڈالنے پر ایک
خالی سطر پیچھے نہیں رہتی۔ اور وہ پیراگراف پہلے سے جو سیدھ لیے ہوئے تھا وہ ویسی
ہی رہتی ہے۔

`boxObject` جو بھرتا ہے وہ `place: 'void'` اور **خاصیت کا جانچنے والا** ہے۔

```ts
boxObject({
  w: 'stamp',
  attrs: { c: (v) => (v === 'red' || v === 'blue' ? v : null) },   // فہرست سے باہر کی قدر گر جاتی ہے
  requires: ['c'],                                                 // نہ ہو تو یہ جسم کھڑا نہیں ہوتا
  toHtml: /* … */,
})
```

`attrs` میں نہ لکھی گئی خاصیت **نامعلوم خانہ سمجھ کر مکمل گر جاتی ہے۔** معاہدے
سے باہر کی قدر محفوظ قدر میں چپکے سے چڑھ جانے کی کوئی جگہ نہیں ہے۔

## اندر مواد رکھنے والا جسم بنانا

`place: 'container'` کے ساتھ `holds` لکھنا لازم ہے — نہ لکھیں تو رجسٹریشن مر
جاتی ہے۔

```ts
import { createNabiWith, toggleWrap, type Command, type Wing } from 'nabi-note'

const toggleNote: Command = (doc, sel, _args, env) => {
  const r = toggleWrap(doc, sel, 'note', env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',                  // اندر پیراگراف رہتے ہیں ('inline' ہو تو صرف حروف)
  allows: ['p'],                    // یہاں اندر آ سکنے والی چیز
  toHtml: (_node, children, ctx) => ctx.element('aside', children(), { 'data-nabi-note': '' }),
  claim: (el, inner) => (el.tag === 'aside' ? [{ w: 'note', ch: inner(true) }] : null),
  commands: { toggleNote },
  inputRules: [{ trigger: 'space', pattern: /^!$/, run: () => ({ name: 'toggleNote' }) }],
  button: {
    group: 'container',
    label: { ur: 'نوٹ' },
    action: { kind: 'command', command: 'toggleNote' },
  },
}
```

`toggleWrap` ایک **toggle** ہے۔ انتخاب میں آنے والے سب سے اوپر کے بلاکس کو اس
ظرف میں لپیٹ دیتا ہے، اور اگر پہلے سے پورا لپٹا ہو تو اندر کا مواد اپنی جگہ کھول
دیتا ہے۔

```
لپیٹنے سے پہلے  [p"پہلی سطر", p"دوسری"]
لپیٹنے کے بعد   [p[ note[ p"پہلی سطر", p"دوسری" ] ]]
دوبارہ دبانے پر  [p"پہلی سطر", p"دوسری"]
```

### `holds`

| | اندر کیا رہتا ہے | مثال |
|---|---|---|
| `'blocks'` | پیراگراف اور دوسرے جسم | quote · تہہ بلاک · جدول کا خانہ |
| `'inline'` | صرف حروف اور mark | تہہ بلاک کی خلاصہ سطر · کوڈ |

### `allows`

لکھیں تو **اس کے سوا کچھ اندر نہیں آ سکتا۔** کور خود ایک صفائی کرنے والا جوڑ
دیتا ہے، پیسٹ ہو یا محفوظ قدر، فہرست سے باہر کی چیز کا خول اتار کر اندر کا متن
صرف پیراگراف بنا کر بیٹھا دیتا ہے۔

نہ لکھیں تو سب کی اجازت ہے۔ `allows` میں نامعلوم نام لکھیں تو **رجسٹر کرتے ہی
مر جاتا ہے۔**

---

## `parts` — بغیر بٹن کا اندرونی ڈھانچہ

جدول کی قطاریں و خانے، تہہ بلاک کی خلاصہ سطر جیسا ڈھانچہ جو **خود کھڑا نہیں ہو
سکتا اور ٹول بار میں بٹن بھی نہیں رکھتا** اسے parts کے طور پر اعلان کیا جاتا ہے۔

```ts
const detailsWing: Wing = {
  w: 'details',
  place: 'container',
  holds: 'blocks',
  boolAttrs: ['o'],                                   // صرف 1 قدر والی خاصیت — کھلی ہے یا نہیں
  parts: { summary: { holds: 'inline' } },            // خلاصہ سطر
  toHtml: /* … */,
  partHtml: { summary: /* … */ },                     // ہر part کا اپنا جوڑنے کا طریقہ ہونا لازم
  repair: repairDetails,
}
```

چار قواعد ہیں۔

- parts صرف **container** پر ہوتے ہیں۔ کسی اور `place` پر لکھیں تو رجسٹریشن مر
  جاتی ہے۔
- ہر part کا `partHtml` ہونا لازم ہے۔ نہ ہو تو رجسٹریشن مر جاتی ہے۔
- part کا نام کسی wing کے نام یا دوسرے part کے نام سے نہیں ٹکرا سکتا۔
- کسی part کو سنوارنا ہو تو `partRepair` میں اس part کے نام سے لکھیں۔

`StructureDecl` تین چیزیں لیتا ہے — `holds` · `singleParagraph` · `boolAttrs`۔

### `singleParagraph`

اندر **صرف ایک پیراگراف تک محدود** ہو جاتا ہے۔ جدول کا خانہ یہی ہے — خانے کے
اندر <kbd>Enter</kbd> دبائیں تو پیراگراف دو حصوں میں نہیں بٹتا، اور دو خانوں پر
پھیلا انتخاب مٹائیں تو خانے آپس میں نہیں ملتے۔ grid کی حفاظت اسی ایک خانے سے
ہوتی ہے۔

### `boolAttrs`

صرف `1` قدر والی خاصیات — تہہ بلاک کا `o` (کھلا ہونا)، to-do فہرست کا `ck`
(چیک ہونا)، پیراگراف کا `dc` (ڈراپ کیپ)۔ بند حالت `0` نہیں بلکہ **خانہ سرے سے
موجود ہی نہ ہونا** ہے۔

## `repair` — محفوظ قدر کے داخلے کا آخری دروازہ

`repair` **JSON کے دستاویز بننے سے عین پہلے** اس node کو ایک بار سنوارتا ہے۔

```ts
repair: (node) => {
  if (!درست(node)) return null    // null — یہ node خول سمیت ہٹ جاتا ہے
  return سنوارا_گیا_node           // ویسا ہی رہنے دیا جا سکتا ہے (وہی آبجیکٹ جواب دیں تو کچھ نہیں بدلتا)
}
```

ہاتھ سے بدلی گئی محفوظ قدر، کسی دوسرے ورژن سے آئی دستاویز، کسی اور کا بنایا
JSON — سب اسی دروازے سے گزرتے ہیں۔ جو یہاں سے گزرے وہی دستاویز بنتا ہے، اس لیے
یہ **وہ واحد جگہ ہے جہاں wing خود اپنے node کی شکل کی ضمانت دے سکتی ہے۔**

`allows` اور `repair` ساتھ لکھیں تو `allows` کی صفائی **پہلے** چلتی ہے اور اس کا
نتیجہ `repair` تک پہنچتا ہے۔

---

## `requiresAnyOf` — ساتھی کے بغیر نہ کھڑی ہونے والی wing

```ts
requiresAnyOf: ['img', 'a']
```

اگر ان میں سے ایک بھی ساتھ رجسٹر نہ ہو تو **رجسٹر کرتے ہی مر جاتا ہے۔** اپ لوڈ
wing یہی استعمال کرتی ہے — چڑھایا گیا مواد تصویر یا لنک بن کر کھڑا ہونا چاہیے،
دونوں غائب ہوں تو چڑھا کر بھی کچھ کیا نہیں جا سکتا۔

---

## پیراگراف کی خاصیت (`place: 'attr'`)

پیراگراف کی خاصیت کوئی node کھڑا نہیں کرتی۔ صرف پیراگراف کے `a` میں ایک قدر
رکھ دیتی ہے۔

```json
{ "w": "p", "a": { "h": 2, "a": "c" }, "ch": ["درمیان میں سیدھی کی گئی سرخی 2"] }
```

::: warning خانے صرف تین پر بند ہیں
`attrKey` صرف تین میں سے ایک ہونا چاہیے: **`h` (سرخی) · `a` (سیدھ) · `dc`
(ڈراپ کیپ)** — اس سے باہر کوئی نام لکھیں تو رجسٹریشن مر جاتی ہے۔ ابھی کے ورژن
میں **نئی پیراگراف کی خاصیت نہیں بنائی جا سکتی** — پیراگراف کا خاصیت خانہ کور کی
جانی ہوئی انہی تین چیزوں پر بند ہے۔

اسی وجہ سے یہ تین پہلے سے `headingWing`·`alignWing`·`dropCapWing` کے پاس ہیں،
اس لیے `place: 'attr'` والی نئی wing لکھنے کی عملاً کوئی جگہ نہیں بچتی۔ ہر
پیراگراف پر قدر لگانا چاہتے ہیں تو ابھی container میں لپیٹنے کا راستہ چنیں۔
:::

قدر سنبھالنے والے دو خانے ہیں۔

| | |
|---|---|
| `attrValues` | قبول کی جانے والی قدروں کی فہرست (سرخی کے لیے `[1,2,3,4,5,6]`) |
| `currentValue` | یہ پیراگراف ابھی جو قدر رکھتا ہے۔ ٹول بار اور سیاق سطر اسی جواب سے دبے ہوئے خانے کو رنگتے ہیں |

## عوامی دستاویز مدد گار

ابھی کا ورژن باہر چار ترمیمی مدد گار نکالتا ہے۔

| | کام |
|---|---|
| `insertLump(doc, caret, lump, env, wrap?)` | ایک جسم کو اس کے wrapper پیراگراف کے ساتھ کھڑا کرتا ہے |
| `removeLump(doc, topIndex, env)` | سب سے اوپر کا ایک wrapper پیراگراف مکمل ہٹا دیتا ہے |
| `toggleWrap(doc, sel, containerW, env)` | انتخاب میں آنے والے بلاکس کو ظرف میں لپیٹتا یا کھولتا ہے |
| `topNodeAt(doc, path)` | یہ راستہ جس سب سے اوپر کے node سے تعلق رکھتا ہے |

چاروں `{ doc, caret }` جواب دیتے ہیں، اس لیے command کے جواب کی شکل میں ایک بار
منتقل کیا جاتا ہے۔

```ts
return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
```

::: tip اس سے باریک ترمیم چاہیے ہو تو
حرف کی سطح پر کاٹنے جوڑنے والے اندرونی مدد گار (mark لگانا، پیراگراف کی خاصیت
لکھنا وغیرہ) ابھی عوامی API نہیں ہیں۔ اس وقت تک `doc` صف خود نئے سرے سے بنا کر
جواب دی جا سکتی ہے — جواب میں دی گئی دستاویز کو `cocoon` ایک بار مزید سنوارتا
ہے، اس لیے قاعدہ توڑنے والی دستاویز باقی نہیں رہتی۔
:::
