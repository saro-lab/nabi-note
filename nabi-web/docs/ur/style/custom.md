# انداز بدلنا

سٹائل شیٹ **میزبان لگاتا ہے** — bundler استعمال کریں تو `import 'nabi-note/nabi.css'`
ایک سطر، CDN ہو تو `<link>` ایک سطر۔ اس کے بعد صرف متغیرات کو اوپر لکھنا ہوتا ہے۔

کمپونینٹ کے قواعد میں **ایک بھی رنگ لفظی (literal) نہیں ہے۔** سب کچھ `--nabi-*`
متغیرات سے کھینچا گیا ہے، اس لیے متغیرات اوپر لکھیں تو باقی خود بخود ساتھ آ جاتا
ہے۔

```css
.nabi.nabi.nabi {
  --nabi-accent: #7c3aed;
}
```

کلاس کو تین بار دہرانے کی وجہ نیچے [مخصوصیت میں نہ پھنسنا](#مخصوصیت-میں-نہ-پھنسنا)
میں ہے۔

::: tip اس دستاویز کی بڑی بنیاد — محفوظ شدہ قدر تنہا نہیں کھڑی ہوتی
باہر جانے والے HTML (`getHtml()`) میں **ایک بھی inline `style` نہیں ہوتا۔** محفوظ
شدہ قدر صرف *کیا* بتاتی ہے خاصیت کے ذریعے (`data-nabi-align="center"`)، اور *کیسا
دکھتا ہے* یہ سٹائل شیٹ بتاتی ہے۔ اسی لیے محفوظ HTML جب پڑھنے والا کہیں اور کھینچے
تب بھی اسے **اسی سٹائل شیٹ والے `.nabi-content` کے اندر** ہونا چاہیے تاکہ ایڈیٹر
جیسا ہی نظر آئے — نیچے [محفوظ شدہ HTML باہر کھینچتے وقت](#محفوظ-شدہ-html-باہر-کھینچتے-وقت)
دیکھیں۔
:::

::: tip گہرا اور روشن انداز پہلے سے موجود ہیں
theme کے لیے میزبان کو اوپر لکھنے والا کوئی ٹوکن **نہیں ہے۔** بنیادی سٹائل شیٹ
روشن default، `.dark` کی نئی تعریف اور واضح `.light` کی نئی تعریف — تینوں ساتھ لے
کر آتی ہے۔ یہ سائٹ بھی ایڈیٹر کے اندر فونٹ کے چار ٹوکن کے سوا کچھ اور اوپر نہیں
لکھتی۔
:::

## رنگ اور شکل کے ٹوکن

| ٹوکن | معنی | default (روشن) |
|---|---|---|
| `--nabi-bg` · `--nabi-soft` | پس منظر · تھوڑی دبی سطح | `#fff` · `rgb(0 0 0 / 4.5%)` |
| `--nabi-fg` · `--nabi-muted` · `--nabi-on-accent` | متن · مدھم متن · اہم رنگ پر متن | `#1b1b1f` · `#6b6b76` · `#fff` |
| `--nabi-line` · `--nabi-accent` | لکیر · اہم رنگ | `#e2e2e8` · `#3b6fe0` |
| `--nabi-danger` · `--nabi-on-danger` | خطرہ · اس پر متن | `#d93b3b` · `#fff` |
| `--nabi-shadow` · `--nabi-scrim` | ڈبے کا سایہ · پیش نظارے کا پس منظر | — |
| `--nabi-radius` · `--nabi-radius-sm` · `--nabi-radius-xs` | کونے | `6px` · `4px` · `3px` |
| `--nabi-layer-radius` | تہہ (panel، پیش نظارہ، lightbox) کا کونا | `.25rem` |
| `--nabi-z-sticky` | چپکنے والی سطر کا تہہ نمبر | `20` |
| `--nabi-grid-cell` | جدول کا سائز طے کرنے والے grid کے خانے کا سائز | `1.125rem` |
| `--nabi-hl-yellow`·`green`·`cyan`·`pink`·`purple`·`orange` | ہائی لائٹ کے چھ رنگ | نیم شفاف رنگ |
| `--nabi-tc-green`·`coral`·`violet`·`amber`·`blue` | متن کے پانچ رنگ | گہرے رنگ |

اس جدول میں صرف وہ شامل ہے جو بنیادی سٹائل شیٹ (`nabi.css`) **خود اعلان** کرتی ہے۔
اعلان کی جگہ صرف `.nabi` نہیں بلکہ تین ہیں —
`:is(.nabi, .nabi-scrim, .nabi-content:where(:not(.nabi *)))`۔ کیونکہ پیش نظارے
کی تہہ `body` کی اولاد ہوتی ہے اس لیے `.nabi` سے وراثت نہیں پہنچتی، اور ایڈیٹر سے
باہر تنہا کھڑے `.nabi-content` کو بھی ٹوکن براہِ راست ملنا چاہیے۔

وہی فہرست تین بار لکھی گئی ہے (روشن default · `.dark` · واضح `.light`)۔ **اوپر
لکھنے والے کو تینوں دیکھنے کی ضرورت نہیں** — صرف مخصوصیت (specificity) میں جیت
جائیں تو ایک بار اوپر لکھی قدر تینوں صورتوں پر لگتی ہے۔ لیکن گہرے انداز میں الگ
قدر چاہیے تو `.dark` شرط خود لگانا ہوگا۔

## بغیر اعلان صرف حوالہ دیے جانے والے ٹوکن

نیچے وہ متغیرات ہیں جنہیں کور **اعلان نہیں کرتا، صرف حوالہ دیتا ہے۔** میزبان قدر
نہ دے تو قوس کے اندر والا fallback کام کرتا ہے۔ اعلان کی کوئی جگہ نہ ہونے کی وجہ
سے **`:root` میں لکھنے سے ہی کام چل جاتا ہے** — اوپر کے رنگ و شکل کے ٹوکن سے یہی
فرق ہے (وہ `.nabi` میں اعلان شدہ ہیں، اس لیے وراثت انہیں نہیں ہرا سکتی)۔

| ٹوکن | معنی | fallback |
|---|---|---|
| `--nabi-font` · `--nabi-font-serif` · `--nabi-font-mono` · `--nabi-font-cursive` | typeface wing کی چار قسموں کو حقیقت میں ملنے والا فونٹ | نظام کا فونٹ |
| `--nabi-cursive-adjust` | ہاتھ کی تحریر کی طرز کا `font-size-adjust`۔ ہاتھ کی تحریر جیسے فونٹ کی x-height کم ہوتی ہے، اس لیے وہی px پر بھی چھوٹا لگتا ہے، یہ قدر x-height کی بنیاد پر دوبارہ ناپتی ہے | `0.4` |
| `--nabi-sticky-top` | چپکنے والی سطر کتنا نیچے آ کر بیٹھے۔ سائٹ پر مقررہ ہیڈر ہو تو اس کی اونچائی | `0px` |
| `--nabi-preview-width` | پیش نظارے کے کارڈ کی چوڑائی۔ **چونکہ `openPreview` کھلتے وقت ترمیمی حصے کی چوڑائی ناپ کر کارڈ پر خود لکھ دیتا ہے،** میزبان باہر سے اوپر لکھے تب بھی وہ inline قدر جیت جاتی ہے | `720px` |

`--nabi-typeface-base` اس گروہ میں نہیں — **کور خود اسے اعلان کرتا ہے** (default
`--nabi-font` کی پیروی کرتا ہے)۔ typeface wing میں یہ قدر طے کرنے کا آپشن نہیں،
اسے بدلنا ہو تو یہی ٹوکن اوپر لکھیں۔

`--nabi-keyboard-top` · `--nabi-keyboard-bottom` بھی اسی جگہ کھڑے ہوتے ہیں مگر
انہیں **کور خود لکھتا ہے** — `mountSticky()` موبائل کی بورڈ نے سکرین کو جتنا
دھکیلا اسے ناپ کر یہاں لکھتا ہے، اور چپکنے والی سطر اور مکمل سکرین وہی قدر پڑھتے
ہیں۔ یہ ہاتھ سے لکھنے کی قدر نہیں ہے۔

## جہاں ٹوکن نہیں — قاعدہ خود اوپر لکھیں

نیچے کے تین کے **کوئی متغیر نہیں۔** کور نے قاعدے میں قدر خود ٹھونک دی ہے، اسے
بدلنا ہو تو وہ selector خود اوپر لکھیں۔

**متن کے سائز کے چار درجے** — `em` میں ہیں، اس لیے parent کے سائز کی پیروی کرتے
ہیں۔

```css
.nabi-content [data-nabi-size="xs"] { font-size: .75em; }
.nabi-content [data-nabi-size="sm"] { font-size: .875em; }
.nabi-content [data-nabi-size="lg"] { font-size: 1.25em; }
.nabi-content [data-nabi-size="xl"] { font-size: 1.5em; }
```

**ڈراپ کیپ کا سائز** — یہ کتنی سطریں گھیرے گا اس کی قدر نہیں بلکہ صرف ایک حرف کا
سائز ہے۔ حقیقت میں کتنی سطریں ڈھکے گا یہ اُس پیراگراف کی line height طے کرتی ہے۔

```css
.nabi-content [data-nabi-dropcap="1"]::first-letter { font-size: 5.9em; line-height: .83; }
```

**کوڈ ٹوکن کا رنگ** — کوڈ wing کی سٹائل شیٹ `[data-nabi-token]` پر رنگ خود لکھتی
ہے۔ ابھی رنگ ملنے والی قسمیں **پانچ** ہیں۔

```css
.nabi-content [data-nabi-token="comment"] { color: #7a8a7a; font-style: italic; }
.nabi-content [data-nabi-token="string"] { color: #a2543a; }
.nabi-content [data-nabi-token="keyword"] { color: #7b4fd0; }
.nabi-content [data-nabi-token="number"] { color: #2f6fd0; }
.nabi-content [data-nabi-token="literal"] { color: #2f8f4e; }
```

رنگ کرنے والا (highlighter) جو `type` جواب دیتا ہے وہ آزاد متن ہے — اگر اوپر کی
پانچ سے باہر کا نام آئے تو بے رنگ رہ جاتا ہے، مزید قسم چاہیے ہو تو میزبان اسی
شکل میں قاعدہ خود بنا لے۔ گہرے انداز میں مختلف رنگ چاہیے تو `.dark` شرط خود
لگائیں — کور ان پانچ کے لیے گہرا ورژن نہیں دیتا۔

اپ لوڈ wing کی پیش رفت کی animation (`--nabi-per`·`--nabi-t`·`--nabi-span`·
`--nabi-clear`·`--nabi-blur-max`) **wing کے اندرونی استعمال کے لیے ہیں** — نام
`--nabi-` سے شروع ہوتا ہے مگر یہ میزبان کے اوپر لکھنے کے لیے کھلی جگہ نہیں ہے۔

## باہر کی پیمائش `rem` میں ہے

بٹن، فاصلہ، ٹول بار چپ سمیت باہر کی زیادہ تر پیمائش `rem` میں ہے، اس لیے **root
(`html`) کے فونٹ سائز کے مطابق بڑھتی ہے۔** صارف براؤزر یا OS سے فونٹ بڑھائے تو
ایڈیٹر کا فریم بھی ساتھ بڑا ہو جاتا ہے۔ سائز بدلنا ہو تو root کا `font-size`
بدلیں۔ لکیر (`border`) پیمائش نہیں بلکہ **لکیر** ہے، اس لیے کہیں کہیں `px` میں ہی
رہ گئی ہے۔

## مخصوصیت میں نہ پھنسنا

رنگ اور شکل کے ٹوکن اوپر لکھنے کے لیے **تین کلاسیں** اکٹھی لگائیں۔

```css
.nabi.nabi.nabi,
.nabi-scrim.nabi-scrim.nabi-scrim {
  --nabi-accent: var(--میرا-اہم-رنگ);
}
```

شمار یوں ہے: روشن default قاعدہ `:is(.nabi, …)` **(0,1,0)** ہے کیونکہ `:is()`
اپنے دلائل میں سے سب سے زیادہ کی پیروی کرتا ہے، اور گہرے انداز کا قاعدہ
`:where(html, body).dark :is(.nabi, …)` **(0,2,0)** ہے کیونکہ `:where()` صفر ہے
جبکہ `.dark` اور `:is()` ہر ایک ایک کلاس کے برابر ہیں۔ اس لیے `.nabi.nabi` سے
گہرے انداز کے ساتھ **برابر** رہ جاتا ہے — برابری میں جو بعد میں لوڈ ہو وہ جیتتا
ہے، اور بنیادی سٹائل شیٹ میزبان کی سٹائل شیٹ کے بعد بھی لوڈ ہو سکتی ہے۔ تین بار
دہرا کر (0,3,0) تک لے جائیں تو ترتیب پر انحصار نہیں رہتا۔

پیش نظارے کی تہہ `.nabi` سے باہر (`body` کی اولاد) کھڑی ہوتی ہے، اس لیے وہاں بھی
یہی رنگ چاہیے تو اُس selector کو بھی ساتھ لکھیں۔

**فونٹ جیسے ٹوکن جنہیں کور اعلان نہیں کرتا انہیں یہ کشمکش نہیں چاہیے** — اعلان
کی جگہ نہ ہونے کی وجہ سے صرف وراثت سے پہنچ جاتے ہیں، `:root` کی ایک سطر کافی ہے۔

```css
:root {
  --nabi-font: 'Noto Sans', system-ui, sans-serif;
}
```

## روشن · گہرا

`html` یا `body` **دو میں سے کسی ایک** پر `dark` کلاس ہو تو گہرا انداز، `light`
ہو تو روشن۔ کلاس نہ ہو تو روشن default ہے، دونوں ساتھ ہوں تو واضح `light` جیتتا
ہے (`.light` قاعدہ `.dark` قاعدے کے بعد لوڈ ہوتا ہے)۔

```html
<html class="dark"><!-- یا <body class="dark"> --></html>
```

کلاس toggle کریں تو CSS خود جواب دیتا ہے۔ بلانے کے لیے کوئی API نہیں۔ theme صرف
رنگ کے متغیرات بدلتا ہے، کمپونینٹ کے قواعد ویسے ہی رہتے ہیں — خود بنائے ہوئے
انداز بھی صرف `--nabi-*` متغیرات استعمال کریں تو گہرے انداز کی پیروی کرتے ہیں۔

## سٹائل شیٹ لگانے کے دو راستے

**① ایک فائل** — سب سے عام راستہ۔ اس میں تمام wing کا CSS شامل ہے۔

```ts
import 'nabi-note/nabi.css'
```

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note/dist/nabi.css">
```

**② صرف رجسٹر شدہ کا انجیکشن** — جب صرف اصل میں آن کی گئی wing کا CSS چاہیے۔

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const drop = injectSheets(document, collectSheets(registry))
// drop() بلانے سے صرف یہی call کیا ہوا حصہ ہٹتا ہے
```

ایک جیسے متن کی سٹائل شیٹ **صرف ایک بار** اندر جاتی ہے — یکجا کرنے کی کلید سٹائل
شیٹ کا **مواد** ہے، اس لیے ایک دستاویز میں کئی ایڈیٹر کھڑے کریں تو بھی نہیں
ڈھیر ہوتی، اور مختلف wing کی ترکیبیں مل جائیں تو بھی ایک ہی مجموعے میں جمع ہو
جاتی ہیں۔

::: tip دونوں میں دو فرق — کیا لے جاتا ہے، اور کب لگتا ہے
**کیا لے جاتا ہے۔** فائل کو معلوم نہیں کہ کون سی wing رجسٹر ہوئی، اس لیے **سب** لے
جاتی ہے۔ انجیکشن `registry` دیکھ کر **صرف رجسٹر شدہ** لے جاتا ہے۔ جو صفحہ صرف محفوظ
HTML دکھاتا ہے اس میں ایڈیٹر نہیں ہوتا، اس لیے `registry` بھی نہیں ہوتا — وہاں فائل
والا راستہ استعمال ہوتا ہے۔

**کب لگتا ہے۔** فائل `<link>` کے ذریعے سر (head) میں آتی ہے اور رینڈر ہونے سے **پہلے
روکتی** ہے، لیکن انجیکشن ایڈیٹر کا جاوا اسکرپٹ **پہنچنے کے بعد ہی** لگتا ہے۔ اس لیے جو
صفحہ دستاویز کو سرور پر پہلے سے کھینچ کر بھیجتا ہے اسے فائل والا راستہ اپنانا چاہیے —
انجیکشن سے سرور کا بھیجا دستاویز پہلے ننگا رینڈر ہوتا ہے اور پھر سٹائل لگنے سے ترتیب
دوبارہ جمتی ہے۔
:::

رجسٹر شدہ wing کی سٹائل شیٹ بنیادی سٹائل شیٹ کے **بعد** آتی ہے، اس لیے یکساں
ترجیح میں wing جیتتی ہے۔

## چپکائی جانے والی جگہیں

جو متغیر سے نہیں ہو سکتا وہ حقیقت میں موجود کلاس کو براہِ راست نشانہ بناتا ہے۔

| selector | کیا | کون لگاتا ہے |
|---|---|---|
| `.nabi` | پورے ایڈیٹر (chrome + ترمیمی حصہ) کو لپیٹنے والا خول۔ رنگ اور شکل کے ٹوکن یہاں لگتے ہیں | میزبان |
| `.nabi-content[contenteditable]` | ترمیمی حصہ خود | میزبان |

| selector | کیا | کون |
|---|---|---|

| `.nabi-scrim` > `.nabi-card.nabi-lightbox` | ایک تصویر بڑی دیکھنے کا ڈبہ | `openImageLightbox()` |

`mountViewTools()` لگا لیں تو دونوں بٹن خود انہیں کھولتے اور بند کرتے ہیں۔ خود
کھولنا ہو تو `openPreview({ nabi, editor })` · `openImageLightbox({ editor, src,
alt?, locale })` · `setFullscreen(root, on)` · `isFullscreen(root)` بلائیں۔

::: tip آلات کی جگہ خود کھڑی ہو جاتی ہے
`mountViewTools` خود `.nabi-tools` ڈبہ بنا کر ملنے والے ظرف کے شروع میں ڈال دیتا
ہے۔ میزبان کو `<span>` ٹول بار سے پہلے رکھنے کی ضرورت نہیں — پہلے سے جگہ بنا کر
رکھیں تو دو ڈبے بن جاتے ہیں۔
:::

ترمیمی سکرین کے مخصوص نشان بھی نشانہ بنائے جا سکتے ہیں — `[data-nabi-token]`
(کوڈ بلاک کے ٹوکن کا رنگ)، `[data-nabi-lang]` (کوڈ بلاک کی زبان)، `[data-color]`
(ہائی لائٹ اور متن کا رنگ — `<mark>`·`<span>` ٹیگ سے پہچانا جاتا ہے)،
`data-nabi-align`·`data-nabi-typeface`·`data-nabi-size`·`data-nabi-dropcap`
(پیراگراف کی خاصیت)۔ ان نشانوں کے اصلی نام ہر wing فائل کے `*_ATTR` کانسٹنٹ میں
اصل ہیں۔

## محفوظ شدہ HTML باہر کھینچتے وقت

باہر جانے والی قدر (`getHtml()`) `data-nabi-*` خاصیات والا HTML ہے، اور **اس
میں ایک بھی inline `style` نہیں ہے۔** یعنی شکل مکمل طور پر سٹائل شیٹ کی ذمہ داری
ہے، اس لیے بغیر سٹائل شیٹ کے کھینچیں تو نہ سیدھ نہ فونٹ سائز نہ جدول کی لکیریں —
ننگا HTML نکلتا ہے۔

ایڈیٹر جیسا ہی دکھانا ہو تو `.nabi-content` سے لپیٹیں — یہ کلاس `.nabi` میں
لپٹے بغیر بھی رنگ اور شکل کے ٹوکن براہِ راست پاتی ہے (`nabi.css` کا
`.nabi-content:where(:not(.nabi *))` قاعدہ)۔

```html
<div class="nabi-content">محفوظ شدہ HTML</div>
```

سٹائل شیٹ اوپر کے «سٹائل شیٹ لگانے کے دو راستے» میں جیسے دکھایا گیا ہے ویسے ہی
لگائیں — bundler ہو تو `import 'nabi-note/nabi.css'`، ورنہ ایک `<link>`۔ جس صفحے
میں ایڈیٹر نہ بھی ہو، صرف `.nabi-content` موجود ہو تو بنیادی سٹائل شیٹ ٹوکن اعلان
کر دیتی ہے۔

### پڑھنے والی طرف چلنے والا عمل — جدول کی ترتیب

ابھی **صرف جدول کی ترتیب (sort)** پڑھنے والی طرف کے مخصوص فنکشن کے طور پر ملتی
ہے۔ من مانی wing کو پڑھنے والا اپنا عمل جوڑ سکے ایسا عام نظام ابھی نہیں ہے۔

```ts
import { attachTableSort } from 'nabi-note/viewer'

const detach = attachTableSort(document.querySelector('#article')!, { locale: 'ur' })
```

`data-nabi-sortable` والے جدول ڈھونڈ کر عنوان کے خانے میں ترتیب کا بٹن لگاتا ہے۔
واپسی فنکشن (`detach`) لگائے گئے بٹن اور بدلی گئی قطاروں کی ترتیب واپس کر دیتا
ہے۔

::: danger ترمیم کے لیے کھلے عنصر پر نہ لگائیں
`attachTableSort()` DOM میں بٹن ڈالتا ہے اور قطاروں کی ترتیب بدلتا ہے۔ اگر اس
لگے ہونے کے دوران کا DOM محفوظ کر لیا تو وہی تبدیلی قدر میں جم جائے گی — صرف
پڑھنے کے لیے بنی نقل پر لگائیں۔
:::
