## یہ سب کیا ہوا

اوپر دی گئی فائل بغیر کچھ پڑھے بھی چلتی ہے۔ صرف اسے بدلنا ہو تو ذیل دیکھیں۔

### دو ٹیگ ہی نصب کرنا ہیں

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/nabi.css">
<script src="https://cdn.jsdelivr.net/npm/nabi-note@latest"></script>
```

پیکج جو **کچھ بھی** ایکسپورٹ کرتا ہے وہ سب ایک عالمی (global) `NabiNote` پر ٹکا ہوتا
ہے۔ **سٹائل شیٹ آپ خود لگاتے ہیں** — mount CSS خود نہیں ڈالتا، اس لیے `<link>` بھول
گئے تو ایڈیٹر ننگا نظر آئے گا۔

### ڈھانچہ

```html
<div id="app" class="nabi">                    <!-- رنگ، کونے، فونٹ اسی جڑ میں رہتے ہیں -->
  <div id="chrome" class="nabi-toolbar">        <!-- ٹول بار اور سیاق سطر ایک ساتھ لگتے ہیں -->
    <div class="nabi-toolbar-row">
      <span id="tools"></span>                 <!-- پیش نظارہ، مکمل سکرین (آخری کنارے پر) -->
      <div id="toolbar"></div>
    </div>
    <div id="context"></div>                   <!-- کیریٹ جس چیز پر ہے اس کے حساب سے خود بھر جاتا ہے -->
  </div>
  <div id="editor" class="nabi-content" contenteditable="true"></div>
</div>
```

`id` کوئی بھی نام ہو سکتا ہے — mount کو جو دیا جاتا ہے وہ **ایلیمنٹ** ہے، نام نہیں۔
چار کلاسیں (`nabi`، `nabi-toolbar`، `nabi-toolbar-row`، `nabi-content`) وہ ہینڈل
ہیں جن کو سٹائل شیٹ پکڑتی ہے، انہیں ویسے ہی رہنے دیں۔ اگر پیش نظارہ اور مکمل سکرین
نہیں چاہیے تو `<span id="tools">` اور `mountViewTools` والی سطر ساتھ ہٹا دیں —
**مگر اسے ٹول بار کے اندر نہ رکھیں۔** یہ جگہ دائیں طرف تیرنے کے لیے ہے، بٹنوں کے
درمیان آ جائے تو قطار بگڑ جاتی ہے۔

### wing چننا

wing چننا ایک ہی builder لائن سے ہوتا ہے۔ اوپر والی فائل انتیس معیاری wing سے شروع ہو کر
اپ لوڈ ہٹاتی ہے، پھر ٹائپ فیس کو دو تک محدود کرتی ہے۔

```js
var wings = N.wings().all().drop('upload').use('tf', { values: ['sans', 'serif'] })
```

- `all()` تمام سرکاری wing سے شروع کرتا ہے۔ **نہ بلائیں تو خالی ہاتھ شروع ہوتا ہے** — صرف
  `use()` سے شامل کی گئی چیز لوڈ ہوتی ہے۔
- `use('نام', آپشن؟)` ایک چیز شامل کرتا ہے۔ جو wing پہلے سے شامل ہو اسے دوبارہ بلائیں تو
  صرف آپشن جڑ جاتے ہیں — اوپر کا `use('tf', { values: [...] })` اسی شکل کا ہے۔ اگر کسی wing
  کو کھڑا ہونے کے لیے دوسری wing درکار ہو (اپ لوڈ کو تصویر یا لنک میں سے ایک چاہیے) تو وہ
  خود بخود ساتھ آ جاتی ہے۔
- `drop('نام')` پہلے سے شامل کوئی چیز ہٹاتا ہے۔ جس wing پر کوئی دوسری wing کھڑی ہو اسے ہٹانے
  کی کوشش کریں تو وہیں پھینک دیتا ہے اور ساتھ کیا ہٹانا ہے بتا دیتا ہے۔
- نام وہ مختصر کلید ہے جو محفوظ قدر میں لکھی جاتی ہے — جیسے `b` (جلی)، `tf` (ٹائپ فیس)،
  `upload`۔ پوری فہرست `console.log(N.wingNames())` سے دیکھیں۔
- **غلط کال اسی سطر پر پھینکتی ہے جس نے کی۔** غلط ہجے والا نام، ناواقف آپشن کلید، فہرست سے
  باہر کی قدر — سب اسی طرح، اور جو پیغام پھینکا جاتا ہے اس میں حل بھی ہوتا ہے — `use('bod')`
  جواب دیتا ہے "کیا آپ کا مطلب 'b' (جلی) تھا؟"۔ کہیں بھی خاموشی سے نظر انداز نہیں ہوتا۔

`createNabiWith` builder کو جوں کا توں لے لیتا ہے، اس لیے `build()` بلانے کی ضرورت نہیں —
یہ صرف وہاں لگتا ہے جہاں array درکار ہو۔ چند wing ہاتھ سے چننی ہوں تو array اب بھی جواب ہے۔

```js
var wings = [N.boldWing, N.italicWing, N.headingWing, N.bulletListWing]
```

خود بنائی گئی wing ایک آبجیکٹ کے طور پر جاتی ہے — جیسے `N.wings().all().use(customWing)`۔
اس کا `w` لازمی طور پر `ex` سے شروع ہونا چاہیے (`exNote`) — کیونکہ بعد میں کسی سرکاری نام
سے محفوظ قدر میں ٹکراؤ ہو تو پہلے سے محفوظ دستاویز کسی اور معنی میں پڑھی جانے لگے گی۔ بنانے
کا طریقہ [{{ t('menu_wing_custom') }}](../wing/custom) میں ہے۔

ہر wing الگ سے [{{ t('menu_wing') }}](../wing/inline/bold) میں دیکھیں۔

### پوچھنے اور بتانے کا راستہ

اوپر والی فائل نے `ask` کو براؤزر کے `alert`·`confirm` سے جوڑا ہے — "غیر محفوظ کام موجود
ہے۔ پھر بھی کھولیں؟" جیسا سوال اسی ڈبے میں جاتا ہے۔ نہ جوڑیں تو ہر سوال کا جواب "نہیں" ہوتا
ہے، اور جس ایک سطر کو جواب کی ضرورت نہ ہو وہ کور کے اپنے toast ٹرے میں ٹول بار کے نیچے نظر
آتی ہے — اپ لوڈ کی خرابی جیسی اطلاع کو الگ سے جوڑنے کی ضرورت نہیں۔ مزید تفصیل
[{{ t('menu_intro_usage') }}](./usage) میں ہے۔

### قدر نکالنا

| | |
|---|---|
| `nabi.getHtml()` | محفوظ کرنے اور شائع کرنے کے لیے HTML |
| `nabi.getJson()` | nabi-tree (JSON) |
| `nabi.setHtml(html)` · `nabi.setJson(json)` | دوبارہ ڈالنا |
| `nabi.onChange(fn)` | جب بھی قدر بدلے |
| `N.renderStoredHtml(json, registry)` | محفوظ شدہ دستاویز کو ایڈیٹر کے بغیر HTML میں بدلنا (نیچے [پڑھنے والی سکرین](#پڑھنے-والی-سکرین) دیکھیں) |

## پتہ (address)

ورژن کو مقفل رکھنے کے لیے پتے میں ورژن نمبر لگائیں۔ unpkg بھی وہی فائل دیتا ہے۔

**ورژن نمبر کے بغیر پتہ (`/npm/nabi-note`) استعمال نہ کریں** — jsDelivr اس جگہ کو
دیر تک cache کرتا ہے، اس لیے bundle اور سٹائل شیٹ دو مختلف ورژن کے مل سکتے ہیں۔

| | پتہ |
|---|---|
| **bundle (تازہ ترین)** | `https://cdn.jsdelivr.net/npm/nabi-note@latest` |
| **bundle (مقفل)** | <code>{{ CDN_BUNDLE }}</code> |
| **سٹائل شیٹ (تازہ ترین)** | `https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/nabi.css` |
| **سٹائل شیٹ (مقفل)** | <code>{{ CDN_SHEET }}</code> |
| **bundle** (unpkg) | `https://unpkg.com/nabi-note` |

bundle npm کے پیکج کے ساتھ ہی نکلتا ہے، اس لیے **CDN الگ سے شائع نہیں ہوتا۔**

## پڑھنے والی سکرین

جو صفحہ محفوظ HTML کو **صرف دکھاتا ہے** وہ ایڈیٹر نہیں کھڑا کرتا۔ وہی سٹائل شیٹ
لگا کر `.nabi-content` کے اندر قدر ڈال دیں تو ایڈیٹر میں جیسا دکھتا تھا ویسا ہی
دکھے گا۔

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/nabi.css">

<div class="nabi-content">
  <!-- getHtml() سے محفوظ کی گئی قدر -->
</div>
```

HTML نہیں بلکہ **nabi tree (JSON) کے طور پر محفوظ کر رکھا ہو** تو ایڈیٹر کھڑا کیے بغیر
وہیں کھینچا جا سکتا ہے۔ درکار چیزیں دو ہیں — محفوظ شدہ دستاویز اور رجسٹر شدہ wing کی
فہرست۔

```html
<script>
  var registry = N.makeRegistry(N.wings().all().build())

  var saved = [{ w: 'p', ch: ['ایک تبصرہ سطر'] }]   // سرور سے ملی nabi tree
  document.querySelector('.nabi-content').innerHTML = N.renderStoredHtml(saved, registry)
</script>
```

nabi tree نہ ہو تو `null` دیتا ہے، اور گزرنے والی قدر ایڈیٹر کی نکالی `getHtml()` سے ایک
حرف بھی مختلف نہیں ہوتی — XSS چھاننے کی جگہ بھی وہی ہے۔ یہ دروازہ DOM استعمال نہیں کرتا،
اس لیے سرور (Node.js) پر بھی جوں کا توں چلتا ہے، اور **HTML سرور پر پہلے سے بنا کر بھیجنے
کا راستہ** اسی دروازے سے کھلتا ہے
([{{ t('menu_intro_ssr') }}](./ssr#صرف-محفوظ-شدہ-دستاویز-دکھانے-کی-جگہ-ایڈیٹر-کھڑا-نہیں-کرتے) دیکھیں)۔

npm سے جوڑنے والا سرور عالمی bundle نہیں بلکہ **`nabi-note/ssr`** استعمال کرتا ہے — یہ صرف
رینڈرنگ کے لیے ضروری چیزیں رکھنے والا داخلی راستہ ہے، اس لیے ترمیمی سطح اور سکرین کے آلات
لوڈ نہیں ہوتے۔

ایک ہی سٹائل شیٹ فائل میں **تمام wing کا CSS شامل ہے** — فائل کو یہ نہیں معلوم کہ
کون سا wing رجسٹر کیا گیا ہے، اس لیے سب کچھ ساتھ لے جاتی ہے۔

نظر آنے والی چیز مکمل طور پر سٹائل شیٹ کی ذمہ داری ہے، مگر **جدول کی ترتیب اور کوڈ کی رنگ
کاری پڑھنے والی طرف کا کام ہے جو JavaScript سے ہوتا ہے** — کالم کا سرا دبا کر قطاریں نئے سرے
سے ترتیب دینا، یا کوڈ کے حروف کو کاٹ کر رنگ چڑھانا، CSS نہیں کر سکتا۔ چاہیں تو پڑھنے والی
طرف کا runtime ایک دروازے سے جوڑ دیں۔

```html
<script type="module">
  import { attachViewer } from 'https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/viewer/index.js'

  attachViewer(document.querySelector('.nabi-content'), { locale: 'ur' })
</script>
```

- نہ جوڑیں تو بھی دستاویز ٹھیک نظر آتی ہے — صرف ترتیب آن کیا گیا جدول ترتیب نہیں دیتا اور
  کوڈ ایک ہی رنگ میں رہتا ہے۔
- جدول کی ترتیب صرف اسی جدول سے جڑتی ہے جس میں ایڈیٹر کے اندر ترتیب آن کی گئی ہو (نشان
  `data-nabi-sortable` رہ جاتا ہے)۔
- کوڈ کی رنگ کاری built-in tokenizer دیتا ہے، اس لیے کسی dependency کی ضرورت نہیں۔ Shiki
  جیسا ہائی لائٹر چاہیے تو اسے hook کے طور پر جوڑیں — `{ locale: 'ur', highlight }` — اس
  کا وزن جس صفحے نے جوڑا اسی کا ہے۔
- عالمی `NabiNote` bundle میں یہ دروازہ نہیں ہے — پڑھنے والا صفحہ پورا ایڈیٹر لوڈ نہ کرے اس
  لیے `nabi-note/viewer` الگ سے رہتا ہے۔ npm سے جوڑنے والا میزبان یہی دروازہ پیش نظارے پر
  بھی جوڑتا ہے، جیسا
  [{{ t('menu_intro_usage') }}](./usage#پیش-نظارے-پر-پڑھنے-والی-طرف-کا-runtime-جوڑنا) میں ہے۔
