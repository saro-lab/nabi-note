# SSR سپورٹ

## صرف محفوظ شدہ دستاویز دکھانے کی جگہ — ایڈیٹر کھڑا نہیں کرتے

تبصروں کی فہرست جیسی صرف دکھانے والی جگہ کو ایڈیٹر کی ضرورت نہیں ہوتی۔ دستاویز کھینچنے
کے لیے صرف رجسٹر شدہ wing کی فہرست (`registry`) درکار ہوتی ہے، اس لیے صرف وہی لینے والا
دروازہ الگ سے موجود ہے۔

```ts
import { makeRegistry, defaultWings, renderStoredHtml, renderStoredEditorHtml } from 'nabi-note/ssr'

// سرور شروع ہوتے وقت ایک بار — محفوظ شدہ دستاویزیں چاہے کتنی ہوں، یہی ایک بار بٹتی ہے
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['ایک تبصرہ سطر'] }]   // ڈیٹابیس سے پڑھی گئی nabi tree

renderStoredHtml(saved, registry)        // '<p>ایک تبصرہ سطر</p>'
renderStoredEditorHtml(saved, registry)  // '<p data-key="n0">ایک تبصرہ سطر</p>'
```

**`nabi-note/ssr` صرف کھینچنے کے لیے درکار چیزیں رکھنے والا داخلی راستہ ہے۔** یہ ایڈیٹنگ
سطح (`surface`) اور اسکرین اوزار (`ui`) میں سے ایک فائل کو بھی نہیں چھوتا (اس کی ضمانت
ٹیسٹ دیتے ہیں)، اس لیے سرور بنڈل میں DOM کوڈ نہیں ملتا۔ یہی دروازہ `nabi-note` میں بھی
موجود ہے، اس لیے جس صفحے پر پہلے سے ایڈیٹر لگا ہو وہ وہی راستہ استعمال کر سکتا ہے۔

| | |
|---|---|
| `renderStoredHtml(json, registry, options?)` | محفوظ و شائع کرنے والا HTML — `getHtml()` جیسی ہی قدر |
| `renderStoredEditorHtml(json, registry, options?)` | ایڈیٹر کا HTML — `getEditorHtml()` جیسی ہی قدر (`data-key` کے ساتھ) |

- **دونوں DOM استعمال نہیں کرتے** — سرور پر جوں کے توں چلتے ہیں۔
- **nabi tree نہ ہو تو `null`** — رد کرنے کا اصول `setJson()` جیسا ہی ہے (پوری دستاویز
  ایک array ہونی چاہیے)۔ یہ throw نہیں کرتا۔
- **ایڈیٹر کی نکالی قدر سے ایک حرف بھی مختلف نہیں ہوتا۔** وہی مرحلہ (normalize → assemble)
  طے ہوتا ہے، اس لیے XSS چھاننے کی جگہ بھی وہی ہے — صرف دکھانے والی طرف کم صاف نہیں ہوتی۔
- `options` صرف `{ allowLocalUrls }` ہے — `createNabiWith` کے اسی آپشن جیسا مطلب رکھتا ہے۔

**ایک ہی محفوظ شدہ دستاویز ہمیشہ ایک ہی `data-key` پاتی ہے۔** اس لیے سرور
`renderStoredEditorHtml` سے ایڈیٹر پہلے سے کھینچ کر بھیجے اور براؤزر `hydrate` سے اسے
سنبھال لے، تو اسکرین دوبارہ نہیں کھینچی جاتی۔

```ts
mountSurface({ nabi, registry, root: surface, hydrate: true })
```

فرق پڑنے پر وہیں نئے سرے سے کھینچا جاتا ہے، اس لیے سرور اور کلائنٹ کی wing فہرست کا ایک
جیسا ہونا ہی کافی ہے۔

::: tip اس ویب سائٹ کا اپنا ہوم پیج ہی وہ نمونہ ہے
ہوم ڈیمو کی دستاویز **بلڈ کے وقت `renderStoredEditorHtml` سے پہلے سے کھینچ کر** صفحے میں
بٹھائی گئی ہے، اور ایڈیٹر اسی کے اوپر `hydrate` سے جاگتا ہے۔ اس لیے ایڈیٹر کا کوڈ پہنچنے
سے پہلے بھی لکھائی پہلے سے پڑھی جا سکتی ہے — خالی جگہ اچانک بھرنے والا وقفہ نہیں ہوتا۔
:::

## ٹول بار بھی پہلے سے کھینچا جا سکتا ہے

بٹنوں کی قطار **دستاویز کو نہیں دیکھتی۔** یہ صرف رجسٹر شدہ wing کی فہرست، زبان اور گروہ کی
ترتیب دیکھتی ہے، اس لیے نکلنے والے حروف **مستقل (constant)** ہیں — سرور شروع ہوتے وقت ایک
بار بلائیں اور وہی حروف مسلسل استعمال کریں۔ ہر درخواست پر دوبارہ بلانے کی ضرورت نہیں۔

```ts
import { makeRegistry, defaultWings, renderToolbarHtml } from 'nabi-note/ssr'

const registry = makeRegistry(defaultWings)

const toolbarHtml = renderToolbarHtml({ registry, locale: 'ur' })
// '<div class="nabi-group" data-group="font">...</div>'
```

یہ حروف ٹول بار کے ڈبے میں جوں کے توں بھیج دیں تو براؤزر میں `mountToolbar` **وہی فنکشن**
استعمال کر کے کھینچتا ہے۔ اگر ویسی ہی سطر پہلے سے موجود ہو تو **دوبارہ نہیں کھینچتا، صرف
تاریں جوڑتا ہے۔**

```ts
mountToolbar({ nabi, registry, surface, root: toolbar })
```

::: warning ڈبے پر `class="nabi-toolbar-row"` بھی لکھ دیں
پہلے سے کھینچی گئی سطر بھیجتے وقت یہ کلاس **پہلی تصویر سے ہی** موجود ہونی چاہیے۔ کور یہ
کلاس نہ ہونے کی صورت میں mount کے وقت خود لگا دیتا ہے، جس سے دائیں بائیں فاصلہ اسی وقت
لگتا ہے اور **بٹنوں کی سطر ایک بار سرک جاتی ہے۔** میزبان پہلے سے لکھ دے تو کور اسے ہاتھ
نہیں لگاتا (صرف وہی ہٹاتا ہے جو خود نے لگایا ہو)۔

```html
<div class="nabi-toolbar-row">پہلے سے کھینچی گئی سطر</div>
```
:::

- **فرق پڑنے پر بھی نہیں ٹوٹتا** — کھڑی سطر ابھی کی wing فہرست سے مختلف ہو تو وہیں نئے سرے
  سے کھینچی جاتی ہے۔ صرف پہلے سے کھینچی قدر ضائع ہوتی ہے، اسکرین ہمیشہ درست رہتی ہے۔
- **پہلے سے کھینچی گئی سطر "کوئی بٹن دبا نہیں، کوئی چھپا نہیں" کی حالت میں ہوتی ہے۔** دبا
  ہونا (`aria-pressed`) اور چھپنا کیریٹ طے کرتا ہے، جسے سرور نہیں جانتا۔ اگر کیریٹ کے
  مطابق بٹن چھپنے والی ترتیب ہو تو mount کے بعد کچھ بٹن غائب ہو کر سطر دوبارہ سکڑ سکتی ہے۔
- **صرف ایڈیٹر کھڑا کرنے والی جگہ پر ہی بھیجیں۔** صرف دکھانے والے صفحے پر ٹول بار نہیں
  ہوتا، اس لیے یہ حروف وہاں لینے کی ضرورت نہیں۔

**پیش نظارہ اور مکمل سکرین کے دو بٹن بھی وہی راستہ اپناتے ہیں۔** یہ دونوں wing نہیں بلکہ
خول کا حصہ ہیں، اس لیے اوپر کے ٹول بار حروف میں شامل نہیں ہوتے — الگ سے کھینچ کر
`mountViewTools` کھڑا ہونے والے ڈبے میں ڈالے جاتے ہیں۔

```ts
import { renderViewToolsHtml } from 'nabi-note/ssr'

renderViewToolsHtml({ locale: 'ur' })
// '<span class="nabi-tools">...</span>'
```

::: tip اس ویب سائٹ کا اپنا ہوم پیج ہی وہ نمونہ ہے
ہوم ڈیمو کا ٹول بار **بلڈ کے وقت `renderToolbarHtml`·`renderViewToolsHtml` سے پہلے سے
کھینچ کر** بٹھایا گیا ہے، اور `mountToolbar`·`mountViewTools` اسی سطر کو پہچان کر صرف
تاریں جوڑتے ہیں۔ اس لیے پینتیس آئیکن دیر سے بھر جانے والا وقفہ نہیں ہوتا۔
:::
