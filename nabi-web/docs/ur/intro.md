# NABI NOTE کیا ہے؟

NABI NOTE ایک براؤزر میں چلنے والا **اوپن سورس WYSIWYG ایڈیٹر** ہے۔

---

## دستاویز کی اصل حقیقت nabi-tree ہے

دستاویز کو اٹھائے پھرنے والا برتن HTML سٹرنگ نہیں بلکہ **nabi-tree** ہے — ایک عام JS
آبجیکٹ صف (array) جو فارمیٹنگ اور خصوصیات کی معلومات رکھتا ہے۔ HTML صرف ان دو
سِروں پر ہے جہاں سے ٹری آتا اور جاتا ہے۔

<FlowChain :steps="stepsIn" caption="اندر آنا — باہر سے آیا HTML setHtml() سے گزر کر nabi-tree بننے کے بعد ہی سکرین پر رکھا جاتا ہے۔" />

<FlowChain :steps="stepsOut" caption="باہر جانا — ایک ہی nabi-tree سے تین چیزیں نکلتی ہیں۔ سکرین کا DOM جوں کا توں باہر نہیں بھیجا جاتا۔" />

| فنکشن | یہ کیا ہے |
|---|---|
| `getHtml()` | **محفوظ کرنے اور شائع کرنے کے لیے HTML۔** اس میں ایڈیٹر کا کوئی نشان نہیں ہوتا |
| `getJson()` | **nabi-tree۔** اندرونی کلید (`_id`) اتار کر نکلتا ہے |
| `getEditorHtml()` | ابھی ایڈیٹر کی سکرین کا HTML۔ اس پر `data-key` لگا ہوتا ہے، یہ محفوظ کرنے والی قدر نہیں ہے |

**محفوظ کرنے کی قدر پہلے دو میں سے ایک ہے۔** `getEditorHtml()` وہ جگہ ہے جب سرور پر
ایڈیٹر پہلے سے کھینچ کر بھیجنا ہو۔ تفصیلی شکل [{{ t('menu_intro_usage') }}](./intro/usage)
میں ہے۔

تینوں **ایک ہی nabi-tree سے اُس وقت شمار** ہوتے ہیں — کہیں بھی HTML سٹرنگ کے طور
پر محفوظ نہیں رکھے جاتے۔ اسی لیے `onChange` سے ملی `getHtml()` کی قدر کو دوبارہ
`setHtml()` سے پڑھ لیں تو وہی nabi-tree نکلتا ہے۔

::: tip باہر جانے کے راستے پر DOM کی ضرورت نہیں
`createNabiWith()` · `getJson()` · `getHtml()` · `getEditorHtml()` خالص حساب ہیں۔
مطلب یہ کہ آپ محفوظ کیے ہوئے nabi-tree کو جوں کا توں ڈال کر سرور (Node.js) پر بھیجنے
والا HTML جوڑ سکتے ہیں — نہ براؤزر چاہیے، نہ جعلی DOM۔ DOM صرف **اندر آنے کے راستے**
(`setHtml()`) اور سکرین سے جڑنے والے `mount*` کو درکار ہے۔

```ts
import { createNabiWith, defaultWings } from 'nabi-note'

const { nabi } = createNabiWith(defaultWings, { doc: محفوظ_شدہ_nabi_tree })
const html = nabi.getHtml()
```
:::

آنے والا HTML (چاہے ہاتھ سے لکھا ہو، چسپاں کیا گیا ہو، یا محفوظ کر کے واپس لایا گیا
ہو) `setHtml()` سے گزرتے ہوئے ان تمام ٹیگز اور خصوصیات سے چھن جاتا ہے جنہیں رجسٹرڈ
wing نہیں جانتا۔ ٹری کو خود `cocoon` ایک بار مزید سنوارتا ہے، جو ضمانت دیتا ہے کہ
بلاک صاف طور پر ایک دوسرے کے اندر بیٹھے ہیں، اندرونی کلید منفرد ہے اور آخری سرے کا
بلاک خالی نہیں۔

::: tip محفوظ کیا ہوا HTML دوبارہ دکھاتے وقت
`getHtml()` نے جو چھانا ہے وہ **غیر رجسٹرڈ مارک اپ** ہے۔ محفوظ کر کے نکالے گئے HTML
کو ایڈیٹر کے بجائے کسی **عام صفحے** پر جوں کا توں دکھاتے وقت اُس صفحے کی اپنی
sanitize اب بھی ضروری ہے — ایڈیٹر کا فلٹر خود ایڈیٹر کے لیے ہے، یہ ضمانت نہیں کہ
کوئی بھی من مانا HTML محفوظ طریقے سے دکھایا جا سکتا ہے۔
:::

## ساری فارمیٹنگ wing ہے

جس اکائی کو دوسرے ایڈیٹر "پلگ اِن" کہتے ہیں، اسے یہاں **wing (پَر)** کہا جاتا ہے۔
کور جو مارک اپ براہِ راست جانتا ہے وہ پیراگراف (`p`)، سطر توڑ (`br`) اور سادہ متن
ہے؛ سرخی، فہرست، جدول اور جلی — سب wing ہیں۔ کوڈ میں بھی وہی نام چلتا ہے — قسم
`Wing` ہے۔

**تمام wing مکمل بنے ہوئے کانسٹنٹ (constant) ہیں۔** انہیں بس صف میں ڈال دینا کافی
ہے۔ صرف دو کو آپشن کی ضرورت ہو تو ان کے لیے فیکٹری فنکشن الگ سے موجود ہے —
`makeImageWing({ allowLocalUrls })` اور `makeUploadWing({ allowLocalUrls })`۔ کوڈ
کی رنگ کاری جیسے کسی ایک کام کو بدلنا ہو تو کانسٹنٹ کو پھیلا کر لکھیں:
`{ ...codeWing, attach: makeCodeAttach({ highlight }) }`۔

```ts
import { createNabiWith, parseNodes, boldWing } from 'nabi-note'

const bare = createNabiWith([], { parseHtml: parseNodes }).nabi
bare.setHtml('<p><b>جلی</b> <i>ترچھا</i></p>')
bare.getHtml()
// '<p>جلی ترچھا</p>'                    — کوئی wing نہیں

const bold = createNabiWith([boldWing], { parseHtml: parseNodes }).nabi
bold.setHtml('<p><b>جلی</b> <i>ترچھا</i></p>')
bold.getHtml()
// '<p><b>جلی</b> ترچھا</p>'              — صرف جلی بچا
```

جو مارک اپ رجسٹر نہ ہو اس کا خول اتر جاتا ہے اور وہ **سادہ متن بن کر گر جاتا ہے۔**
"اس ایڈیٹر سے کیا لکھا جا سکتا ہے" کا جواب آپ کی رجسٹر کی ہوئی wing کی فہرست ہے۔

## ترمیم ایک ہی دروازے سے نکلتی ہے

دستاویز بدلنے کے **تمام** راستے ایک ہی `applyCommand()` سے گزرتے ہیں۔ ٹول بار کا
بٹن بھی، خودکار تبدیلی بھی، چسپاں کرنا بھی اور واپس لانا بھی۔ اصل ٹری کو ہاتھ سے
بدل دینے کا کوئی راستہ شروع ہی سے موجود نہیں۔

```ts
nabi.applyCommand('toggleMark', { w: 'b' })     // جلی — کور کا mark toggle
nabi.applyCommand('setHeading', { value: 2 })   // سرخی سطح 2 — wing کا اپنا command
nabi.undo()
nabi.redo()
```

**command ہمیشہ `boolean` جواب دیتا ہے۔** کوئی exception نہیں پھینکتا، اور اگر کچھ
نہ بدلے تو `false` جواب دیتا ہے اور نہ undo کا نکتہ بنتا ہے نہ کوئی سگنل نکلتا ہے۔

wing جہاں command جوڑتی ہے وہ ایک ہی اعلان ہے (`commands`)۔ **بنیادی wing بھی وہی
دروازہ استعمال کرتی ہیں جو کسی اور کی بنائی wing استعمال کرتی ہے** — "صرف بنیادی
wing کے لیے شارٹ کٹ" جیسی کوئی چیز نہیں ہے۔

یہ ترتیب محض تحریر نہیں **جانچ** ہے۔ نیچے کی تہہ اوپر کی تہہ کو import کرے تو جانچ
گر جاتی ہے۔ ساتھ کی wing کا ایک دوسرے کو بلانا بھی روکا گیا ہے، اس لیے مشترک کوڈ
`wing` تہہ میں اترتا ہے۔

نیا فیچر ایک wing ہے۔ اگر لگے کہ کور فائل بدلنی پڑے گی تو یہ عموماً **اس بات کا
اشارہ ہے کہ معاہدہ (`Wing` قسم) ناکافی ہے۔**

## اصطلاحات

یہ سائٹ اور ریپازٹری جو باقی الفاظ استعمال کرتے ہیں وہ یہ ہیں۔ جن الفاظ کے نام
دوسرے ایڈیٹروں سے ملتے ہیں ان کے معنی بھی مختلف ہو سکتے ہیں، اس لیے انہیں صرف اسی
معنی میں لیا جاتا ہے جو یہاں لکھا ہے۔

### دستاویز کن چیزوں سے بنتی ہے

| لفظ | معنی |
|---|---|
| **mark (نشان)** | حروف پر چڑھائی جانے والی فارمیٹنگ — `<b>` · `<i>` · `<a>`۔ یہ جملے کے اندر، جدول کے خانے میں، سرخی کے اندر — کہیں بھی رہ سکتی ہے |
| **block (بلاک)** | وہ ٹکڑا جو پیراگراف کی جگہ گھیرتا ہے — پیراگراف · سرخی · فہرست · جدول · تصویر |
| **پیراگراف کی خاصیت** | نیا ٹیگ بنائے بغیر صرف پیراگراف کی خاصیت بدلنے والا نشان — سرخی کا درجہ · سیدھ · ڈراپ کیپ |
| **wrapper پیراگراف** | جدول، فہرست، تصویر جیسی چیز کو ایک تہہ میں لپیٹنے والا پیراگراف۔ سیدھ اسی پیراگراف پر لگتی ہے، اور کیریٹ کو چیز کے آگے پیچھے کھڑا ہونے کی جگہ یہی دیتا ہے |
| **claim (دعویٰ)** | یہ فیصلہ کہ کوئی مارک اپ کس wing کا ہے۔ اگر کوئی نہ لے تو خول اتر جاتا ہے |
| **parts (اجزاء)** | وہ بغیر بٹن والا ساختی حصہ جو ایک wing اپنے ساتھ لاتی ہے — جدول کی قطاریں اور کالم، تہہ بلاک کی خلاصہ سطر |

### وہ الفاظ جو صرف ترمیمی سکرین پر ہیں

| لفظ | معنی |
|---|---|
| **caret (کیریٹ)** | وہ جھپکتی لکیر جو بتاتی ہے کہ حرف کہاں داخل ہوگا |
| **context row (سیاق سطر)** | وہ سطر جس میں صرف وہی کام دکھتے ہیں جو کیریٹ کی موجودہ جگہ پر ممکن ہیں — جدول کی قطار و کالم کمانڈ، کوڈ کا زبان والا خانہ، لنک کے پتہ اور نام کے خانے، سرخی کے H1 سے H6 |
| **escape key (فرار کلید)** | mark کے اندر یہ کلید دبائیں تو اگلا حرف اس mark سے باہر جا کھڑا ہوتا ہے — wing اسے `escapeKeys` سے اعلان کرتی ہے |
| **placeholder (جگہ رکھنے والا)** | وہ عارضی جگہ جو صرف اپ لوڈ چلنے کے دوران کھڑی رہتی ہے۔ قدر میں یہ کبھی نہیں رستی |

### وہ الفاظ جو بنانے والے استعمال کرتے ہیں

| لفظ | معنی |
|---|---|
| **cocoon** | nabi-tree کو سنوارنے کا معیاری مرحلہ — **ہر command کے بعد خود چلتا ہے**، اس لیے کوئی بھی command قاعدے توڑنے والی دستاویز چھوڑ نہیں سکتا |
| **attach (منسلک ہونا)** | جب wing کو سکرین کو براہِ راست چھونا ہو تو یہ وہ hook ہے جو اعلان کرتی ہے — جدول کے خانے کو گھسیٹنا، کوڈ کی رنگ کاری، چیک ٹوگل — سب یہی ہیں۔ `mountSurface` رجسٹر شدہ wing کا `attach` خود ساتھ لگا دیتا ہے |
| **input rule (خودکار تبدیلی)** | وہ تبدیلی جو صرف حروف ٹائپ کرنے سے ہو جاتی ہے — ہائفن اور خالی جگہ سے فہرست، `#` اور خالی جگہ سے سرخی |

## پابندیاں

React اور Vue کو import نہیں کیا جاتا، صرف خالص DOM API استعمال ہوتی ہے۔ وجہ یہ ہے
کہ ایک ہی صفحے پر مختلف فریم ورک اور ورژن کے میل کے ساتھ اسے چلنا پڑتا ہے۔

کوڈ بلاک کی رنگ کاری کے لیے **ایک ہلکا سا ٹوکنائزر پیکج کے اندر شامل ہے** — یہ
C-طرز کی زبانیں، Python، JSON، CSS، مارک اپ اور shell کو جانتا ہے۔ اگر زیادہ درست
رنگ کاری چاہیے تو Prism، highlight.js یا Shiki جیسی چیز `makeCodeAttach({ highlight })`
سے جوڑ دیں، پھر وہی رنگ کاری کرے گی۔
