# Ссылка

## Описание

`linkWing` (id `a`) владеет `<a href>`. По нажатию кнопки рядом с кареткой
открывается слой ввода адреса, и кнопка подтверждения становится активной только
для адресов, начинающихся с `http`/`https` — сама эта проверка по белому списку и
есть защита от XSS (схемы вроде `javascript:` не проходят вовсе). Не прошедший
проверку `href` не сохраняется, и в таком случае текст выходит простым, без тега
`<a>`.

В слое два поля — адрес и текст, который будет виден. Если оставить поле текста
пустым, текстом станет сам адрес; а если выделения нет и стоит только каретка,
целью становится вся метка ссылки, внутри которой каретка находится (то же
правило, что у маркера и цвета текста).

## Готовую ссылку правят в контекстной строке

Когда каретка попадает внутрь ссылки, в контекстной строке появляются **два
текстовых поля** — не кнопка, открывающая слой, а поля ввода прямо в этой строке
(`kind: 'text'`). Они появляются уже заполненными текущими значениями, а
изменение применяется по нажатию Enter или по щелчку в стороне. Если значение не
изменилось, ничего не происходит.

| Поле | Что делает |
|---|---|
| Адрес | Меняет только адрес. Видимый текст остаётся прежним. |
| Имя | Меняет только видимый текст. Адрес и пометка вложения остаются прежними. |

**У вложения (файловой ссылки) поле адреса не появляется** — этот адрес назначила
загрузка, и править его вручную не следует. Поле имени появляется одинаково и для
обычной ссылки, и для вложения. Пустое имя не принимается: ссылка без имени — это
не переименование, а удаление.

## Вложение на экране — единый блок

С вложением обращаются как с одним целым. Клик по нему не ставит каретку внутрь —
вместо этого **выделяется вся ссылка целиком**, а нажатие Backspace или Delete
рядом с ней **стирает ссылку одним махом**. Правка — дело контекстной строки, а
не каретки.

Эту работу крыло объявляет через `attach`, и `mountSurface` подключает её сама —
**отдельно монтировать ничего не нужно.**

## Пометка вложения

Ссылка, пришедшая из загрузки, несёт пометку `data-nabi-file` (значение —
расширение файла) — именно она заставляет таблицу стилей рисовать не
подчёркивание, а рамку со скрепкой. Пометка сохраняется и при смене имени, и при
смене адреса. Даже очистка форматирования не снимает её с вложения — если убрать
оболочку, вложение превратится в мёртвый простой текст.

`linkWing` — это **константа**: её не вызывают со скобками и ей нечего передавать
в качестве опций.

::: warning `allowLocalUrls` до ссылки не дотягивается
Переключатель, открывающий адреса `blob:`/`data:`, действует **только на
изображение**. На выходе всё всегда строго: место, где `getHtml()` фильтрует
адрес (`ctx.url`), смотрит на белый список независимо от того, что включил хост.

Поэтому вложение-ссылка с адресом `blob:` **при экспорте падает в простой
текст.** Именно поэтому загрузка не должна оставлять временный адрес как есть —
после реальной загрузки его нужно заменить настоящим адресом, чтобы он остался в
документе.
:::

## Пример использования

```ts
import { createNabiWith, mountSurface, mountToolbar, mountContextToolbar, linkWing } from 'nabi-note'
import 'nabi-note/nabi.css'

const surface = document.querySelector<HTMLElement>('#editor')!

// список крыльев вместе строит знание о видах, команды и сборщики — это и есть `registry`
const { nabi, registry } = createNabiWith([linkWing])

mountSurface({ nabi, registry, root: surface })
mountToolbar({ nabi, registry, surface, root: document.querySelector<HTMLElement>('#toolbar')! })
mountContextToolbar({ nabi, registry, surface, root: document.querySelector<HTMLElement>('#context')! })

// nabi.onChange(() => user_callback(nabi.getHtml()))
```
