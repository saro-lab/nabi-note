# Как сделать своё крыло

Крыло (wing) — это **один объект**. Ни класса, от которого надо наследоваться,
ни отдельной церемонии регистрации нет — положить его в массив, который
передаётся в `createNabiWith`, и *значит* зарегистрировать.

Полужирный, таблица и загрузка файлов сделаны заполнением ровно тех же полей,
что перечислены здесь. Крыло, написанное вами, работает на **тех же условиях**,
что и встроенное — отдельного короткого пути нет.

---

## Самое короткое крыло

Одна строчная метка, которая знает `<kbd>`.

```ts
import { createNabiWith, mountSurface, simpleMark, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const kbdWing: Wing = {
  ...simpleMark({
    w: 'kbd',                                                   // имя этого крыла — оно же `w` в сохранённом значении
    toHtml: (_node, children, ctx) => ctx.element('kbd', children()),   // как рисуется на выходе
  }),
  // объявляем, что владеем тегом `<kbd>` во входящем HTML
  claim: (el, inner) => (el.tag === 'kbd' ? [{ w: 'kbd', ch: inner(false) }] : null),
}

const surface = document.querySelector<HTMLElement>('#editor')!
const { nabi, registry } = createNabiWith([kbdWing])
mountSurface({ nabi, registry, root: surface })
```

Теперь `<kbd>` остаётся в документе. Он переживёт и вставку, и `setHtml()`, и
сохранение с повторной загрузкой.

```
Если зарегистрировано:    <p>Нажмите: <kbd>Ctrl</kbd>+<kbd>S</kbd></p>   →   без изменений
Если не зарегистрировано: <p>Нажмите: <kbd>Ctrl</kbd></p>                →   <p>Нажмите: Ctrl</p>
```

**Эти два поля смотрят в разные стороны.** `toHtml` — путь наружу, а `claim` —
путь внутрь. Не напишете `claim` — рисовать будет можно, но **прочитать заново
не получится**: как только документ сохранят и загрузят снова, оболочка
слетит.

`simpleMark` — короткий путь для метки без атрибутов. Для метки со значением
есть `valueMark`, для объекта — `boxObject`, для семейства списков —
`listFamily`, а в остальных случаях объект `Wing` пишут вручную.

## Крылья — это константы

**Большинство крыльев — уже готовые константы** — такие, как `boldWing` или
`headingWing`, просто кладут в массив. Фабричная функция есть только у двух,
которым нужны опции.

```ts
makeImageWing({ allowLocalUrls: true })
makeUploadWing({ allowLocalUrls: true })
```

Если нужно заменить только работу подключения к экрану, константу
расширяют — это проще, чем строить крыло заново, ведь меняется одно поле.

```ts
const wing = { ...codeWing, attach: makeCodeAttach({ highlight: myHighlighter }) }
```

## Регистрация и порядок

```ts
const { nabi, registry } = createNabiWith([boldWing, italicWing, kbdWing])
```

**Порядок в массиве и есть порядок опроса.** Решая, кому принадлежит кусок
разметки (`claim`), ядро спрашивает крылья именно в этом порядке, и забирает
её то, которое ответило первым. Если её не забрал никто, оболочка снимается.

На панели инструментов сначала идут **группы** (`button.group`). Порядок групп
зафиксирован, а внутри одной группы крылья встают в порядке этого самого
массива.

### Ошибка при регистрации фатальна сразу

`createNabiWith` **немедленно бросает исключение**, если крыло нарушает
контракт. Ошибка не всплывёт позже.

| Что проверяется | Пример |
|---|---|
| Имя — зарезервированное слово | `w: 'p'` · `w: 'br'` |
| Одно и то же имя дважды | `boldWing` зарегистрирован дважды |
| Узел строится, а `toHtml` нет | `place: 'mark'`, но нет способа его нарисовать |
| Имя команды нарушает правило | должно быть «глагол + дополнение» в camelCase (`insertTable`) |
| Нет обязательной пары | загрузка требует рядом `img` или `a` (`requiresAnyOf`) |

## Команда — это чистая функция

Каждый путь, изменяющий документ, проходит через одну команду. Команда **не
знает ни о DOM, ни об экране.**

```ts
import { boxObject, insertLump, type Command, type Wing } from 'nabi-note'

const insertStamp: Command = (doc, sel, args, env) => {
  // значение пришло снаружи — проверяем его; если не то, ничего не делаем
  if (typeof args['text'] !== 'string') return null
  const stamp = { w: 'stamp', a: { t: args['text'] }, ch: [] }
  const r = insertLump(doc, sel.focus, stamp, env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

export const stampWing: Wing = {
  ...boxObject({
    w: 'stamp',
    attrs: { t: (v) => (typeof v === 'string' ? v : null) },
    toHtml: (node, _children, ctx) =>
      ctx.element('span', ctx.escape(String(node.a?.['t'] ?? '')), { 'data-nabi-stamp': '' }),
  }),
  commands: { insertStamp },
  button: {
    group: 'insert',
    label: { ru: 'Штамп', en: 'Stamp' },
    action: { kind: 'command', command: 'insertStamp', args: { text: 'ОК' } },
  },
}
```

| Аргумент | Что это |
|---|---|
| `doc` | текущий документ (массив блоков). **Не меняйте его — верните новый** |
| `sel` | текущее выделение |
| `args` | значение, переданное кнопкой или контекстной строкой. **Оно пришло снаружи, поэтому его нужно проверить** |
| `env` | знание о видах — что что содержит, что является объектом |

Ответ — это `{ doc, selection }` либо **`null`**. **Если ничего не изменилось,
верните `null`** — тогда `applyCommand` ответит `false`, и точка отмены не
добавится. Возвращённый документ ещё раз пройдёт через `cocoon`, так что ни
одна команда не может оставить документ, нарушающий правила.

Вызывают всегда по имени.

```ts
nabi.applyCommand('insertStamp', { text: 'ОК' })   // boolean
```

## Все поля, какие можно заполнить

У `Wing` тридцать одно поле, и **обязательных всего два** (`w`·`place`).

### Что это

| Поле | Значение |
|---|---|
| `w` | имя этого крыла. Становится `w` в сохранённом значении. Зарезервированные слова (`p`·`br`) использовать нельзя |
| `place` | `'mark'` — над текстом · `'void'` — объект без содержимого · `'container'` — объект, содержащий текст · `'attr'` — атрибут абзаца · `'tool'` — инструмент, не оставляющий следа в документе |
| `basic` | **Работает ли сразу, без всякой настройки.** Не укажете — будет `false`. `wings().allBasic()` собирает только те, что несут эту отметку, и **кастомное крыло меряется той же меркой**. Но `allBasic()` обходит только официальный каталог, поэтому крыло, добавленное напрямую через `.use(объект)`, грузится независимо от этого значения |
| `holds` | как устроено содержимое — `'blocks'` или `'inline'` |
| `singleParagraph` | содержимое зафиксировано **одним** абзацем (ячейка таблицы) |
| `boolAttrs` | имена булевых атрибутов, у которых единственное значение — `1` |
| `allows` | имена крыльев, которые могут находиться внутри. Не указано — разрешено всё |
| `noAlign` | **только для объектов.** Поставите — и **абзац-обёртка, несущая этот объект, перестаёт принимать выравнивание**: кнопки выравнивания прячутся на панели инструментов, команда отказывает как «ничего не изменилось», а значение, уже запечённое в старом сохранённом документе, снимается по дороге через cocoon. Первый, кому это нужно, — коробка кода: `pre` наследует `text-align`, поэтому вместо сдвига коробки **сдвигаются строки кода**. Поставьте это на марку, инструмент или атрибут абзаца — и **регистрация умрёт** |
| `requiresAnyOf` | хотя бы одно из перечисленных должно быть зарегистрировано вместе с этим |
| `parts` | структура без кнопок, которую крыло приводит с собой — строка и ячейка таблицы, строка заголовка у спойлера |

### Значение

| Поле | Значение |
|---|---|
| `attrKey` · `attrValues` | имя поля и список допустимых значений, которые использует атрибут абзаца |
| `currentValue` | нажато ли сейчас — по этому ответу панель инструментов и контекстная строка красят поле |

### Пути туда и обратно

| Поле | Значение |
|---|---|
| `toHtml` · `partHtml` | как рисуется на выходе |
| `toMd` | как рисуется на выходе в markdown. **Необязательно — не укажете, и узел падает обратно к `toHtml`** (подчёркивание, YouTube и «Подробности» — из тех, кому в markdown нет места, и это и есть настоящее лицо «md с примесью HTML») |
| `partMd` | markdown-доля частей (`parts`) этого крыла |
| `ioFilter` | это крыло **несёт с собой вставку, сохранение и открытие собственного формата** (файл `.nabi` — как раз такое место). Фильтр — не крыло, а знание, прикреплённое к крылу, поэтому то, что хост подключил через `ioFilters`, встаёт впереди него — см. [Подключение IO-фильтра](#подключение-io-фильтра) ниже |
| `claim` | решает, кому принадлежит этот тег во входящем HTML |
| `repair` · `partRepair` | приводит этот узел в порядок на входе из JSON. Вернёт `null` — узел уберётся вместе с оболочкой |

### Руки и клавиши

| Поле | Значение |
|---|---|
| `commands` | команды, которые добавляет это крыло |
| `onKey` | перехватывает клавишу первым, когда каретка внутри узла этого крыла |
| `escapeKeys` | клавиши, после которых следующий введённый символ выходит за пределы этой метки |
| `doubleKeys` | `{ имя клавиши: имя команды }` — нажмёте эту клавишу **дважды за 350 мс**, и команда запускается. Слово похоже на `escapeKeys`, но значит другое: там — «выйти из метки и писать дальше», здесь — «одним жестом одна команда». Приоритет **самый низкий**, поэтому очередь до неё доходит только после того, как эту клавишу разобрали все остальные. При регистрации **проверяются столкновения клавиш и существование команды** — если два крыла претендуют на одну клавишу или имя указывает на несуществующую команду, регистрация умирает |
| `inputRules` | автозамена, происходящая от одного лишь набора текста |
| `attach` | момент, когда нужно прикоснуться к экрану — перетаскивание ячейки таблицы, подсветка кода |

### Внешний вид

| Поле | Значение |
|---|---|
| `button` · `buttons` | одна или несколько кнопок на панели инструментов |
| `context` | объявление элементов контекстной строки |
| `styles` | CSS, который несёт с собой это крыло |

## Подключение IO-фильтра

**IO-фильтр — это не крыло.** Он стоит только у дверей, через которые проходит документ, —
вставка, сохранение и открытие, — берёт на себя один формат и не ставит в документе ни одного
собственного узла. Контракт — один объект `IoFilter`.

| Поле | Значение |
|---|---|
| `id` · `label` | имя фильтра и имя, показанное на панели. Совпадение `id` **убивает регистрацию прямо на месте** |
| `paste` | смотрит на буфер обмена (`PasteData`) и предлагает кандидата. `null`, если это не его случай, а `build()` копает только после того, как человек выберет этот вариант |
| `save` | `{ extension, write, lossy?, mime? }` — `write` получает `DocSource` и берёт из него `json()`, `html()` или `md()`, что нужно. `lossy` — это то, что кладёт «(с потерями)» на панель сохранения |
| `read` | принимает имя и строку и читает их в nabi-дерево. **`null`, если это не его случай** — тогда идёт к следующему фильтру |

**Все три двери необязательны** — годится и фильтр, который умеет только вставку, и такой, что
только читает. Подключить его можно через `ioFilters` у `mountSurface` и `mountFile`, через
`createNabiWith(wings, { ioFilters })`, а также через поле `ioFilter` из таблицы выше, и
**побеждает тот, кто встал раньше** — mount → хост → крыло → встроенные (`nabi` · `html` ·
`html-open` · `markdown`). Список для открытия отвечает `readExtensions(filters)`, а он **не может
посчитать фильтр без слота сохранения** (встроенный `.html` — как раз такое место, поэтому
хранилище по умолчанию добавляет его вручную, доводя список до четырёх).

Markdown фильтр в одиночку сделать не может — какими символами записать узел, знает **само
крыло**, несущее `toMd`·`partMd` выше. Не укажете их — и узел падает обратно к `toHtml`,
подмешиваясь в md как HTML, а парсер md тоже принимает **только тот синтаксис, который примет
зарегистрированное крыло**.

## `w` — как назвать

`w` — это **строка, которая повторяется в сохранённом значении на каждом
узле**. Чем короче, тем лучше — поэтому у встроенных крыльев она короткая,
вроде `b`·`hl`·`tf`. Но если она совпадёт с чужим именем, регистрация
провалится, так что для своего крыла лучше взять имя чуть длиннее, но точно
не пересекающееся с другими.

Совпадать с именем тега HTML не обязательно — какой тег окажется на выходе,
решает `toHtml`.

::: warning Если переименовать позже
`w` в сохранённом значении и есть само имя, поэтому переименование крыла
означает, что **уже сохранённые документы прочитать не удастся.** Если
переименовать всё же нужно, оставьте переходный период — принимайте старое имя
через `claim` вместе с новым.
:::
