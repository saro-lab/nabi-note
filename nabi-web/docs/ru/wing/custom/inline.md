# Создание строчной метки

`place: 'mark'` — это **формат, наложенный на текст**. Он не занимает места, не
прерывает поток текста и может накладываться друг на друга — так устроены
полужирный, курсив, маркер.

---

## Полностью готовая метка

```ts
import { createNabiWith, mountSurface, simpleMark, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const kbdWing: Wing = {
  ...simpleMark({
    w: 'kbd',
    toHtml: (_node, children, ctx) => ctx.element('kbd', children()),
    button: {
      group: 'emphasis',
      label: { ru: 'Клавиша', en: 'Key' },
      shortcut: 'K',
      action: { kind: 'mark' },        // переключение делает само ядро — команда не нужна
    },
    styles: `.nabi-content kbd {
      font-family: var(--nabi-font-mono, monospace);
      border: 1px solid var(--nabi-line); border-radius: .25em; padding: 0 .3em;
    }`,
  }),
  claim: (el, inner) => (el.tag === 'kbd' ? [{ w: 'kbd', ch: inner(false) }] : null),
}

const surface = document.querySelector<HTMLElement>('#editor')!
const { nabi, registry } = createNabiWith([kbdWing])
mountSurface({ nabi, registry, root: surface })
```

`simpleMark` заполняет за вас два поля — `place: 'mark'` и
`escapeKeys: ['Escape']`. Остальное передаётся как есть.

## Два направления пишутся отдельно

| | Направление | Если не указать |
|---|---|---|
| `toHtml` | документ → HTML | **регистрация проваливается.** Крыло, создающее узел, обязано уметь его нарисовать |
| `claim` | HTML → документ | нарисовать получится, но **прочитать заново — нет.** После сохранения и загрузки оболочка слетит |

Шесть базовых меток (`b`·`i`·`u`·`s`·`sub`·`sup`) и четыре метки со значением
(`hl`·`tc`·`fs`·`tf`) — теги, которые **уже знает само ядро.** Поэтому у
`boldWing` нет ни `toHtml`, ни `claim`. Своё имя ядру незнакомо, так что оба
поля нужно писать самостоятельно.

### `toHtml`

```ts
toHtml: (node, children, ctx) => ctx.element('kbd', children())
```

| Аргумент | Что это |
|---|---|
| `node` | текущий узел. Атрибут достаётся как `node.a?.['ключ']` |
| `children()` | текст, нарисованный внутри. **Рисуется в момент вызова**, не вызовете — содержимое не появится |
| `ctx` | инструменты для безопасной сборки |

Что даёт `ctx`:

| | |
|---|---|
| `ctx.element(tag, inner, attrs?)` | собирает один узел. Значения экранируются автоматически |
| `ctx.escape(text)` | экранирует только текст |
| `ctx.url(raw)` · `ctx.src(raw)` | фильтрует адрес. Ненадёжный адрес — это **`null`** |
| `ctx.keys` | признак того, что сборка идёт **для редактора** (`getEditorHtml()`) |

::: warning Не склеивайте строки вручную
Запись вида `` `<kbd>${node.a?.['t']}</kbd>` `` превратит текст документа прямо
в разметку. Всегда проходите через `ctx.element` или `ctx.escape`.
:::

### `claim`

```ts
claim: (el, inner) => (el.tag === 'kbd' ? [{ w: 'kbd', ch: inner(false) }] : null)
```

| | |
|---|---|
| `el` | `{ kind, tag, attrs, children }` — элемент таким, каким он пришёл |
| `inner(block)` | читает содержимое. Для метки — `false` (место для текста), для блока — `true` |
| Ответ | массив узлов либо **`null`** (не моё — передаём следующему крылу) |

Крылья спрашивают по порядку массива, и забирает **первое, кто отозвался**.

Есть два места, где отвечают `null` — когда тег не мой, и когда **тег мой, но
значение вне списка**. Во втором случае, вернув `inner(false)`, снимают только
оболочку, сохраняя текст.

## Метка со значением

Для метки, которая **выбирает одно значение из фиксированного списка** — как
цвет или размер, — используется `valueMark`.

```ts
import { valueMark, type Wing } from 'nabi-note'

const LEVELS = ['low', 'mid', 'high'] as const

const riskWing: Wing = {
  ...valueMark({
    w: 'risk',
    key: 'v',                        // поле атрибута, где лежит значение
    values: [...LEVELS],             // значение вне этого списка не принимается
    toHtml: (node, children, ctx) =>
      ctx.element('span', children(), { 'data-risk': String(node.a?.['v'] ?? '') }),
  }),
  claim: (el, inner) => {
    if (el.tag !== 'span') return null
    const v = el.attrs['data-risk']
    if (v === undefined) return null
    if (!LEVELS.includes(v as typeof LEVELS[number])) return inner(false)   // вне списка — оставляем только текст
    return [{ w: 'risk', a: { v }, ch: inner(false) }]
  },
}
```

Что добавляет `valueMark`:

- **`currentValue`** — значение в том месте, где сейчас стоит каретка. По
  этому ответу панель инструментов и контекстная строка красят нажатое поле.
- **`repair`** — заново проверяет значение на входе из JSON. Если оно вне
  списка или отсутствует, возвращает `null`, и узел **уберётся вместе с
  оболочкой.** Здесь же отсеивается и сохранённое значение, изменённое
  вручную.

::: tip Команда, меняющая значение
У метки со значением пока нет опубликованного помощника «поставь именно это
значение». Включение и выключение одной кнопкой через `action: { kind:
'mark' }` работает как есть, а если нужен выбор значения, сейчас можно
использовать одну из четырёх встроенных меток со значением (маркер, цвет
текста, размер текста, гарнитура) или развернуть их объявление вручную.
:::

## `escapeKeys` — выход за пределы метки

Когда каретка стоит на самом конце метки, только человек знает, должен ли
следующий символ оказаться внутри неё или снаружи. Для этого и служит
`escapeKeys`.

```ts
escapeKeys: ['Escape']    // значение по умолчанию у simpleMark и valueMark
```

**Каретка при этом не двигается.** Нажатие этой клавиши ставит резерв:
«следующий введённый символ выходит за пределы этой метки». Как только вы
наберёте один символ, резерв срабатывает и исчезает.

```
<kbd>Ctrl</kbd>(каретка)  →  Escape  →  набираем "+"  →  <kbd>Ctrl</kbd>+
```

Одну и ту же клавишу может объявить несколько крыльев — резерв ставится только
если каретка сейчас действительно внутри этой метки, поэтому среди
наложенных друг на друга меток выходят только подходящие. <kbd>Escape</kbd>
также служит для того, чтобы **отменить** уже поставленный резерв.

## У метки не бывает своих клавиш

Даже если объявить `onKey`, **метке он не достанется.** Место каретки — это
`{ path, offset }`, и последний узел на этом пути — **держатель текста**;
метка — это лишь строчный узел внутри такого держателя, и на сам путь она
никогда не попадает. Определяя, кому принадлежит клавиша, ядро идёт по этому
пути вверх и метку просто не встречает.

Причина — наложение. Если нажать <kbd>Enter</kbd> внутри ссылки, вложенной в
курсив, вложенный в полужирный, способа решить, кто из трёх хозяин, не
существует. Единственная дверь, которая есть у метки для работы с клавишами, —
`escapeKeys`.
