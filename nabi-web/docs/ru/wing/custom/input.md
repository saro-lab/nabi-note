# Клавиши, автопреобразования, вставка

У крыла есть три двери на действия человека — **клавиши** (`onKey`), **набор текста**
(`inputRules`) и **экран** (`attach`).

---

## Путь, который проходит клавиша

Нажатие <kbd>Enter</kbd> предлагается по кругу в этом порядке. Кто первым забирает его, тот и
заканчивает путь.

```
① горячие клавиши панели   слушаются везде (вещи вроде Ctrl+B)
② автопреобразования       inputRules — только Enter и Space
③ onKey крыла              владельцу того места, где стоит каретка
④ прицеливание на кусок    backspace в самом начале абзаца → выделяет весь кусок перед ним
⑤ правила ядра             разбиение абзацев, удаление, шаг каретки
⑥ браузер                  только если никто выше не забрал
```

## `onKey` — перехват клавиши

```ts
import type { OnKey } from 'nabi-note'

const noteKeys: OnKey = (intent, doc, sel, env, owner) => {
  if (intent.key !== 'backspace') return null      // не моё дело — верните ядру
  if (sel.focus.offset !== 0) return null
  const first = [...owner.path, 0]
  if (first.length !== sel.focus.path.length) return null
  if (!first.every((v, i) => v === sel.focus.path[i])) return null
  return toggleNote(doc, sel, {}, env)             // backspace в самом начале первого слота — разворачивает заметку
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',
  toHtml: (_node, children, ctx) => ctx.element('aside', children()),
  commands: { toggleNote },
  onKey: noteKeys,
}
```

| Аргумент | Что это |
|---|---|
| `intent` | `{ key, dir? }` — какая клавиша |
| `doc` · `sel` · `env` | те же три, что получает команда |
| `owner` | `{ path, node }` — **узел, владельцем которого меня выбрали** |

Ответ — тот же `{ doc, selection }`, что возвращает команда, либо **`null`**. `null` означает
«не беру», и тогда продолжает ядро — всякий раз, когда ваши условия не выполнены, вы обязаны
ответить `null`.

### Какие клавиши приходят

| `intent.key` | Когда |
|---|---|
| `'enter'` | <kbd>Enter</kbd> **и** <kbd>Shift</kbd>+<kbd>Enter</kbd>, оба |
| `'tab'` · `'shiftTab'` | <kbd>Tab</kbd> · <kbd>Shift</kbd>+<kbd>Tab</kbd> |
| `'backspace'` · `'delete'` | оба удаления |
| `'arrow'` | стрелки. Направление — в `intent.dir` (`'left'`·`'right'`·`'up'`·`'down'`) |

Клавиши символов никогда не приходят. Символы печатает браузер, а ядро их записывает.

### Владелец ровно один

Пройдите **вверх** по пути каретки; первый узел, не являющийся абзацем, и крыло, которому этот
узел принадлежит, и есть владелец.

```
каретка на пути [1, 0, 0]                     кандидат в владельцы
  [1, 0, 0]  →  p        абзац, поэтому пропускается
  [1, 0]     →  note     ← владелец
  [1]        →  p (обёртка)  сюда не доходит
```

Поэтому **побеждает самый внутренний контейнер** — внутри списка внутри таблицы <kbd>Tab</kbd>
достаётся списку. Часть (`parts`) тоже может быть владельцем, и тогда `owner.node` — это узел
части, а вызывается `onKey` того крыла, что её объявило. Поэтому принято сперва разветвляться по
`owner.node.w`, чтобы понять, что именно выбрано.

Марка никогда не может быть владельцем — причина на [странице про инлайн](./inline).

## `inputRules` — построение форматирования одним лишь набором текста

Именно это превращает `# ` в заголовок, а `> ` — в цитату.

```ts
inputRules: [
  { trigger: 'space', pattern: /^>$/, run: () => ({ name: 'toggleQuote' }) },
]
```

| Поле | |
|---|---|
| `trigger` | `'space'` или `'enter'` — измеряется в **момент** нажатия этой клавиши |
| `pattern` | регулярное выражение. `run` получает совпадение |
| `run` | `{ name, args? }` — команда для запуска |
| `scope` | `'block'` (по умолчанию) или `'word'` |

### `'block'` — замена начала строки

Смотрит на **начало строки** перед кареткой. При совпадении удаляет этот префикс (и символ,
вызвавший срабатывание) и запускает команду.

```
набрать "> "   →   "&gt;" удаляется и запускается toggleQuote
```

Срабатывает только на **первой строке** абзаца. На строке, до которой добрались через
<kbd>Shift</kbd>+<kbd>Enter</kbd>, не срабатывает — это не даёт форматированию прорываться
посреди уже написанного текста.

### `'word'` — наложение марки на одно слово

Смотрит на **одно слово** перед кареткой. При совпадении выделяет это слово, запускает команду и
возвращает каретку на место. Текст не удаляется — это форма для правил, накладывающих марку.

Если это слово **уже несёт марку этого крыла, правило пропускается.** Оно не может сработать
дважды в одном месте.

### Общие правила

- Работает только пока каретка **свёрнута**. Нажатие пробела с выделенным диапазоном ничего не
  делает.
- Работает только в обычном абзаце — никогда в абзаце-обёртке, держащем кусок.
- Правила проверяются в порядке массива крыльев, и побеждает **первое сработавшее правило**.
- Если команда отвечает `null` (нечего делать), правило **откатывается и переходит к
  следующему.** Неудавшееся автопреобразование не оставляет в документе следа.

## `attach` — касание экрана

Иногда задача не в том, чтобы изменить документ, а в том, чтобы слушать **происходящее на
экране** — перетаскивание для выбора ячеек таблицы, раскраска кода, клик по треугольнику
раскрытия.

```ts
import type { Attach } from 'nabi-note'

const attachNote: Attach = (host) => {
  const onClick = (ev: MouseEvent): void => { /* … */ }
  host.root.addEventListener('click', onClick)
  return () => host.root.removeEventListener('click', onClick)   // ответьте функцией отключения
}
```

`host` даёт три вещи.

| | |
|---|---|
| `host.root` | элемент поверхности редактирования |
| `host.nabi` | редактор. Изменение документа делается **через команды** |
| `host.pathOfKey(id)` | превращает `data-key` на экране в путь внутри документа |

`mountSurface` подключает `attach` каждого зарегистрированного крыла вместе с собой и вызывает
возвращённые вами функции отключения, когда снимает всё. Это **единственный дом, где живёт код,
знающий DOM** — никогда не трогайте `document` внутри команды, `toHtml` или `repair`.

::: tip Поиск документа через `data-key`
Сборка для редактора (`getEditorHtml()`) помечает каждый узел атрибутом `data-key`. Найдите
ближайший `[data-key]` от кликнутого элемента и передайте его в `host.pathOfKey()`, чтобы
получить место внутри документа.
:::

## Вставка и исходный HTML

Вставка, `setHtml()` и загрузка сохранённого значения — всё проходит через **одну и ту же
дверь**. Единственная задача крыла здесь — `claim`; об этом написано на
[странице про инлайн, раздел `claim`](./inline#claim).

```
вставка       ─┐
setHtml       ─┼→ разбор → claim крыльев → обработка тегов по умолчанию ядром → repair → cocoon → документ
исходный HTML ─┘
```

Без `claim` **с этого тега снимается оболочка, и остаётся только текст внутри.** Именно это
правило не даёт незнакомой разметке, скопированной из чужого редактора, застрять в документе как
есть.

Путь через JSON (`setJson()`) несёт узлы, а не теги, поэтому привратник там — не `claim`, а
`repair`.
