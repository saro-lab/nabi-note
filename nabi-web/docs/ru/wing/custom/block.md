# Создание блоков и атрибутов абзаца

Занимающее место делится на три вида.

| `place` | Что это | Пример |
|---|---|---|
| `'void'` | **объект без содержимого**. Каретка не может зайти внутрь | линия, изображение, YouTube |
| `'container'` | **объект, содержащий текст** | цитата, спойлер, таблица, список, код |
| `'attr'` | значение, прикреплённое к самому абзацу. Узел не создаётся | заголовок, выравнивание, буквица |

---

## Объект живёт внутри абзаца-обёртки

Документ — это **массив блоков**, и на верхнем уровне может стоять только
абзац (`p`). Объект не встаёт на верхний уровень напрямую — он надевает один
абзац, который содержит только его самого.

```json
[{ "w": "p", "ch": [{ "w": "hr", "ch": [] }] }]
```

Этот абзац и есть **абзац-обёртка**, а на экране он рисуется как
`<div data-nabi-p>`.

Причины этому две. У объекта всегда есть место для каретки спереди и сзади (там
всегда стоит один абзац), и **атрибуты абзаца, такие как выравнивание, объект
наследует напрямую** — «картинка по центру» и означает «картинка внутри абзаца
по центру».

## Создание объекта без содержимого

```ts
import { boxObject, createNabiWith, insertLump, type Command, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const insertStar: Command = (doc, sel, _args, env) => {
  const r = insertLump(doc, sel.focus, { w: 'star', ch: [] }, env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const starWing: Wing = {
  ...boxObject({
    w: 'star',
    toHtml: (_node, _children, ctx) => ctx.element('hr', '', { 'data-nabi-star': '' }),
  }),
  commands: { insertStar },
  button: {
    group: 'insert',
    label: { ru: 'Звезда', en: 'Star' },
    action: { kind: 'command', command: 'insertStar' },
  },
}
```

`insertLump` сама надевает абзац-обёртку.

```
<div data-nabi-p><hr data-nabi-star/></div>
```

Если вызвать её над пустым абзацем, она **займёт место этого абзаца** — при
каждой вставке лишняя пустая строка не накапливается. А выравнивание, которое
уже нёс этот абзац, сохраняется как было.

`boxObject` заполняет за вас `place: 'void'` и **проверку атрибутов**.

```ts
boxObject({
  w: 'stamp',
  attrs: { c: (v) => (v === 'red' || v === 'blue' ? v : null) },   // значение вне списка отпадает
  requires: ['c'],                                                 // без него объект не встанет
  toHtml: /* … */,
})
```

Атрибут, не указанный в `attrs`, — это **незнакомое поле, и оно отбрасывается
целиком.** Места, где значение вне контракта незаметно оседало бы в сохранённом
значении, здесь нет.

## Создание объекта с содержимым

`place: 'container'` требует, чтобы рядом всегда стоял `holds` — без него
регистрация провалится.

```ts
import { createNabiWith, toggleWrap, type Command, type Wing } from 'nabi-note'

const toggleNote: Command = (doc, sel, _args, env) => {
  const r = toggleWrap(doc, sel, 'note', env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',                  // внутри живут абзацы (при 'inline' — только текст)
  allows: ['p'],                    // что может находиться внутри
  toHtml: (_node, children, ctx) => ctx.element('aside', children(), { 'data-nabi-note': '' }),
  claim: (el, inner) => (el.tag === 'aside' ? [{ w: 'note', ch: inner(true) }] : null),
  commands: { toggleNote },
  inputRules: [{ trigger: 'space', pattern: /^!$/, run: () => ({ name: 'toggleNote' }) }],
  button: {
    group: 'container',
    label: { ru: 'Заметка', en: 'Note' },
    action: { kind: 'command', command: 'toggleNote' },
  },
}
```

`toggleWrap` — это **переключатель**. Верхнеуровневые блоки, задетые
выделением, оборачивает в этот контейнер, а если они уже все обёрнуты —
разворачивает содержимое на месте.

```
до оборачивания   [p"первая строка", p"вторая"]
после оборачивания [p[ note[ p"первая строка", p"вторая" ] ]]
нажать снова        [p"первая строка", p"вторая"]
```

### `holds`

| | Что живёт внутри | Пример |
|---|---|---|
| `'blocks'` | абзацы и другие объекты | цитата, спойлер, ячейка таблицы |
| `'inline'` | только текст и метки | строка заголовка у спойлера, код |

### `allows`

Если указать, **всё остальное внутрь не попадёт.** Ядро само подключает
уборщика: и при вставке, и в сохранённом значении всё, чего нет в списке,
теряет оболочку, а голый текст опускается в абзац.

Если не указать — разрешено всё. Незнакомое имя в `allows` **убивает
регистрацию на месте.**

## `parts` — внутренняя структура без кнопки

Такие структуры, как строка и ячейка таблицы или строка заголовка у спойлера —
**не могут стоять сами по себе и не имеют собственной кнопки на панели** —
объявляются как части.

```ts
const detailsWing: Wing = {
  w: 'details',
  place: 'container',
  holds: 'blocks',
  boolAttrs: ['o'],                                   // атрибут со значением только 1 — развёрнуто ли
  parts: { summary: { holds: 'inline' } },            // строка заголовка
  toHtml: /* … */,
  partHtml: { summary: /* … */ },                     // у каждой части должна быть своя сборка
  repair: repairDetails,
}
```

Четыре правила.

- Части бывают **только у контейнеров.** Указать их при другом `place` —
  значит убить регистрацию.
- У каждой части обязателен `partHtml`. Нет его — регистрация проваливается.
- Имя части не может совпадать ни с именем крыла, ни с именем другой части.
- Если часть нужно приводить в порядок, это делает `partRepair` с именем части
  в качестве ключа.

`StructureDecl` принимает три поля — `holds` · `singleParagraph` · `boolAttrs`.

### `singleParagraph`

Содержимое **зафиксировано одним абзацем**. Так устроена ячейка таблицы — в ней
<kbd>Enter</kbd> не разбивает абзац надвое, а удаление выделения, протянутого
через две ячейки, не сливает их в одну. Именно это поле бережёт сетку.

### `boolAttrs`

Атрибут, у которого единственное значение — `1`: `o` у спойлера (развёрнут),
`ck` у списка задач (отмечено), `dc` у абзаца (буквица). Выключенное состояние —
не `0`, а **полное отсутствие этого поля**.

---

## `repair` — последняя дверь на входе сохранённого значения

`repair` приводит этот узел в порядок **прямо перед тем, как JSON станет
документом**.

```ts
repair: (node) => {
  if (!правильноЛи(node)) return null    // null — узел уберётся вместе с оболочкой
  return приведённыйУзел                  // можно вернуть как есть (тот же объект = ничего не меняется)
}
```

Через эту дверь проходит всё — сохранённое значение, изменённое вручную,
документ из другой версии, чужой JSON. Документом становится только то, что её
прошло, так что это **единственное место, где крыло само может поручиться за
форму своего узла.**

Если заданы и `allows`, и `repair`, уборка по `allows` проходит **первой**, а
её результат передаётся в `repair`.

---

## `requiresAnyOf` — крыло, которому нужна пара

```ts
requiresAnyOf: ['img', 'a']
```

Если ни одно из перечисленных не зарегистрировано вместе, **регистрация
проваливается на месте.** Этим пользуется крыло загрузки — загруженное нужно
поставить изображением или ссылкой, а без них обоих загрузка ничего не сможет
сделать с результатом.

---

## Атрибут абзаца (`place: 'attr'`)

Атрибут абзаца не создаёт узла. Он лишь кладёт одно значение в `a` самого
абзаца.

```json
{ "w": "p", "a": { "h": 2, "a": "c" }, "ch": ["Заголовок 2 по центру"] }
```

::: warning Поля жёстко ограничены тремя
`attrKey` обязан быть одним из трёх — **`h` (заголовок) · `a` (выравнивание) ·
`dc` (буквица)**, а любое другое имя убьёт регистрацию. **В текущей версии
новый атрибут абзаца создать нельзя** — поле атрибутов абзаца закрыто этими
тремя, которые знает ядро.

По той же причине эти три уже заняты `headingWing`·`alignWing`·`dropCapWing`, и
места для нового крыла с `place: 'attr'` практически не остаётся. Если нужно
класть своё значение на каждый абзац, сейчас лучше выбрать оборачивание
контейнером.
:::

Два поля, отвечающих за значение.

| | |
|---|---|
| `attrValues` | список допустимых значений (для заголовка — `[1,2,3,4,5,6]`) |
| `currentValue` | значение, которое сейчас несёт этот абзац. По этому ответу панель инструментов и контекстная строка красят нажатое поле |

## Опубликованные помощники для документа

Текущая версия отдаёт наружу четыре помощника для правки.

| | Что делает |
|---|---|
| `insertLump(doc, caret, lump, env, wrap?)` | ставит объект вместе с абзацем-обёрткой |
| `removeLump(doc, topIndex, env)` | убирает целиком один верхнеуровневый абзац-обёртку |
| `toggleWrap(doc, sel, containerW, env)` | оборачивает задетые блоки в контейнер или разворачивает их |
| `topNodeAt(doc, path)` | верхнеуровневый узел, которому принадлежит этот путь |

Все четыре возвращают `{ doc, caret }`, поэтому их результат один раз
переносят в форму, которую ожидает команда.

```ts
return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
```

::: tip Если нужна более тонкая правка
Внутренние помощники для правки на уровне символов (наложение метки, запись
атрибута абзаца и тому подобное) пока не входят в публичный API. До тех пор
можно собрать массив `doc` заново вручную — возвращённый документ ещё раз
пройдёт через `cocoon`, так что документ, нарушающий правила, не останется.
:::
