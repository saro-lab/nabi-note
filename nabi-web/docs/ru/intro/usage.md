# Базовое использование

Способ через npm. Про способ с одним `<script>` — в [{{ t('menu_intro_cdn') }}](./cdn).

```sh
npm i nabi-note
```

## Соединяем части вместе

Хост строит слоты и подключает mount-функции одну за другой. Ниже — минимальная сборка, и каждый
пример на страницах крыльев — этот же скелет с одним-двумя вставленными крыльями.

```html
<div id="app" class="nabi">
  <div id="chrome" class="nabi-toolbar">
    <div id="toolbar"></div>
    <div id="context"></div>
  </div>
  <div id="editor" class="nabi-content" contenteditable="true"></div>
</div>
```

```ts
import {
  createNabiWith,
  mountSurface,
  mountToolbar,
  mountContextToolbar,
  mountHints,
  mountViewTools,
  mountSticky,
  watchSettle,
  parseNodes,
  boldWing,
  italicWing,
} from 'nabi-note'
import 'nabi-note/nabi.css'

const app = document.querySelector<HTMLElement>('#app')!
const surface = document.querySelector<HTMLElement>('#editor')!

// Список крыльев строит вместе знание о видах, команды и сборщики — это и есть `registry`
const { nabi, registry } = createNabiWith([boldWing, italicWing], {
  parseHtml: parseNodes,
})

mountSurface({ nabi, registry, root: surface })

const settle = watchSettle(document, { surface })
const shared = { nabi, registry, surface, settle, locale: 'ru' }

const toolbar = mountToolbar({ ...shared, root: document.querySelector<HTMLElement>('#toolbar')! })
const context = mountContextToolbar({ ...shared, root: document.querySelector<HTMLElement>('#context')! })

mountHints({ toolbar, context, root: document.querySelector<HTMLElement>('#chrome')!, surface })
mountViewTools({ nabi, surface, root: app, container: document.querySelector<HTMLElement>('#toolbar')!, locale: 'ru' })
mountSticky({ root: app, surface })

// При каждом изменении значения — повесьте здесь свой код
// nabi.onChange(() => user_callback(nabi.getHtml()))
```

Хост строит слоты, а **ядро знает, как эти слоты выглядят** — mount сам крепит к своей коробке
`.nabi-toolbar-row`, `.nabi-context` и `.nabi-editing`, и сам поднимает свою панель инструментов.
Это значит, что хосту никогда не приходится продумывать раскладку, поэтому в разметке выше всего
три класса.

- **`class="nabi"`** — токены цвета и таблицы стилей живут только внутри него. Это ещё и коробка,
  которую целиком фиксирует полноэкранный режим, поэтому панель инструментов и область письма
  должны быть внутри неё **вместе**.
- **`class="nabi-toolbar"`** — связывает строку панели инструментов и контекстную строку в один
  кусок, чтобы они прилипали (**sticky**) вместе. Прикрепите их по отдельности — и текст будет
  сдвигаться вниз при появлении контекстной строки, экран задёргается.
- **`class="nabi-content" contenteditable`** — сама область письма.

Если на сайте есть закреплённая шапка, сдвиньте редактор вниз на её высоту через
`--nabi-sticky-top`; подключите `mountSticky()`, и ядро измерит, насколько мобильная клавиатура
подвинула экран вверх, и вернёт как было.

**Таблицу стилей подключает хост.** С бандлером достаточно `import 'nabi-note/nabi.css'`, а если
нужен только CSS зарегистрированных крыльев, вызовите
`injectSheets(document, collectSheets(registry))`. **Страницу, которая приходит уже отрисованной
сервером, подключайте через файл** — инъекция крепится только после того, как прибудет JS
редактора, и в эту паузу документ на миг отрисовывается голым.

**То же слово определяет и направление текста.** Дайте арабский (`ar`) или урду (`ur`), и к корню
этого mount добавится `dir="rtl"` — письмо встанет справа налево, даже если сама страница ничего
не говорит через `<html dir>`. Если `locale` не задан, направление никто не трогает: свой выбор
хоста, держащего направление в своих руках, ничто не перекрывает. Какому языку какое направление
соответствует, отвечает `localeDirection(code)`.

```ts
mountSurface({ nabi, registry, root: surface, locale: 'ar' })   // область письма — RTL
mountToolbar({ nabi, registry, surface, root: toolbar, locale: 'ar' })   // и панель инструментов — зеркалом
```

Язык отображения задаётся для каждого mount через `locale` — текст документа остаётся как есть,
меняются только названия на панели инструментов и в контекстной строке. **Хосту достаточно
объявить локаль один раз** — сложите её в одну общую запись (как shared в примере выше) и
передайте всем mount-функциям: когда встаёт панель инструментов, она заодно прописывает свою
`locale` и в ядре (`nabi.$bindLocale`), поэтому и слова, которые говорит само ядро (например,
toast), выходят на том же языке. Там, где панели инструментов нет, тот же язык задаётся опцией
`locale` у `createNabiWith`. Чтобы нарисовать переключатель, используйте `LOCALES` (список кодов),
который экспортирует пакет.

### Текст-подсказка в пустом редакторе

Пустой редактор бледным цветом показывает текст-подсказку в первой строке. Она исчезает в тот
момент, когда появляется хотя бы один символ, и появляется снова, если строку стереть до конца.
**Она показывается сама, без какой-либо настройки** — слова берутся из словаря ядра и следуют
языку этого mount. Место, где она стоит, определяет **направление письма** (слева при LTR, справа
при RTL) — даже если сама строка выровнена по центру или справа, подсказка направление не
повторяет.

```ts
mountSurface({ nabi, registry, root: surface, placeholder: 'Оставьте здесь заметку' })
mountSurface({ nabi, registry, root: surface, placeholder: 'Первая строка\nВторая строка' })   // несколько строк
mountSurface({ nabi, registry, root: surface, placeholder: '' })   // без подсказки
```

Перевод строки (`\n`) становится обычной строкой. Но подсказка стоит **вне потока** (чтобы не
сдвигать каретку), поэтому многострочная подсказка уходит вниз за пределы области письма, если та
короче самой подсказки. Пустая область письма по умолчанию уже стоит высотой `12.5rem`, так что в
большинстве случаев её можно не трогать; если нужно больше, увеличьте её через
`--nabi-content-min-height`. Это значение действует **только на поверхность редактирования** — в
опубликованном или предпросмотренном документе высоту задаёт сам текст.

**Подсказка — отдельный слой.** Она поднята на `::before` корня редактирования, поэтому **не
зависит от форматирования документа** — будь то заголовок, выравнивание по центру или буквица.
Где ей стоять, решает только направление письма.

Текст попадает в переменную `--nabi-placeholder` на корне области письма, а рисует её таблица
стилей. Чтобы изменить цвет или начертание, переопределите это правило.

```css
.nabi-content.nabi-editing:has(> :is(p, h1, h2, h3, h4, h5, h6):only-child > br:only-child)::before {
  color: #999;
}
```

Чтобы поменять только цвет, переопределять правило вовсе не нужно — хватит одной строки
`--nabi-placeholder-color`.

| Часть | Обязательна | Что делает |
|---|---|---|
| `createNabiWith(wings, options?)` | да | отвечает `{ nabi, registry }`. DOM не нужен. Принимает как массив крыльев, так и билдер выбора (`wings()`, см. [{{ t('menu_intro_cdn') }}](./cdn#выбор-крыльев)) |
| `mountSurface({ nabi, registry, root })` | да | согласует каретку, IME и ввод обратно с nabi-деревом. Также подключает `attach` каждого зарегистрированного крыла |
| `mountToolbar({ nabi, registry, root, surface?, locale?, file? })` | нет | основная панель инструментов. Без неё редактировать напрямую через `applyCommand()` всё равно можно. Вставьте в `file` ответ `mountFile()` — и **панель сохранения встанет без всякой проводки**: её открывают кнопка сохранения и <kbd>⌘</kbd><kbd>S</kbd>. Не вставите — нажатие, как и раньше, идёт к хосту через `onHost('save')`. `surface` — это ещё и **земля, на которой живут акселераторы** (см. [Где слышны акселераторы](#где-слышны-акселераторы)) |
| `mountContextToolbar({ nabi, registry, root, surface? })` | нет | контекстная строка по месту каретки (строки и столбцы таблицы, язык кода, адрес и имя ссылки и т. п.) |
| `mountHints({ toolbar, context?, root, surface? })` | нет | значки горячих клавиш, всплывающие при двойном нажатии Shift |
| `mountViewTools({ nabi, surface, root, container, onBody? })` | нет | кнопки предпросмотра и полноэкранного режима. `root` — коробка `.nabi`, которую зафиксирует полноэкранный режим, `onBody` — хук, подключающий рантайм чтения к телу предпросмотра (ниже) |
| `mountSticky({ root, surface, chrome?, nabi? })` | нет | возвращает столько, насколько мобильная клавиатура подняла прилипшую панель инструментов. Передайте `nabi` — и **после правки каретка сама выйдет из-под панели инструментов**; не передадите — всё работает как раньше, только когда хост сам зовёт `aim()` (см. [Мобильная клавиатура и прилипшая панель инструментов](#мобильная-клавиатура-и-прилипшая-панель-инструментов)) |
| `mountPickedMark({ nabi, surface })` | нет | пометка для выбранного изображения или видео (браузер её не рисует) |
| `mountFile({ nabi, store, registry, parse?, name? })` | при использовании save и open | сохраняет в **трёх** форматах — `.nabi`, `.nhtml`, `.md` — и открывает **четыре**: те же три плюс обычный `.html` откуда угодно. **`registry` обязателен** — из него берутся и список форматов, и сборка md и HTML. `parse` — дверь, читающая HTML; в браузере её можно не передавать, вместо неё встанет `parseNodes`, но в безголовом месте (сервер, тесты) её нужно передать, чтобы открывались `.nhtml` и `.html`. Возвращаемый `FileMount` — **канонический способ сохранять и открывать без крыльев** (`file.save()` · `file.saveAs(id, name)` · `file.formats()` · `await file.open()`) |
| `mountLocalHistory({ nabi, storage })` | при использовании localHistory | запись в браузере через заданный интервал. Поднимается и когда `storage` равен `null` (например, в заблокированном `file://`) — так кнопка может сказать через toast, почему она не работает |
| `mountUpload({ … })` + `mountUploadView({ … })` | при использовании upload | выполнение и отображение загрузок из перетаскивания, вставки или выбора файла |

**Для изображений, чекбоксов, перетаскивания ячеек таблицы и подсветки кода отдельно монтировать
нечего** — всё это крылья держат в `attach`, и `mountSurface` подключает это вместе с ними.
Единственное, для чего нужно кого-то подключить, — подсветка кода (`makeCodeAttach`, см.
[{{ t('menu_block_code') }}](../wing/block/code)).

### Где слышны акселераторы

Место, что слышит акселераторы вроде <kbd>⌘</kbd><kbd>S</kbd>, одно — панель инструментов.
Докуда достаёт её слух, рисует `mountToolbar({ surface })` — **только клавиша, поднятая внутри
этой поверхности или строк панели**, принадлежит этому редактору.

- **Если на странице два редактора, обязательно передайте `surface`.** Не передадите — панель по
  старой дороге слушает весь документ, и тогда <kbd>⌘</kbd><kbd>S</kbd>, набранная в нижнем
  редакторе, сохраняет текст верхнего. Редактор заберёт себе даже клавишу, нажатую в обычном поле
  ввода самого хоста.
- **Не зарегистрируете крыло — клавиши вообще нет.** Сохранение и открытие живут в ядре
  (`mountFile`), но кнопка и акселератор принадлежат крылу — поэтому у редактора, собранного одним
  лишь `wings().allBasic()`, нет ни <kbd>⌘</kbd><kbd>S</kbd>, ни <kbd>⌘</kbd><kbd>O</kbd>.
  Единственный путь назад — `.use('save').use('open')`.
- **Если некуда дойти, клавиша не проглатывается.** В настройке, где кнопка сохранения никуда не
  доходит (ни `file`, ни `onHost` не подключены к панели), клавиша течёт дальше — браузеру, как
  своя. Мы не отбираем сочетание клавиш ради работы, которую сами не делаем — проглотить его молча
  значило бы, что читатель решит, будто его браузер сломан.

Чтобы сохранять и открывать без крыльев, пользуйтесь ручкой, которую отдаёт `mountFile` — в
редакторе без кнопки и без акселератора хост сам зовёт `file.save()` и `file.open()`.

### Мобильная клавиатура и прилипшая панель инструментов

`mountSticky` теперь на мобильных делает больше — она следит, как поднимается и опускается
клавиатура, и выводит каретку **под панель инструментов и над клавиатуру**. Три вещи, которые
должен знать хост.

- **Двигается только пока редактор держит фокус.** Без фокуса — ни шагу: страница не должна
  прыгать, пока хост вталкивает значение через `setHtml()`.
- **Пока рука прокручивает, не сдвигается ни на пиксель.** После прокрутки стоит замок на 250 мс —
  отбирать экран у прокручивающей руки и есть то самое дрожание.
- **Ворота открывает только перемена размером с клавиатуру.** Схлопывание адресной строки
  (десятки пикселей) ничего не двигает; ворота открываются только за порогом `max(120px, 15%
  высоты окна)`.

Печать двигает **ровно настолько, насколько нужно** — тащить экран к панели инструментов на каждый
символ было бы невозможно использовать. Зато в момент, когда встаёт клавиатура, вид выстраивается
так, чтобы **панель инструментов встала у самого верха окна**, а когда область просмотра
успокаивается, выравнивание повторяется ещё раз.

`--nabi-bar-height` — значение, на которое опирается этот шаг: `mountSticky` записывает на корень
`.nabi` **реально измеренную высоту** крома, к которому подключена, а `.nabi-content > *` таблицы
стилей прибавляет это значение к `scroll-margin-block-start`. **Это не значение для настройки
хостом, а объяснение того, почему каретка никогда не прячется под панелью** — без этого mount
встанет приближённое `3.5rem`, а этого сильно не хватает, когда панель стоит в две строки или
поднята контекстная строка.

::: warning Не блокируйте масштабирование через viewport-мету
iOS Safari масштабирует всю страницу целиком, если фокус попадает в поле формы с текстом мельче
16px. Ядро останавливает это, **делая текст крупнее** — `--nabi-touch-font-size` (по умолчанию
`16px`). Мы **не пошли** другим путём — блокировать само масштабирование через
`user-scalable=no` или `maximum-scale=1`: этот путь отбирает у читателя право приблизить экран.
Если хост пишет эту мету на своей странице, установленный ядром пол теряет смысл — не пишите её.
:::

### Подключаем рантайм чтения к предпросмотру

Предпросмотр — это статический HTML, в который вставлен ровно `getHtml()`, поэтому то, что делает
JavaScript **на стороне чтения** — сортировка таблиц, подсветка кода, — само собой не подключается.
`attachViewer` из `nabi-note/viewer` вешает всё это одним вызовом, а в предпросмотре для него есть
хук `onBody` — замените строку `mountViewTools` из минимальной сборки выше вот так.

```ts
import { attachViewer } from 'nabi-note/viewer'

mountViewTools({
  nabi,
  surface,
  root: app,
  container: document.querySelector<HTMLElement>('#toolbar')!,
  locale: 'ru',
  onBody: (body) => attachViewer(body, { locale: 'ru' }),
})
```

`onBody` вызывается, когда встаёт тело предпросмотра, а функция снятия, которую вы вернёте в
ответ, вызывается, когда крышка закрывается. На опубликованной странице вешается **та же строка**
(`attachViewer`) — смысл этого хука именно в том, чтобы предпросмотр и опубликованная страница
несли одну и ту же дверь. Подробности — в
[{{ t('menu_intro_cdn') }} ▸ Сторона чтения](./cdn#сторона-чтения).

Подсветку кода по умолчанию берёт на себя встроенный токенизатор (без внешних зависимостей). Хост,
использующий такой подсвечиватель, как Shiki, передаёт тот же хук как
`attachViewer(body, { locale, highlight })` — если это тот же обработчик, что передан в
`makeCodeAttach({ highlight })`, цвета экрана редактирования и экрана чтения не разойдутся.

Чтобы заменить крылья, снимите все эти части (`unmount()`) и соберите заново — разметка, которую
держало удалённое крыло, тут же опускается до обычного текста. Демо на этом сайте работают именно
так: переключите чип крыла — и вся сборка пересоздаётся целиком.

CSS-переменные, включая цвета и формы, — в [{{ t('menu_style_custom') }}](../style/custom).

## Три пути наружу

```ts
nabi.getHtml()        // HTML, который вы сохраняете и публикуете
nabi.getJson()        // nabi-дерево (JSON)
nabi.getEditorHtml()  // HTML экрана редактора в текущем виде (несёт data-key)
```

**Сохраняйте одно из первых двух.** `getEditorHtml()` несёт пометку только для экрана
(`data-key`), поэтому это не то значение, которое вы экспортируете, — оно для предварительной
отрисовки редактора на сервере (SSR).

Исходящий JSON выглядит так. **Документ — это массив блоков**, без оборачивающего корневого узла.

```json
[
  {"w":"p","a":{"h":2},"ch":["Заголовок"]},
  {"w":"p","ch":["текст ",{"w":"b","ch":["жирный"]}," и ",
    {"w":"a","a":{"href":"https://nabi.saro.me/"},"ch":["ссылка"]}]},
  {"w":"p","a":{"a":"c"},"ch":["по центру"]},
  {"w":"p","ch":[{"w":"ul","ch":[
    {"w":"li","ch":[{"w":"p","ch":["один"]}]},
    {"w":"li","ch":[{"w":"p","ch":["два"]}]}]}]}
]
```

Читать его — всего четыре правила, и это всё.

- **`w` — это id крыла, которое рисует узел.** Зарезервированы только два слова, `p` (абзац) и
  `br` (строка); всё остальное — id зарегистрированного вами крыла: `b`, `ul`, `li` и подобные.
  Заголовок — не отдельное крыло, а **атрибут абзаца** (`{"w":"p","a":{"h":2}}`).
- **Строка — это текст, объект — это крыло.** Отдельного поля, называющего вид, нет.
- **`a` — это значение, которое несёт крыло** — адрес ссылки, цвет маркера, уровень заголовка.
  Отсутствует, когда нечего нести. Значение выравнивания — тоже `a`, но оно живёт **внутри** этого
  поля, так что два никогда не путаются (`{"w":"p","a":{"a":"c"}}` — абзац по центру).
- **Всё, что занимает место абзаца, — таблица, список или изображение, — обёрнуто одним слоем
  абзаца** (посмотрите на `ul` выше). Именно этот абзац несёт на себе выравнивание, и именно он
  даёт каретке, где встать до и после куска. В HTML он выходит как `<div data-nabi-p>` — потому
  что `<p>` по грамматике не может содержать таблицу или список.

Дерево, работающее внутри, несёт на каждом узле ещё одну вещь, `_id` — **внутренний адрес, по
которому каретка указывает на узел**. Большинство правок переиздают его заново, и он снимается на
выходе (464 → 317 байт для примера выше). То, что вышло, отправляется прямо обратно в `setJson()`
как есть.

## Четыре пути внутрь

```ts
createNabiWith(wings, { doc })   // начать с уже готового nabi-дерева
nabi.setJson(json)               // заменить весь документ на nabi-дерево
nabi.setHtml(html)               // заменить весь документ на строку HTML
nabi.applyCommand('setHeading', { value: 2 })  // команда редактирования (тот же шлюз, что используют крылья)
```

Все четыре **отвечают об успехе или неудаче через `boolean`.** Они не бросают исключений, а при
неудаче оставляют документ нетронутым. Слегка сбившееся значение **исправляется по ходу чтения**, а
не отвергается — пустая ячейка таблицы, не-строчный потомок таблицы, слияние с перехлёстом — а
опасные URL отфильтровываются на том же шаге. Отказ оставлен только для форм, которые вообще нельзя
прочитать. И даже значение, которое бросает исключение посреди чтения, никогда не останавливает
редактор — оно превращается в отказ (`false`), о котором сообщается через `console.error`.

| Где ответ `false` | |
|---|---|
| `setJson` | это не форма nabi-дерева (пустое значение — отдельный случай, см. ниже) |
| `setHtml` | адаптер `parseHtml` не подключён (ниже) или редактирование заблокировано (пустое значение — отдельный случай) |
| `applyCommand` | такой команды нет, или **ничего не меняется** |

**У пустого документа одна форма — `[{"w":"p","ch":[]}]`.** Стерев всё (выделить всё, затем
Backspace), вы получите именно её: заголовок или выравнивание первого блока не переживают этого.
Стереть один абзац из нескольких — другое дело: каретка остаётся там же, чтобы дописывать строку,
поэтому тот абзац сохраняет собственные атрибуты.

**Пустое значение — не ошибка формата, это пустой документ.** Дайте ему `null`, `undefined`, пустую
строку (пробелы тоже считаются) или пустой массив — и оно не откажет: **встанет пустым экраном и
ответит `true`**. Это верно и для `setJson`, и для `setHtml` — именно поэтому «стереть всё» всегда
получается. Пустому значению нечего читать, так что для него не нужен и адаптер `setHtml` (ниже).
Значение неправильной формы всё равно отвергается — пустое и искажённое не одно и то же.

Последняя строка — правило само по себе — **когда ничего не меняется, всё остаётся тихо.**
Наложите `setHeading` на абзац, уже являющийся заголовком уровня 2, и получите `false`, не
оставив ни точки отмены, ни сигнала.

Третий аргумент `applyCommand` — это **позвавшая рука**: у `applyCommand(name, args?, by?)`
параметр `by` — `'keyboard' | 'pointer'` (тип `CommandHand`), и если его не назвать, это
клавиатура. Разница проявляется в одном месте: команда-марка на схлопнутой каретке с клавиатуры
ставит резерв (применится к следующему набранному символу), а с указателя — без резерва отвечает
`false` и говорит через toast «нечего применять». Если вы строите свой UI и сами вызываете
команды, называйте `'pointer'` со стороны клика.

### `setHtml` нужен адаптер

Чтение HTML — работа `DOMParser` браузера. Ядро не знает DOM, поэтому вы подключаете этот адаптер
там, где объявляете редактор.

```ts
import { createNabiWith, parseNodes } from 'nabi-note'

const { nabi } = createNabiWith(wings, { parseHtml: parseNodes })
```

Для `setJson` адаптер не нужен — сохранённый JSON можно передать **прямо с сервера (Node.js)**.
Сборка (`getHtml`) тоже не использует DOM, так что путь чтения JSON на сервере и отправки
получившегося HTML открыт как есть.

## Вставка, сохранение и открытие

**Вставка читает один и тот же буфер обмена несколькими глазами** — `HTML`, `MARKDOWN`, `TEXT` и
собственный формат nabi (`NABI`). Если возможных прочтений больше одного, встаёт небольшая
панель с вопросом, какое взять; если оно одно, вставляется без вопросов. Вставка без единого
символа текста (только файлы) панель пропускает и уходит в
[{{ t('menu_etc_upload') }}](../wing/etc/upload).

**Сохраняются три формата** — `.nabi` (оригинал), `.nhtml` (самостоятельная HTML-страница) и
`.md` (markdown; всё, чему там нет места, подмешивается как HTML, поэтому может не вернуться в
прежнем виде). **Открываются четыре** — те же три плюс обычный `.html` откуда угодно. Для этой
двери нужен `mountFile()` из таблицы выше, а как подключить ещё один формат, написано в
[{{ t('menu_wing_custom') }}](../wing/custom#подключение-io-фильтра).

## Уведомления выходят через toast

Ошибка загрузки, подсказка локальной истории, «нечего применять» — все такие короткие сообщения
выходят **одним путём, через toast.** Коробку по умолчанию держит ядро, поэтому подключать ничего
не нужно — как только встаёт панель инструментов, toast появляется в закреплённом месте чуть ниже
неё (это место не сдвигается, даже когда контекстная строка появляется и исчезает).

- Уровней три — `'info' | 'warn' | 'error'`. Это не результат «успех/неудача», а шкала того,
  **насколько напряжённым должен быть читающий.**
- По умолчанию исчезает через секунду (последние 0,5 секунды тускнеет), закрывается и по клику.
  Одновременно стоит по умолчанию не больше 3 — при переполнении первым уходит тот, у кого меньше
  всего осталось времени.
- Сообщение может нести `\n`, и рисуется одинаково и в светлой, и в тёмной теме.

Две опции, меняющие поведение, и одна, целиком подменяющая отображение, — в `createNabiWith`.

```ts
const { nabi } = createNabiWith(wings, {
  toastMs: 2000,   // время жизни — по умолчанию 1000ms. Вызывающая сторона может задать его и на разовый вызов
  toastMax: 5,     // предел одновременно стоящих — по умолчанию 3
  // у страницы со своей системой уведомлений подменяется только отображение — коробка ядра по умолчанию ни разу не рисуется
  // toast: (level, message, ms) => user_callback(level, message),
})
```

У крыльев для этого тоже одна дверь — `nabi.$toast(level, message, ms?)`. Время передаётся вместе
с сообщением, поэтому ради одного длинного уведомления не нужно увеличивать общее значение по
умолчанию.

## Как редактор спрашивает

Открытие файла требует вопроса вроде «здесь уже что-то написано. Всё равно открыть?». Вы
подключаете эту коробку **один раз, там, где объявляете редактор**.

```ts
const { nabi } = createNabiWith(wings, {
  ask: {
    message: (text) => window.alert(text),
    confirm: (text) => window.confirm(text),
  },
})
```

| | Форма |
|---|---|
| `message` | `(text: string) => void` — одно сообщение, ответ не принимается |
| `confirm` | `(text: string) => boolean \| Promise<boolean>` — принимается и синхронный, и асинхронный вариант |
| `choose` | `(question: string, options: ChooseOption[]) => number \| Promise<number>` — один из нескольких. Ответ — **индекс**, а `-1` (или что угодно вне диапазона) — отмена. `ChooseOption` — это `{ label, icon? }`, где `icon` — **внутренность** svg 16×16 — не укажете, и останется одно имя |

**Ядро никогда само не тянется к браузерным диалогам.** Серая коробка не должна вламываться на
страницу с собственными диалогами, а у хоста-плагина (IntelliJ, VS Code) вообще нет
`window.confirm`. Эти три строки — дело хоста.

**Побеждают только подключённые слоты** — подключить один `message`, или один `confirm`, вполне
годится. Не подключённый `message` выходит как core toast (info), а не подключённый `confirm`
отвечает «нет».

**`choose` обычно не подключают.** Панель кандидатов вставки вешает себя на ядро сама, как только
встаёт панель инструментов (тот же приём, что и у toast-коробки), поэтому странице, которая
поднимает панель инструментов, ничего доподключать не нужно. Подключайте этот слот только когда
меняете панель на свою собственную. Если нет ни повешенной панели, ни подключённого слота, **ответ
— 0 (верхний)** — направление другое, чем «нет» у `confirm`. Ответь здесь отменой — и вставка
исчезнет целиком, а первый кандидат в списке всегда «самое вероятное прочтение», так что раз
спросить некого, это и есть верный ответ.

::: warning Не зададите — `confirm` отвечает «нет», а `choose` — верхним
Вопрос, на который никто не ответил, — это не «да»: это значит то же, что отмена, Escape и
закрытие окна. Этот ответ ложится на «выбросить написанное и открыть?», поэтому когда спросить
некого, нельзя идти по пути выбрасывания. На сервере (Node) это значение тоже тихо проходит мимо.
:::

**Это принадлежит одному редактору** — не странице, поэтому два редактора на одной странице могут
спрашивать по-разному. Крылья получают то же самое (`nabi.$ask`) — об этом рассказано в
[{{ t('menu_wing_custom') }} ▸ UI и поведение](../wing/custom/ui).

## Имя этого редактора и «изменилось ли»

```ts
nabi.sessionId   // '1755245678901-1x9k3af' — <unix-время>-<nonce>, по одному на экземпляр
nabi.isChanged() // сдвинулся ли документ с последней базовой точки
```

`sessionId` создаётся один раз и никогда не меняется. Время говорит, когда этот редактор встал, и
само по себе задаёт порядок сортировки, а nonce различает два редактора, вставших в одну и ту же
миллисекунду. Это метка, которую вешают на черновик, строку лога или ключ автосохранения.

**Новую базовую точку для `isChanged()` проводят три вещи** — целиком поставленный документ
(`createNabiWith({ doc })`, `setJson()`, `setHtml()`) и сообщение о том, что сохранение прошло.

```ts
nabi.$markSaved(savedDoc)   // после успешного сохранения — передайте документ, который сохранили именно тогда
```

**Передавайте дерево на момент сохранения** (не дерево в текущем виде). Символы, набранные во
время долгого сохранения, должны остаться «изменёнными». Крыло сохранения (`save`) вызывает это
после того, как файл действительно записан, поэтому сохранение в `.nabi` делает `isChanged()`
равным `false`.

::: warning Базовую точку двигает только `.nabi`
То, что выходит как `.nhtml` или `.md`, — это **копия**, и копия базовую точку не двигает — после
сохранения `isChanged()` остаётся `true`. Считайте копию «сохранённой», и окно закроется без
вопросов, унеся с собой настоящий текст. Если сохранение асинхронно, базовая точка двигается
**только после успеха** — неудавшееся сохранение её не трогает.
:::

**Отмените действия до начального состояния — и снова будет `false`** — nabi-дерево неизменяемо и
целиком заменяется при каждой правке, так что это известно на месте, без обхода или хеширования,
чтобы спросить, тот ли это документ.

```ts
window.addEventListener('beforeunload', (e) => {
  if (nabi.isChanged()) e.preventDefault()
})
```
