## Что вы только что сделали

Файл выше работает без чтения этого раздела. Загляните сюда, только когда захотите его изменить.

### Два тега — вся установка

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/nabi.css">
<script src="https://cdn.jsdelivr.net/npm/nabi-note@latest"></script>
```

**Всё**, что экспортирует пакет, висит на одной глобальной переменной `NabiNote`. **Таблицу стилей
вы подключаете сами** — mount-функции не внедряют CSS, так что если пропустить `<link>`, редактор
предстанет голым.

### Скелет

```html
<div id="app" class="nabi">                    <!-- корень, где живут цвета, скругления и шрифты -->
  <div id="chrome" class="nabi-toolbar">        <!-- панель инструментов и контекстная строка крепятся одним куском -->
    <div class="nabi-toolbar-row">
      <span id="tools"></span>                 <!-- предпросмотр и полноэкранный режим (крайний справа) -->
      <div id="toolbar"></div>
    </div>
    <div id="context"></div>                   <!-- заполняется сама в зависимости от того, на что указывает каретка -->
  </div>
  <div id="editor" class="nabi-content" contenteditable="true"></div>
</div>
```

`id` может быть любым — mount-функции передаётся **элемент**, а не имя. Четыре класса (`nabi`,
`nabi-toolbar`, `nabi-toolbar-row`, `nabi-content`) оставьте как есть — за них цепляется таблица
стилей. Если предпросмотр и полноэкранный режим не нужны, удалите `<span id="tools">` вместе со
строкой `mountViewTools`. Контейнер можно передать любой — свою коробку, плывущую к правому краю,
`mountViewTools` строит сама, поэтому даже передав ей саму панель инструментов, вы не собьёте
строку кнопок.

### Выбор крыльев

Выбор крыльев — это одна строка билдера. Файл выше берёт все двадцать девять стандартных крыльев,
убирает upload и сужает шрифт до двух вариантов.

```js
var wings = N.wings().all().drop('upload').use('tf', { values: ['sans', 'serif'] })
```

- `all()` начинает со всех официальных крыльев. **Если его не вызвать, список пуст** —
  загружается только то, что добавлено через `use()`.
- `use('имя', опции?)` — это добавление одного крыла. Вызванный для уже добавленного крыла, он
  просто добавляет опции — так устроен `use('tf', { values: [...] })` выше. Если нужному крылу
  требуется опора (upload не живёт без изображения или ссылки), она молча подтягивается вместе с
  ним.
- `drop('имя')` — это удаление из списка. Если вы пытаетесь убрать крыло, на которое опирается
  другое, билдер тут же бросает исключение и называет, что нужно убрать вместе с ним.
- Имя — это короткий ключ, который попадает в сохранённое значение: `b` (жирный), `tf` (шрифт),
  `upload` и подобные. Полный список — `console.log(N.wingNames())`.

  **Неверный вызов бросает исключение прямо в этой строке.** Опечатка в имени, незнакомый ключ
  опции, значение вне списка — исключение несёт способ починки: `use('bod')` отвечает «может быть,
  'b' (жирный)?». Молча игнорируемых мест нет.

`createNabiWith` принимает билдер как есть, так что вызывать `build()` незачем — он превращает
билдер в массив только там, где нужен именно массив. Когда выбирают лишь несколько крыльев, массив
по-прежнему годится.

```js
var wings = [N.boldWing, N.italicWing, N.headingWing, N.bulletListWing]
```

Своё крыло добавляется как объект — `N.wings().all().use(customWing)`. Его `w` должен начинаться
с `ex` (`exNote`) — если оно совпадёт с будущим официальным именем в сохранённом значении, уже
сохранённый документ прочитается по-другому. Как его сделать, написано в
[{{ t('menu_wing_custom') }}](../wing/custom).

Крылья по отдельности описаны в [{{ t('menu_wing') }}](../wing/inline/bold).

### Вопросы и уведомления

Файл выше подключил `alert`/`confirm` браузера через `ask` — вопрос вроде «здесь уже что-то
написано. Всё равно открыть?» идёт в эту коробку. Если её не подключить, ответом на вопрос будет
«нет», а короткие сообщения, не требующие ответа, показывает toast-коробка ядра под панелью
инструментов — для таких уведомлений, как ошибка загрузки, отдельно подключать ничего не нужно.
Подробности — в [{{ t('menu_intro_usage') }}](./usage).

### Извлечение значения

| | |
|---|---|
| `nabi.getHtml()` | HTML, который вы сохраняете и публикуете |
| `nabi.getJson()` | nabi-дерево (JSON) |
| `nabi.setHtml(html)` · `nabi.setJson(json)` | вставить обратно |
| `nabi.onChange(fn)` | при каждом изменении значения |
| `N.renderStoredHtml(json, registry)` | сохранённое значение в HTML без редактора (ниже, [Сторона чтения](#сторона-чтения)) |

## Адреса

Чтобы зафиксировать версию, добавьте номер версии в адрес. unpkg отдаёт тот же файл.

**Не используйте адрес без версии (`/npm/nabi-note`)** — jsDelivr долго кеширует это место, и
пакет со стилями могут перемешаться из разных версий.

| | Адрес |
|---|---|
| **пакет (последняя версия)** | `https://cdn.jsdelivr.net/npm/nabi-note@latest` |
| **пакет (зафиксированная версия)** | <code>{{ CDN_BUNDLE }}</code> |
| **таблица стилей (последняя версия)** | `https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/nabi.css` |
| **таблица стилей (зафиксированная версия)** | <code>{{ CDN_SHEET }}</code> |
| **пакет** (unpkg) | `https://unpkg.com/nabi-note` |

Пакет поставляется внутри самого npm-релиза, поэтому **CDN — не отдельный релиз.**

## Сторона чтения

Страница, которая только **показывает** сохранённый HTML, не поднимает редактор. Подключите ту же
таблицу стилей, поместите значение внутрь `.nabi-content` — и получится точно так же, как выглядело
в редакторе.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/nabi.css">

<div class="nabi-content">
  <!-- значение, сохранённое через getHtml() -->
</div>
```

Если значение сохранено **не как HTML, а как nabi-дерево (JSON)**, редактор поднимать тоже не
нужно — отрисуйте его прямо на месте. Нужны только сохранённое значение и список
зарегистрированных крыльев.

```html
<script>
  var registry = N.makeRegistry(N.wings().all().build())

  var saved = [{ w: 'p', ch: ['одна строка комментария'] }]   // nabi-дерево, полученное с сервера
  document.querySelector('.nabi-content').innerHTML = N.renderStoredHtml(saved, registry)
</script>
```

Если это не nabi-дерево, ответ — `null`, а прошедшее значение не отличается ни на один символ от
`getHtml()` редактора — место, где отфильтровывается XSS, то же самое. Эта дверь не использует
DOM, поэтому одинаково работает и на сервере (Node.js) — тем самым путём открывается и
**заблаговременная сборка HTML на сервере** (см.
[{{ t('menu_intro_ssr') }}](./ssr#место-где-рисуют-только-сохранённое-значение-без-редактора)).

Сервер, подключаемый через npm, использует не глобальный пакет, а **`nabi-note/ssr`** — это вход,
несущий только то, что нужно для отрисовки, поэтому поверхность редактирования и элементы экрана
в него не попадают.

В одном файле таблицы стилей содержится **CSS всех крыльев** — файл не может знать, какие крылья
вы зарегистрировали, поэтому несёт их все.

То, как выглядит документ, целиком берёт на себя таблица стилей, но **сортировка таблиц и
подсветка кода — это работа, которую на стороне чтения должен делать JavaScript** — переставить
строки по клику на заголовок столбца или разбить код на части и раскрасить их CSS не может. Если
это нужно, рантайм стороны чтения подключается одной дверью.

```html
<script type="module">
  import { attachViewer } from 'https://cdn.jsdelivr.net/npm/nabi-note@latest/dist/viewer/index.js'

  attachViewer(document.querySelector('.nabi-content'), { locale: 'ru' })
</script>
```

- Без этого документ всё равно виден нормально — просто включённая сортировка таблицы не работает,
  а код остаётся одного цвета.
- Сортировка таблиц подключается только к таблице, у которой сортировка была включена в редакторе
  (на ней остаётся пометка `data-nabi-sortable`).
- Подсветку кода по умолчанию берёт на себя встроенный токенизатор — зависимости не нужны. Чтобы
  использовать такой подсвечиватель, как Shiki, подключите его через хук —
  `{ locale: 'ru', highlight }`; эта нагрузка ложится на страницу, которая его подключила.
- В глобальном пакете `NabiNote` этой двери нет — чтобы читающая страница не тащила весь редактор
  целиком, `nabi-note/viewer` существует отдельно. Хост, подключающий пакет через npm, вешает ту же
  дверь и на предпросмотр — так же, как в
  [{{ t('menu_intro_usage') }}](./usage#подключаем-рантайм-чтения-к-предпросмотру).
