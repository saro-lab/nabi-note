# Поддержка SSR

## Место, где рисуют только сохранённое значение — без редактора

Такому месту, как список комментариев, который **только показывает** документ, редактор не нужен.
Всё, что требуется для отрисовки документа, — это список зарегистрированных крыльев (`registry`),
поэтому для него есть отдельная дверь, принимающая только его.

```ts
import { makeRegistry, defaultWings, renderStoredHtml, renderStoredEditorHtml } from 'nabi-note/ssr'

// один раз при старте сервера — на него опирается любое число сохранённых документов
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['одна строка комментария'] }]   // nabi-дерево, прочитанное из БД

renderStoredHtml(saved, registry)        // '<p>одна строка комментария</p>'
renderStoredEditorHtml(saved, registry)  // '<p data-key="n0">одна строка комментария</p>'
```

**`nabi-note/ssr` — это вход, в котором есть только то, что нужно для отрисовки.** Он не задевает
ни одного файла поверхности редактирования (`surface`) или элементов экрана (`ui`) — это следит
сеть, — поэтому в серверную сборку не может попасть код, завязанный на DOM. Та же дверь есть и в
`nabi-note`, так что странице, уже несущей редактор, можно пользоваться ею напрямую.

| | |
|---|---|
| `renderStoredHtml(json, registry, options?)` | HTML, который вы сохраняете и публикуете — то же значение, что и `getHtml()` |
| `renderStoredEditorHtml(json, registry, options?)` | HTML редактора — то же значение, что и `getEditorHtml()` (несёт `data-key`) |

- **Обе не используют DOM** — одинаково работают на сервере.
- **Если это не nabi-дерево — `null`.** Правило отказа то же, что у `setJson()` (весь документ
  должен быть массивом). Исключений не бросают.
- **Не отличаются ни на один символ от значения, которое отдаёт редактор.** Обе проходят один и
  тот же путь (нормализация → сборка), поэтому и место, где отфильтровывается XSS, одно и то же —
  сторона показа не бывает отфильтрована слабее.
- `options` — это только `{ allowLocalUrls }`, в том же смысле, что и у `createNabiWith`.

**Одно и то же сохранённое значение всегда получает один и тот же `data-key`.** Поэтому если
сервер заранее отрисовал редактор через `renderStoredEditorHtml` и отправил его вниз, а браузер
подхватил это через `hydrate`, экран не перерисовывается заново.

```ts
mountSurface({ nabi, registry, root: surface, hydrate: true })
```

Если что-то не сошлось, экран в этом месте просто перерисовывается заново — нужно лишь, чтобы
список крыльев на сервере и на клиенте совпадал.

::: tip Главная страница этого сайта — тот самый образец
Документ демо на главной странице **отрисован во время сборки через `renderStoredEditorHtml`** и
вшит в страницу, а редактор просыпается поверх него через `hydrate`. Поэтому текст читается ещё
до того, как прибудет код редактора — не бывает промежутка, где место пусто, а потом вдруг
заполняется.
:::

## Панель инструментов тоже можно отрисовать заранее

Строка кнопок **не смотрит на документ.** Она зависит только от списка зарегистрированных крыльев,
названий и порядка групп, поэтому получающиеся символы — **константа**: сервер вызывает функцию
один раз при старте и дальше просто использует эту строку. Незачем вызывать её заново на каждый
запрос.

```ts
import { makeRegistry, defaultWings, renderToolbarHtml } from 'nabi-note/ssr'

const registry = makeRegistry(defaultWings)

const toolbarHtml = renderToolbarHtml({ registry, locale: 'ru' })
// '<div class="nabi-group" data-group="font">…</div>'
```

Отправьте эту строку прямо внутрь коробки панели инструментов — в браузере `mountToolbar` рисует
**той же функцией**. Если такая же строка уже стоит, он **не перерисовывает её заново, а только
подключает обработчики.**

```ts
mountToolbar({ nabi, registry, surface, root: toolbar })
```

::: warning Пометьте коробку классом `class="nabi-toolbar-row"` заранее
Когда вы отправляете заранее отрисованную строку, этот класс должен быть **с самого первого
кадра**. Если его нет, ядро само добавит его при mount — но тогда боковые отступы появятся именно
в этот момент, и **строка кнопок на миг сдвинется в сторону.** Если хост пропишет класс заранее,
ядро его не трогает (снимает только то, что повесило само).

```html
<div class="nabi-toolbar-row">заранее отрисованная строка</div>
```
:::

- **Несовпадение ничего не ломает** — если стоящая строка отличается от нынешнего списка крыльев,
  она в этот же момент перерисовывается заново. Теряется только заранее отрисованное значение,
  экран всегда остаётся верным.
- **Заранее отрисованная строка стоит в состоянии «ничего не нажато, ничего не скрыто».**
  Нажатость (`aria-pressed`) и скрытость определяет каретка, а сервер её не знает. Если в вашей
  сборке кнопки скрываются в зависимости от каретки, после mount часть из них может исчезнуть, и
  строка снова сожмётся.
- **Кладите это только там, где поднимаете редактор.** У страницы, которая только читает, нет
  панели инструментов, и получать эти символы ей незачем.

**Две кнопки, предпросмотр и полноэкранный режим, идут тем же путём.** Они не крылья, а часть
собственного слоя, поэтому в строку панели инструментов выше не входят — отрисовываются отдельно
и вставляются в коробку, которую поднимает `mountViewTools`.

```ts
import { renderViewToolsHtml } from 'nabi-note/ssr'

renderViewToolsHtml({ locale: 'ru' })
// '<span class="nabi-tools">…</span>'
```

::: tip Главная страница этого сайта — тот самый образец
Панель инструментов демо на главной странице **отрисована во время сборки через
`renderToolbarHtml` и `renderViewToolsHtml`** и вшит в страницу, а `mountToolbar` и
`mountViewTools` узнают эту строку и только подключают обработчики. Поэтому тридцать пять иконок
не появляются с запозданием.
:::
