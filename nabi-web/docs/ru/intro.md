# Что такое NABI NOTE?

NABI NOTE — это **открытый WYSIWYG-редактор**, работающий в браузере.


## Nabi-дерево

Обработка через строку HTML напрямую невозможна на сервере — там нет DOM. Поэтому документ
хранится как **nabi-дерево** — обычный объект JavaScript, который сериализуется в обе стороны,
в JSON и в HTML. При самом преобразовании между nabi-деревом и HTML элементы, пригодные для XSS,
отфильтровываются.

> Все крылья, которые поставляет сам nabi-note, защищены от XSS, но для **кастомных крыльев
> (сторонних плагинов)** защиту от XSS нужно уточнять у их автора.

## SSR без DOM (поддержка на стороне сервера)

Сохранённое nabi-дерево можно **прочитать прямо на сервере (Node.js)** и собрать из него HTML,
который будет отправлен клиенту. DOM нужен только для **входа** (`setHtml()`) и для функций
`mount*`, которые крепятся к экрану.

Странице, которая лишь показывает документ, не нужно поднимать редактор целиком — достаточно
одной функции. На вход она принимает сохранённое дерево и `registry` (список зарегистрированных
крыльев), на выходе отдаёт строку HTML.

**На сервере используется вход `nabi-note/ssr`** — в нём есть только то, что нужно для отрисовки,
поэтому поверхность редактирования и элементы экрана в него вообще не попадают.

```ts
import { makeRegistry, defaultWings, renderStoredHtml } from 'nabi-note/ssr'

// Список крыльев собирается один раз при старте сервера — на него опирается любое число сохранённых документов.
const registry = makeRegistry(defaultWings)

const saved = [{ w: 'p', ch: ['одна строка комментария'] }]   // nabi-дерево, прочитанное из БД
renderStoredHtml(saved, registry)
// '<p>одна строка комментария</p>'
```

**Если это не nabi-дерево, ответ — `null`.** Правило отказа то же, что у `setJson()`. Прошедшее
значение **не отличается ни на один символ** от того, что отдаёт `getHtml()` редактора — оба
проходят один и тот же путь (нормализация → сборка), а значит, и место, где отфильтровывается
XSS, одно и то же.

Чтобы заранее отрисовать на сервере сам редактор, есть парная функция — к разметке добавляется
только `data-key`.

```ts
import { renderStoredEditorHtml } from 'nabi-note/ssr'

renderStoredEditorHtml(saved, registry)
// '<p data-key="n0">одна строка комментария</p>'
```

Одно и то же сохранённое значение всегда получает один и тот же `data-key`, поэтому если отправить
такой HTML как есть и подхватить его в браузере через
`mountSurface({ nabi, registry, root, hydrate: true })`, экран не перерисовывается заново.
**Демонстрация на главной странице этого сайта устроена именно так** — документ на первом экране
отрисован сервером, и редактор просто просыпается поверх него.

### Три входа

| Что подключить | Что внутри | Когда |
|---|---|---|
| `nabi-note` | Редактор целиком — сборка, поверхность, элементы экрана | Там, где документ **пишут** |
| `nabi-note/ssr` | Только отрисовка сохранённого значения в HTML | Сервер, или страница, которая только читает |
| `nabi-note/viewer` | Поведение на стороне чтения (сортировка таблиц, подсветка кода) | Там, где опубликованный HTML **показывают** |

`nabi-note/ssr` **не задевает ни одного файла** поверхности редактирования (`surface`) или
элементов экрана (`ui`) — это проверяет сеть, обходящая исходники. Поэтому в серверную сборку не
может случайно попасть код, завязанный на DOM.

## Каждый формат — это крыло

То, что другие редакторы называют «плагином», мы называем **крылом (wing)**. Ядро напрямую знает
только абзац (`p`), строку (`br`) и обычный текст — заголовки, списки, таблицы и жирный шрифт
целиком относятся к крыльям.

```ts
import { createNabiWith, parseNodes, boldWing } from 'nabi-note'

const bare = createNabiWith([], { parseHtml: parseNodes }).nabi
bare.setHtml('<p><b>жирный</b> <i>курсив</i></p>')
bare.getHtml()
// '<p>жирный курсив</p>'                    — крыльев не объявлено, всё стало обычным текстом.

const bold = createNabiWith([boldWing], { parseHtml: parseNodes }).nabi
bold.setHtml('<p><b>жирный</b> <i>курсив</i></p>')
bold.getHtml()
// '<p><b>жирный</b> курсив</p>'              — объявлен только boldWing, поэтому выжил только он, остальное стало текстом.
```

Разметка, которую вы не зарегистрировали крылом, **превращается в обычный текст.** Поэтому
необъявленный HTML отсеивается сам собой, а все крылья, официально поддерживаемые nabi, снимают
вредоносные скрипты.


## Интерфейс

Документ можно изменить только через `applyCommand()`.

```ts
nabi.applyCommand('toggleMark', { w: 'b' })     // жирный
nabi.applyCommand('setHeading', { value: 2 })   // заголовок 2 уровня
nabi.undo()
nabi.redo()
```

Команда **отвечает `boolean`** — успела она или нет. Если ничего не изменилось, ответ — `false`,
и ни история, ни сам документ при этом не трогаются.


## Слои складываются снизу вверх

**Порядок ниже не означает, что значение течёт именно в такой последовательности.** Это
направление **зависимостей**, сложенное снизу вверх, и правило одно — **нижний слой не знает о
верхнем**. Поэтому нижние слои (`schema`, `doc`, `html`) не касаются DOM, и именно поэтому они
одинаково работают на сервере. Путь, по которому течёт само значение, — это схема nabi-дерева
выше.

Это направление — не договорённость на бумаге, а то, что **проверяет сеть**: стоит появиться
хотя бы одному импорту, идущему против слоёв, и тест в этом месте падает.


## Глоссарий

| Слово | Значение |
|---|---|
| **марка (mark)** | форматирование текста, например `<b>` · `<i>` · `<a>` |
| **блок (block)** | например абзац · заголовок · список · таблица · изображение |
| **атрибут абзаца (paragraph attribute)** | свойство самого абзаца, например выравнивание · буквица |
| **абзац-обёртка** | абзац, который оборачивает такие однопараграфные объекты, как таблица, список, изображение |
| **притязание (claim)** | суждение о том, какому крылу принадлежит та или иная разметка |
| **части (parts)** | внутренние элементы крыла, например строки и ячейки таблицы, строка резюме в «Подробностях» |

### Экран редактирования

| Слово | Значение |
|---|---|
| **каретка (caret)** | курсор выделения внутри редактора |
| **контекстная строка (context row)** | панель, управляющая тем, что выбрано в данный момент под кареткой, например команды строк и столбцов таблицы, поле языка кода, поля адреса и имени ссылки, H1–H6 заголовка |

### Ядро

| Слово | Значение |
|---|---|
| **cocoon** | шаг нормализации nabi-дерева. Выполняется **после каждой команды**, поэтому ни одна команда не может оставить документ, нарушающий правила |
| **attach** | хук, который крыло объявляет, когда ему нужно коснуться экрана, например перетаскивание ячеек таблицы, подсветка кода, переключение задачи. `mountSurface` подключает то, что принадлежит зарегистрированным крыльям |
| **автопреобразование (input rule)** | преобразование, происходящее от одного лишь набора текста, например дефис и пробел становятся списком, `#` и пробел становятся заголовком |
