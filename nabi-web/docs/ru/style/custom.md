# Настройка стилей

**Таблицу стилей подключает хост** — с бандлером одна строка `import 'nabi-note/nabi.css'`, на
CDN один `<link>`. После этого всё сводится к переопределению переменных.

В правилах компонентов **нет ни одного цветового литерала.** Всё нарисовано через переменные
`--nabi-*`, так что переопределите переменные — и остальное подтянется само.

```css
.nabi.nabi.nabi {
  --nabi-accent: #7c3aed;
}
```

Почему класс повторён трижды — в разделе [Не попасться на
специфичность](#не-попасться-на-специфичность) ниже.

::: tip Главная предпосылка этой страницы — сохранённое значение не стоит само по себе
В исходящем HTML (`getHtml()`) **нет ни одного символа инлайнового `style`.** Сохранённое
значение говорит только *чем* что-то является, через атрибуты (`data-nabi-align="center"`), а как
это выглядит, говорит эта таблица стилей. Поэтому, когда сторона чтения рисует сохранённый HTML,
она должна быть **внутри `.nabi-content` с этой таблицей стилей**, чтобы выглядеть так же, как в
редакторе, — см. [Отрисовка сохранённого HTML в другом месте](#отрисовка-сохранённого-html-в-другом-месте)
ниже.
:::

::: tip Тёмная и светлая темы уже встроены
**Нет** ни одного токена, который хосту нужно переопределять ради темы. Основная таблица стилей
несёт все три сразу — светлые значения по умолчанию, переопределение `.dark` и явное
переопределение `.light`. Внутри редактора этот сайт не переопределяет ничего, кроме четырёх
токенов шрифта.
:::

## Токены цвета и формы

| Токен | Значение | По умолчанию (светлая тема) |
|---|---|---|
| `--nabi-bg` · `--nabi-soft` | фон · слегка вдавленная поверхность | `#fff` · `rgb(0 0 0 / 4.5%)` |
| `--nabi-fg` · `--nabi-muted` · `--nabi-on-accent` | текст · приглушённый текст · текст на акценте | `#1b1b1f` · `#6b6b76` · `#fff` |
| `--nabi-line` · `--nabi-accent` | линии · акцентный цвет | `#e2e2e8` · `#3b6fe0` |
| `--nabi-danger` · `--nabi-on-danger` | опасность · текст на ней | `#d93b3b` · `#fff` |
| `--nabi-shadow` · `--nabi-scrim` | тень коробки · фон предпросмотра | — |
| `--nabi-radius` · `--nabi-radius-sm` · `--nabi-radius-xs` | скругления | `6px` · `4px` · `3px` |
| `--nabi-layer-radius` | скругления слоя (панель, предпросмотр, лайтбокс) | `.25rem` |
| `--nabi-z-sticky` | номер слоя прилипшей строки | `20` |
| `--nabi-grid-cell` | размер ячейки сетки размера таблицы | `1.125rem` |
| `--nabi-hl-yellow`·`green`·`cyan`·`pink`·`purple`·`orange` | шесть цветов маркера | полупрозрачные цвета |
| `--nabi-tc-green`·`coral`·`violet`·`amber`·`blue` | пять цветов текста | насыщенные цвета |

Эта таблица содержит только то, что основная таблица стилей (`nabi.css`) **объявляет сама**.
Объявление находится в трёх местах, а не только в `.nabi` —
`:is(.nabi, .nabi-scrim, .nabi-content:where(:not(.nabi *)))`. Оверлей предпросмотра — дочерний
элемент `body`, поэтому наследование от `.nabi` до него не доходит, а `.nabi-content`, стоящий сам
по себе вне редактора, тоже должен получать токены напрямую.

Один и тот же список выписан трижды (светлые значения по умолчанию, `.dark`, явный `.light`).
**Переопределяющей стороне не нужно смотреть на все три** — победите специфичность один раз, и
записанное вами значение применится во всех трёх случаях. Но если в тёмной теме нужно другое
значение, условие `.dark` придётся прикрепить самостоятельно.

## Токены, на которые только ссылаются, но не объявляют

Ниже — переменные, на которые ядро **только ссылается, не объявляя их**. Не задайте им значение —
и сработает запасное значение в скобках. Раз места объявления нет, **запись в `:root` срабатывает
как есть** — этим они отличаются от цветовых и формостных токенов выше (те объявлены на `.nabi`, где
наследование не может победить).

| Токен | Значение | Запасное значение |
|---|---|---|
| `--nabi-font` · `--nabi-font-serif` · `--nabi-font-mono` · `--nabi-font-cursive` | шрифты, реально привязанные к четырём видам крыла шрифта | системные шрифты |
| `--nabi-cursive-adjust` | `font-size-adjust` для курсива. У рукописного шрифта низкая x-height, и при том же px он выглядит мельче, а это значение заново соизмеряет его по x-height | `0.4` |
| `--nabi-sticky-top` | насколько низко садится прилипшая строка. Если у сайта есть закреплённая шапка — её высота | `0px` |
| `--nabi-preview-width` | ширина карточки предпросмотра. **`openPreview` при открытии измеряет ширину области редактирования и записывает её прямо на карточку**, так что инлайновое значение побеждает всё, что вы зададите снаружи | `720px` |

`--nabi-typeface-base` не из этого разряда — **его объявляет ядро** (по умолчанию следует за
`--nabi-font`). У крыла шрифта нет опции для этого, так что для изменения переопределяйте токен.

`--nabi-keyboard-top` и `--nabi-keyboard-bottom` стоят в том же месте, но их **пишет ядро** —
`mountSticky()` измеряет, насколько мобильная клавиатура подняла экран, и записывает сюда, а
прилипшая строка и полноэкранный режим читают это значение. Это не значения для ручной записи.

## Где нет токена — переопределяйте правило

У трёх ниже **нет переменной**. Ядро зашивает значение прямо в правило, так что для изменения
переопределяйте его селектор.

**Четыре размера текста** — в `em`, поэтому следуют размеру родителя.

```css
.nabi-content [data-nabi-size="xs"] { font-size: .75em; }
.nabi-content [data-nabi-size="sm"] { font-size: .875em; }
.nabi-content [data-nabi-size="lg"] { font-size: 1.25em; }
.nabi-content [data-nabi-size="xl"] { font-size: 1.5em; }
```

**Размер буквицы** — не число строк для обёртывания, а всего лишь размер буквы. Сколько строк она
реально накроет, решает высота строки того абзаца.

```css
.nabi-content [data-nabi-dropcap="1"]::first-letter { font-size: 5.9em; line-height: .83; }
```

**Цвета токенов кода** — таблица стилей крыла кода пишет цвета прямо на `[data-nabi-token]`.
Сейчас цвет получают **пять** видов.

```css
.nabi-content [data-nabi-token="comment"] { color: #7a8a7a; font-style: italic; }
.nabi-content [data-nabi-token="string"] { color: #a2543a; }
.nabi-content [data-nabi-token="keyword"] { color: #7b4fd0; }
.nabi-content [data-nabi-token="number"] { color: #2f6fd0; }
.nabi-content [data-nabi-token="literal"] { color: #2f8f4e; }
```

`type`, которым отвечает подсветчик, — произвольная строка: любое имя вне этих пяти рисуется без
цвета, так что для нужных видов добавьте правило той же формы. Для других цветов в тёмной теме
прикрепите условие `.dark` сами — ядро не поставляет тёмный вариант для этих пяти.

Анимация прогресса крыла загрузки (`--nabi-per`, `--nabi-t`, `--nabi-span`, `--nabi-clear`,
`--nabi-blur-max`) — **внутренняя реализация этого крыла** — имена начинаются с `--nabi-`, но это
не место, открытое для переопределения хостом.

## Внешние размеры — в `rem`

Внешние размеры — кнопки, отступы, чипы панели инструментов и прочее — по большей части в `rem`,
поэтому они **растут вместе с размером шрифта корня (`html`).** Увеличьте текст в браузере или ОС —
и рамка редактора вырастет вместе с ним. Чтобы изменить размер, меняйте `font-size` корня. Граница
(`border`) — это *линия*, а не размер, поэтому местами `px` остаётся.

## Не попасться на специфичность

Чтобы переопределить цветовой или формостный токен, повторите класс **трижды**.

```css
.nabi.nabi.nabi,
.nabi-scrim.nabi-scrim.nabi-scrim {
  --nabi-accent: var(--мой-акцент);
}
```

Если посчитать, получается так. Правило светлых значений по умолчанию `:is(.nabi, …)` имеет
специфичность **(0,1,0)**, поскольку `:is()` берёт наибольшую из своих аргументов; тёмное правило
`:where(html, body).dark :is(.nabi, …)` имеет **(0,2,0)**, поскольку `:where()` считается как ноль,
а `.dark` и `:is()` дают по одному классу каждый. Поэтому `.nabi.nabi` лишь **сравнивается вничью**
с тёмной темой — а при ничьей побеждает загруженное позже, и основная таблица стилей вполне может
загружаться после хостовой. Повторите класс трижды, чтобы получить (0,3,0), и порядок загрузки
перестанет иметь значение.

Оверлей предпросмотра стоит вне `.nabi` (как дочерний элемент `body`), поэтому его селектор нужно
написать рядом, чтобы получить тот же цвет.

**Токену, который ядро не объявляет, например шрифту, вся эта борьба не нужна** — раз места
объявления нет, до него доходит одно лишь наследование, и достаточно одной строки в `:root`.

```css
:root {
  --nabi-font: 'Noto Sans', system-ui, sans-serif;
}
```

## Светлая и тёмная темы

Класс `dark` на `html` **или** `body` означает тёмную тему, `light` — светлую. Без класса по
умолчанию действует светлая, а если есть оба — побеждает явный `light` (правила `.light`
загружаются после правил `.dark`).

```html
<html class="dark"><!-- или <body class="dark"> --></html>
```

Переключите класс — и CSS отреагирует. Вызывать API не нужно. Тема меняет только цветовые
переменные; правила компонентов остаются как есть — стили, написанные вами самостоятельно, тоже
следуют тёмной теме, если используют только переменные `--nabi-*`.

## Два способа подключить таблицу стилей

**① Один файл** — самый распространённый путь. В нём CSS всех крыльев.

```ts
import 'nabi-note/nabi.css'
```

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/nabi-note/dist/nabi.css">
```

**② Внедрить только зарегистрированное** — когда нужны таблицы стилей только тех крыльев, что
реально включены.

```ts
import { collectSheets, injectSheets } from 'nabi-note'

const drop = injectSheets(document, collectSheets(registry))
// вызовите drop(), и уберётся только то, что добавил этот вызов
```

Таблица стилей с одинаковым текстом добавляется **один раз** — ключ, по которому она схлопывается,
это **содержимое** таблицы, так что подъём нескольких редакторов в одном документе никогда не
накапливает дубликаты, а смешение разных наборов крыльев собирается в единое объединение.

:::: tip Две разницы между способами — что несёт и когда подключается
**Что несёт.** Файл не может знать, какие крылья вы зарегистрировали, поэтому несёт **все**.
Внедрение читает `registry` и несёт **только зарегистрированное**. Страница, которая лишь
показывает сохранённый HTML, не имеет редактора и, следовательно, `registry`, поэтому идёт путём
файла.

**Когда подключается.** Файл приходит как `<link>` в `head` и **блокирует отрисовку** до своей
загрузки. Внедрение подключается только **после того, как прибудет JavaScript редактора**. Поэтому
странице, чей документ заранее отрисован на сервере и отправлен вниз, стоит идти путём файла — при
внедрении такой документ сначала на миг отрисуется голым, а затем перестроится и переверстается
заново, когда придёт таблица стилей.
::::

Таблицы стилей зарегистрированных вами крыльев подключаются **после** основной таблицы стилей, так
что при равном приоритете побеждает крыло.

## Что можно нацелить

То, что не решается переменной, нацеливайте на реально существующие классы.

| Селектор | Что это | Кто подключает |
|---|---|---|
| `.nabi` | оболочка, оборачивающая весь редактор (chrome + область письма). Здесь висят токены цвета и формы | хост |
| `.nabi-content[contenteditable]` | сама область письма | хост |
| `.nabi-toolbar` | слот, оборачивающий строку панели инструментов и контекстную строку. Этот класс *и есть* «прилипает сверху» | хост |
| `.nabi-toolbar-row` | контейнер, в котором сидит панель инструментов | `mountToolbar()` |
| `.nabi-context` | контейнер, в котором сидит контекстная строка | `mountContextToolbar()` |
| `.nabi-tools` | слот для кнопок предпросмотра и полноэкранного режима — ядро плавает его вправо вверх | `mountViewTools()` |
| `.nabi-tool` | сами эти две кнопки | `mountViewTools()` |
| `.tb-group` | группа кнопок панели инструментов | `mountToolbar()` |
| `.ctb-group` · `.ctb-button` · `.ctb-swatch` · `.ctb-input` | группы, кнопки, образцы цвета и текстовые поля контекстной строки | `mountContextToolbar()` |
| `.tb-picker` · `.tb-picker-grid` · `.tb-picker-cell` | коробка, открывающаяся под кнопкой, например сетка размера таблицы | `mountToolbar()` |
| `.tb-prompt` · `.tb-prompt-input` | слой ввода адреса, открывающийся при вставке чего-то нового | `mountToolbar()` |
| `.nabi-hints [data-hint]` | значки горячих клавиш от двойного нажатия Shift — сам значок это `::before`, а подпись `::after`, так что оба показываются вместе | `mountHints()` |
| `[data-nabi-tip]` | подсказка (tooltip) — рисуется только через CSS `::after` | ядро повсеместно |
| `.nabi-content.nabi-dropping` | область письма, пока над ней перетаскивают файл. Текст подсказки лежит на атрибуте `data-nabi-drop` | `mountUpload()` |

Предпросмотр и полноэкранный режим тоже **строит ядро**.

| Селектор | Что это | Кто |
|---|---|---|
| `.nabi-scrim` > `.nabi-card` > (`.nabi-close` · `.nabi-content.nabi-preview-body`) | оверлей предпросмотра документа | `openPreview()` |
| `.nabi-scrim` > `.nabi-card.nabi-lightbox` | коробка для просмотра одной картинки крупно | `openImageLightbox()` |
| `.nabi.is-fullscreen` | полноэкранный режим — фиксирует коробку `.nabi` на экране | `setFullscreen()` (имя класса — `FULLSCREEN_CLASS`) |

Подключите `mountViewTools()`, и две кнопки сами открывают и закрывают это. Чтобы открыть
самостоятельно, вызовите `openPreview({ nabi, editor })`,
`openImageLightbox({ editor, src, alt?, locale })`, `setFullscreen(root, on)` или
`isFullscreen(root)`.

::: tip Слот инструментов строит себя сам
`mountViewTools()` **поднимает свою собственную коробку** и добавляет её в начало переданного вами
контейнера — она не превращает этот контейнер в `.nabi-tools`. Поэтому передайте ей саму панель
инструментов, и ничего не сломается: класс, который плавает к правому краю, стоит на собственном
span ядра, идущем первым, а уже имеющиеся в строке кнопки обтекают его.
:::

Можно нацеливаться и на пометки, существующие только на экране редактора — `[data-nabi-token]`
(цвета токенов блока кода), `[data-nabi-lang]` (язык блока кода), `[data-color]` (цвет маркера и
текста — различаются тегами `<mark>` и `<span>`), а также `data-nabi-align`, `data-nabi-typeface`,
`data-nabi-size`, `data-nabi-dropcap` (атрибуты абзаца). Настоящие имена этих пометок задаются
константами `*_ATTR` в файле каждого крыла.

## Отрисовка сохранённого HTML в другом месте

Исходящее значение (`getHtml()`) — это HTML с оставшимися атрибутами `data-nabi-*`, и **без
единого символа инлайнового `style`.** Это значит, что вид целиком — дело таблицы стилей, и
поэтому отрисовка без неё даёт голый HTML без выравнивания, без размеров текста и без линий
таблицы.

Чтобы нарисовать так же, как в редакторе, оберните это в `.nabi-content` — этот класс получает
токены цвета и формы напрямую, без обёртки `.nabi` вокруг (правило
`.nabi-content:where(:not(.nabi *))` в `nabi.css`).

```html
<div class="nabi-content">ваш сохранённый HTML</div>
```

Саму таблицу стилей подключайте способом ① из раздела выше — на странице без редактора нет
`registry`, из которого можно было бы что-то собрать.

### Поведение на стороне чтения — сортировка таблиц

Сейчас как функция только для стороны чтения поставляется **одна лишь сортировка таблиц**. Общей
системы, позволяющей произвольному крылу вешать собственное поведение для стороны чтения, пока
нет.

```ts
import { attachTableSort } from 'nabi-note/viewer'

const detach = attachTableSort(document.querySelector('#article')!, { locale: 'ru' })
```

Находит таблицы с атрибутом `data-nabi-sortable` и вставляет кнопки сортировки в ячейки заголовка.
Функция снятия (`detach`) убирает вставленные кнопки и возвращает изменённый порядок строк.

::: danger Не подключайте к редактируемому элементу
`attachTableSort()` вставляет кнопки в DOM и меняет порядок строк. Сохраните DOM, пока это
подключено, — и это застынет в значении. На стороне чтения подключайте только к копии только для
чтения.
:::
