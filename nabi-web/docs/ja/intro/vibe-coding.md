# AIバイブコーディング

**`llms.txt`** はウェブサイトがAIエージェント(LLM)に内容を渡すために作った規格です。
HTMLの代わりに、エージェントがそのまま読みやすいマークダウンでプロジェクトの構造と
使い方を整理しておきます。詳しい規格は[llmstxt.org](https://llmstxt.org/)にあります。

このサイトもその門を開けています。アドレスを覚える必要はありません — 下の例のように
**エージェントにアドレスだけ渡せば**、残りはエージェントが自分でたどっていきます。

```
https://nabi.saro.me/llms.txt
```

Cursor, Claude Code, OpenAI Codex, Windsurf などは llms.txt 標準をサポートしています。

## 最初に導入するとき

まだ nabi-note を使っていないサイトに最初に取り入れるときは、何を有効にしたいか・
ライト/ダークモードがあるか・配布方式が何かだけ一度に伝えれば、残りはエージェントが
自分で組み立てます。**配布方式だけが違い、残りの文はそのまま使えます** — 下の三つが
分かれるところです。

### npm + サーバーレンダリング(SSR) — リクエストごとにサーバー(Node)で描いて渡す場合

Node バックエンドを自分で立てていても、Next.js・Nuxt・SvelteKit のような SSR
フレームワークを使っていても、これに当たります — どちらもリクエストごとに Node 上で
ドキュメントを描いて渡すのは同じです。

```
私たちのサイトに nabi-note を新しいエディタとして導入したい。説明書は
https://nabi.saro.me/llms.txt を参考にして。サイトにライト/ダークモードがあるから
エディタもそれに合わせて。翼(wing)は標準で提供されるものを全部有効にして。

私たちは Nuxt でサーバーレンダリングをしていて、訪れたらすぐ文章がもう見えるように
サーバーであらかじめ描いて渡したい。npm でインストールして SSR + hydrate で付けて。
```

### npm + ブラウザだけで組み立て(CSR) — バンドラーはあるがサーバーレンダリングは要らない場合

```
私たちのサイトに nabi-note を新しいエディタとして導入したい。説明書は
https://nabi.saro.me/llms.txt を参考にして。サイトにライト/ダークモードがあるから
エディタもそれに合わせて。翼(wing)は標準で提供されるものを全部有効にして。

Vite でビルドするフロントエンドで、サーバーレンダリングは要らない。npm でインストールして
ブラウザだけで組み立てて。
```

### CDN — ビルドツールのない静的ページ

```
私たちのサイトに nabi-note を新しいエディタとして導入したい。説明書は
https://nabi.saro.me/llms.txt を参考にして。サイトにライト/ダークモードがあるから
エディタもそれに合わせて。翼(wing)は標準で提供されるものを全部有効にして。

このページはビルドツールのない静的 HTML だ。`<script>` タグで付けて。
```

::: tip ライト・ダークは別に伝えることがありません
`nabi.css` がライトの既定値・ダーク・明示的なライトの三揃いを全部持っています —
ページの `dark`/`light` クラスをそのままにしておけば、エディタが自然に従います。
ブランドの色だけ変えたければ、`llms/styling.md` も一緒に読ませてください。
:::

三つの例は配布方式だけが違い、残りの文は同じです — エージェントはそれぞれ
`llms/ssr.md`(+`llms/quickstart-npm.md`)・`llms/quickstart-npm.md`・
`llms/quickstart-cdn.md` を見つけて読み、その方式で付けます。

## 機能を直したり足したり抜いたりするとき

すでに付いているところで何かを変えたり足したりするときは、**すぐ実装させるより
まず調べて計画を立てさせる**方が安全です — 特にバックエンドまで関わる機能は
何を準備すべきかから知る必要があります。

### 例 — 調査と計画から

```
アップロード機能を付けたい。https://nabi.saro.me/llms/wings.md と
https://nabi.saro.me/llms/api-reference.md を見て、upload 翼を有効にするには
私たちのバックエンド側に何が必要か(アップロードを受け取るアドレス、許可する拡張子・
容量制限、失敗したときの応答の形など)まず調べて。すぐ実装せずに、何を準備すべきか
計画だけ立てて見せて。
```

エージェントは `llms/wings.md` で `upload` が `Uploader` を受け取る道具(tool)翼だという
ことを、`llms/api-reference.md` で `mountUpload`・`Uploader`・`allowLocalUrls` のような
実際のシグネチャを確認したうえで、バックエンドに開けるべき場所とフロントで決める値を
分けて計画としてまとめます。計画を見て承認したあとに実装を続けさせればいいです。

### もっと簡単な例 — すぐ頼んでいいもの

計画まで要らない狭い修正はすぐに頼んでも構いません。

```
https://nabi.saro.me/llms/styling.md を見て、アクセントカラーと
ダークテーマの背景だけ私たちのブランドカラーに変えて。
```

::: tip 契約を破った翼は登録するその場で投げられます
新しい翼を作らせるときは [`llms/custom-wing.md`](https://nabi.saro.me/llms/custom-wing.md)
も一緒に読ませてください。予約語を名前に使ったり、ノードを立てるのに `toHtml` が
なかったりするようなよくある間違いは、あとで出るのではなく**登録した瞬間に**
投げられます — そのドキュメントの「登録するその場で死にます」節に何が引っかかるか
まとまっています。
:::

::: tip 導入が終わったら一行だけ残しておきましょう
一度付けたら、次から毎回アドレスをまた教える必要はありません。プロジェクトの
ルールファイル(`CLAUDE.md`・`.cursorrules` など)にこう書いておけば、「nabi-note で
〜して」とだけ言ってもエージェントが自分でアドレスを見つけます。

```md
このプロジェクトはエディタとして `nabi-note` を使っています。関連作業の前に
https://nabi.saro.me/llms.txt を先に確認してください。
```
:::
