# లింక్

వచనాన్ని ఎంచుకుని దానికి చిరునామాను జోడించండి. వచనం ఎంచుకోకుండా చిరునామా ఇస్తే, చిరునామానే లింక్ వచనంగా చేరుతుంది. `http://` లేదా `https://` చిరునామా టైప్ చేసి Space లేదా Enter నొక్కినా అది లింక్‌గా మారుతుంది.

లింక్‌లు `http:`, `https:`, అలాగే `.` లేదా `/`తో మొదలయ్యే అదే సైట్ మార్గాలనే నిల్వ చేస్తాయి. `javascript:` లేదా `//example.com` వంటి మూలం స్పష్టంగా తెలియని చిరునామాలు తిరస్కరించబడతాయి. అప్‌లోడ్ సృష్టించిన జోడింపు లింక్‌లు ఫైల్ సమాచారాన్నీ ఉంచుతాయి; వాటిని సాధారణ లింక్‌లా చేతితో సృష్టించలేరు.

## URLలను పేస్ట్ చేయడం

ముందు, వెనుక ఉన్న ఖాళీ అక్షరాలను తీసివేసిన తర్వాత పేస్ట్ చేసిన మొత్తం విషయం చెల్లుబాటు అయ్యే `http://` లేదా `https://` URL అయితే, అది వెంటనే లింక్‌గా చేర్చబడుతుంది. వాక్యాల్లోని URLలు, పలు URLలు ఉన్న పాఠ్యం, సాపేక్ష పాత్‌లు ఇప్పటికే ఉన్న పేస్ట్ ప్రవర్తననే అనుసరిస్తాయి. కోడ్ బ్లాక్‌లలో, లింక్ wing లేని ఎడిటర్‌లలో విషయం పాఠ్యంగానే ఉంటుంది. అసలు ఫార్మాటింగ్‌ను కాపాడటానికి ఎడిటర్ నుంచి కాపీ చేసిన చెల్లుబాటు అయ్యే అంతర్గత క్లిప్‌బోర్డ్ డేటాకు ప్రాధాన్యం ఉంటుంది.

లింక్‌లో కనిపించే పాఠ్యాన్ని నిర్ణయించడానికి `mountSurface()`లోని `onPasteUrl` callbackను ఉపయోగించండి.

| ఆర్గ్యుమెంట్ | విలువ |
| --- | --- |
| `url` | ముందు, వెనుక ఉన్న ఖాళీ అక్షరాలను తీసివేసిన పూర్తి URL |
| `isSameOrigin` | URLలోని ప్రోటోకాల్, హోస్ట్, పోర్ట్ ఎడిటర్ ఉన్న పత్రం యొక్క originతో సరిపోలుతున్నాయా లేదా |
| `path` | `/`తో మొదలయ్యే పాత్, query మరియు fragmentతో సహా. ఉదాహరణ: `/posts/1?a=2#top` |

```ts
const surface = mountSurface({
  nabi,
  registry,
  root: document.querySelector<HTMLElement>('#editor')!,
  onPasteUrl(url, isSameOrigin, path) {
    if (isSameOrigin && path === '/guide') return 'NABI NOTE'
    return url
  },
})
```

తిరిగి ఇచ్చిన స్ట్రింగ్‌లో ఖాళీ అక్షరాలు కాకుండా ఇతర అక్షరాలు ఉంటే, అదే కనిపించే పాఠ్యం అవుతుంది. callback లేకపోతే, ఖాళీ లేదా స్ట్రింగ్ కాని విలువను తిరిగి ఇస్తే, లేదా విఫలమైతే, పేస్ట్ చేసిన URLనే కనిపించే పాఠ్యంగా ఉంచుతుంది. తిరిగి ఇచ్చిన స్ట్రింగ్‌లను ఎప్పుడూ HTMLగా పరిగణించదు; అవి లింక్ చిరునామాను మార్చవు.

callback, `async` ఫంక్షన్‌లు మరియు Promiseలను కూడా మద్దతు ఇస్తుంది. ప్రతిస్పందన కోసం వేచి ఉన్నప్పుడే URL లింక్ వెంటనే చేర్చబడుతుంది; తర్వాత చెల్లుబాటు అయ్యే ఫలితం వస్తే ఆ లింక్‌లో కనిపించే పాఠ్యం మాత్రమే మారుతుంది. ఈలోపు లింక్‌ను సవరించినా లేదా తొలగించినా, కొత్త పత్రాన్ని లోడ్ చేసినా, లేదా surfaceను అన్‌మౌంట్ చేసినా, ఆలస్యంగా వచ్చిన ఫలితాన్ని పట్టించుకోదు.

## CSS శైలులు

సాధారణ లింక్‌లకు `.nabi-content a`, జోడింపు లింక్‌లకు విడిగా `.nabi-content a[data-nabi-file]`తో శైలి ఇవ్వండి.

```css
.article-body a:not([data-nabi-file]) {
  color: var(--nabi-accent);
  text-decoration-thickness: .08em;
  text-underline-offset: .16em;
}

.article-body a[data-nabi-file] {
  display: inline-flex;
  gap: .35em;
  padding: .25em .55em;
  background: var(--nabi-soft);
}
```

జోడింపు లింక్‌లోని `::before`, `::after` భాగాలు చిహ్నం, ఫైల్ పొడిగింపును చూపుతాయి; కాబట్టి సాధారణంగా వాటి `content`ను మార్చడం లేదా తొలగించడం మంచిది కాదు.
