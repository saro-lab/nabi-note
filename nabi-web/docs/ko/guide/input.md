# 입력·IME·캐럿

한글·일본어·중국어처럼 조합 중인 입력은 브라우저가 잠시 DOM을 소유합니다. NABI는 이 구간에서 문서 정규화와 캐럿 보정을 미루고, 조합이 끝난 뒤 모델과 화면을 맞춥니다. 호스트가 이 흐름을 방해하지 않는 것이 가장 중요합니다.

## 입력 흐름

```text
키보드/IME 조합 시작 → 브라우저가 composing DOM 갱신 → 조합 종료
                                           ↓
                          NABI가 정규화·선택 복원·변경 알림
```

## 입력 처리에서 유의할 점

| 할 일 | 이유 |
| --- | --- |
| surface가 만든 편집 DOM을 그대로 유지합니다. | 노드와 선택 경로가 서로 일치해야 합니다. |
| `onChange`에서 즉시 `redrawAll()`을 호출하지 않습니다. | 조합 중인 글자를 덮어쓸 수 있습니다. |
| `[data-key]` 편집 노드의 display와 white-space를 바꾸지 않습니다. | DOM과 트리, 캐럿의 위치 계산이 달라질 수 있습니다. |
| 입력 영역에 생성 pseudo-element를 추가하지 않습니다. | 실제 텍스트 위치를 가릴 수 있습니다. |
| 모바일 입력 글자 크기는 16px 이상으로 유지합니다. | iOS의 자동 확대를 피할 수 있습니다. |

## 드롭캡

게시 화면의 드롭캡은 `::first-letter`를 쓸 수 있지만, 편집 화면에서는 캐럿 위치가 어긋날 수 있습니다. 편집 중에는 첫 grapheme을 실제 표시 전용 span으로 감싼 editor HTML을 사용합니다. 다음을 하지 마세요.

```css
/* 편집 surface 안에서는 금지: 캐럿 좌표와 composing DOM을 바꿀 수 있습니다. */
.nabi-editing [data-nabi-dropcap="1"]::first-letter { /* ... */ }
```

대신 패키지 CSS를 유지하고, 색·간격은 [스타일·로케일](/ko/guide/style)의 `--nabi-*` 토큰으로 바꾸세요.

## 재현을 기록할 때

모바일 입력 오류는 기종만이 아니라 키보드 앱, 언어, 입력 속도, 조합 시작/종료 시점이 중요합니다. 이 네 가지와 실제 입력·결과 문자열, selection 위치를 함께 기록하면 원인을 구분할 수 있습니다.

1. OS와 브라우저, 키보드 앱과 버전을 기록합니다.
2. 입력 언어와 재현 문자열을 기록합니다.
3. 빠르게 입력하거나 삭제한 정확한 순서를 기록합니다.
4. 기대 결과와 실제 결과, 화면상 캐럿과 실제 삽입 위치의 차이를 기록합니다.
