# بناء الكتل وخصائص الفقرة

ما يشغل مكانًا ثلاثة أصناف.

| `place` | ماذا | مثال |
|---|---|---|
| `'void'` | **جسم بلا محتوى داخلي.** لا يستطيع المؤشر الدخول فيه | خط أفقي · صورة · يوتيوب |
| `'container'` | **جسم يحمل نصًّا داخله** | اقتباس · كتلة قابلة للطي · جدول · قائمة · كود |
| `'attr'` | قيمة تُلصَق بالفقرة نفسها. لا يُقام عنصر | عنوان · محاذاة · حرف استهلالي |

---

## الأجسام تعيش داخل فقرة حاضنة

المستند **مصفوفة من الكتل**، ولا يجوز أن يقف في أعلى المستوى إلا الفقرة (`p`). لا
يقف الجسم مباشرة في أعلى المستوى، بل يرتدي **فقرة تحمله وحده**.

```json
[{ "w": "p", "ch": [{ "w": "hr", "ch": [] }] }]
```

هذه الفقرة هي **الفقرة الحاضنة**، وتُرسَم على الشاشة `<div data-nabi-p>`.

سبب هذا اثنان. يظل هناك دائمًا مكان للمؤشر قبل الجسم وبعده (فالفقرة موجودة هناك
دومًا)، و**يستقبل الجسم خصائص الفقرة كالمحاذاة كما هي** — فـ"صورة موسَّطة" هي في
الحقيقة "صورة داخل فقرة موسَّطة".

---

## بناء جسم بلا محتوى داخلي

```ts
import { boxObject, createNabiWith, insertLump, type Command, type Wing } from 'nabi-note'
import 'nabi-note/nabi.css'

const insertStar: Command = (doc, sel, _args, env) => {
  const r = insertLump(doc, sel.focus, { w: 'star', ch: [] }, env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const starWing: Wing = {
  ...boxObject({
    w: 'star',
    toHtml: (_node, _children, ctx) => ctx.element('hr', '', { 'data-nabi-star': '' }),
  }),
  commands: { insertStar },
  button: {
    group: 'insert',
    label: { ar: 'نجمة' },
    action: { kind: 'command', command: 'insertStar' },
  },
}
```

يلبس `insertLump` الفقرة الحاضنة تلقائيًّا.

```
<div data-nabi-p><hr data-nabi-star/></div>
```

إن استُدعي فوق فقرة فارغة **يستبدل تلك الفقرة نفسها** — فلا يبقى سطر فارغ مع كل
إدراج. وتبقى المحاذاة التي كانت تلك الفقرة تحملها كما هي.

ما يملؤه `boxObject` هو `place: 'void'` و**فاحص الخصائص**.

```ts
boxObject({
  w: 'stamp',
  attrs: { c: (v) => (v === 'red' || v === 'blue' ? v : null) },   // القيمة خارج القائمة تسقط
  requires: ['c'],                                                 // بدونها لا يُقام هذا الجسم
  toHtml: /* … */,
})
```

الخاصية غير المكتوبة في `attrs` **خانة مجهولة فتسقط كاملة.** لا مكان تتسلل منه قيمة
خارج العقد إلى القيمة المحفوظة خلسة.

## بناء جسم يحمل محتوى داخليًّا

يجب أن يُكتَب `holds` دائمًا مع `place: 'container'` — بدونه يموت التسجيل.

```ts
import { createNabiWith, toggleWrap, type Command, type Wing } from 'nabi-note'

const toggleNote: Command = (doc, sel, _args, env) => {
  const r = toggleWrap(doc, sel, 'note', env)
  return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',                  // فقرات تعيش بداخله ('inline' لو نص فقط)
  allows: ['p'],                    // ما يمكن أن يدخل هنا
  toHtml: (_node, children, ctx) => ctx.element('aside', children(), { 'data-nabi-note': '' }),
  claim: (el, inner) => (el.tag === 'aside' ? [{ w: 'note', ch: inner(true) }] : null),
  commands: { toggleNote },
  inputRules: [{ trigger: 'space', pattern: /^!$/, run: () => ({ name: 'toggleNote' }) }],
  button: {
    group: 'container',
    label: { ar: 'ملاحظة' },
    action: { kind: 'command', command: 'toggleNote' },
  },
}
```

`toggleWrap` **زر تبديل.** يلفّ الكتل العليا التي يطالها التحديد بهذا الوعاء، وإن
كانت ملفوفة بالكامل بالفعل يفرد المحتوى في مكانه.

```
قبل اللف   [p"سطر أول", p"ثانٍ"]
بعد اللف   [p[ note[ p"سطر أول", p"ثانٍ" ] ]]
الضغط مجددًا  [p"سطر أول", p"ثانٍ"]
```

### `holds`

| | ما يعيش بداخله | مثال |
|---|---|---|
| `'blocks'` | فقرات وأجسام أخرى | اقتباس · كتلة قابلة للطي · خلية جدول |
| `'inline'` | نص وعلامات فقط | سطر ملخّص الكتلة القابلة للطي · الكود |

### `allows`

إن كُتِبت **لا يدخل شيء خارجها.** تضيف النواة مُنظِّمًا تلقائيًّا، فسواء جاء من لصق
أو من قيمة محفوظة، ينزع قشرة ما هو خارج القائمة ويُنزِل نصّه إلى فقرة.

بلا كتابتها الكل مسموح. وإن كُتِب في `allows` اسم مجهول **يموت التسجيل فورًا.**

## `parts` — بنية داخلية بلا زر

بنى **لا تقف وحدها ولا زر لها في شريط الأدوات**، كصفوف الجدول وخلاياه أو سطر
ملخّص الكتلة القابلة للطي، تُصرَّح كأجزاء.

```ts
const detailsWing: Wing = {
  w: 'details',
  place: 'container',
  holds: 'blocks',
  boolAttrs: ['o'],                                   // خاصية قيمتها 1 فقط — هل هي مفتوحة
  parts: { summary: { holds: 'inline' } },            // سطر الملخّص
  toHtml: /* … */,
  partHtml: { summary: /* … */ },                     // يجب أن يكون لكل جزء تجميعه الخاص
  repair: repairDetails,
}
```

أربع قواعد.

- لا يحمل الأجزاء إلا **الحاوية.** كتابتها في `place` آخر يميت التسجيل.
- يجب أن يكون لكل جزء `partHtml`. بدونه يموت التسجيل.
- لا يجوز أن يتطابق اسم الجزء مع اسم جناح أو اسم جزء آخر.
- إن احتاج جزء ترتيبًا اكتبه في `partRepair` باسم ذلك الجزء.

يستقبل `StructureDecl` ثلاثة: `holds` و`singleParagraph` و`boolAttrs`.

### `singleParagraph`

يُثبَّت الداخل على **فقرة واحدة.** هذه حال خلية الجدول — الضغط على <kbd>Enter</kbd>
داخل خلية لا يشطر الفقرة إلى اثنتين، وحذف تحديد يمتد عبر خليتين لا يدمجهما معًا.
هذه الخانة الواحدة هي ما يحفظ الشبكة.

### `boolAttrs`

خصائص قيمتها `1` فقط — `o` (الفتح) في الكتلة القابلة للطي، و`ck` (التحديد) في قائمة
المهام، و`dc` (الحرف الاستهلالي) في الفقرة. الحالة المطفأة ليست `0` بل **غياب
الخانة كليًّا.**

---

## `repair` — البوابة الأخيرة عند مدخل القيمة المحفوظة

يرتّب `repair` هذه العقدة مرة واحدة **قبيل أن يصير JSON مستندًا.**

```ts
repair: (node) => {
  if (!صحيحة(node)) return null    // null — تُنزَع قشرة هذه العقدة كاملة
  return العقدة_المرتَّبة           // يجوز أن تبقى كما هي (إن أجبت بنفس الكائن لا شيء يتغيّر)
}
```

القيمة المحفوظة المعدَّلة يدويًّا، والمستند القادم من إصدار آخر، وJSON الذي بناه
غيرك — كلها تمر بهذه البوابة. لا يصير مستندًا إلا ما عبرها، فهي **الموضع الوحيد
الذي يستطيع فيه الجناح أن يضمن بنفسه شكل عقدته.**

إن كُتِب `allows` مع `repair` معًا يعمل تنظيم `allows` **أولًا** وتصل نتيجته إلى
`repair`.

---

## `requiresAnyOf` — جناح لا يقوم إلا برفيق

```ts
requiresAnyOf: ['img', 'a']
```

إن لم يكن أحد هذين مسجَّلًا معه **يموت التسجيل فورًا.** يستعمل جناح الرفع هذا —
فما يُرفَع يجب أن يُقام صورة أو رابطًا، وإن غاب الاثنان معًا رُفِع الملف دون أن
يمكن فعل شيء به.

---

## خاصية الفقرة (`place: 'attr'`)

خاصية الفقرة لا تُقيم عنصرًا. تضع فقط قيمة واحدة في `a` الخاصة بالفقرة.

```json
{ "w": "p", "a": { "h": 2, "a": "c" }, "ch": ["عنوان 2 موسَّط"] }
```

::: warning الخانات الثلاث مثبَّتة
يجب أن يكون `attrKey` واحدًا من ثلاث فقط: **`h` (العنوان) · `a` (المحاذاة) ·
`dc` (الحرف الاستهلالي)**، وكتابة أي اسم غيرها تميت التسجيل. **لا يمكن في هذا
الإصدار ابتكار خاصية فقرة جديدة** — خانة خصائص الفقرة مغلقة على الثلاث التي
تعرفها النواة.

وللسبب نفسه، هذه الثلاث تشغلها بالفعل `headingWing` و`alignWing` و`dropCapWing`،
فلا مكان عمليًّا لكتابة جناح جديد بـ`place: 'attr'`. إن أردت إلصاق قيمة بكل فقرة
فاختر الآن طريق اللف بحاوية بدلًا من ذلك.
:::

خانتان تتوليان القيمة.

| | |
|---|---|
| `attrValues` | قائمة القيم المقبولة (للعنوان مثلًا `[1,2,3,4,5,6]`) |
| `currentValue` | القيمة التي تحملها هذه الفقرة الآن. يلوّن بها شريط الأدوات والشريط السياقي الخانة المضغوطة |

## مساعدات المستند المُصدَّرة

يُصدِّر هذا الإصدار أربع مساعدات تحرير إلى الخارج.

| | ماذا تفعل |
|---|---|
| `insertLump(doc, caret, lump, env, wrap?)` | يُقيم جسمًا واحدًا مع فقرته الحاضنة |
| `removeLump(doc, topIndex, env)` | يزيل فقرة حاضنة واحدة في أعلى المستوى كاملة |
| `toggleWrap(doc, sel, containerW, env)` | يلفّ الكتل التي يطالها التحديد بوعاء أو يفردها |
| `topNodeAt(doc, path)` | العقدة في أعلى المستوى التي ينتمي إليها هذا المسار |

تجيب الأربعة كلها بـ`{ doc, caret }`، فتُنقَل مرة واحدة إلى الشكل الذي يجيب به
الأمر.

```ts
return { doc: r.doc, selection: { anchor: r.caret, focus: r.caret } }
```

::: tip إن احتجت تحريرًا أدق من هذا
المساعدات الداخلية التي تقطع وتصل على مستوى الحرف (كإلصاق علامة أو كتابة خاصية
فقرة) ليست بعد واجهة برمجية عامة. حتى ذلك الحين يمكنك بناء مصفوفة `doc` جديدة
يدويًّا والإجابة بها — فالمستند الذي تجيب به يُرتَّبه `cocoon` مرة أخرى، فلا يبقى
مستند يخالف القواعد.
:::
