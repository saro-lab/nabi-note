# المفاتيح والتحويل التلقائي واللصق

للجناح ثلاث بوابات يستقبل منها لمسة الإنسان — **المفتاح** (`onKey`)، **الحرف**
(`inputRules`)، **الشاشة** (`attach`).

---

## الطريق الذي يمر به المفتاح

عند الضغط على <kbd>Enter</kbd> يُسأَل بهذا الترتيب. من عالجه أولًا لا يصل إلى من
بعده.

```
① اختصار شريط الأدوات    يُستمَع إليه في أي مكان (كـ Ctrl+B)
② التحويل التلقائي        inputRules — Enter و Space فقط
③ onKey الخاص بالجناح     لصاحب الموضع الذي يقف فيه المؤشر
④ تصويب على جسم           باكسبيس عند بداية فقرة ← يحدَّد الجسم السابق كاملًا
⑤ قاعدة النواة            شطر الفقرة، الحذف، خطوة المؤشر
⑥ المتصفح                فقط إن لم يأخذها أحد حتى هنا
```

---

## `onKey` — اعتراض المفتاح

```ts
import type { OnKey } from 'nabi-note'

const noteKeys: OnKey = (intent, doc, sel, env, owner) => {
  if (intent.key !== 'backspace') return null      // ليس شأني — أعِدها للنواة
  if (sel.focus.offset !== 0) return null
  const first = [...owner.path, 0]
  if (first.length !== sel.focus.path.length) return null
  if (!first.every((v, i) => v === sel.focus.path[i])) return null
  return toggleNote(doc, sel, {}, env)             // باكسبيس عند أول خلية بداية — يفرد الملاحظة
}

const noteWing: Wing = {
  w: 'note',
  place: 'container',
  holds: 'blocks',
  toHtml: (_node, children, ctx) => ctx.element('aside', children()),
  commands: { toggleNote },
  onKey: noteKeys,
}
```

| الوسيط | ما هو |
|---|---|
| `intent` | `{ key, dir? }` — أي مفتاح |
| `doc` · `sel` · `env` | نفسها التي يستقبلها الأمر |
| `owner` | `{ path, node }` — **العقدة التي انتُخِبت أنا صاحبها** |

الجواب مثل الأمر تمامًا: `{ doc, selection }` أو **`null`**. `null` تعني "لم آخذه"
فتتولاه النواة — أجب بـ`null` دائمًا حين لا يتحقق الشرط.

### المفاتيح القادمة

| `intent.key` | متى |
|---|---|
| `'enter'` | <kbd>Enter</kbd> **و**<kbd>Shift</kbd>+<kbd>Enter</kbd> معًا |
| `'tab'` · `'shiftTab'` | <kbd>Tab</kbd> · <kbd>Shift</kbd>+<kbd>Tab</kbd> |
| `'backspace'` · `'delete'` | كلا الحذفين |
| `'arrow'` | السهم. الاتجاه في `intent.dir` (`'left'`·`'right'`·`'up'`·`'down'`) |

مفاتيح الحروف لا تصل. يكتب المتصفح الحرف وتستقبله النواة.

### الصاحب واحد فقط

الصاحب هو الجناح الذي يملك **أول عقدة غير فقرة** تُصادَف بصعود مسار المؤشر إلى
أعلى.

```
مؤشر عند المسار [1, 0, 0]                 المرشّح صاحبًا
  [1, 0, 0]  →  p        فقرة فيُتخطّى
  [1, 0]     →  note     ← هو الصاحب
  [1]        →  p(حاضنة)  لا يصل إلى هنا
```

لذلك **يغلب الوعاء الأعمق دائمًا** — الضغط على <kbd>Tab</kbd> في قائمة داخل جدول
تستقبله القائمة. يمكن للجزء (`parts`) أيضًا أن يكون صاحبًا، وحينها يكون
`owner.node` عقدة ذلك الجزء لكن يُستدعى `onKey` الخاص بالجناح الذي صرّح به. لذلك
جرت العادة أن يُميَّز أولًا بـ`owner.node.w` أيّ عقدة انتُخِبت.

لا يمكن للعلامة أن تكون صاحبًا —
[السبب في صفحة العلامة السطرية](./inline#العلامات-لا-تملك-مفاتيح).

## `inputRules` — البناء من الكتابة وحدها

هذا ما يجعل كتابة `# ` عنوانًا وكتابة `> ` اقتباسًا.

```ts
inputRules: [
  { trigger: 'space', pattern: /^>$/, run: () => ({ name: 'toggleQuote' }) },
]
```

| الخانة | |
|---|---|
| `trigger` | `'space'` أو `'enter'` — يُلتقَط **لحظة** كتابة هذا المفتاح |
| `pattern` | تعبير نمطي (regex). يستقبل `run` تلك المطابقة |
| `run` | `{ name, args? }` — الأمر الذي سيُشغَّل |
| `scope` | `'block'` (الافتراضي) أو `'word'` |

### `'block'` — يستبدل بداية السطر

ينظر إلى **بداية السطر** أمام المؤشر. إن طابقت، يحذف تلك البداية (وحرف المُشغِّل)
ويُشغِّل الأمر.

```
كتابة "> "   →   يُحذَف "&gt;" ويعمل toggleQuote
```

لا يُلتقَط إلا في **أول سطر** من الفقرة. لا يُلتقَط في السطر التالي بعد نزول سطر
بـ<kbd>Shift</kbd>+<kbd>Enter</kbd> — فهذا يمنع ظهور تنسيق مفاجئ وسط نص مكتوب
بالفعل.

### `'word'` — يُلقى على كلمة واحدة

ينظر إلى **كلمة واحدة** أمام المؤشر. إن طابقت، يحدّدها ويُشغِّل الأمر ثم يعيد
المؤشر إلى مكانه. لا يُحذَف النص — هذا هو طريق إلقاء علامة على النص.

إن كانت الكلمة **تحمل بالفعل علامة هذا الجناح فيُتخطّى.** لا يُلتقَط مرتين في نفس
الموضع.

### قواعد مشتركة

- يعمل فقط حين يكون المؤشر **مطويًّا (بلا تحديد).** حتى لو حدَّدت مدى وضغطت مسافة
  لا يُلتقَط.
- يعمل فقط في فقرة عادية — لا يُلتقَط في فقرة حاضنة تحمل جسمًا.
- يُفحَص بترتيب مصفوفة الأجنحة، وتغلب **أول قاعدة تنجح.**
- إن أجاب الأمر بـ`null` (أي لا شيء ليُفعَل) **يُتراجَع ويُنتقَل إلى القاعدة
  التالية.** فلا يبقى أثر لتحويل تلقائي فشل في المستند.

## `attach` — لمس الشاشة

أحيانًا لا تحتاج لتعديل المستند بل للاستماع إلى **ما يحدث على الشاشة** — سحب
لاختيار خلايا جدول، تلوين كود، الضغط على مثلث الطي.

```ts
import type { Attach } from 'nabi-note'

const attachNote: Attach = (host) => {
  const onClick = (ev: MouseEvent): void => { /* … */ }
  host.root.addEventListener('click', onClick)
  return () => host.root.removeEventListener('click', onClick)   // أجب بدالة الفك
}
```

يمنحك `host` ثلاثة.

| | |
|---|---|
| `host.root` | عنصر سطح التحرير |
| `host.nabi` | المحرر. تعديل المستند يتم **عبر الأوامر** فقط |
| `host.pathOfKey(id)` | يحوّل `data-key` على الشاشة إلى مسار في المستند |

يُلصِق `mountSurface` جميع دوال `attach` الخاصة بالأجنحة المسجَّلة معًا، ويستدعي
دوال الفك التي أجابت بها عند الإزالة. **هذا هو المسكن الوحيد الذي يعيش فيه كود
يعرف DOM** — لا تلمس `document` داخل أمر أو `toHtml` أو `repair`.

::: tip إيجاد المستند عبر `data-key`
يضع التجميع المخصَّص للمحرر (`getEditorHtml()`) `data-key` على كل عقدة. ابحث عن
أقرب `[data-key]` من العنصر المضغوط ومرِّره إلى `host.pathOfKey()` فيخرج موضعه في
المستند.
:::

## اللصق وHTML الأولي

اللصق و`setHtml()` واستعادة قيمة محفوظة **كلها تمر ببوابة واحدة.** ما على الجناح
فعله هنا هو `claim` فقط — مشروح في
[`claim` بصفحة العلامة السطرية](./inline#claim).

```
لصق ──────┐
setHtml ──┼→ تحليل → claim الخاص بالجناح → تطابق النواة الافتراضي للوسم → repair → cocoon → مستند
HTML أولي ─┘
```

بلا `claim` **تُنزَع قشرة ذلك الوسم ويبقى النص وحده.** بفضل هذه القاعدة لا يُثبَّت
ترميز غريب منسوخ من محرر آخر في المستند كما هو.

طريق الدخول عبر JSON (`setJson()`) عقدة لا وسم، فليس `claim` هو الحارس بل
`repair`.
