# الاستعمال الأساسي

هذا هو طريق npm. طريق سطر `<script>` واحد بلا أدوات بناء في
[{{ t('menu_intro_cdn') }}](./cdn).

```sh
npm i nabi-note
```

---

## توصيل القطع

يبني المضيف المكان ويعلّق نداءات mount واحدًا واحدًا. ما يلي أدنى تركيب، والأمثلة
التي تظهر في كل صفحة جناح كلها هذا الهيكل نفسه مع جناح أو اثنين مضافين.

```html
<div id="app" class="nabi">
  <div id="chrome" class="nabi-toolbar">
    <div id="toolbar"></div>
    <div id="context"></div>
  </div>
  <div id="editor" class="nabi-content" contenteditable="true"></div>
</div>
```

```ts
import {
  createNabiWith,
  mountSurface,
  mountToolbar,
  mountContextToolbar,
  mountHints,
  mountViewTools,
  mountSticky,
  watchSettle,
  parseNodes,
  boldWing,
  italicWing,
} from 'nabi-note'
import 'nabi-note/nabi.css'

const app = document.querySelector<HTMLElement>('#app')!
const surface = document.querySelector<HTMLElement>('#editor')!

// قائمة الأجنحة تبني معًا معرفة الأصناف والأوامر والمُجمِّع — وذلك هو `registry`
const { nabi, registry } = createNabiWith([boldWing, italicWing], {
  parseHtml: parseNodes,
})

mountSurface({ nabi, registry, root: surface })

const settle = watchSettle(document, { surface })
const shared = { nabi, registry, surface, settle, locale: 'ar' }

const toolbar = mountToolbar({ ...shared, root: document.querySelector<HTMLElement>('#toolbar')! })
const context = mountContextToolbar({ ...shared, root: document.querySelector<HTMLElement>('#context')! })

mountHints({ toolbar, context, root: document.querySelector<HTMLElement>('#chrome')!, surface })
mountViewTools({ nabi, surface, root: app, container: document.querySelector<HTMLElement>('#toolbar')!, locale: 'ar' })
mountSticky({ root: app, surface })

// في كل مرة تتغيّر فيها القيمة — علِّق كودك هنا
// nabi.onChange(() => user_callback(nabi.getHtml()))
```

يبني المضيف المكان، لكن **النواة هي التي تعرف شكل ذلك المكان** — تُلصِق نداءات mount
بنفسها `.nabi-toolbar-row` و`.nabi-context` و`.nabi-editing` بأوعيتها، وتُقيم صندوق
الأدوات بنفسها أيضًا. أي أن المضيف لا يحتاج إلى رسم أي تخطيط، ولذلك لا يحمل الترميز
أعلاه إلا ثلاثة أصناف.

- **`class="nabi"`** — تعيش رموز الألوان والصفحة النمطية داخل هذا وحده. وهو أيضًا
  الصندوق الذي يثبّته ملء الشاشة بأكمله، فيجب أن يكون شريط الأدوات ومنطقة التحرير
  **معًا** داخله.
- **`class="nabi-toolbar"`** — يجمع صف شريط الأدوات والشريط السياقي كتلة واحدة
  **تلتصق أعلى الشاشة (sticky)**. فإن التصقا منفصلَين اهتزّت الشاشة حين يظهر الشريط
  السياقي فيدفع النصّ.
- **`class="nabi-content" contenteditable`** — منطقة التحرير نفسها.

إن كان في الموقع شريط رأس ثابت فاخفضه بمقدار `--nabi-sticky-top`، وإن علّقت
`mountSticky()` قاست النواة مقدار ما دفعته لوحة مفاتيح الجوال من الشاشة وأعادته.

**المضيف هو من يعلّق الصفحة النمطية.** مع أداة تجميع يكفي سطر
`import 'nabi-note/nabi.css'`، وإن أردت حمل CSS الأجنحة المسجَّلة فقط فاستدعِ
`injectSheets(document, collectSheets(registry))`. **اجعل الصفحة المُعَدّة سلفًا
على الخادم تسلك طريق الملف** — فالحقن لا يلتصق إلا بعد وصول جافاسكربت المحرر،
فيُرسَم المستند القادم من الخادم عاريًا مرة واحدة قبل ذلك.

**تلك اللغة نفسها تقرر اتجاه الكتابة أيضًا.** أعطِ العربية (`ar`) أو الأردية (`ur`)
فيُلصَق `dir="rtl"` بجذر ذلك الـ mount فيقف من اليمين إلى اليسار — حتى لو لم تقل
الصفحة شيئًا عبر `<html dir>`. **إن لم تُعطِ `locale` فلا يُمَسّ شيء** — لا يطغى على
مضيف يمسك الاتجاه بيده. تجيب `localeDirection(code)` عن اتجاه أي رمز لغة.

```ts
mountSurface({ nabi, registry, root: surface, locale: 'ar' })   // منطقة التحرير RTL
mountToolbar({ nabi, registry, surface, root: toolbar, locale: 'ar' })   // شريط الأدوات أيضًا كالمرآة
```

تُحدَّد لغة العرض عبر `locale` في كل نداء mount — يبقى نص المستند كما هو وتتغيّر أسماء
شريط الأدوات والشريط السياقي فقط. **يكفي أن يصرّح المضيف باللغة مرة واحدة** — اجمعها
في حزمة واحدة (`shared`) كما في المثال أعلاه ومرّرها لنداءات mount، فحين يقوم شريط
الأدوات يُلصِق `locale` الخاص به بالنواة أيضًا (`nabi.$bindLocale`) فتخرج كلمات
النواة (كالـ toast) باللغة نفسها. أما الأماكن التي لا تستعمل شريط أدوات فتُعطى
`locale` عبر خيار `createNabiWith`. لرسم مُنتقٍ استعمل `LOCALES` (قائمة الرموز)
التي تصدّرها الحزمة.

### نص العنصر النائب في المحرر الفارغ

المحرر الفارغ يُقيم نصًّا خافتًا في سطره الأول. يزول بمجرد دخول حرف واحد، ويعود إن
عاد المحرر فارغًا بعد المحو. **يظهر بلا أي تعليق** — كلماته من قاموس النواة فتتبع لغة
ذلك الـ mount. ويقرر مكانه **اتجاه الكتابة** (يسارًا في LTR، ويمينًا في RTL) — حتى لو
كان ذلك السطر موسَّطًا أو محاذًى لليمين، لا يتبع النص النائب محاذاته.

```ts
mountSurface({ nabi, registry, root: surface, placeholder: 'دوّن ملاحظتك هنا' })
mountSurface({ nabi, registry, root: surface, placeholder: 'سطر أول\nسطر ثانٍ' })   // أسطر عدة
mountSurface({ nabi, registry, root: surface, placeholder: '' })   // بلا نص نائب
```

سطر جديد (`\n`) يصبح سطرًا كما هو. غير أن النص النائب يقف **خارج التدفّق** (لكي لا يدفع
المؤشر)، فإن كانت منطقة التحرير بارتفاع سطر واحد فاض النص النائب المتعدد الأسطر إلى
الأسفل — إن كنت ستكتب أسطرًا عدة فأعطِ منطقة التحرير أدنى ارتفاع يكفيها.

يدخل النص عبر `--nabi-placeholder` في جذر منطقة التحرير، والذي يرسمه هو الصفحة النمطية.
لتغيير اللون أو الطابع عدِّل هذه القاعدة.

```css
.nabi-content.nabi-editing > :is(p, h1, h2, h3, h4, h5, h6):only-child:has(> br:only-child)::before {
  color: #999;
}
```

| التركيب | إلزامي | ماذا يفعل |
|---|---|---|
| `createNabiWith(wings, options?)` | نعم | يُرجِع `{ nabi, registry }`. لا يحتاج DOM. يقبل أيضًا مصفوفة أجنحة، أو باني الاختيار (`wings()`، راجع [{{ t('menu_intro_cdn') }}](./cdn#اختيار-الأجنحة)) |
| `mountSurface({ nabi, registry, root })` | نعم | يوفّق المؤشر وIME والإدخال مع شجرة نابي. يُلصِق أيضًا `attach` الخاص بالأجنحة المسجَّلة |
| `mountToolbar({ nabi, registry, root, surface?, locale? })` | لا | شريط الأدوات الرئيسي. بدونه يظل التحرير ممكنًا مباشرة عبر `applyCommand()` |
| `mountContextToolbar({ nabi, registry, root, surface? })` | لا | الشريط السياقي بحسب مكان المؤشر (صف الجدول وعموده، لغة الكود، عنوان الرابط واسمه، وغيرها) |
| `mountHints({ toolbar, context?, root, surface? })` | لا | شارة الاختصارات التي تظهر بضغط Shift مرتين متتاليتين |
| `mountViewTools({ nabi, surface, root, container, onBody? })` | لا | زرّا المعاينة وملء الشاشة. `root` هو صندوق `.nabi` الذي يثبّته ملء الشاشة، و`onBody` خطّاف يُلصِق وقت تشغيل جانب القراءة في متن المعاينة (أدناه) |
| `mountSticky({ root, surface })` | لا | يُعيد شريط الأدوات الملتصق بمقدار ما دفعته لوحة مفاتيح الجوال من الشاشة |
| `mountPickedMark({ nabi, surface })` | لا | إشارة اختيار صورة أو فيديو (لا يرسمها المتصفح) |
| `mountFile({ nabi, store, name? })` | عند استعمال save·open | الحفظ والفتح كملف `.nabi` |
| `mountLocalHistory({ nabi, storage })` | عند استعمال localHistory | التسجيل في المتصفح كل مدة محددة |
| `mountUpload({ … })` + `mountUploadView({ … })` | عند استعمال upload | تقدّم رفع الملفات بالإفلات أو اللصق أو الاختيار وعرض ذلك |

**لا حاجة لأي mount مستقل للصورة أو صندوق الاختيار أو سحب خلايا الجدول أو تلوين
الكود** — كلها يحملها الجناح عبر `attach` ويُلصِقها `mountSurface` معًا. لتلوين الكود
فقط وصِّل من يتولى التلوين (`makeCodeAttach`، راجع
[{{ t('menu_wing_code') }}](../wing/block/code)).

### يُلصَق وقت تشغيل جانب القراءة في المعاينة

المعاينة HTML ساكن أُلصِق فيه `getHtml()` كما هو، فما يقوم به **جافاسكربت من جهة
القراءة** — كفرز الجدول أو تلوين الكود — لا يلتصق تلقائيًّا. تجمع `attachViewer`
من `nabi-note/viewer` ذلك كله في بوابة واحدة، وخطّاف `onBody` في المعاينة هو مكان
تعليقها — بدِّل سطر `mountViewTools` في التركيب الأدنى أعلاه إلى هذا:

```ts
import { attachViewer } from 'nabi-note/viewer'

mountViewTools({
  nabi,
  surface,
  root: app,
  container: document.querySelector<HTMLElement>('#toolbar')!,
  locale: 'ar',
  onBody: (body) => attachViewer(body, { locale: 'ar' }),
})
```

يُنادى `onBody` حين يقوم متن المعاينة، والدالة التي تعيدها تُنادى حين يُرفَع الغطاء.
عَلِّق **السطر نفسه** (`attachViewer`) على الصفحة المنشورة أيضًا — إذ يجب أن تطابق
المعاينة الصفحة المنشورة، وهذا هو مغزى هذا الخطّاف: تعليق البوابة نفسها على
الاثنين. التفاصيل في [{{ t('menu_intro_cdn') }} ▸ جانب القراءة](./cdn#جانب-القراءة).

يجيب المُجزِّئ المضمَّن افتراضيًّا على تلوين الكود (بلا أي اعتماد خارجي). المضيف
الذي يستعمل مُلوِّنًا كـShiki يمرّر الخطّاف نفسه عبر
`attachViewer(body, { locale, highlight })` — إن كان نفس ما مرَّرته إلى
`makeCodeAttach({ highlight })` لم يختلف لون شاشة التحرير عن شاشة القراءة.

لاستبدال الأجنحة، اجمع هذه القطعة كلها (`unmount()`) وابنِها من جديد — الترميز الذي
كان يحمله الجناح المستبعَد يسقط في مكانه نصًّا صرفًا. عرض هذا الموقع التوضيحي يعمل
بهذا فعلًا — أطفئ رقاقة جناح وأشعلها مجددًا فيُعاد بناء التركيب كله.

متغيّرات CSS من ألوان وأشكال في [{{ t('menu_style_custom') }}](../style/custom).

## المخارج الثلاثة لإخراج المستند

```ts
nabi.getHtml()        // الـ HTML الذي تحفظه وتنشره
nabi.getJson()        // شجرة نابي (JSON)
nabi.getEditorHtml()  // HTML شاشة المحرر الآن (يحمل data-key)
```

**احفظ إحدى الأوليين.** يحمل `getEditorHtml()` علامة خاصة بالشاشة (`data-key`)، فليس
هو القيمة التي تُصدَّر — مكانه رسم المحرر مسبقًا بالعرض من الخادم (SSR).

هذا شكل الـ JSON الصادر. **المستند مصفوفة من الكتل**، ولا وجود لعقدة جذر تلفّها.

```json
[
  {"w":"p","a":{"h":2},"ch":["عنوان"]},
  {"w":"p","ch":["نص ",{"w":"b","ch":["غامق"]}," و ",
    {"w":"a","a":{"href":"https://nabi.saro.me/"},"ch":["رابط"]}]},
  {"w":"p","a":{"a":"c"},"ch":["توسيط"]},
  {"w":"p","ch":[{"w":"ul","ch":[
    {"w":"li","ch":[{"w":"p","ch":["واحد"]}]},
    {"w":"li","ch":[{"w":"p","ch":["اثنان"]}]}]}]}
]
```

قواعد القراءة أربع فقط.

- **`w` هو معرّف الجناح الذي يرسم تلك العقدة.** الكلمتان المحجوزتان هما `p` (فقرة)
  و`br` (سطر) فقط، وما عداهما معرّفات أجنحة سجّلتها — مثل `b` و`ul` و`li`. العنوان
  ليس جناحًا مستقلًّا بل **خاصية للفقرة** (`{"w":"p","a":{"h":2}}`).
- **النص الصرف حرف، والكائن جناح.** لا خانة مستقلة تكتب الصنف.
- **`a` هي القيمة التي يحملها ذلك الجناح** — عنوان الرابط، لون التظليل، مستوى العنوان
  وما شابه. إن لم توجد قيمة لا توجد خانة. وقيمة المحاذاة أيضًا `a` لكنها تقع **داخل**
  هذه الخانة فلا لبس (`{"w":"p","a":{"a":"c"}}` — فقرة موسَّطة).
- **ما يشغل مكان فقرة كالجدول والقائمة والصورة تلفّه فقرة طبقة واحدة** (انظر `ul`
  أعلاه). تلك الفقرة تحمل المحاذاة، وهي ما يمنح المؤشر مكانًا يقف فيه قبل تلك الكتلة
  وبعدها. يخرج في HTML وسمًا `<div data-nabi-p>` — لأن `<p>` لا يستطيع نحويًّا أن
  يحمل جدولًا أو قائمة.

تحمل كل عقدة في الشجرة الدائرة داخليًّا مفتاحًا إضافيًّا هو `_id` — وهو **عنوان داخلي
يشير به المؤشر إلى العقدة**، فيُعاد ترقيمه في معظم التحريرات ويُنزَع عند الخروج (في
المثال أعلاه من 470 إلى 323 بايتًا). والقيمة الخارجة تصلح لإعادة إدخالها مباشرة في
`setJson()`.

## المداخل الأربعة لإدخال المستند

```ts
createNabiWith(wings, { doc })   // البدء بشجرة نابي جاهزة
nabi.setJson(json)               // استبدالها كاملة بشجرة نابي
nabi.setHtml(html)               // استبدالها كاملة بنص HTML
nabi.applyCommand('setHeading', { value: 2 })  // أمر تحرير (البوابة نفسها التي تستعملها الأجنحة)
```

الأربعة كلها **تجيب بنجاح أو فشل كـ`boolean`.** لا ترمي استثناءً، وإن فشلت لا تمسّ
المستند.

| متى تجيب `false` | |
|---|---|
| `setJson` | ليست على شكل شجرة نابي |
| `setHtml` | لم تُوصَّل مهيّئ `parseHtml` (أدناه)، أو التحرير مقفل |
| `applyCommand` | لا يوجد أمر بهذا الاسم، أو **لم يتغيّر شيء** |

السطر الأخير قاعدة بذاتها — **إن لم يتغيّر شيء فالجواب صامت.** إن طبّقت `setHeading`
مجددًا على فقرة هي أصلًا عنوان من المستوى 2 أجاب بـ`false` ولم يترك خلفه نقطة تراجع
ولا إشارة.

المعطى الثالث لـ`applyCommand` هو **اليد التي نادت** — `by` في `applyCommand(name, args?, by?)`
هو `'keyboard' | 'pointer'` (النوع `CommandHand`)، والافتراضي إن لم تُحدَّد هو لوحة المفاتيح.
يظهر الفرق في مكان واحد: أمر تظليل عند مؤشر منطبق يُحجَز إن كانت اليد لوحة مفاتيح (يُطبَّق من
الحرف التالي)، وإن كانت مؤشر إشارة (pointer) أجاب بـ`false` بلا حجز وأخبر بـ toast أن "لا يوجد
ما يُطبَّق عليه". إن بنيت واجهة تنادي الأوامر مباشرة فحدِّد `'pointer'` عند مقبض النقر.

### يحتاج `setHtml` إلى مهيّئ

قراءة الـ HTML تتولاها `DOMParser` الخاصة بالمتصفح. النواة لا تعرف DOM، فتُوصِّل ذلك
المهيّئ عند التصريح.

```ts
import { createNabiWith, parseNodes } from 'nabi-note'

const { nabi } = createNabiWith(wings, { parseHtml: parseNodes })
```

لا يحتاج `setJson` مهيّئًا — يمكن **تلقيم JSON محفوظ كما هو من خادم (Node.js)
مباشرة**. والتجميع (`getHtml`) أيضًا لا يستعمل DOM، فيظل طريق قراءة JSON من الخادم
وتجميع HTML لإرساله مفتوحًا كما هو.

## التنبيهات تخرج عبر toast

خطأ الرفع، وتنبيه السجل المحلي، وعبارة "لا يوجد ما يُطبَّق عليه" وأمثالها كلها
تخرج عبر **طريق toast واحد.** الوعاء الافتراضي تحمله النواة فلا حاجة لتوصيل شيء —
إن قام شريط الأدوات ظهر في مكان ثابت أسفله (لا يتحرك ذلك المكان ولو ظهر الشريط
السياقي واختفى).

- الدرجات ثلاث — `'info' | 'warn' | 'error'`. ليست درجة نجاح أو فشل بل درجة **مدى
  توتر القارئ المطلوب**.
- تُطوى افتراضيًّا بعد ثانية واحدة (تبدأ بالتلاشي قبل انتهائها بنصف ثانية)، وتُغلَق
  بالنقر أيضًا. الحد الافتراضي للقائمة في وقت واحد ثلاثة — فإن زاد العدد طُوي
  الأقل وقتًا متبقيًا أولًا.
- تحمل الرسالة `\n`، وتُرسَم في الوضعين الفاتح والداكن كليهما.

خياران يبدّلان الطابع وخيار يستبدل العرض كله، كلها في `createNabiWith`.

```ts
const { nabi } = createNabiWith(wings, {
  toastMs: 2000,   // مدة البقاء — الافتراضي 1000ms. يمكن للمنادي أن يعلّقها لكل استدعاء
  toastMax: 5,     // الحد الأقصى في وقت واحد — الافتراضي 3
  // الصفحة التي لها نظام تنبيه خاص تستبدل العرض فقط — لا يُرسَم وعاء النواة الافتراضي إطلاقًا
  // toast: (level, message, ms) => user_callback(level, message),
})
```

هذه هي البوابة الوحيدة التي تتكلم بها الأجنحة أيضًا — `nabi.$toast(level, message, ms?)`.
تُحمَل المدة مع الرسالة نفسها، فلا حاجة لتمديد الافتراضي كله لأجل تنبيه طويل واحد.

## طريق سؤال المحرر للمستخدم

عند فتح ملف قد تحتاج سؤالًا كـ"لديك كتابة غير محفوظة. أتريد المتابعة رغم ذلك؟".
تُوصَّل تلك النافذة **مرة واحدة عند التصريح**.

```ts
const { nabi } = createNabiWith(wings, {
  ask: {
    message: (text) => window.alert(text),
    confirm: (text) => window.confirm(text),
  },
})
```

| | الشكل |
|---|---|
| `message` | `(text: string) => void` — رسالة واحدة، لا تستقبل جوابًا |
| `confirm` | `(text: string) => boolean \| Promise<boolean>` — يقبل متزامنًا أو غير متزامن |

**لا تستعمل النواة تلقائيًّا حوارات المتصفح.** فصفحة لها حوارها الخاص لا ينبغي أن
يقتحمها صندوق رمادي، والإضافات (IntelliJ وVS Code) لا تملك `window.confirm` أصلًا.
الأسطر الثلاثة أعلاه يبنيها المضيف.

::: warning إن لم تُوصِّلها فالجواب "لا"
السؤال الذي لا يجيب عنه أحد ليس "نعم" — كإلغاء أو Escape أو إغلاق النافذة تمامًا.
وبما أن هذا الجواب يقرر "أأتخلى عن الكتابة غير المحفوظة وأفتح؟"، فغياب من يسأل يجب
ألا يقود إلى التخلي عنها. وعلى الخادم (Node) أيضًا تمر بهذه القيمة بصمت.
:::

**هذا خاص بمحرر واحد** — ليس عامًّا، فيمكن لمحررَين في صفحة واحدة أن يسألا بطريقتين
مختلفتين. تستقبل الأجنحة الشيء نفسه (`nabi.$ask`) —
[{{ t('menu_wing_custom') }} ▸ الواجهة والسلوك](../wing/custom/ui) يتناول ذلك.

## اسم هذا المحرر و"هل تغيّر"

```ts
nabi.sessionId   // '1755245678901-1x9k3af' — <وقت يونكس>-<nonce>، واحد لكل نسخة
nabi.isChanged() // هل تحرّك المستند منذ آخر خط أساس
```

يُصنَع `sessionId` مرة واحدة ولا يتغيّر. الوقت يقول متى قام هذا المحرر ويُرتَّب به
تلقائيًّا، وnonce يفرّق بين محررَين قاما في نفس الميلي ثانية. اسم تعلّقه على مفاتيح
المسودّة والسجل والحفظ التلقائي.

**ثلاثة أمور فقط ترسم خطًّا أساسيًّا جديدًا لـ`isChanged()`**: إدخال المستند كاملًا
(`createNabiWith({ doc })`، `setJson()`، `setHtml()`)، والإبلاغ بأن الحفظ تم.

```ts
nabi.$markSaved(savedDoc)   // بعد أن يتم الحفظ فعلًا — مرِّر تلك الشجرة التي حُفظت حينها
```

**مرِّر الشجرة كما كانت لحظة الحفظ** (لا الشجرة الحالية). فما تكتبه أثناء استغراق
الحفظ وقتًا طويلًا يجب أن يبقى "متغيّرًا". يستدعي جناح الحفظ (`save`) هذا بعد أن يُكتَب
الملف فعلًا، فحين تحفظ بصيغة `.nabi` يصير `isChanged()` قيمته `false`.

**والتراجع إلى النقطة الأولى يعيده إلى `false` أيضًا** — فشجرة نابي غير قابلة للتغيير
وتُستبدَل كاملة مع كل تحرير، فمعرفة تطابق المستند لا تحتاج مسحًا ولا تجزئة، بل تُعرَف
في مكانها.

```ts
window.addEventListener('beforeunload', (e) => {
  if (nabi.isChanged()) e.preventDefault()
})
```
