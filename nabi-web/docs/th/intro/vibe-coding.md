# AI vibe coding

NABI NOTE มี [`llms.txt`](/llms.txt) สำหรับ AI และเครื่องมืออัตโนมัติ แทนที่จะให้เอเจนต์เดาไลบรารีทั้งหมด ให้เริ่มจากดัชนีนี้และให้มันอ่านเฉพาะเอกสารที่งานนั้นต้องใช้

## พรอมป์ต์สำหรับเริ่มต้น

กรอก framework และฟีเจอร์ที่คุณต้องการในตัวอย่างด้านล่าง

```text
สร้างเครื่องมือแก้ไขด้วย NABI NOTE (nabi-note)
ก่อนอื่นให้อ่าน https://nabi.saro.me/llms.txt แล้วอ่านเฉพาะเอกสารที่จำเป็นสำหรับงานนี้

สภาพแวดล้อม: Vue 3 + TypeScript
ฟีเจอร์: การจัดรูปแบบพื้นฐาน ตาราง รูปภาพ และการอัปโหลด
แหล่งข้อมูลที่บันทึก: NABI TREE JSON
การเผยแพร่: เรนเดอร์ JSON ที่บันทึกไว้เป็น HTML บนเซิร์ฟเวอร์

ใช้เฉพาะ export สาธารณะและ API ที่มีอยู่จริงใน type ที่ติดตั้ง
หลังทำเสร็จ ให้รันการตรวจ type และ build แล้วรายงานไฟล์ที่เปลี่ยนและผลการตรวจสอบ
```

หากเอเจนต์เปิด URL ไม่ได้ ให้ใส่ `llms.txt` และเนื้อหาเอกสารที่ลิงก์และเกี่ยวข้องลงในการสนทนาด้วย

## ชี้ไปยังเฉพาะสิ่งที่จำเป็น

`llms.txt` เป็นดัชนีแบบกระชับ การให้เอเจนต์ดูเฉพาะหน้าที่เกี่ยวข้องมักมีประโยชน์กว่าการส่งเอกสารทุกฉบับพร้อมกัน

- การประกอบด้วย npm: [`quickstart-npm.md`](https://nabi.saro.me/llms/quickstart-npm.md)
- การตั้งค่า CDN: [`quickstart-cdn.md`](https://nabi.saro.me/llms/quickstart-cdn.md)
- การเลือก wing: [`wings.md`](https://nabi.saro.me/llms/wings.md)
- JSON ที่บันทึก HTML และเหตุการณ์เปลี่ยนแปลง: [`document-model.md`](https://nabi.saro.me/llms/document-model.md)
- ขอบเขตการนำเข้า HTML การวาง และการอัปโหลด: [`io-security.md`](https://nabi.saro.me/llms/io-security.md)
- wing แบบกำหนดเองและการเรนเดอร์บนเซิร์ฟเวอร์: [`custom-wing.md`](https://nabi.saro.me/llms/custom-wing.md), [`ssr.md`](https://nabi.saro.me/llms/ssr.md)
- viewer, diff, style และ drop cap: [`viewer-diff.md`](https://nabi.saro.me/llms/viewer-diff.md), [`styling.md`](https://nabi.saro.me/llms/styling.md)
- import และ type ที่แน่นอน: [`api-reference.md`](https://nabi.saro.me/llms/api-reference.md)

## ใส่ข้อกำหนดของผลิตภัณฑ์ด้วย

เอเจนต์ไม่สามารถอนุมานวิธีเก็บข้อมูล นโยบายความปลอดภัย หรือพฤติกรรมการอัปโหลดจากหน้าจอแก้ไขเพียงอย่างเดียวได้ ระบุ framework ที่ใช้จริง wing ที่รวมและไม่รวมไว้ JSON และ HTML ถูกเก็บหรือไม่ ข้อตกลง request และ response ของ endpoint อัปโหลด ข้อจำกัดไฟล์ และหน้าที่เผยแพร่ต้องใช้ SSR พฤติกรรม viewer หรือ diff หรือไม่

สำหรับสิ่งที่ยังไม่ตัดสินใจ ให้ขอให้เอเจนต์อธิบายตัวเลือกและผลกระทบก่อนเลือกนำไปใช้

## ตรวจทานผลลัพธ์

ตรวจทานโค้ดที่สร้างขึ้นเช่นเดียวกับโค้ดทั่วไป โดยเฉพาะให้ตรวจว่ามัน:

- โหลด `nabi-note/nabi.css` ให้ทั้งการแก้ไขและเนื้อหาที่เผยแพร่
- ใช้ `registry` เดียวกันสำหรับ wing ที่เลือกและทุก mount
- เก็บ `getJson()` และไม่เก็บ `getEditorHtml()`
- ไม่เขียนลง `innerHTML` ของ element `.nabi-content` ที่กำลังแก้ไขโดยตรง
- unmount ทุก mount เมื่อปิดหน้าจอ
- ตรวจสอบ MIME type ขนาด สิทธิ์ และตำแหน่งจัดเก็บบนเซิร์ฟเวอร์อัปโหลด
- ใช้ลำดับ wing และตัวเลือกที่มีผลต่อ HTML ตรงกันบนเซิร์ฟเวอร์และเบราว์เซอร์
- ยืนยันชื่อ export ที่มีจริงด้วยการตรวจ type การทดสอบ และ build

พฤติกรรม IME และ caret รวมถึงเส้นทางบันทึกและโหลด ต้องตรวจสอบจริงแม้หน้าจะดูทำงานได้ครั้งหนึ่งแล้ว ให้ทดสอบการป้อนแบบ composition บนมือถือรวมทั้งการกู้คืนเอกสารที่บันทึก

## ให้ความสำคัญกับเวอร์ชันที่ติดตั้ง

เมื่อโปรเจ็กต์ติดตั้ง `nabi-note` อยู่แล้ว export ใน `package.json` และ type declaration ของมันเกี่ยวข้องโดยตรงกว่าหน้าเว็บที่สร้างสำหรับรุ่นอื่น ขอให้เอเจนต์ตรวจสอบความต่างของเวอร์ชันนั้นก่อนเขียนโค้ด
